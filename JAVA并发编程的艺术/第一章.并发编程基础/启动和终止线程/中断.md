### 一、中断的本质

中断可以理解为线程的一个 ==**标识符属性**==，它表示一个运行中的线程是否被其他线程执行了中断操作。中断机制是 Java 中实现线程间协作的一种优雅方式，与 `stop()` 方法直接强制终止线程不同，中断只是"建议"目标线程停止，目标线程完全可以自行决定如何处理这个中断信号。

中断操作通过 ==**`interrupt()`**== 方法执行。当线程 A 调用线程 B 的 `interrupt()` 方法时，线程 B 的中断状态会被设置为 `true`，但 B 并不会立即停止运行。

### 二、检查中断状态

线程可以通过以下方法检查自身是否被中断：

| 方法                             | 类型   | 是否清除中断标志    | 说明                                     |
| ------------------------------ | ---- | ----------- | -------------------------------------- |
| ==**`isInterrupted()`**==      | 实例方法 | ==**不清除**== | 检查调用对象的中断状态，多次调用返回值不变                  |
| ==**`Thread.interrupted()`**== | 静态方法 | ==**清除**==  | 检查**当前执行线程**的中断状态，调用后会将中断标志重置为 `false` |

**面试要点**：`Thread.interrupted()` 是一个非常有用的方法，它既检查了中断状态，又清除中断标志，为后续的检查提供了一个干净的起点。但要注意，==它只能检查当前正在执行代码的线程，不能用于检查其他线程==。

### 三、终端状态下检查中断标志

如果线程已经处于 ==**终止状态**==（`TERMINATED`），即使该线程曾经被中断过，调用该线程对象的 `isInterrupted()` 也会返回 `false`。这是因为线程结束后，中断状态失去了意义，JVM 会自动清理这个标志位。

### 四、阻塞状态下被中断

当线程处于阻塞状态（如调用 `Object.wait()`、`Thread.sleep()`、`Thread.join()` 或 `BlockingQueue.take()` 等方法）时，如果其他线程调用该线程的 `interrupt()` 方法，目标线程会立即被唤醒并抛出 ==**`InterruptedException`**==。

关键细节：==**在抛出 `InterruptedException` 之前，JVM 会先将该线程的中断标识位清除，然后再抛出异常。**== 因此，在 `catch` 块中调用 `isInterrupted()` 会返回 `false`。

**设计原因**：这种设计赋予了 `InterruptedException` 更高的优先级。当线程因为中断而醒来时，它面对的是一个"干净"的状态，可以重新决定自己的去向。

### 五、完整流程图

**线程 A 调用线程 B 的 interrupt()**
        **↓**
**线程 B 的中断标志被设为 true**
        **↓**
    **┌── B 处于运行状态 → 中断标志保持 true，B 通过 isInterrupted() 检查并自行处理**
    **│**
    **└── B 处于阻塞状态（sleep/wait/join/take）**
            **↓**
        **抛出 InterruptedException**
            **↓**
        **抛出前，JVM 自动清除中断标志（置为 false）**
            **↓**
        **B 在 catch 块中捕获异常并决定后续行为**

### 六、最佳实践：中断后恢复中断状态

**当代码捕获了 `InterruptedException` 但又无法在此层级彻底处理时，应该恢复中断状态，让上层调用者感知到中断请求：**
try {
    Thread.sleep(1000);
} catch (InterruptedException e) {
    // 恢复中断状态
    Thread.currentThread().interrupt();
    // 或者抛出不可检查的异常让上层处理
}

**面试要点**：直接 `catch` 了 `InterruptedException` 但不做任何处理（空 catch 块），也不恢复中断状态，是常见的错误做法。这会导致上层调用者无法感知到中断请求，破坏了线程间协作的语义。
