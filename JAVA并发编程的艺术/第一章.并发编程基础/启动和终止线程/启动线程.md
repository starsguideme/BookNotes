### 一、`start()` 方法的真正含义

调用 `start()` 方法后，当前线程（父线程）会通知 JVM **创建一个新的操作系统线程**。具体什么时候执行 `run()` 方法，由**操作系统调度**决定，不由父线程控制。
父线程调用 t1.start()
        ↓
JVM 创建对应的 OS 线程，新线程进入就绪状态
        ↓
父线程继续向下执行（不阻塞，不等待 t1 结束）
        ↓
t1 的 run() 方法何时执行 → 由 OS 线程调度器决定

### 二、为什么不保证立即执行？

线程启动后需要经历以下过程：

| 步骤                      | 说明                                         |
| ----------------------- | ------------------------------------------ |
| ==**1. JVM 创建 OS 线程**== | ==`start()` 最终调用 `native` 方法，创建真正的操作系统线程== |
| ==**2. 线程进入就绪状态**==     | 新线程创建完毕后，进入就绪队列等待 CPU 调度                   |
| ==**3. 操作系统调度**==       | 何时真正执行 `run()`，完全由操作系统的线程调度器决定             |

**面试要点**：多次调用 `start()` 创建的多个线程，其启动顺序与执行顺序没有必然联系，根本原因在于**操作系统的调度策略**(一般是时间片的方式调度)。

### 三、`start()` 方法的完整流程

**① 父线程调用 t1.start()**
        **↓**
**② JVM 检查线程状态是否为 NEW（未启动过）**
   **→ 如果不是 NEW，抛出 IllegalThreadStateException**
        **↓**
**③ 将线程加入线程组**
        **↓**
**④ JVM 调用本地方法，创建操作系统线程**
        **↓**
**⑤ 新线程进入就绪状态，等待 CPU 调度**
        **↓**
**⑥ 父线程立即返回，继续执行后续代码**
   **（不会等待 t1 执行完毕）**

### 四、命名线程

在线程启动之前，使用 ==**`setName(String name)`**== 方法为线程设置一个有意义的名字。这样在使用 `jstack`、`Thread.getAllStackTraces()` 等工具排查死锁或 CPU 飙高时，能快速定位问题线程。

**反面教材**：日志里全是 `Thread-0`、`Thread-1`、`Thread-2`，出问题时根本不知道是哪个业务模块创建的线程。

**最佳实践**：线程名采用 `业务模块-功能-编号` 格式，如 `order-pool-1`。

### 五、面试追问

**Q：`start()` 可以调用多次吗？**

不能。线程状态一旦从 `NEW` 变为 `RUNNABLE` 后，再次调用 `start()` 会抛出 `IllegalThreadStateException`。一个线程对象只能启动一次。

**Q：直接调用 `run()` 和 `start()` 有什么区别？**

`run()` 只是一个普通的方法调用，在当前线程中同步执行，不会创建新线程。`start()` 会创建一个新的操作系统线程，并在那个新线程中异步执行 `run()` 方法。
