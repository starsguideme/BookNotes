### 一、构造线程对象

在运行线程之前，需要先通过 `new Thread()` 构造一个线程对象。构造时可以显式传入或由系统默认设置线程所需的各种属性：

| 属性                        | 说明                         |
| ------------------------- | -------------------------- |
| ==**线程组 (ThreadGroup)**== | 线程所属的线程组，用于批量管理线程          |
| ==**线程优先级 (Priority)**==  | 优先级范围1-10，默认为5             |
| ==**是否为守护线程 (Daemon)**==  | `true` 为守护线程，`false` 为用户线程 |
| **线程名字 (Name)**           | 默认格式为 `"Thread-" + 自增数字`   |
| **Runnable 任务**           | 线程要执行的任务逻辑                 |

### 二、构造流程

**当你调用 `new Thread()` 时，构造方法内部会经历以下流程：**
**① 调用 init() 方法开始初始化**
        **↓**
**② 获取当前正在执行的线程作为父线程**
   **（谁创建了这个新线程，谁就是父线程）**
        **↓**
**③ 将新线程的 daemon 属性、priority 属性设置为父线程的对应属性**
   **（子线程默认继承父线程的这些属性）**
        **↓**
**④ 将父线程的 inheritableThreadLocals 复制到新线程中**
   **（InheritableThreadLocal 的值由此传递给子线程）**
        **↓**
**⑤ 分配一个全局唯一的线程 ID（tid）**
   **（通过静态变量 threadSeqNumber 自增生成）**

### 三、关键特性

- ==**默认继承父线程属性**==：在构造阶段，新线程的 `daemon` 和 `priority` 属性默认直接继承自父线程。如果需要自定义，可以在构造后通过 `setDaemon()` 和 `setPriority()` 修改。
    
- ==**只是构造，还未启动**==：`new Thread()` 仅仅在 JVM 内部创建了一个 Java 对象，此时尚未与操作系统线程关联。**真正的 OS 线程创建发生在调用 `start()` 方法之后。**
    

### 四、面试追问应对

**Q：如果父线程是守护线程，子线程默认也是守护线程吗？**

> ==**是的。**== 子线程的 `daemon` 属性默认继承父线程。因此，如果用守护线程来创建子线程，所有默认的子线程也都会是守护线程。**如果希望子线程是用户线程，必须显式调用 `setDaemon(false)`**。

**Q：线程 ID 是唯一的吗？线程名字呢？**

> ==**线程 ID 在 JVM 的生命周期内是全局唯一的**==，即使线程结束后也不会被重用。线程名字默认是 `"Thread-0"`、`"Thread-1"` 这种自增格式，但可以通过 `setName()` 手动修改，可能重复。

**Q：`new Thread()` 和 `start()` 的核心区别是什么？**

> `new Thread()` 只是在 Java 堆中创建了一个线程对象，没有与 OS 线程关联。`start()` 才会真正创建一个 OS 线程，并让这个 OS 线程去执行 `run()` 方法。如果直接调用 `run()`，只是执行了一个普通方法，不会启动新线程。
