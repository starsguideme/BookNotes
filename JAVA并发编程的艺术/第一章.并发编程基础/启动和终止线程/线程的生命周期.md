### 一、构造线程

在线程启动之前，可以通过 `new Thread()` 方法先构造一个线程对象。一个线程对象在构造时需要提供五个核心属性：

|属性|说明|
|---|---|
|==**线程组 (ThreadGroup)**==|线程所属的线程组，用于批量管理线程|
|==**线程名 (Name)**==|默认格式为 `"Thread-" + 自增数字`，可通过 `setName()` 设置|
|==**线程优先级 (Priority)**==|范围 1~10，默认继承父线程的优先级|
|==**守护线程 (Daemon)**==|`true` 为守护线程，`false` 为用户线程|
|==**可执行函数 (Runnable)**==|线程要执行的任务逻辑|

构造流程：

① 调用 init() 方法开始初始化
        ↓
② 获取当前正在执行的线程作为父线程
   （谁创建了这个新线程，谁就是父线程）
        ↓
③ 将新线程的 daemon 属性、priority 属性设置为父线程的对应属性
   （子线程默认继承父线程的这些属性）
        ↓
④ 将父线程的 inheritableThreadLocals 复制到新线程中
   （InheritableThreadLocal 的值由此传递给子线程）
        ↓
⑤ 分配一个全局唯一的线程 ID（tid）
   （通过静态变量 threadSeqNumber 自增生成）

详见：[[构造线程]]

**面试要点**：`new Thread()` 只是在 Java 堆中创建了一个 Java 对象，此时尚未与操作系统线程关联。真正的 OS 线程创建发生在调用 `start()` 方法之后。如果父线程是守护线程，子线程默认也是守护线程，需要显式调用 `setDaemon(false)` 才能改为用户线程。

### 二、启动线程

初始化线程之后，就来到了启动线程阶段。调用 `start()` 方法后，JVM 会创建一个新的操作系统线程，但线程并不会立即执行——线程的启动由操作系统的**时间片调度**决定。

关键要点：

- 线程的启动顺序与执行顺序没有必然联系，完全由操作系统调度器决定。
    
- ==**`start()` 方法只能调用一次**==。一旦启动，线程状态就从 `NEW` 变为 `RUNNABLE`，再次调用 `start()` 会抛出 `IllegalThreadStateException`。一个线程对象只能使用一次，无法复用。
    

详见：[[启动线程]]

### 三、中断线程

在线程的运行过程中，可能会由于错误或意外情况需要中断某个线程。中断机制通过 `interrupt()` 方法实现：

- `interrupt()` 并不强制终止线程，而是为要关闭的线程**附上一个标识符**（设置中断标志为 `true`）。
    
- 线程通过 `isInterrupted()` 检查自身是否被中断，然后自行决定如何响应。
    
- 如果线程处于阻塞状态（`sleep`、`wait`、`join`），被中断时会抛出 `InterruptedException`，JVM 在抛出异常前会**自动清除中断标志**。
    

核心原理：==**中断是"建议"而不是"命令"，线程有权决定自己的退出时机，在退出前完成必要的清理工作。**==

详见：[[中断]]

### 四、线程调用的反例

在线程的使用过程中，存在三种已被标记为过时的方法，它们会导致严重的问题：

|方法|作用|问题|
|---|---|---|
|==**`suspend()`**==|暂停线程|暂停线程但**不释放锁**，可能导致死锁；与 `resume()` 存在竞态条件，可能造成线程永久挂起|
|==**`resume()`**==|恢复被暂停的线程|如果 `resume()` 先于 `suspend()` 执行，线程将错过唤醒信号，永久挂起|
|==**`stop()`**==|强制终止线程|强制释放所有锁，但线程执行了一半的操作可能导致数据不一致，**破坏原子性**|

这些错误轻则导致线程阻塞，重则丢失重要资源，破坏线程之间的原子性，甚至直接造成**死锁问题**。这也是为什么在同一个同步方法中，使用 `Lock` 时要始终在 `finally` 块中释放锁，使用 `synchronized` 时要尽量缩小同步块的范围——避免出现锁未释放导致的阻塞。

详见：[[线程调用的反例]]

### 五、线程的正确终止方式

与过时方法不同，正确的线程终止方式采用了**协作式**设计：

|方式|原理|适用场景|
|---|---|---|
|==**中断机制**==|`interrupt()` 设置中断标志，线程通过 `isInterrupted()` 检查并自行决定退出时机|线程中有可响应中断的阻塞操作（`sleep`、`wait`、`BlockingQueue.take()`）|
|==**布尔变量**==|使用 `volatile boolean` 标志位，线程在循环中检查该标志决定是否退出|纯计算任务，没有阻塞操作|

==**两者结合使用**==是最安全的方式，覆盖所有任务场景。核心思想是：由目标线程自行决定退出的时机，在退出前完成必要的清理工作（关闭文件、释放连接等），而不是被其他线程强制终止。

详见：[[正确的调用线程]]

### 六、线程生命周期总览



**NEW（线程对象创建，还未 start）**
        **↓ 调用 start()**
**RUNNABLE（就绪或运行中，由 OS 调度）**
        **↓**
    **┌── 正常执行完毕 ──────────→ TERMINATED（终止）**
    **│**
    **├── 调用 wait() ──────────→ WAITING（无限等待，直到 notify/notifyAll）**
    **│**
    **├── 调用 wait(timeout) ──→ TIMED_WAITING（超时等待）**
    **│     或 sleep(timeout)**
    **│**
    **├── 被 synchronized 阻塞 ─→ BLOCKED（等待获取锁）**
    **│**
    **└── 调用 interrupt() ─────→ 抛出 InterruptedException 或检查标志位**
                                 **线程自行决定是否终止**
