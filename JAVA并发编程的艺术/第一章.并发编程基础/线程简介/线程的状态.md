#### 1. **NEW（初始状态）**

- 线程对象被创建，但**还没有调用 `start()` 方法**。
    
- 此时它只是一个普通的 Java 对象，操作系统层面还没有对应的线程。
    

#### 2. **RUNNABLE（运行状态）**

- Java 把操作系统中的**就绪**和**运行中**两种状态统一叫 `RUNNABLE`。
    
- 处于此状态的线程**可能正在执行**，也**可能在等待操作系统分配时间片**，这两者在 Java 层面无法区分。
    

#### 3. **BLOCKED（阻塞状态）**

- 线程**在等待进入 `synchronized` 方法或代码块**时就是这个状态。
    
- 本质是**在等一个监视器锁**，试图获取一个被其他线程持有的锁。
    

#### 4. **WAITING（等待状态）**

- 进入方式：调用没有超时参数的 `Object.wait()`、`Thread.join()`、`LockSupport.park()` 等方法。
    
- 特点：**需要其他线程显式唤醒**（如 `notify()`/`notifyAll()`），否则会无限等待。
    

#### 5. **TIMED_WAITING（超时等待状态）**

- 进入方式：调用带超时参数的方法，如 `Thread.sleep(long)`、`Object.wait(long)`、`Thread.join(long)`、`LockSupport.parkNanos()` 等。
    
- 特点：**无需显式唤醒**，超时后会自动返回，比 `WAITING` 多了一个超时保护。
    

#### 6. **TERMINATED（终止状态）**

- 线程的 `run()` 方法**正常执行完毕**，或者因为**未捕获的异常**而意外终止。

**7. 补充**
- java将OS中的**运行和就绪合并为运行状态**，阻塞状态是线程阻塞在使用`synchronized` 关键字修饰的方法或代码块(获取锁)时的状态，但是阻塞在java的并发包中，LOCK接口是等待状态，因为java的并发包中LOCK的接口实现使用了LockSupport类中的相关方法
