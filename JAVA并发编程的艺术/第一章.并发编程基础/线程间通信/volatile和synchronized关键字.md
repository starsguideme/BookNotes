### 一、`volatile`

**1. 定义**

`volatile` 可以用来修饰字段，告知程序任何对该变量的访问均需要**从共享内存中获取**，而对它的改变必须**同步刷新回共享内存**。它能保证线程的**可见性**。

**2. 运作机制**

被 `volatile` 修饰的变量会直接存储在共享内存中。当某个线程修改了这个变量时，新值会被立即刷回共享内存，让其他线程看到最新的值。其他线程在读取该变量时，也会直接从共享内存中获取，而不是使用自己线程内部的缓存副本。

**3. 性能影响**

当对被 `volatile` 修饰的字段进行修改时，需要让其他在共享内存中的线程看到这个修改，得知这个修改之后再进行下一步操作。所以当共享内存中被 `volatile` 修饰的数据过多时，会因为频繁的缓存一致性协议通信而**影响效率**。

**4. `volatile` 的局限性**

`volatile` 只能保证**可见性**，不能保证**原子性**。例如 `count++` 这种复合操作（读取-修改-写入），即使 `count` 被 `volatile` 修饰，多个线程同时执行仍然会出现数据不一致。

### 二、`synchronized`

**1. 定义**

`synchronized` 可以修饰方法或以同步块的形式来使用，它主要确保在同一时刻只能有一个线程处于方法或同步块中，从而保证线程对变量访问的**可见性**与**排他性**。

**2. 底层实现**

`synchronized` 的底层实现依赖于 **Monitor（监视器）**：

- **同步块**：使用 `monitorenter` 和 `monitorexit` 指令来实现。进入同步块时执行 `monitorenter`，退出时执行 `monitorexit`。
    
- **同步方法**：依靠方法修饰符上的 `ACC_SYNCHRONIZED` 标志位来判断，无需显式插入指令。
    

但无论哪种形式，本质都是对一个对象的 Monitor 进行获取，这个获取是**排他**的。任何一个 Java 对象都有自己的 Monitor。当对象被同步块或同步方法调用时，执行方法的线程必须先获取该对象的 Monitor 才能进入，没有获取到的线程就会进入**阻塞状态（BLOCKED）**，直到持有 Monitor 的线程释放。

**3. 对象、Monitor、同步队列与线程的关系**

**任意 Java 对象**
    **↓  关联**
**一个 Monitor（监视器）**
    **↓  管理**
**一个同步队列（EntryList）**
    **↓  存放**
**所有等待获取该对象 Monitor 的线程（处于 BLOCKED 状态）**
    **↓**
**持有 Monitor 的线程执行完后，通过退出命令释放 Monitor**
    **↓**
**Monitor 通知同步队列中的下一个线程获取锁**

**4. `synchronized` 与 `volatile` 的核心区别**

`volatile` 解决的是**可见性**问题，适合一写多读场景；`synchronized` 同时解决**可见性**和**原子性**问题，适合对代码块进行整体加锁的场景。两者解决的是不同层级的问题，在实际开发中经常配合使用。
