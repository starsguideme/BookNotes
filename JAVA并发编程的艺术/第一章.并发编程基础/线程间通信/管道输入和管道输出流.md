### 一、什么是管道流

管道输入/输出流和普通的文件输入/输出流或网络输入/输出流最大的不同在于：它主要用于**线程之间的数据传输**，而传输的媒介是**内存**。

在生产者-消费者模式中，管道流提供了一种**基于流的通信方式**。一个线程通过管道输出流写入数据，另一个线程通过管道输入流读取数据，两个线程通过共享的管道缓冲区实现数据传递。

### 二、四种管道流实现

管道流分为四种实现，按数据类型可以分成两组：

| 组别          | 输出流                 | 输入流                | 处理类型            |
| ----------- | ------------------- | ------------------ | --------------- |
| ==**字节流**== | `PipedOutputStream` | `PipedInputStream` | 处理**字节**（二进制数据） |
| ==**字符流**== | `PipedWriter`       | `PipedReader`      | 处理**字符**（文本数据）  |

- `PipedOutputStream` / `PipedInputStream` → 处理**字节**，即二进制数据。
    
- `PipedWriter` / `PipedReader` → 处理**字符**，即文本数据。后缀带 `Reader/Writer` 的是字符流，带 `InputStream/OutputStream` 的是字节流。
    

### 三、管道流的使用方式

管道流使用时必须将输入流和输出流进行**连接**，有两种连接方式：

**方式一：通过构造函数连接**


PipedWriter writer = new PipedWriter();
PipedReader reader = new PipedReader(writer);

**方式二：通过 `connect()` 方法连接**
PipedWriter writer = new PipedWriter();
PipedReader reader = new PipedReader();
reader.connect(writer);    // 或 writer.connect(reader);

### 四、管道流的运行机制

管道流内部维护了一个**循环缓冲区**（默认大小为 1024 字节），写入操作会将数据放入缓冲区，读取操作从缓冲区中取出数据。当缓冲区为空时，读操作会**阻塞**等待；当缓冲区已满时，写操作会**阻塞**等待。这种内置的阻塞机制使得管道流天然适合生产者-消费者场景，无需额外使用 `wait/notify` 来控制流量。

### 五、面试要点

**Q：管道流和 BlockingQueue 在生产者-消费者模式中有什么区别？**

| 维度        | 管道流                     | `BlockingQueue`  |
| --------- | ----------------------- | ---------------- |
| **数据形式**  | **字节流/字符流，以流式数据为导向**    | **对象，以消息为导向**    |
| **适用场景**  | **线程间传输原始字节或字符**        | **线程间传递结构化对象**   |
| **实现复杂度** | **简单，直接操作流**            | **更灵活，支持多种阻塞策略** |
| **底层机制**  | **内置循环缓冲区，满则阻塞写，空则阻塞读** | **基于锁和条件变量实现**   |

**Q：使用管道流需要注意什么？**

管道流必须在**不同的线程**中使用。如果读写两端在同一个线程中，会形成"自己写、自己读"的闭环，一旦缓冲区为空或已满，该线程就会**死锁**。

**Q：为什么管道流需要 `connect()` 或构造时绑定？**

管道流是单工的——数据从写端流向读端。`connect()` 负责在内部建立写端和读端之间的共享缓冲区，并检查两端是否属于同一个线程（同线程会抛出异常，防止死锁）。没有 `connect()`，写端和读端就没有共享的缓冲区，无法传递数据。
