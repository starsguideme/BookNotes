### 一、为什么需要线程池

服务端程序经常面对客户端发来的大量小额任务，需要快速处理后返回相应的结果。如果服务器每次接收到一个任务就创建一个新线程，会带来两个严重问题：

- ==**频繁的上下文切换**==：线程数量逐步增加，CPU 需要在大量线程之间来回切换，切换开销会严重影响处理效率。
    
- ==**线程创建与销毁开销**==：每个线程的创建和销毁都需要系统调用和内存分配，对于执行时间很短的任务来说，创建线程的开销可能比任务本身还要大。
    

### 二、线程池如何解决这个问题

线程池预先创建若干数量的线程，将它们放入一个"池子"中统一管理。用户不能直接控制线程的创建，只能将任务提交给线程池，由池中的工作者线程来执行。通过固定数目的线程来复用，可以有效减少频繁创建和销毁线程的资源开销。

### 三、线程池的接口定义
public interface ThreadPool {
    // 提交任务给线程池执行
    void execute(Job job);
    // 关闭线程池，停止接受新任务
    void shutdown();
    // 增加工作者线程
    void addWorkers(int num);
    // 减少工作者线程
    void removeWorker(int num);
    // 获取当前等待处理的任务数量
    int getJobSize();
}

**客户端通过 `execute(Job)` 方法将任务提交给线程池执行，客户端自身不需要等待任务执行完成。** 除了 `execute(Job)` 方法以外，线程池还提供了增加或减少工作者线程的方法。工作者线程是线程池中重复执行任务的线程，而每个提交的任务都会进入一个工作队列中等待工作者线程的处理。

### 四、线程池的本质

线程池的本质是一个**线程安全的工作队列连接工作者线程和客户端线程**。具体协作模式如下：

- **客户端线程**：将任务放入工作队列的尾部。
    
- **工作者线程**：不断从工作队列中取出任务并执行。
    
- **队列为空时**：所有工作者线程都在工作队列上等待（`wait()`）。
    
- **有任务提交时**：通知任意一个工作者线程（`notify()`），随着大量任务被提交，更多的工作者线程被唤醒去处理任务。

客户端线程 1 ──→ Job1
客户端线程 2 ──→ Job2  ──→  工作队列  ──→  工作者线程1 取出 Job1 执行
客户端线程 3 ──→ Job3                        工作者线程2 取出 Job2 执行
                                             工作者线程3 取出 Job3 执行

### 五、线程安全的实现

线程池中的所有方法由于是同步方法（被 `synchronized` 修饰），所以每个方法都具有原子性。这意味着多个客户端线程同时提交任务时，不会出现任务丢失或队列状态不一致的问题。

### 六、面试要点

**Q：线程池的核心优势是什么？**

线程池通过**线程复用**避免了频繁创建和销毁线程的开销，通过**控制线程数量**避免了线程过多导致的上下文切换和内存消耗，通过**任务队列**实现了任务的异步处理和解耦。

**Q：线程池的核心参数有哪些？**

|参数|作用|
|---|---|
|==**核心线程数**==|线程池常驻的核心线程数量|
|==**最大线程数**==|线程池允许的最大线程数量|
|==**工作队列**==|存放等待执行的任务|
|==**拒绝策略**==|当队列满且线程数达到最大值时，新任务如何处理|

**Q：线程池的线程数应该怎么设置？**

- **CPU 密集型任务**：`核心线程数 = CPU 核心数 + 1`，避免过多线程竞争 CPU。
    
- **I/O 密集型任务**：`核心线程数 = CPU 核心数 × 2` 或更多，因为 I/O 等待期间线程不会占用 CPU，可以多开线程提高并行度。
    
- 实践中通常根据实际压测数据来调整，没有绝对的公式。

2. 线程池实现

java
import java.util.LinkedList;
import java.util.List;
import java.util.concurrent.atomic.AtomicInteger;

public class DefaultThreadPool implements ThreadPool {
    // 最大工作者线程数量
    private static final int MAX_WORKER_NUMBERS = 10;
    // 默认工作者线程数量
    private static final int DEFAULT_WORKER_NUMBERS = 5;
    // 最小工作者线程数量
    private static final int MIN_WORKER_NUMBERS = 1;

    // 工作队列，存储待执行的任务
    private final LinkedList<Job> jobs = new LinkedList<>();
    // 工作者线程列表
    private final List<Worker> workers = new LinkedList<>();
    // 线程编号生成器
    private static final AtomicInteger threadNum = new AtomicInteger();

    public DefaultThreadPool() {
        initializeWorkers(DEFAULT_WORKER_NUMBERS);
    }

    public DefaultThreadPool(int num) {
        int workerNum = Math.min(num, MAX_WORKER_NUMBERS);
        workerNum = Math.max(workerNum, MIN_WORKER_NUMBERS);
        initializeWorkers(workerNum);
    }

    // 初始化工作者线程
    private void initializeWorkers(int num) {
        for (int i = 0; i < num; i++) {
            Worker worker = new Worker();
            workers.add(worker);
            new Thread(worker, "Worker-" + threadNum.incrementAndGet()).start();
        }
    }

    @Override
    public void execute(Job job) {
        if (job != null) {
            synchronized (jobs) {
                jobs.addLast(job);   // 将任务放入工作队列
                jobs.notify();       // 通知一个等待的工作者线程
            }
        }
    }

    @Override
    public void shutdown() {
        for (Worker worker : workers) {
            worker.shutdown();
        }
    }

    @Override
    public void addWorkers(int num) {
        synchronized (jobs) {
            int size = Math.min(workers.size() + num, MAX_WORKER_NUMBERS);
            int addCount = size - workers.size();
            for (int i = 0; i < addCount; i++) {
                Worker worker = new Worker();
                workers.add(worker);
                new Thread(worker, "Worker-" + threadNum.incrementAndGet()).start();
            }
        }
    }

    @Override
    public void removeWorker(int num) {
        synchronized (jobs) {
            if (num >= workers.size()) {
                throw new IllegalArgumentException("超过当前工作者线程数量");
            }
            for (int i = 0; i < num; i++) {
                Worker worker = workers.remove(workers.size() - 1);
                worker.shutdown();
            }
        }
    }

    @Override
    public int getJobSize() {
        synchronized (jobs) {
            return jobs.size();
        }
    }

    // 工作者线程，不断从工作队列中取出任务并执行
    class Worker implements Runnable {
        private volatile boolean running = true;

        @Override
        public void run() {
            while (running) {
                Job job = null;
                synchronized (jobs) {
                    // 工作队列为空时等待
                    while (jobs.isEmpty() && running) {
                        try {
                            jobs.wait();
                        } catch (InterruptedException e) {
                            Thread.currentThread().interrupt();
                            return;
                        }
                    }
                    // 取出一个任务
                    if (!jobs.isEmpty()) {
                        job = jobs.removeFirst();
                    }
                }
                // 在同步块外部执行任务，避免长时间持有锁
                if (job != null) {
                    try {
                        job.execute();
                    } catch (Exception e) {
                        // 忽略任务执行过程中的异常，不影响工作者线程继续运行
                    }
                }
            }
        }

        public void shutdown() {
            running = false;
            // 确保等待中的线程能被唤醒
            synchronized (jobs) {
                jobs.notifyAll();
            }
        }
    }
}
3. 客户端使用示例

java
public class Client {
    public static void main(String[] args) {
        // 创建线程池，默认 5 个工作者线程
        DefaultThreadPool pool = new DefaultThreadPool();

        // 提交 20 个任务
        for (int i = 0; i < 20; i++) {
            int taskId = i;
            pool.execute(() -> {
                System.out.println(Thread.currentThread().getName() + " 正在执行任务 " + taskId);
                try {
                    Thread.sleep(1000); // 模拟任务执行耗时
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
                System.out.println(Thread.currentThread().getName() + " 完成任务 " + taskId);
            });
        }

        // 等待所有任务执行完毕
        try {
            Thread.sleep(5000);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }

        // 关闭线程池
        pool.shutdown();
    }
}
八、设计要点总结
设计点	实现方式	说明
==工作队列==	LinkedList<`Job`>	双端队列，从尾部添加任务，从头部取出任务，FIFO 顺序
==同步机制==	synchronized(jobs) + wait/notify	保证线程安全，队列空时工作者线程等**待，新任务到来时唤醒**
**==任务执行==	在同步块外调用 job.execute()	避免任务执行期间长时间持有锁，提高并发度**
**==增加工作者==	addWorkers(int num)	动态扩容，上限受 MAX_WORKER_NUMBERS 限制**
**==减少工作者==	removeWorker(int num)	从列表末尾移除，调用 shutdown() 安全退出**
**==优雅关闭==	volatile boolean running + notifyAll()	设置标志位并唤醒所有等待线程，确保线程能检查到 running=false 后退出**
### 九、面试要点补充

**Q：为什么 `job.execute()` 要在同步块外部执行？**

如果 `execute()` 也在同步块内部执行，任务执行期间会一直持有 `jobs` 锁。其他客户端线程的 `execute()` 提交操作、工作者线程的取出操作都会被阻塞。任务执行是耗时的操作，放在同步块外部可以让锁尽快释放，提高整个线程池的并发吞吐量。

**Q：为什么关闭时不仅要设置 `running=false`，还要调用 `notifyAll()`？**

如果只设置 `running=false` 而不调用 `notifyAll()`，此时如果有工作者线程正在 `jobs.wait()` 中等待，它将永远无法被唤醒，也就无法检查到 `running` 的变化，导致线程永久阻塞无法退出。`notifyAll()` 确保所有等待的工作者线程都被唤醒，检查到 `running=false` 后安全退出循环。
