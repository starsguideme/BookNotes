
### 一、三个核心类

Java 提供了三种原子更新字段的类：

| 类名 | 说明 |
|------|------|
| ==**`AtomicIntegerFieldUpdater`**== | 原子更新整型字段的更新器 |
| ==**`AtomicLongFieldUpdater`**== | 原子更新长整型字段的更新器 |
| ==**`AtomicStampedReference`**== | 原子更新带有版本号的引用类型，将整数值与引用关联起来，用于解决 CAS 的 ABA 问题 |

### 二、使用步骤

在更新字段时需要两步：

**第一步**：因为原子更新字段类都是抽象类，所以每次使用这个类的时候必须使用静态 `newUpdater()` 创建一个更新器，并且需要设置想要更新的**类**与**属性**。

**第二步**：更新类的字段（属性）必须使用 **`public volatile`** 修饰，否则 `AtomicIntegerFieldUpdater` 无法通过反射访问该字段。

### 三、使用示例

```java
// 第一步：创建更新器
AtomicIntegerFieldUpdater<User> updater = 
    AtomicIntegerFieldUpdater.newUpdater(User.class, "age");

// 第二步：原子更新字段
User user = new User();
updater.getAndIncrement(user);       // 原子自增
updater.compareAndSet(user, 0, 20);  // 如果当前值是 0，则设置为 20
```

### 四、适用范围

| 适用场景 | 说明 |
|---------|------|
| ==**需要对已有类的字段进行原子操作**== | 不需要修改原有类，通过反射方式更新字段 |
| ==**需要解决 ABA 问题的场景**== | 使用 `AtomicStampedReference`，通过版本号判断数据是否被修改过 |

| 不适用场景 | 说明 |
|-----------|------|
| ==**字段不是 `public volatile` 修饰的场景**== | `AtomicIntegerFieldUpdater` 无法访问非 `public volatile` 字段 |
| ==**需要频繁更新字段的场景**== | CAS 自旋会消耗 CPU，竞争激烈时性能反而低于锁 |
| ==**需要同时更新多个字段的场景**== | 原子类只能保证单个字段的原子性 |

### 五、面试要点

| 问题                                       | 回答                                                                                    |
| ---------------------------------------- | ------------------------------------------------------------------------------------- |
| **原子更新字段类有哪三种**                          | ==**`AtomicIntegerFieldUpdater`、`AtomicLongFieldUpdater`、`AtomicStampedReference`**== |
| **使用 `AtomicIntegerFieldUpdater` 的前提条件** | 字段必须是 **`public volatile`** 修饰                                                        |
| **`AtomicStampedReference` 的作用**         | 通过**版本号**解决 CAS 的 ABA 问题                                                              |
| **为什么字段必须是 `volatile`**                  | 保证可见性，`CAS` 配合 `volatile` 才能实现原子更新                                                    |
