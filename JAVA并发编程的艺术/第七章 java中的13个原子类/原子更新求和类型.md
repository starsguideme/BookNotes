
### 一、四个核心类

在 JDK 8 之后，并发包中的原子类新增了 4 个工具类：

| 类名 | 说明 |
|------|------|
| ==**`LongAdder`**== | 原子 `long` 求和器，适合高并发场景下的计数器 |
| ==**`DoubleAdder`**== | 原子 `double` 求和器，适合高并发场景下的计数器 |
| ==**`LongAccumulator`**== | 原子 `long` 累加器，支持自定义累加函数 |
| ==**`DoubleAccumulator`**== | 原子 `double` 累加器，支持自定义累加函数 |

### 二、分散累加的核心思想

这四种方法都是通过使用**分散累加**的技术来提高并发更新计数器的效率。这种方法会将计数器的值分为**多个部分（Cell）**，每个部分单独累加，最后将它们加起来得到总和。

**为什么比 `AtomicLong` 效率更高？**

当多个线程同时更新同一个 `AtomicLong` 时，只有一个线程的 CAS 能成功，其他线程必须自旋等待，竞争激烈时性能会急剧下降。而分散累加让每个线程更新自己对应的 Cell，不同线程之间没有竞争，最后通过 `sum()` 汇总所有 Cell 的值。

### 三、求和器中的两个核心类

| 类名 | 底层实现 |
|------|---------|
| ==**`LongAdder`**== | 底层是 `Striped64` 类的 `longAccumulate` 方法 |
| ==**`DoubleAdder`**== | 底层是 `Striped64` 类的 `doubleAccumulate` 方法 |

这两个方法主要是用于处理并发的原子操作。

### 四、适用场景

| 场景 | 推荐类 | 说明 |
|------|--------|------|
| ==**高并发计数器**== | `LongAdder` / `DoubleAdder` | 写多读少，对实时精度要求不高 |
| ==**需要实时精确值的场景**== | `AtomicLong` / `AtomicInteger` | 读多写少，需要每次读取都是精确值 |
| ==**需要自定义累加逻辑**== | `LongAccumulator` / `DoubleAccumulator` | 如求最大值、最小值、乘积等 |
