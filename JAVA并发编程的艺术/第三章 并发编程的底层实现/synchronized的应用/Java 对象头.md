**Java 对象头与 Mark Word 的存储结构**

### 一、对象头的整体结构

`synchronized` 用的锁存在于 **Java 对象头** 中。根据对象类型的不同，对象头的宽度也不同：

|对象类型|对象头大小|
|---|---|
|==**数组类型**==|3 个字宽（Mark Word + Class Metadata Address + Array Length）|
|==**非数组类型**==|2 个字宽（Mark Word + Class Metadata Address）|

**字宽的定义**：在 32 位 JVM（X32）中，1 字宽 = 4 字节 = 32 位；在 64 位 JVM 中，1 字宽 = 8 字节 = 64 位。

对象头的存储结构如下：

| 组成部分                           | 长度      | 说明                                  |
| ------------------------------ | ------- | ----------------------------------- |
| ==**Mark Word**==              | 32/64 位 | 存储对象的 HashCode、GC 分代年龄、锁标志位等运行时动态信息 |
| ==**Class Metadata Address**== | 32/64 位 | 指向方法区中该对象所属类元数据的指针                  |
| ==**Array Length**==           | 32/64 位 | 数组的长度（仅当对象是数组类型时存在）                 |

### 二、Mark Word 的存储结构（32 位 JVM 无锁状态）

在 32 位 JVM 中，无锁状态下的 Mark Word 默认存储结构如下：


锁状态      25位              4位         1位             2位
无锁状态   对象的 HashCode    对象分代年龄   是否为偏向锁(0)   锁标志位(01)

|字段|位数|说明|
|---|---|---|
|==**HashCode**==|25 位|对象的哈希码|
|==**分代年龄**==|4 位|GC 分代年龄，范围 0~15|
|==**偏向锁标志**==|1 位|0 表示不是偏向锁|
|==**锁标志位**==|2 位|01 表示无锁状态|

### 三、Mark Word 的状态变化（32 位 JVM）

随着锁竞争程度的变化，Mark Word 中存储的内容也会发生相应变化。以下是五种锁状态下的 Mark Word 存储结构：

|锁状态|23位|2位|4位|1位（偏向锁标志）|2位（锁标志位）|
|---|---|---|---|---|---|
|==**无锁**==|对象的 HashCode|25 位中剩余的 2 位|对象分代年龄|0|01|
|==**偏向锁**==|线程 ID（23 位）|Epoch（2 位）|对象分代年龄|1|01|
|==**轻量级锁**==|指向线程栈中 Lock Record 的指针（前 30 位）|—|—|—|00|
|==**重量级锁**==|指向 Monitor 的指针（前 30 位）|—|—|—|10|
|==**GC 标记**==|空|—|—|—|11|

**记忆要点**：锁标志位是区分锁状态的核心依据——`01` 可能是无锁或偏向锁（通过偏向锁标志位区分），`00` 是轻量级锁，`10` 是重量级锁，`11` 是 GC 标记。

### 四、锁升级的触发条件与流程

无锁（01，偏向锁标志=0）
        ↓ 线程 A 第一次获取该锁
偏向锁（01，偏向锁标志=1，记录线程 A 的 ID）
        ↓ 线程 B 尝试竞争该锁，但线程 A 仍持有锁
轻量级锁（00，指向线程 A 栈中 Lock Record 的指针）
        ↓ 线程 B CAS 自旋超过一定次数仍未获取到锁
重量级锁（10，指向 Monitor 对象的指针）
        ↓ 线程 B 进入 BLOCKED 状态，在 Monitor 的同步队列中等待

**各状态的简要说明**：

- **偏向锁**：锁总是被同一个线程获取，为了减少该线程获取锁的开销，在 Mark Word 中记录该线程 ID。该线程再次进入时只需检查 ID 是否匹配，无需 CAS 操作。
    
- **轻量级锁**：两个线程竞争锁，但还没有同时进入临界区。通过 CAS 自旋来尝试获取锁，避免线程阻塞和唤醒的开销。
    
- **重量级锁**：锁竞争激烈，线程 CAS 自旋消耗 CPU 时间过长，此时将锁升级为 Monitor 锁。未获取锁的线程进入 BLOCKED 状态，不再消耗 CPU。
    

### 五、面试要点

**Q：`synchronized` 的锁信息存在哪里？**

存在 Java 对象头中的 Mark Word 里。Mark Word 会根据锁的状态动态变化：无锁时存储 `HashCode` 和分代年龄，重量级锁时存储指向 Monitor 的指针。

**Q：锁升级的过程是怎样的？**

无锁 → 偏向锁（一个线程反复获取）→ 轻量级锁（两个线程竞争，通过 CAS 自旋）→ 重量级锁（竞争激烈，自旋开销过大，线程进入 BLOCKED 状态）。这个升级过程是不可逆的，锁只会升级不会降级。

**Q：为什么偏向锁被废弃了？**

在 JDK 15 之后，偏向锁被默认关闭。因为现代应用大多使用线程池，线程复用率高，锁不会被"某一个线程长期反复获取"，偏向锁的撤销操作本身开销较大，反而得不偿失。在 JDK 21 中，偏向锁的代码已被彻底移除。
