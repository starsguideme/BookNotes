**三种锁的优缺点对比**

| 维度           | 偏向锁                                    | 轻量级锁                         | 重量级锁                                   |
| ------------ | -------------------------------------- | ---------------------------- | -------------------------------------- |
| ==**优点**==   | 加锁/解锁时不需要额外的 CAS 消耗，执行时与非同步方法只存在纳秒级的误差 | 竞争的线程不会阻塞，通过自旋等待，程序响应速度很快    | 线程竞争不会使用自旋，不会消耗 CPU 资源                 |
| ==**缺点**==   | 如果线程间存在锁竞争，会有额外的偏向锁撤销消耗                | 如果始终得不到锁，竞争线程会一直自旋，消耗 CPU 资源 | 线程阻塞和唤醒涉及上下文切换，响应时间较长                  |
| ==**适用场景**== | 仅有一个线程反复访问同步块                          | 两个线程交替执行同步块，追求响应时间           | 多个线程同时竞争锁，追求系统整体吞吐量                    |
| ==**核心机制**== | Mark Word 记录偏向线程 ID，同一线程再次进入时无需 CAS    | CAS 自旋获取锁，自旋失败超过阈值后膨胀为重量级锁   | 基于 Monitor，未获取锁的线程进入 BLOCKED 状态，让出 CPU |

### 锁升级路径总结


**偏向锁（一个线程反复获取）**
    **↓ 另一个线程竞争，撤销偏向锁**
**轻量级锁（两个线程交替执行，CAS 自旋）**
    **↓ 自旋超阈值，锁膨胀**
**重量级锁（多个线程激烈竞争，线程阻塞等待）**

### 面试话术

“这三种锁分别对应三种不同的竞争程度。偏向锁解决的是只有一个线程反复获取锁的场景，加锁解锁的开销几乎为零。轻量级锁解决的是两个线程交替执行的场景，通过 CAS 自旋来获取锁，响应快但自旋会消耗 CPU。重量级锁解决的是多个线程同时激烈竞争的场景，让等待的线程阻塞以释放 CPU，追求整体吞吐量。三种锁会根据竞争程度自动升级，从偏向锁到轻量级锁再到重量级锁，不会反向降级。”
