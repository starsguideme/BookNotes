**追加字节优化 volatile 性能**

### 一、为什么要追加字节？

追加字节优化性能的核心思想是**避免缓存锁定降级为总线锁定**。在较新的处理器中，Lock 前缀指令通常通过缓存锁定来保证原子性——只锁定单个缓存行，其他处理器仍可访问不在该缓存行中的数据。

但如果一个共享变量**跨越了两个缓存行**，缓存锁定就无法生效，处理器只能降级为**总线锁定**。总线锁定的开销远大于缓存锁定，因为它会阻塞所有其他处理器对任何内存的访问。为了避免这种情况，可以通过追加字节的方式，确保 volatile 变量完全落在一个缓存行内。

### 二、追加多少字节？

一般情况下，缓存行大小为 64 字节，因此追加字节的目标是让 volatile 变量所在的缓存行被充分填充，避免它与相邻变量共享缓存行而导致跨缓存行访问。Java 中通常使用 `long` 类型（8 字节）作为填充单位。

### 三、两种不需要追加字节的情况

**1. 缓存行为非 64 字节宽的处理器**

如果处理器的缓存行宽度不是 64 字节（例如某些 ARM 处理器为 32 字节），则不需要按照 64 字节的标准来填充，可以根据实际的缓存行宽度调整填充大小。

**2. 共享变量不会被频繁执行写操作**

如果共享变量只是偶尔被写入，那么即使发生总线锁定，带来的性能影响也微乎其微。频繁的写操作才会让总线锁定的累积开销变得显著。对于写操作很少的 volatile 变量，追加字节带来的内存开销可能不值得。

### 四、面试要点

**Q：为什么 volatile 变量要追加字节？**

为了防止跨缓存行访问导致缓存锁定降级为总线锁定。如果 volatile 变量跨越了两个缓存行，处理器无法使用开销较小的缓存锁定，只能锁住整个总线，这会阻塞其他所有处理器的内存访问。通过追加字节，确保 volatile 变量完全落在一个缓存行内，就能使用高效的缓存锁定机制。

**Q：Java 中如何实现追加字节？**

Java 8 之前，通常手动在变量前后添加多个 `long` 类型的占位字段，每个 `long` 占 8 字节，填充到 64 字节。Java 8 提供了 `@Contended` 注解，可以自动完成缓存行填充，`ConcurrentHashMap` 内部的 `CounterCell` 就使用了这个技术。

**Q：什么情况下不需要追加字节？**

有两种情况：一是处理器的缓存行宽度不是 64 字节，需要根据实际宽度调整；二是共享变量不会被频繁写操作，总线锁定的累积开销微乎其微，此时追加字节带来的内存开销不值得
