### 一、`volatile` 与 `synchronized` 的定位

在多线程编程中，==`synchronized`== 和 ==`volatile`== 都有不同定位上的重要作用。**`volatile` 是轻量级同步机制**，它在处理多任务中保证线程对共享变量访问的可见性，资源开销也比 `synchronized` 要低，因为不会有[[上下文切换]]带来的问题和调度线程的额外开销。

详细参考：[[volatile和synchronized关键字]]

### 二、Java 对 `volatile` 的规范

Java 编程语言允许线程访问共享变量，为了确保共享变量能被准确且一致地更新，线程应使用排他性锁单独获得这个变量。Java 提供了 `volatile`，它在某些方面比 `synchronized` 更方便。如果一个字段被 `volatile` 关键字所修饰，这个变量的修改对所有线程立即可见。为了更好的理解 `volatile` 的作用，需要补充以下 CPU 层面的基础知识。

### 三、CPU 缓存与内存屏障术语表

| 中文术语          | 英文术语               | 术语描述                                                                                                   |
| ------------- | ------------------ | ------------------------------------------------------------------------------------------------------ |
| ==**缓存行**==   | Cache Line         | CPU 缓存与主内存之间交互数据的最小单位，通常大小为 64 字节。即使 CPU 只读取一个字节，也会把包含该字节的整个缓存行加载到缓存中                                  |
| ==**缓存行填充**== | Cache Line Padding | 在变量前后填充无意义的字节，使**关键变量**独占一个缓存行，从而避免多个线程修改不同变量时因为共享同一缓存行而导致的伪共享问题。Java 8 中可使用 **`@Contended`** 注解自动完成填充 |
| ==**缓存命中**==  | Cache Hit          | CPU 读取数据时，所需数据已经存在于缓存中，可以直接从缓存读取，无需访问主内存。缓存命中率越高，程序执行效率越高                                              |
| ==**写命中**==   | Write Hit          | CPU 执行写操作时，目标内存地址所在的缓存行已经存在于缓存中，可以直接在缓存中更新数据，无需先从主内存加载                                                 |
| ==**写缺失**==   | Write Miss         | CPU 执行写操作时，目标内存地址所在的缓存行不在缓存中，需要先从主内存加载对应的缓存行到缓存中，然后再执行写操作。写缺失会带来额外的内存访问开销                              |
| ==**内存屏障**==  | Memory Barrier     | 一组处理器指令，用于实现对内存操作的顺序控制。它强制屏障前后的内存操作按照指定顺序执行，防止 CPU 指令重排，同时确保缓存数据的一致性。主要分为**读屏障和写屏障**两种基本类型             |
| ==**原子操作**==  | Atomic Operation   | 不可被中断的一个或一系列操作。在 CPU 层面，通过单条原子指令（如 `CMPXCHG`）或总线锁定/缓存锁定来保证操作期间其他 CPU 无法访问对应内存区域                        |

### 四、术语之间的关联

**CPU 操作数据的最小单位：缓存行**
        **↓**
**读写缓存行时可能发生：缓存命中 / 写命中 / 写缺失**
        **↓**
**多个 CPU 核心修改同一缓存行 → 伪共享**
        **↓**
**解决伪共享 → 缓存行填充**
        **↓**
**解决多核可见性 → 内存屏障**
        **↓**
**锁的替代方案 → 原子操作（通过 CPU 原子指令实现，无需阻塞线程）**

### 五、Lock 前缀指令与缓存一致性机制

当被 `volatile` 修饰的变量在实际运行后，产生的 x86 汇编代码会比没加 `volatile` 的字段多一个 **Lock 前缀指令**。通过这个 Lock 指令，CPU 会完成以下两件事：

1. **将当前处理器缓存行的数据写回到系统内存**：Lock 前缀强制将修改后的数据从缓存刷新回主内存，确保其他处理器能看到最新的值。
    
2. **使其他 CPU 中缓存了该数据的缓存行失效**：通过缓存一致性协议，通知其他所有处理器——你们缓存中的这个数据已经过期了，下次读取必须去主内存拿最新的。
    

这两步操作共同保证了 `volatile` 的**可见性**。

### 六、为什么需要这么复杂的过程？

为了提高处理速度，处理器不直接和内存进行通信，而是先将系统内存的数据读取到内部缓存（L1、L2 等，具体看 CPU 有几级缓存）后再进行操作。在多处理器系统下，一个 CPU 修改了缓存中的数据后，其他 CPU 并不知道这个修改，仍然使用自己缓存中的旧值——这就是缓存一致性问题。

如果对声明了 `volatile` 的变量进行写操作，JVM 就会向处理器发送一条 Lock 指令，强制将变量所在缓存行的数据写回到系统内存。但即使写回了内存，如果其他处理器缓存的值依旧是旧的，此时执行操作还是会带来数据不一致的问题。因此，Lock 指令还会通过缓存一致性协议通知其他处理器：你们缓存中的这个缓存行已经失效了，下次读取必须重新从内存加载。

### 七、`volatile` 无法保证原子性的根本原因

这就是为什么 `volatile` 无法解决原子性问题。

`volatile` 只能保证**单个读操作**和**单个写操作**的原子性——读取一个 `volatile` 变量时，一定能读到最新的值；写入一个 `volatile` 变量时，新值会立刻对其它线程可见。

但对于 `count++` 这种**复合操作**（读取 → 加 1 → 写入），`volatile` 就无能为力了。原因在于：Lock 前缀只能保证单次内存操作的原子性，而 `count++` 是三次内存操作（读、修改、写），Lock 前缀无法保证这三步之间不被其他线程打断。线程 A 刚读完 `count=0`，还没来得及写回，线程 B 也读到了 `count=0`。**虽然两个线程各自的读操作都是原子的、写操作也都是原子的，但"读-改-写"这三个步骤整体上不是原子的，这就是典型的原子性问题，需要 `synchronized` 或 `AtomicInteger` 的 CAS 来解决。**

### 八、从 Java 代码到 CPU 指令的完整链路

**Java 层面：volatile 修饰变量**
        **↓**
**JVM 层面：在写操作后插入 StoreStore 和 StoreLoad 屏障**
         **在读操作前插入 LoadLoad 和 LoadStore 屏障**
        **↓**
**汇编层面：生成 Lock 前缀指令**
        **↓**
**CPU 层面：Lock 指令触发以下操作：**
    **① 将当前缓存行的数据写回系统内存**
    **② 通过缓存一致性协议使其他 CPU 的对应缓存行失效**
    **③ 其他 CPU 再次读取该变量时，必须从主内存重新加载**
        **↓**
**结果：保证了 volatile 变量的可见性**
      **（但无法保证复合操作的原子性）**

### 九、面试要点

**Q：`volatile` 是锁吗？**

不是。`volatile` 是一种轻量级同步机制，它通过内存屏障和缓存一致性协议来保证可见性，不涉及线程的阻塞和唤醒。锁（如 `synchronized`）会在获取不到时让线程进入 BLOCKED 状态，涉及上下文切换。

**Q：`volatile` 的 Lock 前缀指令和 `synchronized` 的锁有什么区别？**

Lock 前缀指令是硬件层面的操作，通过缓存一致性协议来保证可见性，整个过程不涉及线程阻塞和唤醒，没有上下文切换。`synchronized` 是操作系统层面的锁，获取不到锁的线程会进入 BLOCKED 状态，涉及上下文切换。Lock 前缀只保证一条指令的原子执行，而 `synchronized` 可以保护任意长度的代码块。

**Q：既然 Lock 前缀能写回内存，为什么 `volatile` 不能保证原子性？**

Lock 前缀只能保证单次内存操作（单次读或单次写）的原子性。但 `count++` 是三次内存操作（读、修改、写），Lock 前缀无法保证这三步之间不被其他线程打断。线程 A 和线程 B 各自的读写操作都是原子的，但"读-改-写"这个复合操作整体上不是原子的。这就是 `volatile` 无法保证原子性的根本原因。
