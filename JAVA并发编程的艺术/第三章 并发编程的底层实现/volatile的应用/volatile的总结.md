### volatile 字段的总结

1. volatile 是一个**轻量级同步机制**，主要处理的是线程之间的**可见性**问题。它不保证原子性，也不阻塞线程，因此没有上下文切换的开销，可以参考下[[volatile的使用]]。
    
2. 当 volatile 修饰的变量被写操作时，JVM 会向处理器发送一条汇编指令，其中带有 **Lock 前缀**。这个 Lock 前缀会触发两个操作：将当前处理器缓存行的数据写回到系统内存，同时通过缓存一致性协议使其他处理器中缓存了该数据的缓存行失效，从而让修改后的值对所有线程立即可见,这就是[[volatile的实现原则]]。
    
3. Lock 信号锁定的是**缓存行**，而不是总线。原因在于，总线锁定会把所有处理器与内存之间的通道全部锁住，同一时刻只有一个处理器能访问内存，这几乎把多线程变成了单线程。当线程数量越多，阻塞等待的开销就越大。而缓存锁定只锁定单个缓存行，阻止多个处理器同时修改同一缓存行中的数据，其他处理器依然可以访问不在该缓存行中的其他内存区域。相比总线锁定，缓存锁定的影响范围更小、开销更低，所以 Lock 信号在数据已被缓存的情况下优先使用缓存锁定。
    
4. 通过以上机制已经可以保证 volatile 变量的可见性。但当一个 volatile 变量**跨越了两个缓存行**时，缓存锁定无法生效，处理器只能降级为总线锁定，性能会急剧下降。为了解决这个问题，可以通过**追加字节到 64 字节**的方式，确保 volatile 变量完全落在一个缓存行内，从而避免缓存锁定降级为总线锁定。不过有两种情况不需要这样处理：一是处理器缓存行本身不是 64 字节宽，二是共享变量不会被频繁执行写操作，此时即使发生总线锁定，累积开销也可以忽略,这就是[[volatile的优化方法]]。
