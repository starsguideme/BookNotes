### 一、CPU 层面：两种锁定方式

处理器实现原子操作主要通过锁定机制来保证。当一个指令需要原子执行时，CPU 会锁定对应的内存区域，确保其他处理器无法同时访问。

|方式|原理|优缺点|
|---|---|---|
|==**锁总线**==|处理器发出 LOCK# 信号，锁住整个系统总线|能保证原子性，但开销太大，其他处理器完全无法访问内存|
|==**锁缓存行**==|锁定单个缓存行，利用缓存一致性协议保证原子性|开销小，不影响其他内存访问，是优先使用的方式|

**有两种情况必须通过锁总线执行：一是操作的数据跨多个缓存行时，二是处理器设备老旧不支持缓存锁定时。**

### 二、Java 层面：两种实现方式

Java 中也有类似锁缓存行的思路，但具体实现是通过软件层面的机制：

| 方式                              | 原理                                    | 特点                                            |
| ------------------------------- | ------------------------------------- | --------------------------------------------- |
| ==**自旋 CAS**==                  | 基于处理器提供的 `cmpxchg` 指令，循环进行 CAS 操作直到成功 | 最简单，线程不阻塞，但会消耗 CPU 资源，有 ABA 问题                |
| ==**`synchronized` / `Lock`**== | 通过互斥锁保证同一时刻只有一个线程执行同步块                | `synchronized` 每次只允许一个线程执行；`Lock` 功能更强大但实现较复杂 |
|                                 |                                       |                                               |

### 三、CPU 与 Java 的对应关系

| 层面          | 实现机制                         | 对应关系                        |
| ----------- | ---------------------------- | --------------------------- |
| **CPU 硬件**  | 锁缓存行（通过 Lock 前缀指令 + MESI 协议） | Java 的 `volatile` 直接利用了这个机制 |
| **CPU 硬件**  | `cmpxchg` 原子指令               | Java 的 CAS 自旋直接调用了这条指令      |
| **Java 软件** | CAS 自旋（`AtomicInteger`）      | 底层依赖 CPU 的 `cmpxchg` 指令     |
| **Java 软件** | `synchronized`（Monitor 锁）    | 底层依赖操作系统管程，涉及线程阻塞与唤醒        |
| **Java 软件** | `Lock`（`AQS`）                | 基于 CAS + 队列实现，功能更丰富         |
