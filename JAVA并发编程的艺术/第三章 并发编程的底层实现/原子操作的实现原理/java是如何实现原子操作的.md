### 一、两种实现方式

在 Java 中可以通过**循环 CAS** 和**锁**两种方式来实现原子操作。

**1. 使用循环 CAS 实现原子操作**

JVM 中的 CAS 操作正是利用了处理器提供的 **`cmpxchg` 指令**实现的。自旋 CAS 实现的基本思路就是循环进行 CAS 操作直到成功为止。

在 Java 中可以使用 `AtomicInteger` 这个类来实现原子操作。`AtomicInteger` 内部使用了 `volatile` 修饰的 `value` 字段来保证可见性——当一个线程修改了 `value` 的值，其他线程能立即看到最新值。然后通过 CAS 自旋来修改这个值，读写都是原子的，所以整体是一个完整的原子操作。

**2. 使用锁实现原子操作**

当共享变量较多、CAS 无法保证多个变量同时被原子更新时，可以使用 **`synchronized` 或 `Lock`** 等锁机制，通过互斥来保证一段代码的原子性。

### 二、CAS 实现原子操作的三大问题

**1. ABA 问题**

CAS 在比较时只检查"值是否相同"，但如果值从 A 变成 B 再变回 A，CAS 检测不到中间的变化。为了解决这个脏数据修改的问题，最好的办法就是**加版本号**——让线程读取版本号来判断数据是否被修改过，然后执行下一步操作。版本号本身是一个自增的整数，每次修改时加一。`AtomicStampedReference` 就是通过维护值和版本戳来解决 ABA 问题的。

**2. 循环时间开销大**

由于 CAS 在未成功的时候会一直自旋，而自旋也是需要消耗 CPU 资源的，所以这对 CPU 来说是个很大的开销。如果 JVM 能支持处理器提供的 `pause` 指令，效率会有提升。`pause` 指令有两个作用：一是**延迟 CPU 流水线的执行指令**，减少自旋对流水线的冲击；二是在自旋等待期间降低 CPU 功耗。

**3. 只能保证一个共享变量的原子操作**

当对一个共享变量进行操作时，可以使用循环 CAS 的方式来保证原子操作。但随着共享变量的增多，循环 CAS 就无法保证多个变量同时被原子更新，这时就需要使用 `synchronized` 或 `Lock` 等锁方法来实现原子操作。

| -------------- | -------------------------------------------------------------------- |
| **如何用 CAS 实现原子操作** | 循环进行 CAS 操作直到成功，`AtomicInteger` 内部使用 `volatile` 保证可见性，通过 CAS 保证更新原子性 |
