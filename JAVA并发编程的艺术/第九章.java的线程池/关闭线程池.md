

**线程池的关闭**

### 一、关闭线程池的两种方法

可以使用线程池中的 `shutdown` 或 `shutdownNow` 方法来关闭线程池。它们的实现大致是先遍历线程池中的正在执行任务的工作线程，然后逐个对工作线程使用**中断方法**来中断该线程。但如果此时出现**无法响应中断任务**的线程，该线程就可能永远无法终止。

### 二、`shutdown` 与 `shutdownNow` 的区别

这两个方法有共性，但也存在一定区别：

| 维度 | `shutdown` | `shutdownNow` |
|------|-----------|-------------|
| ==**状态设置**== | 将线程池的状态设置成 **`SHUTDOWN`** | 将线程池的状态设置成 **`STOP`** |
| ==**中断范围**== | 中断所有**没有正在执行任务**的工作线程 | 尝试停止**所有**正在执行任务或暂停任务的工作线程 |
| ==**返回值**== | **无返回值** | 返回**等待执行任务的线程列表** |
| ==**对已提交任务的处理**== | 已提交的任务会继续执行完毕 | 已提交但未执行的任务会被取消 |
| ==**使用场景**== | 一般情况下的优雅关闭 | 需要**中途打断线程**的场景 |

### 三、线程池关闭的状态判断

在使用这两个方法的其中任意一个方法，`isShutdown` 就会返回 `true`。当**所有的任务都已关闭**后，才表示线程池已被关闭，此时调用 `isTerminated` 方法会返回 `true`。

| 方法 | 说明 |
|------|------|
| ==**`shutdown()`**== | 启动优雅关闭，不再接受新任务，但已提交的任务会继续执行 |
| ==**`shutdownNow()`**== | 尝试立即停止所有正在执行的任务，返回等待执行的任务列表 |
| ==**`isShutdown()`**== | 线程池是否已经启动了关闭流程 |
| ==**`isTerminated()`**== | 线程池是否已经**完全关闭**，所有任务都已完成 |

### 四、使用选择

具体使用哪个方法一般是交由线程池中的**任务特性**来决定的：

| 场景 | 推荐方法 |
|------|---------|
| ==**一般情况下的优雅关闭**== | `shutdown` |
| ==**需要立即停止所有任务**== | `shutdownNow` |
| ==**需要等待线程池完全关闭**== | `shutdown` + `awaitTermination(timeout, unit)` |

### 五、面试要点

| 问题 | 回答 |
|------|------|
| 关闭线程池有哪两种方法 | ==**`shutdown` 和 `shutdownNow`**== |
| `shutdown` 和 `shutdownNow` 的区别 | `shutdown` 只中断空闲线程，已提交任务继续执行；`shutdownNow` 中断所有线程，返回未执行的任务列表 |
| `isShutdown` 和 `isTerminated` 的区别 | `isShutdown` 表示是否**启动了关闭流程**；`isTerminated` 表示是否**完全关闭** |
| 无法响应中断的任务会导致什么 | 该线程可能**永远无法终止**，导致线程池无法完全关闭 |
