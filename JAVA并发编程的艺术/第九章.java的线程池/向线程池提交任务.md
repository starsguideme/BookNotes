
### 一、两种提交方式

有两种方法可以向线程池提交任务，其 API 为 `execute` 和 `submit` 方法：

| 方法 | 是否有返回值 | 能否判断任务是否执行成功 |
|------|------------|---------------------|
| ==**`execute(Runnable command)`**== | 否 | ==**不能**== |
| ==**`submit(Callable<T> task)`**== | 是，返回 `Future<T>` | ==**能**== |

### 二、`execute` 方法

`execute` 方法可以用于**不需要返回值**的任务。正因此，其**无法判断任务是否被线程池成功执行**。

### 三、`submit` 方法

`submit` 方法用于提交任务后**需要返回值**的 API。线程池会返回一个 **`Future` 类型**的对象，通过这个 `Future` 对象可以**判断任务是否执行成功**，同时通过 `Future` 中的 `get` 方法得到返回值。

但 `get` 方法会**阻塞当前线程直到任务完成**。而使用 `get` 的**超时时间**方法会阻塞线程一段时间后立即返回，但此时**任务可能无法完全完成**。

### 四、`execute` 与 `submit` 对比

| 维度 | `execute` | `submit` |
|------|----------|---------|
| ==**参数类型**== | `Runnable` | `Callable` 或 `Runnable` |
| ==**返回值**== | 无 | 有，返回 `Future<T>` |
| ==**是否阻塞主线程**== | 否 | 否（仅 `get()` 会阻塞） |
| ==**能否判断任务是否成功**== | ==**不能**== | ==**能**==（通过 `Future.get()` 或 `Future.isDone()`） |
| ==**使用场景**== | 不需要返回值的任务 | 需要返回值或需要感知任务执行结果的任务 |

### 五、面试要点

| **问题**                    | 回答                                                |
| --------------------- | ------------------------------------------------- |
| **向线程池提交任务有哪两种方式**        | ==**`execute` 和 `submit`**==                      |
| **`execute` 能否获取返回值**     | ==**不能**==，只能提交 `Runnable`，无法感知任务执行结果             |
| **`submit` 返回什么**         | ==**`Future<T>`**==，可以通过 `get()` 获取返回值            |
| **`get()` 方法会阻塞吗**        | ==**会**==，阻塞直到任务完成；使用带超时的 `get(timeout)` 可以避免永久阻塞 |
| **如何判断 `submit` 的任务是否成功** | 通过 `Future.isDone()` 或 `Future.get()` 的返回值        |
