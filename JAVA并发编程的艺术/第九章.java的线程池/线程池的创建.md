
### 一、ThreadPoolExecutor 的核心构造参数

一般情况下线程池的创建主要是由 `ThreadPoolExecutor` 来创建一个线程池。在这个线程池中需要输入几个参数：

| 参数 | 说明 |
|------|------|
| ==**`corePoolSize`（核心线程池大小）**== | 当提交一个任务到线程池时，线程池会创建一个线程来执行任务，即使其他空闲的线程可以执行新任务，但等到需要执行的任务数大于线程池基本大小时就**不会再创建**。如果调用了线程池的 `prestartAllCoreThreads()` 方法，线程池会提前创建并启动所有核心线程 |
| ==**`workQueue`（可运行的任务队列）**== | 用于保存正在等待需要执行任务的阻塞队列 |
| ==**`maximumPoolSize`（线程池最大数量）**== | 线程池允许创建的最大线程数，包括核心线程和非核心线程 |
| ==**`threadFactory`（线程工厂）**== | 用于创建新线程的工厂，可以自定义线程名、优先级等 |
| ==**`handler`（饱和策略）**== | 当线程池和队列都满了，对新提交的任务采取的拒绝策略 |
| ==**`keepAliveTime`（线程活动保持时间）**== | 非核心线程空闲后保持存活的时间 |
| ==**`unit`（线程活动保持的时间单位）**== | `keepAliveTime` 的时间单位 |

### 二、可运行的任务队列

| 队列类型 | 说明 |
|---------|------|
| ==**`ArrayBlockingQueue`（数组阻塞队列）**== | 一个基于数组结构的有界阻塞队列，此数组按 **FIFO** 原则对元素进行排序 |
| ==**`LinkedBlockingQueue`（链表阻塞队列）**== | 一个基于链表结构的阻塞队列，此链表以 **FIFO** 对元素进行排序。如果不指定容量，默认是 `Integer.MAX_VALUE` |
| ==**`SynchronousQueue`（同步队列）**== | 一个**不存储元素**的阻塞队列。每个插入操作必须等待另一个线程使用移除操作 |

### 三、饱和策略

当线程池和队列都满了，对新提交的任务采取的拒绝策略：

| 策略                                  | 说明                                      |
| ----------------------------------- | --------------------------------------- |
| ==**`AbortPolicy`（直接抛出异常）**==       | 默认策略，抛出 `RejectedExecutionException` 异常 |
| ==**`CallerRunsPolicy`（调用者运行）**==   | 只用调用者所在线程来运行任务，不会丢弃任务也不会抛出异常            |
| ==**`DiscardOldestPolicy`（丢弃最旧）**== | 丢弃队列里**最近的一个任务**，并执行当前任务                |
| ==**`DiscardPolicy`（丢弃当前）**==       | 不处理，**直接丢弃掉**当前任务，不会抛出异常                |

### 四、线程池执行任务流程

```text
提交任务
    ↓
① 当前线程数 < corePoolSize？
    ├── 是 → 创建新线程执行任务
    │
    └── 否 → 尝试将任务加入 workQueue
              ↓
        ② workQueue 是否已满？
              ├── 未满 → 任务入队，等待空闲线程执行
              │
              └── 已满 → 尝试创建新线程
                        ↓
                  ③ 当前线程数 < maximumPoolSize？
                        ├── 是 → 创建新线程执行任务
                        │
                        └── 否 → 执行饱和策略（handler）
```

### 五、面试要点

| 问题                   | 回答                                                                                      |
| -------------------- | --------------------------------------------------------------------------------------- |
| **线程池的核心参数有哪些**          | ==**corePoolSize、workQueue、maximumPoolSize、threadFactory、handler、keepAliveTime、unit**== |
| **核心线程池大小的作用**           | 当提交一个任务到线程池时，线程池会创建一个线程来执行任务，直到任务数超过核心线程数                                               |
| **饱和策略有哪四种**             | ==**AbortPolicy、CallerRunsPolicy、DiscardOldestPolicy、DiscardPolicy**==                  |
| **默认的饱和策略**              | ==**`AbortPolicy`**==，直接抛出 `RejectedExecutionException` 异常                              |
| **SynchronousQueue 的特点** | ==**不存储元素**==，每个插入操作必须等待一个移除操作                                                          |
