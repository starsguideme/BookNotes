
### 一、任务提交后的三步判断

当一个新任务提交到线程池后，线程池的处理流程大致如下：

| 步骤 | 判断条件 | 处理方式 |
|------|---------|---------|
| ==**第一步**== | 当前运行的线程是否少于**核心线程数**（`corePoolSize`） | 是 → 创建新的工作线程来执行任务 |
| ==**第二步**== | 核心线程池中的线程都在执行任务，判断**工作队列是否已满** | 未满 → 将新任务存入工作队列中等待执行 |
| ==**第三步**== | 工作队列已满，判断线程池的线程是否都处于工作状态 | 未满 → 创建新的工作线程来执行任务；已满 → 使用**饱和策略**来处理任务 |

### 二、`execute` 方法的执行流程

在 `ThreadPoolExecutor` 执行 `execute` 方法时会遇到以下 **4 种情况**：

```text
execute(task) 的执行流程：

① 提交任务
    ↓
② 判断当前运行的线程是否少于 corePoolSize
    ↓
    ├── 是 → 创建新的工作线程来执行任务（需要全局锁支持）
    │
    └── 否 → 尝试将任务加入阻塞队列（workQueue）
              ↓
        ③ 判断阻塞队列是否已满
              ↓
              ├── 未满 → 任务入队成功，等待空闲线程执行
              │
              └── 已满 → 尝试创建新的线程来执行任务（需要全局锁支持）
                        ↓
                  ④ 判断当前线程数是否超过 maximumPoolSize
                        ↓
                        ├── 未超过 → 创建新线程执行任务
                        │
                        └── 已超过 → 调用饱和策略（RejectedExecutionHandler）拒绝任务
```

### 三、四种情况的详解

| 情况           | 触发条件                    | 处理方式               | 是否需要全局锁    |
| ------------ | ----------------------- | ------------------ | ---------- |
| ==**情况 1**== | 当前运行的线程少于核心线程数          | 创建新的工作线程来执行任务      | ==**需要**== |
| ==**情况 2**== | 运行的线程等于或多于核心线程数         | 将任务加入到阻塞队列中        | 不需要        |
| ==**情况 3**== | 无法将任务加入到阻塞队列中（队列已满）     | 创建新的线程来处理任务        | ==**需要**== |
| ==**情况 4**== | 创建新线程会让当前运行的线程超过最大线程数上限 | 任务被拒绝执行，调用**饱和策略** | 不需要        |

### 四、全局锁的性能影响

在线程池中，一旦遇到了全局锁的情况，系统可能会因为线程阻塞的限制导致其性能遇到**断崖式下降**。因此在线程池完成**预热**之后，执行器的执行几乎都是使用的是**步骤 2**——即“如果运行的线程等于或多于核心线程数，则会将任务加入到阻塞队列中”。这样可以最大限度地避免全局锁的开销。

### 五、工作线程（Worker）

**工作线程**：线程池创建线程时，会将线程封装成工作线程 `Worker`。`Worker` 在执行完任务后，还会**循环获取工作队列中的任务来执行**。线程池中的线程执行任务时分为两类：

| 分类 | 说明 |
|------|------|
| ==**在 `execute` 方法中创建一个线程**== | 该线程会执行当前任务 |
| ==**Worker 循环获取队列中的任务**== | 执行完当前任务后，继续从工作队列中取出下一个任务执行 |

### 六、面试要点

| **问题**               | 回答                                 |
| ---------------- | ---------------------------------- |
| **线程池处理任务的三步判断**     | ==**核心线程 → 工作队列 → 最大线程数**==        |
| **哪些情况需要全局锁**        | 创建新线程时（==**情况 1 和情况 3**==）         |
| **线程池完成预热后主要使用哪种方式** | ==**情况 2**==：将任务加入阻塞队列，避免全局锁开销     |
| **工作线程 Worker 的特点**  | 执行完任务后，会**循环获取工作队列中的任务**继续执行       |
| **饱和策略在什么情况下触发**     | 当前线程数已达到 `maximumPoolSize`，且工作队列已满 |
