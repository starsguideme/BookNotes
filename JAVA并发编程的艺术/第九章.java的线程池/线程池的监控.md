
### 一、为什么需要监控线程池？

如果在系统中使用大量的线程池，为了防止在后续的使用中出现问题，亦或是在出现时可以快速定位，因此就需要对线程池进行监控。

### 二、常用监控属性

在监控线程池的时候可以使用以下属性：

| 属性 | 说明 |
|------|------|
| ==**`taskCount`**== | 线程池需要执行的任务数量，包括已完成、正在执行和队列中等待的任务 |
| ==**`completedTaskCount`**== | 线程池在运行过程中已完成的任务数量，小于或等于 `taskCount` |
| ==**`largestPoolSize`**== | 线程池里曾经创建过的最大线程数量。通过这个数据可以知道线程池是否曾经满过，用于判断是否需要调整 `maximumPoolSize` |
| ==**`getPoolSize`**== | 线程池当前的线程数量。如果线程池不销毁，线程池的线程不会自动销毁，即这个大小**只增不减** |
| ==**`getActiveCount`**== | 正在处于活跃状态（正在执行任务）的线程数 |

### 三、监控实践

除了以上基础属性，还可以通过以下方式扩展监控：

| 监控方式 | 说明 |
|---------|------|
| ==**继承 `ThreadPoolExecutor`**== | 重写 `beforeExecute`、`afterExecute`、`terminated` 方法来记录任务的执行时间、异常信息等 |
| ==**使用 `ThreadPoolExecutor` 提供的钩子方法**== | 在任务执行前后插入自定义的监控逻辑 |
| ==**结合监控系统**== | 将线程池的关键指标（如队列大小、活跃线程数）上报到监控系统（如 Prometheus）中进行可视化展示 |

### 四、面试要点

| 问题                                   | 回答                                                                                        |
| ------------------------------------ | ----------------------------------------------------------------------------------------- |
| **线程池监控有哪些关键指标**                         | ==**`taskCount`、`completedTaskCount`、`largestPoolSize`、`getPoolSize`、`getActiveCount`**== |
| **`largestPoolSize` 的作用**                | 判断线程池是否曾经满过，用于评估 `maximumPoolSize` 是否合理                                                   |
| **`getPoolSize` 和 `getActiveCount` 的区别** | `getPoolSize` 是线程池当前的线程总数，`getActiveCount` 是正在执行任务的活跃线程数                                  |
| **如何扩展线程池的监控能力**                         | ==**重写 `beforeExecute`、`afterExecute`、`terminated` 方法**==                                 |
