
### 一、同步队列的核心概念

同步队列是 AQS 内部维护的一个 FIFO 双向队列，当线程尝试获取锁失败时，会将当前线程的状态等信息封装成一个 **Node 节点**并加入到队列中。在队列中又依靠着**双向链表**这个数据结构来管理等待线程，并向其他线程进行在同步状态上的一些修改。

### 二、Node 节点的属性

根据节点的属性不同，可以分为以下内容：

| 属性 | 说明 |
|------|------|
| ==**`int waitStatus`**== | 等待状态标志位，如 `CANCELLED`（1）、`SIGNAL`（-1）、`CONDITION`（-2）等 |
| ==**`Node prev`**== | 指向当前节点的**前驱节点**的引用 |
| ==**`Node next`**== | 指向当前节点的**后继节点**的引用 |
| ==**`Node nextWaiter`**== | 指向下一个在 **Condition 条件队列**中等待的节点 |
| ==**`Thread thread`**== | 当前节点所代表的**线程对象** |

### 三、同步队列的基本结构

同步器中包含了两个节点类型的引用：一个指向**头节点**，一个指向**尾节点**。

```text
┌──────────────┐
│   同步器      │
│  (AQS)       │
│              │
│  head ───────┼──→ Node1 (头节点，已获取锁的线程)
│  tail ───────┼──→ Node2 (尾节点)
│  state = 1   │
└──────────────┘

同步队列结构：
Node1 (头节点，持有锁)
  │ next
  ▼
Node2 (等待线程 B)
  │ next
  ▼
Node3 (等待线程 C)
  │ next
  ▼
null (尾节点)
```

### 四、新节点入队的过程

由于互斥的特性导致其他线程在获取锁失败后会被安排到同步器中。这个入队操作必须保证具有**线程安全**的特性，因此必须通过 **CAS 设置尾节点**的方法。只有 CAS 成功设置了尾节点之后，才可以将新的节点与之前的节点通过双向链表连接起来。

```text
入队前：
┌───┐    ┌───┐
│ A │───→│ B │ (B 是当前尾节点)
└───┘    └───┘

线程 C 入队：
① CAS 将 tail 从 B 改为 C
┌───┐    ┌───┐    ┌───┐
│ A │───→│ B │    │ C │ (新节点，尚未连接)
└───┘    └───┘    └───┘

② 如果 CAS 成功，则建立双向连接：
┌───┐    ┌───┐    ┌───┐
│ A │───→│ B │───→│ C │
└───┘    └───┘    └───┘
           ↑        ↑
           │  prev   │
           └─────────┘
```

### 五、首节点的出队机制

由于同步队列是在队列上实现的，因此只有当首节点处理完之后才会唤醒其下一个节点。而下一个节点被唤醒后，根据队列的特性将自己设置为**首节点**并执行下一步操作。

```text
出队前：
head
  ↓
┌───┐    ┌───┐    ┌───┐
│ A │───→│ B │───→│ C │
└───┘    └───┘    └───┘

A 释放锁，唤醒 B：
         head
           ↓
┌───┐    ┌───┐    ┌───┐
│ A │    │ B │───→│ C │
└───┘    └───┘    └───┘
(A 被 GC 回收)

B 成为新的头节点，持有锁
```

由于这个出队过程是由前一个持有锁的线程在释放锁时唤醒下一个节点来完成的，本质上是**单线程操作模型**（每次只有释放锁的那个线程在操作头节点），因此就**无需 CAS 再为其执行同步机制**。

### 六、面试要点

| 问题 | 回答 |
|------|------|
| 同步队列是什么数据结构 | ==**FIFO 双向链表**== |
| Node 节点包含哪些属性 | ==**waitStatus、prev、next、nextWaiter、thread**== |
| 为什么入队需要 CAS | 多个线程可能同时入队，必须保证**线程安全** |
| 为什么出队不需要 CAS | 出队是释放锁的线程单线程操作，不存在竞争 |
