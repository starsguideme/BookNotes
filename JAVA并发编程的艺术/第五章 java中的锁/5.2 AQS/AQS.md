
### 一、什么是 `AQS`？

`AQS` 也叫队列同步器，全称 **`AbstractQueuedSynchronizer`**，它是[[Lock接口]]中一个很核心的组件，主要是用来构建锁或其他同步组件的基础架构。它使用了一个 `int` 成员变量表示**同步状态**，并通过**队列**的机制来完成线程的排队工作。

```text
AQS 的三大核心组件：
├── volatile int state（同步状态，0 表示锁空闲，≥1 表示被持有）
├── CAS（原子修改 state，保证只有一个线程能成功获取锁）
└── CLH 同步队列（获取锁失败的线程被封装成节点，加入队列尾部并阻塞等待）
```

### 二、`AQS` 的使用方式

同步器的主要使用是通过**继承**的方式。子类通过继承同步器并实现它的抽象方法来管理同步状态。由于在操作中会遇到对状态的修改，因此就需要同步器提供三种方法来进行操作：

| 方法 | 说明 |
|------|------|
| ==**`getState()`**== | 获取当前同步状态的值 |
| ==**`setState(int newState)`**== | 设置当前同步状态的值 |
| ==**`compareAndSetState(int expect, int update)`**== | 通过 CAS 原子地更新同步状态，保证状态的改变是安全的 |

子类通常会被定义为可自定义的**静态内部类**的组件。由于 `AQS` 是一个抽象的机制，同步器不仅可以**独占式**地获取同步状态，还可以支持**共享式**的线程同步，这样就可以根据实际需求来设计出一个合适的自定义锁。

### 三、`AQS` 的两种同步模式

| 模式          | 说明                | 典型实现                         |
| ----------- | ----------------- | ---------------------------- |
| ==**独占式**== | 同一时刻只有一个线程能获取同步状态 | `ReentrantLock`              |
| ==**共享式**== | 多个线程可以同时获取同步状态    | `Semaphore`、`CountDownLatch` |

### 四、同步器与锁的关系

综上所述，同步器（也可以是任意同步组件）是实现锁的一种很关键的东西。同步器和锁的关系，差不多是：**同步器是实现锁的基础，而锁是同步器的结果**。

| 维度 | 同步器（AQS） | 锁（Lock） |
|------|------------|----------|
| ==**面向对象**== | 面向**实现者** | 面向**使用者** |
| ==**关注点**== | 如何管理同步状态、如何排队线程 | 提供 `lock()`、`unlock()` 等使用接口 |
| ==**典型代表**== | AQS | `ReentrantLock`、`Semaphore` |

同步器是面向实现者的，它定义了如何管理同步状态和线程队列；锁是面向使用者的，它提供了简单的 `lock()` 和 `unlock()` 接口，隐藏了底层的复杂实现。
