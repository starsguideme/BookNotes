
**可重入锁与公平锁/非公平锁**

### 一、可重入锁的核心要点

可重入锁的核心要点有两个：

| 要点              | 说明                                                                                                 |
| --------------- | -------------------------------------------------------------------------------------------------- |
| ==**线程再次获取锁**== | 锁需要判断当前获取锁的线程是否为已获锁的线程，如果是则再次获取成功                                                                  |
| ==**锁的最终释放**==  | 重复多少次加锁，就会进行多少次解锁，并由 `state` 字段来判断当前线程是否持有锁。如果 `state` 不为 0，则一直解锁到 `state` 字段为 0 的时候，此时就说明已经完全释放锁了 |

**`ReentrantLock` 通过组合自定义同步器来完成锁的获取与释放**。判断锁的数量是依靠 `state` 这个标识符来判断的。根据锁获取的次数，假设获取次数为 N，在 N-1 之前使用 `release` 方法一般返回都是 `false`，直到完全释放完才返回 `true` 并将占有锁的线程设置为 `null`。这个也是根据 `state` 字段来判断的。

### 二、公平锁

**公平性与否是针对获取锁而言的**。如果一个锁是公平的，那么其只会按照**绝对的时间顺序**来获取锁。

在实际使用中，会优先使用 `hasQueuedPredecessors` 方法来判断 AQS 中该节点是否仍然存在前驱节点。如果存在返回 `true`，但根据公平锁的设计理念，该节点就会处于线程等待的状态，让前驱节点优先使用锁。

**公平锁的代价**：由于太过讲究规则，以及频繁的上下文切换（从用户态切换到内核态），会导致其处于一个排队的情况，从而降低线程效率和造成资源上的浪费。

### 三、非公平锁

除了公平锁以外的锁一般都是非公平锁。其是按照**谁优先使用 CAS + 自旋的方式抢到资源就优先处理谁**。

这可能会导致某些线程虽然是先来的，但可能会被其他线程优先抢走资源（即**线程饥饿**），但这样的好处是不会造成排队的情况，因此其**效率和吞吐量比较高**。

### 四、公平锁与非公平锁对比

| 维度 | 公平锁 | 非公平锁 |
|------|--------|---------|
| ==**获取顺序**== | 按绝对时间顺序（FIFO） | 不保证顺序，谁抢到谁用 |
| ==**判断方法**== | `hasQueuedPredecessors()` 检查是否有前驱节点 | 直接 CAS 尝试获取 |
| ==**效率**== | 较低（需要排队，频繁上下文切换） | ==**较高**==（允许插队，减少线程切换开销） |
| ==**线程饥饿**== | 不会发生 | ==**可能发生**== |
| ==**适用场景**== | 对线程执行顺序有严格要求的场景 | 追求吞吐量的场景（默认） |

### 五、面试要点

| **问题**            | 回答                                                             |
| ------------- | -------------------------------------------------------------- |
| **可重入锁的两个核心要点**   | ==**线程再次获取锁时判断是否为锁持有者**==；==**重复多少次加锁就进行多少次解锁，直到 state 为 0**== |
| **公平锁如何保证公平性**    | 通过 ==**`hasQueuedPredecessors()`**== 检查是否有前驱节点，有则排队等待          |
| **非公平锁为什么效率高**    | 直接 CAS 尝试获取，允许插队，减少上下文切换开销                                     |
| **非公平锁的缺点**       | ==**可能导致线程饥饿**==                                               |
| **`state` 字段的作用** | 判断锁的持有状态，0 表示未持有，大于 0 表示持有                                     |
