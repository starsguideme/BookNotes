


### 一、写锁的本质

由前文已知，写锁的本质其实就是一种类似于**互斥锁**的机制。如果此时的线程已经获取到了写锁，就会增加写状态（低 16 位加 1）。但如果此时该线程的读锁并没有获取到，或读锁已经被其他线程获取到了，则该线程就会进入**等待状态**。

### 二、读锁存在时写锁的处理

在获取写锁时，代码中增加了**读锁是否存在**的判断。如果读锁存在，则写锁就不能获取。这是因为在读写锁中，读锁必须对写锁可见，所以要想获取写锁就必须等待**所有线程全部释放完读锁**。

等待释放完读锁之后才能进行写操作，而一旦进入写锁，其他线程（包括读线程和其他写线程）就会被阻塞。

### 三、写锁获取的核心流程

```text
tryAcquire(arg) 获取写锁的流程：
    ↓
① 判断读锁是否存在（readCount != 0）
    ↓
    ├── 读锁存在 → 进入等待状态（读锁对写锁必须可见）
    │
    └── 读锁不存在 → 继续判断
              ↓
        ② 判断当前线程是否已经持有写锁（可重入判断）
              ↓
              ├── 是 → 增加写状态（低 16 位加 1），获取成功
              │
              └── 否 → CAS 尝试获取写锁
                        ↓
                        ├── 成功 → 设置当前线程为锁持有者
                        │
                        └── 失败 → 进入等待队列
```

### 四、面试要点

| 问题                | 回答                              |
| ----------------- | ------------------------------- |
| **写锁的本质**             | ==**互斥锁**==，同一时刻只有一个线程能持有       |
| **获取写锁时为什么要判断读锁是否存在** | ==**读锁必须对写锁可见**==，需要等待所有读线程释放读锁 |
| **写锁获取成功后会发生什么**      | 其他读线程和写线程都会被**阻塞**              |
| **写锁支持可重入吗**          | ==**支持**==，当前线程可以多次获取写锁         |
