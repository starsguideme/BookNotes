
### 一、读写锁的核心特性

读写锁的特性为同一时刻可以有**多个线程读**，但在写的时候只能有**一个线程执行写操作**。并且在写操作的时候，读线程会和其他写线程一起被阻塞。

读写锁将**读和写进行分离**，这使得并发性比其他的互斥锁更高。这是因为读操作的使用时间要远大于写操作，因此只需要保证写操作执行完之后立即对其他线程拥有可见性，就可以降低资源调度时间。这也是为什么读写锁的效率要比互斥锁的吞吐量和并发量更高。

### 二、ReentrantReadWriteLock 的核心特性

具体实现则由 `ReentrantReadWriteLock` 这个 API 来实现，其特性大致如下：

| 特性 | 说明 |
|------|------|
| ==**公平性选择**== | 支持公平锁与非公平锁两种模式，默认为非公平锁（吞吐量更高） |
| ==**重进入**== | 读锁和写锁都支持重进入，同一个线程可以多次获取读锁或写锁 |
| ==**锁降级**== | 允许从写锁降级为读锁（先获取写锁，再获取读锁，最后释放写锁），但**不允许锁升级**（不能从读锁升级为写锁） |

**锁降级的意义**：一个线程在持有写锁时，可以继续获取读锁，然后释放写锁，最后释放读锁。这样可以在不丢失可见性的前提下，将写操作降级为读操作，提高并发性。但反过来，**锁升级是不允许的**——如果一个线程持有读锁，它不能直接获取写锁，否则可能导致死锁。

### 三、读写锁与互斥锁的对比

| 维度 | 互斥锁（ReentrantLock） | 读写锁（ReentrantReadWriteLock） |
|------|----------------------|-------------------------------|
| ==**并发度**== | 同一时刻只有一个线程能访问 | 多个读线程可以同时访问 |
| ==**写操作**== | 独占 | 独占，且阻塞所有读线程和其他写线程 |
| ==**适用场景**== | 读写比例不确定，或写操作较多 | ==**读多写少**==的场景 |
| ==**吞吐量**== | 较低 | ==**更高**== |

### 四、面试要点

| **问题**            | 回答                                  |
| ------------- | ----------------------------------- |
| **读写锁的核心特性**      | 同一时刻可以有**多个线程读**，但只能有**一个线程写**      |
| **什么是锁降级**        | ==**从写锁降级为读锁**==，先获取写锁，再获取读锁，最后释放写锁 |
| **为什么不允许锁升级**     | 读锁升级为写锁可能导致**死锁**                   |
| **读写锁适用于什么场景**    | ==**读多写少**==的场景                     |
| **读写锁为什么比互斥锁效率高** | 读操作之间不互斥，多个读线程可以并发执行                |
