
### 一、StampedLock 的核心机制

StampedLock 用来创建其他的线程安全组件。当使用这个锁的时候，就会得到当前锁状态的**快照（stamp）**，后续在操作锁时会先使用这个快照。新的快照与旧的快照进行对比，如果两个快照一致，则说明线程是安全的；否则会抛出锁异常。

因此 StampedLock 的使用方法和以往的所有锁机制都是不一样的。在获取写锁后会返回一个**长整型的快照**，当写锁执行完写操作的同步逻辑之后，在释放锁时需要**传入先前获取的快照**。如果在获取写锁时，写锁已经被其他线程获取，则 `writeLock()` 方法会被阻塞并返回一个新的快照。

### 二、StampedLock 的视图方法

由于 StampedLock 和其他锁都不一样，因此其没有直接实现读写锁和一般意义上的互斥锁，但拥有只属于自己的视图方法：

| 方法 | 说明 |
|------|------|
| ==**`asReadLock()`**== | 返回一个只读的 `ReadLock` 视图 |
| ==**`asWriteLock()`**== | 返回一个只写的 `WriteLock` 视图 |
| ==**`asReadWriteLock()`**== | 返回一个 `ReadWriteLock` 视图 |

### 三、StampedLock 的三种锁模式

StampedLock 有三种获取锁的方式：

| 模式 | 说明 | 与 ReentrantReadWriteLock 的对比 |
|------|------|-------------------------------|
| ==**写模式**== | 独占锁，同一时刻只有一个线程能持有 | 类似于 `ReentrantReadWriteLock` 的写锁 |
| ==**读模式**== | 共享锁，多个线程可以同时持有 | 类似于 `ReentrantReadWriteLock` 的读锁 |
| ==**乐观读模式**== | 读锁的一种**弱化版**，不会阻塞写锁的获取 | **StampedLock 独有的模式** |

**乐观读模式的特殊之处**：根据乐观锁的策略，它不会阻塞写锁的获取。在乐观读模式下，线程先读取数据，然后通过 `validate(stamp)` 判断读取期间是否有写操作发生。如果没有，读取的数据就是有效的；如果有，需要升级为悲观读锁或重试。

### 四、StampedLock 的底层实现

StampedLock 的实现方式并不是像 AQS 那样基于 CLH 队列来实现，而是选择了一种 **CLH 的变体**。这个变体优化了读锁和写锁的访问，其核心特点包括：

| 特点 | 说明 |
|------|------|
| ==**相对公平策略**== | 采用一种相对公平的机制，在队列的首节点使用了**随机自旋**方式 |
| ==**减少上下文切换**== | 随机自旋可以有效减少不必要的线程阻塞和上下文切换开销 |
| ==**支持锁转换**== | 不仅支持锁降级（写锁 → 读锁），还支持**锁升级**（读锁 → 写锁） |

### 五、StampedLock 的代价

| 代价 | 说明 |
|------|------|
| ==**不允许重进入**== | 同一个线程不能多次获取同一个锁 |
| ==**不支持 Condition 检测**== | 没有 `Condition` 对象，无法使用等待/通知机制 |
| ==**可能导致死锁**== | 由于支持锁升级，使用不当会产生死锁 |

### 六、适用范围

| 适用场景 | 说明 |
|---------|------|
| ==**读多写少的高并发场景**== | 乐观读模式不会阻塞写锁，适合读操作远多于写操作的场景，吞吐量高于 `ReentrantReadWriteLock` |
| ==**需要避免锁升级死锁的场景**== | StampedLock 支持锁升级（读锁 → 写锁），在需要从读锁转换为写锁时不会产生死锁（但需要手动处理） |
| ==**不需要重进入的场景**== | StampedLock 不支持重进入，适合锁持有逻辑简单、不会递归调用的场景 |
| ==**需要精细控制锁状态的场景**== | 通过快照（stamp）机制可以判断读取期间是否有写操作发生，适合需要乐观读校验的场景 |

| 不适用场景 | 说明 |
|-----------|------|
| ==**需要可重入的场景**== | StampedLock 不支持重进入，如果同一个线程需要多次获取同一个锁，应使用 `ReentrantReadWriteLock` |
| ==**需要 Condition 等待/通知的场景**== | StampedLock 没有 `Condition` 对象，无法使用 `await/signal` 机制，应使用 `ReentrantLock` |
| ==**需要严格公平性的场景**== | StampedLock 采用相对公平策略而非绝对 FIFO，如果对公平性要求极高，应使用公平模式的 `ReentrantReadWriteLock` |
| ==**锁持有逻辑复杂的场景**== | StampedLock 需要手动传入快照来释放锁，使用不当容易出错，适合锁持有逻辑简单的场景 |

### 七、三种读写锁的选择指南

| 锁类型 | 适用场景 |
|--------|---------|
| ==**ReentrantReadWriteLock**== | 读多写少，需要可重入、需要 Condition |
| ==**StampedLock**== | 读非常多写非常少，需要乐观读、不需要可重入 |
| ==**ReentrantLock**== | 读写比例不确定，或写操作较多，只需要互斥锁 |
