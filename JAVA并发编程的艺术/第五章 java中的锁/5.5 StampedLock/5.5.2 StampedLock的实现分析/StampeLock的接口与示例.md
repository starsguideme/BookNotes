
### 一、StampedLock 的方法分类

StampedLock 提供了很多方法，但可以具体分为 **5 大类**：

| 类别 | 说明 |
|------|------|
| ==**获取与释放读锁**== | 包括普通读锁、乐观读锁的获取与释放 |
| ==**获取与释放写锁**== | 写锁的获取与释放，操作与读锁类似 |
| ==**获取状态与校验快照**== | 通过快照对比判断写锁是否被获取，数据是否有效 |
| ==**获取锁视图**== | 通过 `as` 开头的方法获取对应的锁视图 |
| ==**锁转换**== | 支持读锁、写锁、乐观读锁三种模式之间的相互转换 |

### 二、获取与释放读锁的 API

| API | 说明 |
|-----|------|
| ==**`long readLock()`**== | 获取普通读锁，阻塞直到成功获取，返回快照 |
| ==**`long tryReadLock(long time, TimeUnit unit)`**== | 带超时的尝试获取读锁 |
| ==**`long tryOptimisticRead()`**== | 获取乐观读锁，**不阻塞**，仅返回快照，开销极小 |
| ==**`void unlockRead(long stamp)`**== | 释放读锁，需要传入获取时返回的快照 |

### 三、锁视图与快照校验

通过使用 `as` 开头的方法来获取对应的锁视图，比如说 `asReadWriteLock()` 方法可以获得关于读写锁的引用视图。

而快照校验方法会检查获取乐观读锁后是否有其他线程获取了写锁。如果快照对比一致，则表示写锁没有被获取，本地数据是有效的。此过程在读多写少的场景会带来较大幅度的性能提升，这点是通过锁视图无法做到的。

除了这个方法，StampedLock 还支持获取锁的状态，并以此判断写锁是否已经被获取。

### 四、锁转换

StampedLock 支持三种模式的相互转换。比如说，在获取了读锁后，如果此时需要升级为写锁，就可以使用之前获取读锁的快照，并通过 `long tryConvertToWriteLock(long stamp)` 将读锁升级为写锁。

**只有 StampedLock 可以进行锁升级**，这是它与其他读写锁的重要区别。但在升级锁的过程中如果遇到锁转换失败的情况，返回的快照状态会变为 `0`，此时需要再次调用 `writeLock()` 获取写锁。

### 五、乐观读锁的使用方法

乐观读锁的获取方法仅仅返回了获取那一刻锁状态的快照，所以乐观读锁的开销其实很小。获取到乐观读锁后，需要复制数据到本地变量。如果之后的快照比对失败，就需要根据获取到的读锁来刷新之前的本地变量。

但这种操作一旦遇到了多个线程/对象一起使用，会导致大量的冗余代码和边界条件的考虑。所以 API 中会使用 `for` 循环来减少冗余代码，不断循环重试直到数据读一致为止。

```text
乐观读锁的使用流程：

① 获取乐观读锁 → 返回快照 stamp
    ↓
② 复制共享数据到本地变量
    ↓
③ 通过 validate(stamp) 校验快照
    ↓
    ├── 快照一致 → 数据有效，直接返回
    │
    └── 快照不一致 → 说明有写操作发生
              ↓
        ④ 升级为普通读锁，重新读取数据
              ↓
        ⑤ 释放读锁，返回数据
```

### 六、SLCache 的写操作

`SLCache` 的写操作 `putIfAbsent` 方法演示了乐观锁升级为写锁的方法，与 `get` 方法升级到读锁类似。通过使用 `tryConvertToWriteLock()` 方法，将非阻塞的轻量级乐观读锁升级为具备使线程阻塞能力的重量级写锁。

但在升级锁的过程中遇到锁转换失败的情况，返回的快照状态会成为 `0`，此时需要再次调用 `writeLock()` 获取写锁，以确保数据一致性。

| 问题                   | 回答                                               |

| **StampedLock 的方法分为几大类** | ==**5 大类**==：获取与释放读锁、获取与释放写锁、获取状态与校验快照、获取锁视图、锁转换 |
| **乐观读锁的特点**              | 获取时不阻塞，仅返回快照，开销极小；通过 `validate(stamp)` 校验数据是否有效  |

| **如何处理乐观读锁校验失败**         | 升级为普通读锁，通过 `for` 循环重试，直到数据读一致                    |
