

### 一、写锁获取的流程

邮戳锁获得写锁的流程主要包括两部分：

| 阶段 | 说明 |
|------|------|
| ==**尝试获取写锁并自旋入队**== | 先自旋尝试获取写锁，失败后创建节点加入同步队列 |
| ==**队列中自旋获取写锁**== | 进入队列后继续自旋，直到成功获取写锁或被阻塞 |

### 二、尝试获取写锁

线程在获取写锁时，首先会尝试自旋获取。获取的操作就是在没有读写状态的情况下设置写状态（将第 8 位置为 1）。如果设置成功会立即返回一个快照（stamp）。

如果设置失败（说明当前存在读锁或写锁已经被其他线程持有），则会创建节点并加入同步队列。

### 三、队列中自旋获取写锁

进入队列后，线程会基于此继续判断该节点的前驱节点是否处于等待状态。如果是，该线程会进入**阻塞状态**。但如果该节点的前驱是**首节点**，在获取写锁时会将其设置成写状态。被阻塞的线程会被前驱节点唤醒。

这种机制和 CLH 队列的实现机制类似——前驱节点释放锁后唤醒后继节点。

### 四、写锁获取与释放的完整流程

```text
写锁获取流程（writeLock）：

① 自旋尝试 CAS 设置写状态（第 8 位置为 1）
    ↓
    ├── 成功 → 返回快照 stamp，持有写锁
    │
    └── 失败（存在读锁或写锁已被持有）
              ↓
        ② 创建 WNode 节点，加入同步队列
              ↓
        ③ 判断前驱节点状态
              ↓
              ├── 前驱是首节点 → 尝试获取写锁
              │         ↓
              │    ├── 成功 → 将当前节点设为新的首节点，返回 stamp
              │    │
              │    └── 失败 → 继续自旋
              │
              └── 前驱不是首节点 或 前驱处于等待状态
                        ↓
                   ④ 阻塞当前线程，等待被前驱节点唤醒


写锁释放流程（unlockWrite）：

① 释放写锁：state += WBITS（第 8 位置为 0，版本号 +1）
    ↓
② 判断同步队列中是否有等待节点
    ↓
    ├── 队列为空 → 直接返回
    │
    └── 队列不为空 → 唤醒后继节点
              ↓
        ③ 被唤醒的线程继续自旋，尝试获取写锁
```

### 五、写锁释放时的状态一致性

如上文所示，由于写锁具有**排他性**，从写锁的获取到释放，其状态不会发生改变，因此之前返回的快照（stamp）和当前状态理应相等。

但释放写锁会唤醒后续节点对应的线程。被唤醒的线程会依旧执行自身获取锁的逻辑，并尝试以**自旋**的方式来获取锁。

### 六、面试要点

| 问题           | 回答                                      |
| ------------ | --------------------------------------- |
| **写锁获取分哪两个阶段**   | ==**尝试获取写锁并自旋入队**== + ==**队列中自旋获取写锁**== |
| **获取写锁成功的前提条件**  | 当前**不存在读锁**，且**写锁未被其他线程持有**             |
| **写锁释放后版本号如何变化** | `state += WBITS`，第 8 位置为 0，版本号 **+1**   |
| **释放写锁后会做什么**    | 唤醒同步队列中的**后继节点**                        |
| **被唤醒的线程如何获取锁**  | 继续**自旋**尝试获取写锁                          |
