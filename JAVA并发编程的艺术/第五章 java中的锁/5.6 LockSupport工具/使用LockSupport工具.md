
### 一、LockSupport 的核心定位

当需要阻塞和唤醒一个线程的时候，都会使用这个工具类来完成。在这个工具类中会使用一些共有的静态方法，这些方法提供了最基本的**线程阻塞和唤醒功能**，并基于此成为构建核心同步组件的基础设施之一。

### 二、LockSupport 的核心方法

在 LockSupport 接口中定义了一组以 `park` 开头的方法用来阻塞当前线程，以及使用 `unpark` 方法来唤醒一个被阻塞的线程。

**JDK 5 引入的基础方法**：

| 方法 | 说明 |
|------|------|
| ==**`void park()`**== | 阻塞当前线程，直到被 `unpark` 唤醒或线程被中断 |
| ==**`void parkNanos(long nanos)`**== | 阻塞当前线程指定纳秒数，超时自动返回 |
| ==**`void parkUntil(long deadline)`**== | 阻塞当前线程到指定的绝对时间点 |
| ==**`void unpark(Thread thread)`**== | 唤醒指定线程 |

**JDK 6 新增的方法**：

| 方法                                                      | 说明                              |
| ------------------------------------------------------- | ------------------------------- |
| ==**`void park(Object blocker)`**==                     | 阻塞当前线程，并记录当前线程在等待的对象（`blocker`） |
| ==**`void parkNanos(Object blocker, long nanos)`**==    | 带超时的阻塞，并记录等待对象                  |
| ==**`void parkUntil(Object blocker, long deadline)`**== | 阻塞到指定时间点，并记录等待对象                |

### 三、`blocker` 参数的作用

其中 `blocker` 是用来表示当前线程在等待的对象，该对象的核心作用有两个：

| 作用            | 说明                                         |
| ------------- | ------------------------------------------ |
| ==**GC 排查**== | 在 GC 日志中可以知道线程在等待哪个对象，方便分析内存问题             |
| ==**充当监视器**== | 在 `jstack` 等线程诊断工具中，可以直接看到线程的等待对象，便于排查并发问题 |

### 四、面试要点

| **问题**                    | 回答                                     |
| --------------------- | -------------------------------------- |
| **LockSupport 的核心作用**     | ==**阻塞和唤醒线程**==，是构建同步组件的基础设施           |
| **`park` 和 `unpark` 的区别** | `park` 阻塞当前线程，`unpark` 唤醒指定线程          |
| **`blocker` 参数的作用**       | 用于 **GC 排查**和**充当监视器**，方便诊断工具识别线程等待的对象 |
| **JDK 6 新增了什么**           | 新增了带 `blocker` 参数的方法，用于记录线程等待的对象       |
