
### 一、Condition 的依赖关系

从[[Condition接口]]中定义了等待和唤醒两种方式。当线程使用这些方法时，需要提前获取到 `Condition` 接口中对象关联的锁，这些锁是由 `Lock` 对象所创建出来的。换句话说，**`Condition` 完全依赖于 `Lock`**。

当 `Condition` 对象作为成员变量且使用 `await()` 方法时，当前线程会**释放锁并进入等待状态**。直到其他线程调用 `Condition` 对象的 `signal()` 方法并通知当前线程后，线程才从 `await()` 方法返回。因此线程一般情况下都是在**返回前就已经重新获取了锁**。

### 二、Condition 的 API

以下是 `Condition` 接口的核心方法及其描述：

| 方法 | 说明 |
|------|------|
| ==**`void await()`**== | 当前线程进入等待状态，直到被通知或中断 |
| ==**`void awaitUninterruptibly()`**== | 当前线程进入等待状态，**不响应中断** |
| ==**`long awaitNanos(long nanosTimeout)`**== | 带超时的等待，超时自动返回 |
| ==**`boolean awaitUntil(Date deadline)`**== | 等待到指定的绝对时间点 |
| ==**`void signal()`**== | 唤醒一个等待在 Condition 上的线程 |
| ==**`void signalAll()`**== | 唤醒所有等待在 Condition 上的线程 |

从以上的 API 来看，必须通过 `Lock.newCondition()` 方法获取一个 `Condition` 实例。

### 三、有界队列示例

下面通过一个[[有界队列]]来深入理解 Condition 的使用方式。

**BoundedQueue 的核心逻辑**：

-   **添加方法（`add`）**：首先需要获得锁，目的是确保数组修改时的**可见性和互斥性**。当数组数量等于数组长度时，则表示数组已满，有界队列会调用 `notFull.await()`，当前线程随之释放锁并进入等待状态。如果数组数量不等于数组长度，说明数组未满，则有界队列会将元素添加至数组中，同时通知等待在 `notEmpty` 上的线程进行新一轮的线程获取。

-   **移除方法（`remove`）**：首先需要获得锁。当数组数量为 0 时，则表示数组为空，有界队列会调用 `notEmpty.await()`，当前线程随之释放锁并进入等待状态。如果数组数量不等于 0，说明数组非空，则有界队列会将元素从数组中移除，同时通知等待在 `notFull` 上的线程可以继续添加。

**两个 Condition 的分工**：

| Condition | 用途 | 等待条件 | 唤醒时机 |
|-----------|------|---------|---------|
| ==**`notFull`**== | 控制生产者等待 | 数组已满时，生产者等待 | 消费者移除元素后唤醒生产者 |
| ==**`notEmpty`**== | 控制消费者等待 | 数组为空时，消费者等待 | 生产者添加元素后唤醒消费者 |

**Condition 相较于 `wait/notify` 的核心优势**：通过两个不同的 Condition，可以精准唤醒生产者或消费者，而不是像 `notifyAll()` 那样唤醒所有等待线程，从而减少不必要的线程上下文切换开销。

### 四、面试要点

| 问题                                | 回答                                                                  |
| --------------------------------- | ------------------------------------------------------------------- |
| **Condition 和 Lock 的关系**          | ==**Condition 完全依赖于 Lock**==，Condition 对象由 `Lock.newCondition()` 创建 |
| **`await()` 方法执行后会发生什么**          | 当前线程**释放锁**并进入等待状态，直到被 `signal()` 唤醒并**重新获取锁**                      |
| **有界队列为什么需要两个 Condition**         | ==**`notFull` 控制生产者等待**==，==**`notEmpty` 控制消费者等待**==，实现精准唤醒         |
| **Condition 相较于 wait/notify 的优势** | 支持**多个等待队列**，可以精准唤醒对应条件的线程                                          |
