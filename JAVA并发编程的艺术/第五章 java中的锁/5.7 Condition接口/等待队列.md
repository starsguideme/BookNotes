

**Condition 的等待队列**

### 一、等待队列的 FIFO 特性

既然是队列，那么其就有 **FIFO（先进先出）** 的特性。在该队列中的每个节点都包含了一个**线程引用**，该线程就是在 Condition 对象上等待的线程。如果一个线程使用了 `Condition.await()` 方法，将会释放锁并将构造的新节点加入到队列中，并进入线程等待状态。

事实上，等待队列中的节点定义也复用了同步器中节点的定义。也就是说，无论是**同步队列**还是**等待队列**，其节点类型在 AQS 中都是同一个静态内部类 `AbstractQueuedSynchronizer.Node`。

### 二、等待队列的基本结构

如果一个 Condition 包含了一个等待队列，这个队列中拥有着不同的**首节点（firstWaiter）**和**尾节点（lastWaiter）**。如果当前线程使用了 `Condition.await()` 方法，将会以当前线程构造新的节点，并将新的节点从尾端添加到等待队列中。

```text
Condition 的等待队列结构：

Condition 对象
    │
    ├── firstWaiter → Node1 (等待线程 A)
    │                      │ nextWaiter
    │                      ▼
    │                   Node2 (等待线程 B)
    │                      │ nextWaiter
    │                      ▼
    │                   Node3 (等待线程 C)
    │                      │ nextWaiter
    │                      ▼
    │                    null
    │
    └── lastWaiter → Node3
```

### 三、新增节点的流程

如上图所示，Condition 拥有着首尾节点的引用。新增节点只需要将原有的尾节点的 `nextWaiter` 指向它，并更新尾节点。

```text
新增节点的流程：

① 当前线程调用 condition.await()
    ↓
② 以当前线程构造新的 Node 节点
    ↓
③ 将原有尾节点的 nextWaiter 指向新节点
    ↓
④ 更新 lastWaiter 为新节点
    ↓
⑤ 当前线程释放锁，进入等待状态
```

### 四、为什么不需要 CAS 保证原子性？

新增节点的操作中并没有使用 CAS 来保证更新操作，因此原子性不一定会得到保证。之所以不使用 CAS 的方法，这是因为**在使用 `await()` 方法的线程必定都是获取到了锁的线程**。既然已经持有了锁，那么等待队列的操作就变成了单线程操作，就不必再使用 CAS 来确保原子性了。

这一点和 AQS 同步队列的入队操作不同——同步队列的入队发生在获取锁失败时，多个线程可能同时入队，因此必须通过 CAS 保证线程安全。而等待队列的入队发生在已经持锁的线程调用 `await()` 时，不存在并发竞争。

### 五、等待队列与同步队列的对比

| 维度 | 同步队列（CLH） | 等待队列（Condition） |
|------|---------------|---------------------|
| ==**数据结构**== | 双向链表（`prev` + `next`） | 单向链表（仅 `nextWaiter`） |
| ==**入队是否需要 CAS**== | ==**需要**==（多线程同时入队） | ==**不需要**==（已持有锁，单线程操作） |
| ==**节点类型**== | `AbstractQueuedSynchronizer.Node` | 同左，复用同一个内部类 |
| ==**入队时机**== | 获取锁失败时 | 调用 `await()` 时 |

### 六、面试要点

| 问题                 | 回答                                   |
| ------------------ | ------------------------------------ |
| **等待队列和同步队列的节点类型是否相同** | ==**相同**==，都使用 AQS 中的静态内部类 `Node`    |
| **为什么等待队列入队不需要 CAS**   | 调用 `await()` 的线程必定**已经持有了锁**，不存在并发竞争 |
| **等待队列是双向链表还是单向链表**    | ==**单向链表**==，仅通过 `nextWaiter` 连接     |
| **同步队列入队为什么需要 CAS**    | 多个线程可能同时获取锁失败并入队，必须保证**线程安全**        |
