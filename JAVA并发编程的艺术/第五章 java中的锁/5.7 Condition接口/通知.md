

**Condition 的唤醒机制**

### 一、`signal()` 方法的核心流程

使用 `Condition` 的 `signal()` 方法，将会唤醒在等待队列中**等待时间最长的节点**（即首节点），并在唤醒该节点之前，将其**移动到同步队列**中。

**使用 `signal()` 方法的前置条件**：当前线程必须获取了锁。可以看到 `signal()` 方法进行了 `isHeldExclusively()` 检查，也就是当前线程必须是获取了锁的线程。由前文得知，`Condition` 的实现是基于等待队列的，而等待队列中可以获取锁资源的节点一般都是**首节点**。

### 二、`signal()` 的执行过程

当调用 `signal()` 时，会将等待队列的首节点移动到同步队列中，并使用 `LockSupport.unpark()` 唤醒该节点中的线程。

**详细的执行流程**：

1.  **移动节点**：通过调用同步器的 `enq()` 方法，等待队列中的头节点线程将以**线程安全**的方式将节点移动到同步队列中。
2.  **唤醒线程**：当节点移动到同步队列后，当前线程会再次使用 `LockSupport` 接口中的 API 让该节点被唤醒。详细的 API 参考[[使用LockSupport工具]]。
3.  **重新竞争锁**：被唤醒后的线程将从 `await()` 方法的 `while` 循环中退出并返回 `true`，但前提是节点已经存在于同步队列中。进而调用同步器的 `acquireQueued()` 方法将该线程加入到同步状态的资源获取中。
4.  **成功获取锁**：一旦成功地获取了同步状态之后，被唤醒的线程将从先前调用的 `await()` 方法返回，此时就说明该线程已经成功地获取了锁。

### 三、`signal()` 的完整流程图

```text
signal() 的执行流程：

① 当前线程持有锁
    ↓
② 调用 condition.signal()
    ↓
③ 检查当前线程是否持有锁（isHeldExclusively()）
    ↓
    ├── 未持有锁 → 抛出 IllegalMonitorStateException
    │
    └── 持有锁
              ↓
        ④ 获取等待队列的首节点（等待时间最长的节点）
              ↓
        ⑤ 通过 enq() 将首节点从等待队列移动到同步队列的尾部
              ↓
        ⑥ 通过 LockSupport.unpark() 唤醒该节点中的线程
              ↓
        ⑦ 被唤醒的线程在 await() 的 while 循环中检查自己是否已在同步队列中
              ↓
        ⑧ 调用 acquireQueued() 重新竞争锁
              ↓
        ⑨ 获取锁成功后，从 await() 方法返回
```

### 四、`signalAll()` 方法

`Condition` 的 `signalAll()` 方法相当于对等待队列中的每个节点都执行一次 `signal()` 方法，效果就是所有节点重复 `signal()` 方法——将等待队列中的**所有节点全部移动到同步队列中**，并唤醒每个节点的线程。

```
signalAll() 和 signal() 的区别：

signal()：
等待队列首节点 → 移动到同步队列 → 唤醒一个线程

signalAll()：
等待队列所有节点 → 全部移动到同步队列 → 唤醒所有线程
```

### 五、面试要点

| 问题                                 | 回答                                                           |
| ---------------------------------- | ------------------------------------------------------------ |
| **`signal()` 方法的作用**               | 唤醒等待队列中**等待时间最长的节点**，并将其移动到同步队列中                             |
| **`signal()` 的前置条件**               | 当前线程必须**持有锁**，否则抛出 `IllegalMonitorStateException`            |
| **`signalAll()` 和 `signal()` 的区别** | `signal()` 只唤醒**一个**节点，`signalAll()` 将**所有**等待节点全部移动到同步队列并唤醒 |
| **被唤醒的线程如何重新获取锁**                  | 通过 `acquireQueued()` 方法在同步队列中**重新竞争锁**                       |
| **唤醒后线程从 `await()` 返回的前提**         | 节点**已经存在于同步队列中**，并且成功获取了锁                                    |
