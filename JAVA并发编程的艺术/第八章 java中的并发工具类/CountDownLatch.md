

### 一、核心定位

CountDownLatch 允许**一个或多个线程**处于等待状态，直到其他线程执行完剩余的线程操作后，等待线程才被唤醒继续执行。

### 二、核心机制

CountDownLatch 的构造参数可以接受一个 `int` 类型的参数作为**计数器**（count）。当调用 CountDownLatch 中的 `countDown()` 方法时，计数器的值就会 **减 1**。CountDownLatch 的 `await()` 方法会**阻塞当前线程**，直到计数器的值变为 **0** 才停止调用该方法，等待线程被唤醒。

因为 `countDown()` 方法可以用在任何地方，所以这里的 N 可以是 **N 个步骤**，也可以是 **N 个线程**。对于多线程时，可以把 CountDownLatch 的引用传递到线程里即可。

**注意**：CountDownLatch **不可能重新初始化或修改**内部计数器的值。计数器一旦归零，就不能再被重置。如果需要可重置的计数器，应使用 `CyclicBarrier`。

### 三、`countDown()` 和 `await()` 的关系

线程中的 `countDown()` 方法要比 `await()` 方法**先发生**——即先有线程执行完任务并调用 `countDown()` 将计数器减到 0，调用 `await()` 的等待线程才能被唤醒继续执行。

### 四、使用示例

```java
// 等待 3 个任务完成后，主线程继续执行
CountDownLatch latch = new CountDownLatch(3);

// 启动 3 个子线程
for (int i = 0; i < 3; i++) {
    new Thread(() -> {
        // 执行任务...
        latch.countDown();  // 每个线程完成任务后，计数器减 1
    }).start();
}

latch.await();  // 主线程等待，直到计数器变为 0
// 主线程继续执行...
```

### 五、适用范围

| 适用场景 | 说明 |
|---------|------|
| ==**等待多个线程完成任务**== | 主线程需要等待所有子线程执行完毕后再继续执行 |
| ==**等待外部资源初始化**== | 等待外部资源（如数据库连接）初始化完成后再处理请求 |
| ==**多线程协作**== | 一个线程需要等待其他多个线程完成各自的任务后再汇总结果 |

| 不适用场景 | 说明 |
|-----------|------|
| ==**需要重复使用的场景**== | CountDownLatch 只能使用一次，需要重复使用应使用 `CyclicBarrier` |
| ==**需要阻塞主线程等待子线程的场景**== | 也可以用 `join()` 替代，但 `join()` 需要逐个等待，不如 CountDownLatch 方便 |
