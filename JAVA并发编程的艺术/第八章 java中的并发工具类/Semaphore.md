

**Semaphore 信号量**

### 一、核心定位

[[信号量]]是用来**同时控制特定资源的线程数量**中一个核心的特征点，它可以通过协调各个线程来保证合理的使用公共资源。

### 二、使用场景

信号量的使用场景：用于**控制流量**（如消息队列的削峰），特别适用于共有资源处于**资源有限**的情况。

| 适用场景 | 说明 |
|---------|------|
| ==**流量控制/削峰填谷**== | 限制同时访问某个资源的线程数量，如 API 限流 |
| ==**连接池管理**== | 数据库连接池、线程池等资源有限的场景 |
| ==**生产者-消费者模式**== | 控制生产者与消费者的速率匹配 |

| 不适用场景 | 说明 |
|-----------|------|
| ==**只需要互斥的场景**== | 如果只需要一个许可证，使用 `ReentrantLock` 或 `synchronized` 更简单 |
| ==**需要条件等待的场景**== | Semaphore 不提供 `Condition` 对象，需要条件等待时应使用锁 |

### 三、常用 API

| API | 说明 |
|-----|------|
| ==**`int availablePermits()`**== | 返回当前可用的许可证数量 |
| ==**`int getQueueLength()`**== | 获取正在等待获取许可证的线程数量 |
| ==**`boolean hasQueuedThreads()`**== | 判断是否有线程正在等待获取许可证 |
| ==**`void reducePermits(int reduction)`**== | 减少可用许可证的数量，不可逆 |
| ==**`Collection<Thread> getQueuedThreads()`**== | 获取所有正在等待获取许可证的线程集合 |

### 四、核心方法

| 方法 | 说明 |
|------|------|
| ==**`acquire()`**== | 获取一个许可证，如果没有则阻塞等待 |
| ==**`release()`**== | 释放一个许可证，将其归还给信号量 |
| ==**`tryAcquire()`**== | 尝试获取一个许可证，成功返回 `true`，失败立即返回 `false` |
| ==**`tryAcquire(timeout, unit)`**== | 带超时的尝试获取许可证 |

### 五、使用示例

```java
// 创建一个信号量，允许最多 3 个线程同时访问资源
Semaphore semaphore = new Semaphore(3);

// 线程获取许可证
semaphore.acquire();
try {
    // 访问共享资源
} finally {
    semaphore.release();  // 释放许可证
}
```

### 六、面试要点

| 问题                            | 回答                                  |
| ----------------------------- | ----------------------------------- |
| **Semaphore 的核心作用**               | ==**控制同时访问特定资源的线程数量**==             |
| **Semaphore 的典型使用场景**             | 流量控制、连接池管理、限流削峰                     |
| **`acquire()` 和 `release()` 的作用** | `acquire()` 获取许可证，`release()` 释放许可证 |
| **Semaphore 和锁的区别**               | 锁只允许一个线程访问，Semaphore 允许多个线程同时访问     |
| **`reducePermits` 的特点**           | ==**不可逆**==，减少后无法再增加                |
