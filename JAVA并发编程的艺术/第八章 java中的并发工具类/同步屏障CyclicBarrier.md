
### 一、核心定位

CyclicBarrier 的作用是让一组线程达到任意一个屏障时被**阻塞**，直到最后一个线程到达屏障时，屏障才会结束，所有线程才可以继续执行。

### 二、核心机制

CyclicBarrier 的默认构造方法是 `CyclicBarrier(int parties)`，其参数表示**屏障拦截时的线程数量**。每个线程都会使用 `await()` 方法来告诉 CyclicBarrier 已经到达了屏障，然后当前线程会**陷入阻塞状态**。

**与 CountDownLatch 的区别**：

| 维度 | CountDownLatch | CyclicBarrier |
|------|---------------|--------------|
| ==**核心作用**== | 一个或多个线程等待其他线程完成任务 | 一组线程**互相等待**，直到所有线程都到达屏障 |
| ==**计数器是否可重置**== | 不可重置 | ==**可重置**==，可以重复使用 |
| ==**适用场景**== | 等待任务完成 | 多线程同步，如多线程计算后合并结果 |

### 三、适用限制

这个同步屏障只能适用于**几个少数的线程**。因为一旦线程多了起来，同步屏障要求**所有线程必须全部到达屏障**才可以让线程继续执行。因此如果某个线程开始卡顿、阻塞或死锁，就会让系统完全宕机——所有其他线程都会被永久阻塞在屏障处。

### 四、高级构造函数

除了 `CyclicBarrier(int parties)`，还可以使用 `CyclicBarrier(int parties, Runnable barrierAction)` 这种高级构造函数。这种方法可以**优先处理**任意线程达到屏障时的操作：当所有线程都到达屏障时，会**优先执行 `barrierAction`** 这个线程，然后再让所有等待线程继续执行。

### 五、使用示例

```java
// 等待 3 个线程都到达屏障后，优先执行汇总操作，再让所有线程继续
CyclicBarrier barrier = new CyclicBarrier(3, () -> {
    System.out.println("所有线程到达屏障，开始汇总...");
});

for (int i = 0; i < 3; i++) {
    new Thread(() -> {
        // 执行任务...
        barrier.await();  // 到达屏障，等待其他线程
        // 所有线程到达后，继续执行...
    }).start();
}
```

### 六、适用范围

| 适用场景 | 说明 |
|---------|------|
| ==**多线程同步计算**== | 多个线程分别计算一部分数据，全部完成后合并结果 |
| ==**需要重复使用的屏障**== | CyclicBarrier 可以重置，适合多次同步的场景 |
| ==**优先执行汇总操作**== | 使用 `barrierAction` 在所有线程到达后优先执行汇总 |

| 不适用场景 | 说明 |
|-----------|------|
| ==**线程数量较多的场景**== | 某个线程阻塞会导致所有线程被永久阻塞 |
| ==**只需要等待任务完成的场景**== | 使用 CountDownLatch 即可，不需要 CyclicBarrier 的复杂机制 |
| ==**线程数量不确定的场景**== | CyclicBarrier 需要预先指定线程数量 |
