

### 一、三个核心方法

常用的方法共有 3 种，分别为**读方法（get）**、**写方法（put）**和**获得大小的方法（size）**。

### 二、get 读方法

`Segment` 的 `get` 操作实现十分简单和高效。会先经历一遍 Hash 算法，然后再通过得到的 hash 值进行散列运算，定位到 `Segment`，并以此定位到 `Segment` 内部的 `HashEntry` 元素。

**get 方法高效的核心原因**：整个过程完全**不需要加锁**，除非读取到的值是 `NULL`，才会上锁后重新获取资源。

在[[ConcurrentHashMap的总结]]中，我提到了 `Hashtable` 在每次执行的时候都需要使用一把 `synchronized` 锁机制。为了避免频繁的加锁和解锁操作，`ConcurrentHashMap` 在 `get` 方法上使用了 **`volatile`** 来修饰变量，让变量存储在共享内存中，以此让线程之间变得相互具有可见性。

虽然在读操作上可以被多线程同时操作，但在写操作的时候借鉴了**读写锁的机制**。不过这种读写锁并非是由重量级锁来完成的，而是基于 **`volatile` + 内存屏障**来完成的。

### 三、put 写方法

由于 `put` 方法需要对共享变量进行写入操作，考虑到线程安全的情况，在操作共享变量时**必须加锁**。`put` 方法首先会定位到 `Segment`，然后在 `Segment` 里执行插入操作。插入操作会经历两个步骤：

#### 1. 判断是否需要扩容

在插入元素前会判断 `Segment` 里的 `HashEntry` 数组是否超过容量（阈值）。如果超过阈值，则对数组进行**扩容**。这种扩容方式是基于当前数组剩余容量和即将要插入的元素数量来判断的，所以其在扩容时不会产生任何不必要的空间浪费。

#### 2. 如何扩容

在扩容的时候，首先会创建一个容量是原来容量**两倍**的数组，然后通过将原数组里的元素进行**再散列**插入到新的数组里。这个操作只会生效于**某个 `Segment` 对象**中——每个 `Segment` 独立扩容，不会影响其他 `Segment`。

### 四、size 方法

如果要统计整个 `ConcurrentHashMap` 里所有元素的总大小，就必须要统计**所有 `Segment` 里的元素大小之和**。这是因为 `Segment` 里的全局变量 `count` 是一个被 `volatile` 修饰的共享变量。

`size` 方法会根据 `put`、`remove` 和 `clean` 中的 `modCount` 变量来辅助判断 `count` 是否被其他线程修改过，以此得到准确的计算值。如果 `modCount` 在统计前后没有变化，说明统计结果是准确的；如果发生了变化，说明有其他线程在此期间修改了数据，就需要**重新统计**。

### 五、面试要点

| 问题              | 回答                                                       |
| --------------- | -------------------------------------------------------- |
| **get 方法为什么不需要加锁**  | ==**volatile**== 保证了可见性，读取操作不需要加锁                        |
| **put 方法需要加锁吗**     | ==**需要**==，对共享变量写入时必须保证线程安全                              |
| **扩容的范围是多少**        | 每次扩容为原来容量的 **2 倍**，且只针对**当前 Segment**                    |
| **size 方法如何保证准确性**  | 通过 `modCount` 辅助判断，如果统计前后 `modCount` 不变，则结果准确；否则重新统计     |
| **与 Hashtable 的区别** | Hashtable 每次操作都需要锁整个表，ConcurrentHashMap 只锁**当前 Segment** |
