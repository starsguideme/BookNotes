ConcurrentHashMap是一个在多线程下保证线程安全的HashMap的，因此其具有HashMap的所有特性，之所以有这个接口，是因为一般类的HashMap无法满足多线程查询的使用情况，当使用一般类的HashMap的时候可能会导致程序的死循环. 
使用ConcurrentHashMap的原因在于以下三点
- 线程不安全的HashMap:在多线程下，使用HashMap的put方法可能导致程序死循环，也可能导致CPU的利用率接近100%,这是因为HashMap在并发执行put操作时会引起死循环的原因是在于多线程会导致HashMap的Entry链表形成环形数据结构，也就是说Entry的next节点永不为空导致其变成死循环
- 效率低下的HashTable:HashTable容器使用了synchornized来保证线程安全，但在线程竞争激烈的情况下HashTable的效率非常低下(这是互斥锁的特性)
- ConcurrentHashMap的锁分段技术可以提高并发访问率:HashTable容器在竞争激烈的并发环境下表现出效率的原因在于所有的线程都会访问且竞争同一把锁，而ConcurrentHashMap则采用了将所有锁放入到一个容器里，多线程访问容器会获得不同的线程资源，因此线程间不存在资源竞争的情况，所以效率高，这就是ConcurrentHashMap的锁分段技术
