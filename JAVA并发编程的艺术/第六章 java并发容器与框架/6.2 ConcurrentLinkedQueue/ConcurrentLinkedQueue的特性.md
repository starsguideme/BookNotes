
### 一、核心定位

`ConcurrentLinkedQueue` 是一个**线程安全的无界非阻塞队列**，基于**链接节点**实现。它使用 **FIFO（先进先出）** 的规则来对节点进行排序。当我们添加一个元素的时候，它会将该元素添加到队列的**尾部**；当获取一个元素时，会使用 **CAS 算法**来返回队列的**首节点**的数据。

### 二、非阻塞队列的线程安全机制

非阻塞队列会使用**循环 CAS** 的方式来实现线程安全。与阻塞队列（如 `ArrayBlockingQueue`、`LinkedBlockingQueue`）不同，非阻塞队列在队列为空或满时不会阻塞线程，而是通过 CAS 自旋来不断尝试操作，直到成功为止。

### 三、入队过程

入队列的过程分为以下步骤：

| 步骤 | 说明 |
|------|------|
| ==**1. 定位尾节点**== | 找到当前队列的尾节点 `tail` |
| ==**2. 设置入队节点为尾节点的下一个节点**== | 通过 CAS 将新节点设置为 `tail.next` |
| ==**3. 更新 tail 节点**== | 通过 HOPS 机制决定是否需要更新 `tail` 引用 |

**入队的具体逻辑**：将入队节点设置成当前队列尾节点的下一个节点。通过 CAS 更新 `tail` 节点，使得 `tail` 的 `next` 节点不为空，并将新入队的节点改成 `tail` 节点。但如果此时 `tail` 节点为空，则将新入队的节点改成 `tail` 节点的 `next` 节点。

### 四、HOPS 的设计意图

**HOPS（跳数）** 是 `ConcurrentLinkedQueue` 的核心优化设计。`tail` 节点并不总是实时更新为真正的尾节点，而是允许 `tail` 和真正的尾节点之间存在一定的距离（默认 HOPS = 1）。每次入队时，只有当 `tail` 距离真正尾节点超过 HOPS 时，才通过 CAS 更新 `tail` 引用。

这样设计的好处是**减少 CAS 操作次数**，从而减少多线程竞争开销，提高入队效率。

### 五、出队过程

出队列的步骤主要包括：

| 步骤 | 说明 |
|------|------|
| ==**1. 获取 head 节点的元素**== | 通过 CAS 获取 `head` 节点的元素值 |
| ==**2. 清空该节点对元素的引用**== | 将该节点的 `item` 设置为 `null`，使其成为哨兵节点 |
| ==**3. 更新 head 节点**== | 通过 HOPS 机制决定是否需要更新 `head` 引用 |

出队时返回节点的元素，并清空该节点对元素的引用。和 `tail` 类似，`head` 也不会实时更新，而是通过 HOPS 机制来减少 CAS 操作次数。

### 六、入队出队流程图

```text
入队流程：

① 定位当前 tail 节点
    ↓
② CAS 将新节点设置为 tail.next
    ↓
    ├── CAS 成功 → 判断是否需要更新 tail 引用
    │              ↓
    │         tail 距离真正尾节点 > HOPS → CAS 更新 tail
    │
    └── CAS 失败 → 重新定位尾节点，继续自旋


出队流程：

① 获取当前 head 节点
    ↓
② 获取 head.item 的值
    ↓
③ CAS 将 head.item 设置为 null
    ↓
④ 判断是否需要更新 head 引用
    ↓
    ├── head 距离真正首节点 > HOPS → CAS 更新 head
    │
    └── 不需要更新 → 直接返回之前获取的元素值
```

### 七、面试要点

| **问题**                            | 回答                                     |
| ----------------------------- | -------------------------------------- |
| **ConcurrentLinkedQueue 的线程安全机制** | 通过 ==**循环 CAS**== 实现，非阻塞方式             |
| **HOPS 设计意图**                     | 减少 **CAS 操作次数**，降低多线程竞争开销              |
| **入队时 tail 节点一定实时更新吗**            | ==**不一定**==，通过 HOPS 机制延迟更新             |
| **出队时如何保证线程安全**                   | 通过 CAS 将元素置为 `null`，并通过 HOPS 更新 `head` |
| **与阻塞队列的区别**                      | 阻塞队列为空/满时会阻塞线程；非阻塞队列通过 CAS 自旋不断尝试      |
