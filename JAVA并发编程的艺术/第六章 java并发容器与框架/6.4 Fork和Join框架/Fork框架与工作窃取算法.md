

### 一、Fork/Join 框架的核心思想

Fork/Join 框架的核心思想就是将一个大任务变成若干个子任务后**并发执行**，最后组成一个大的正确的结果。简单来说就是会把一个大的任务分割成若干个子任务，然后子任务对应的数据会分配到不同的队列中，然后再利用**工作窃取算法**来完成正确的操作。

### 二、工作窃取算法的原理

工作窃取算法指的是某个线程会从**其他队列里窃取任务来执行**。该算法会让线程与队列一一对应：

| 角色 | 操作方式 | 操作端 |
|------|---------|--------|
| ==**被窃取任务的线程**== | 从自己的队列中取任务 | **头部**（LIFO） |
| ==**窃取任务的线程**== | 从其他队列中取任务 | **尾部**（FIFO） |

**为什么窃取线程要从双端队列的尾部获取？**

要想让窃取任务与窃取线程尽可能减少线程竞争，需要使用**双端队列**。被窃取任务的线程从队列**头部**取任务（LIFO，后进先出），窃取任务的线程从队列**尾部**取任务（FIFO，先进先出）。这样双方操作的是队列的不同端，避免了竞争。

### 三、工作窃取算法的优缺点

| 维度         | 说明                                          |
| ---------- | ------------------------------------------- |
| ==**优点**== | 减少大任务变成若干个子任务处理时线程间并发所需时间，充分利用线程资源          |
| ==**缺点**== | 当线程不足够多或任务不够多时，会因为创建多个线程和多个双端队列而造成**空间的浪费** |

### 四、工作窃取算法的流程图

```text
Fork/Join 框架的执行流程：

① 提交一个大任务到 ForkJoinPool
    ↓
② 将大任务 fork 成若干个子任务
    ↓
③ 每个子任务分配到对应的队列中（每个线程一个双端队列）
    ↓
④ 每个线程从自己队列头部取任务执行（LIFO）
    ↓
⑤ 当某个线程完成任务后：
    ├── 自己的队列中还有任务 → 继续从头部取任务执行
    │
    └── 自己的队列为空 → 从其他线程的队列尾部窃取任务执行（FIFO）
              ↓
        ⑥ 被窃取的线程可能处于空闲状态，不会产生竞争
    ↓
⑦ 所有子任务执行完毕后，合并结果得到最终结果
```

### 五、适用场景

| 适用场景 | 说明 |
|---------|------|
| ==**计算密集型任务**== | 如大规模数据排序、矩阵运算等可以被拆分成独立子任务的计算 |
| ==**递归分治问题**== | 如归并排序、快速排序、斐波那契数列等天然适合分治的任务 |
| ==**需要充分利用多核 CPU 的场景**== | 通过并行执行子任务提高 CPU 利用率 |

| 不适用场景 | 说明 |
|-----------|------|
| ==**I/O 密集型任务**== | I/O 密集型任务更适合使用线程池，工作窃取对 I/O 等待无明显优化 |
| ==**任务之间依赖复杂的场景**== | 如果子任务之间有强依赖关系，Fork/Join 的分治模型不适用 |
| ==**任务数量少或粒度不均的场景**== | 可能导致线程间负载不均衡，甚至只有一个线程在干活 |
