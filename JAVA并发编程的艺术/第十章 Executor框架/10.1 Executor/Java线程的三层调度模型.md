
### 一、底层：操作系统线程映射

在HotSpot的JVM线程模型中，Java线程被**一对一映射**为本地操作系统线程。详细参考[[java线程的实现]]。等待该线程结束之后，这个操作系统线程将会被JVM进行回收。操作系统会调度所有线程并将其分配给目前可用的CPU。

### 二、中层：用户级调度器

在上层接口中，Java多线程程序会把应用分解成若干个任务，很像[[Fork和join框架的设计]]。分解之后，会使用**用户级调度器**将这些任务映射为固定数量的线程。

### 三、上层：Java线程池的抽象封装

Java线程池（如 `ThreadPoolExecutor`、`ForkJoinPool`）就是对用户级调度器的具体实现。它们将任务提交、任务调度、线程管理抽象成简洁的API，让开发者不需要直接操作操作系统线程，只需要关心任务的拆分和提交。

### 四、三层调度模型总览

```text
Java线程的三层调度模型：

上层（Java应用层）
    ├── 将应用分解成若干个任务
    └── 提交任务到线程池（ThreadPoolExecutor / ForkJoinPool）
        ↓
中层（用户级调度器）
    ├── 将任务映射为固定数量的线程
    └── 管理线程的生命周期和任务队列
        ↓
底层（操作系统内核）
    ├── Java线程 1:1 映射到 OS 线程
    └── OS将线程映射到硬件处理器（CPU）
```

在最底层，操作系统内核会将这些线程映射到硬件处理器上。调度模型拥有着相似的框架结构与接口，详细参考[[框架的结构与属性]]。

### 五、面试要点

| **问题**               | 回答                                         |
| ---------------- | ------------------------------------------ |
| **Java线程的三层调度模型**    | ==**上层应用分解任务 → 中层用户级调度器 → 底层OS线程映射到CPU**== |
| **Java线程与OS线程的映射关系** | ==**1:1**==，每个Java线程对应一个OS线程               |
| **Fork/Join框架属于哪一层** | ==**中层**==，用户级调度器，将大任务分解并调度执行              |
| **线程池在三层模型中属于哪一层**   | ==**中层**==，对用户级调度器的抽象封装                    |
