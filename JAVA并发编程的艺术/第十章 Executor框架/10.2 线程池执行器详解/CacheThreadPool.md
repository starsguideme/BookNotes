
### 一、核心定位

`CachedThreadPool` 是一种会根据需要来**创建新线程**的线程池。通常情况下，其核心线程池的大小会设置为 **0**，而其最大值会被设置为 **`Integer.MAX_VALUE`**，但其活跃时间一般是**每分钟（60 秒）**。

### 二、与 FixedThreadPool 和 SingleThreadExecutor 的区别

与[[FixedThreadPool]]和[[SingleThreadExecutor]]使用无界队列不同，`CachedThreadPool` 使用的是**没有容量的同步队列**（`SynchronousQueue`）。`SynchronousQueue` 不存储任何元素，每个插入操作必须等待一个移除操作。

### 三、执行流程

```text
CachedThreadPool 的执行流程：

① 提交任务
    ↓
② 尝试将任务放入 SynchronousQueue
    ↓
    ├── 队列中有空闲线程等待接收任务 → 任务直接交给空闲线程执行
    │
    └── 队列中无空闲线程 → 入队失败
              ↓
        ③ 创建新线程来执行任务
              ↓
        ④ 线程执行完任务后，进入 SynchronousQueue.poll(keepAliveTime) 等待新任务
              ↓
        ⑤ 如果 60 秒内没有新任务到达，该线程被回收
```

### 四、核心特性

| 特性 | 说明 |
|------|------|
| ==**核心线程数**== | 0 |
| ==**最大线程数**== | `Integer.MAX_VALUE`（理论上无限） |
| ==**工作队列**== | `SynchronousQueue`（无容量，不存储元素） |
| ==**线程存活时间**== | 60 秒 |

### 五、潜在风险

由于 `CachedThreadPool` 的最大值是无限的，这意味着如果主线程提交任务的速度**高于处理任务的速度**时，`CachedThreadPool` 会不断地创建新线程。在某些情况下会因创建过多线程而**耗尽 CPU 和内存资源**。

| 风险 | 说明 |
|------|------|
| ==**CPU 资源耗尽**== | 线程数过多导致频繁上下文切换，CPU 时间被调度消耗 |
| ==**内存溢出（OOM）**== | 每个线程占用约 1MB 栈内存，线程数过多导致内存耗尽 |

### 六、适用范围

| 适用场景 | 说明 |
|---------|------|
| ==**短期异步任务**== | 任务执行时间短，提交频率不高的场景 |
| ==**负载较轻的服务器**== | 服务器资源充足，任务量不大的场景 |

| 不适用场景 | 说明 |
|-----------|------|
| ==**高并发场景**== | 提交任务速度持续高于处理速度时，会导致线程数爆炸 |
| ==**资源受限环境**== | 内存或 CPU 资源有限时，应使用 `FixedThreadPool` 控制线程数 |

### 七、面试要点

| **问题**                                           | 回答                                                                                         |
| -------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **CachedThreadPool 的核心特点**                       | ==**核心线程数为 0，最大线程数无限，使用 SynchronousQueue**==                                               |
| **CachedThreadPool 和 FixedThreadPool 的工作队列有何不同** | CachedThreadPool 使用 **SynchronousQueue**（无容量），FixedThreadPool 使用**无界 LinkedBlockingQueue** |
| **CachedThreadPool 的主要风险**                       | 提交任务速度持续高于处理速度时，会**不断创建新线程**，耗尽 CPU 和内存                                                    |
| **CachedThreadPool 的线程存活时间**                     | ==**60 秒**==，空闲线程超过 60 秒会被回收                                                               |
