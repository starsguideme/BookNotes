
### 一、核心定位

该线程池被称为**可重用固定线程数的线程池**。

### 二、工作流程

| 步骤 | 条件 | 处理方式 |
|------|------|---------|
| ==**步骤 1**== | 当前运行的线程数**小于核心线程池大小** | 创建新线程来执行任务 |
| ==**步骤 2**== | 线程池完成预热之后，当前运行的线程数**等于核心线程大小** | 任务会被加入到**无界阻塞队列**中 |
| ==**步骤 3**== | 线程执行完步骤 1 的任务后 | 从阻塞队列中获取任务继续执行 |

### 三、无界队列带来的影响

`FixedThreadPool` 会使用**无界阻塞队列**（`LinkedBlockingQueue`，默认容量为 `Integer.MAX_VALUE`）作为线程池的工作队列。使用无界队列作为工作队列时会对线程池带来如下影响：

| 影响 | 说明 |
|------|------|
| ==**线程池中的线程数不会超过核心池大小**== | 当线程池中的线程数达到核心池大小后，新任务会在无界队列中进行等待，因此线程池中的线程数绝对不会超过核心池大小 |
| ==**最大线程数成为无效参数**== | 由于步骤 1 和步骤 2 的存在，任务永远不会触发创建超过核心线程数的线程，因此 `maximumPoolSize` 成为无效参数 |
| ==**线程存活时间成为无效参数**== | 由于步骤 1 和步骤 2 的存在，`keepAliveTime` 也变成无效参数 |
| ==**不会拒绝任何任务**== | 由于使用无界队列，运行中的 `FixedThreadPool` 将不会拒绝任何任务（除非内存耗尽导致 OOM） |

### 四、潜在风险

| 风险 | 说明 |
|------|------|
| ==**内存溢出（OOM）**== | 无界队列可能导致任务堆积，最终耗尽内存 |

### 五、面试要点

| 问题 | 回答 |
|------|------|
| FixedThreadPool 的核心特点 | ==**固定线程数 + 无界队列**== |
| 无界队列导致哪些参数无效 | ==**`maximumPoolSize` 和 `keepAliveTime`**== |
| FixedThreadPool 会拒绝任务吗 | ==**不会**==，除非内存耗尽导致 OOM |
| FixedThreadPool 的线程数会超过核心线程数吗 | ==**不会**==，因为新任务会先入无界队列，不会触发创建新线程 |
