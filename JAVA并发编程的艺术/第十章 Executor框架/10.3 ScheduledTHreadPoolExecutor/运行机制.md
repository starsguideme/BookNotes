
### 一、核心定位

`ScheduledThreadPoolExecutor` 的队列一般是无界队列（`DelayQueue`），也正因如此，其**最大线程数（`maximumPoolSize`）是无意义的**——任务永远不会因为队列满而触发创建新线程。

### 二、执行流程

`ScheduledThreadPoolExecutor` 的执行主要分为两个部分：

| 步骤 | 说明 |
|------|------|
| ==**步骤 1**== | 当调用 `scheduleAtFixedRate` 方法或 `scheduleWithFixedDelay` 方法时，会向 `ScheduledThreadPoolExecutor` 的 **`DelayQueue`** 添加一个已经实现了的 `ScheduledFutureTask` 类 |
| ==**步骤 2**== | 线程池中的线程会从 `DelayQueue` 中获取 `ScheduledFutureTask`，然后执行任务 |

### 三、对线程池执行器的修改

为了更好地执行定时任务，其对 `ThreadPoolExecutor` 进行如下修改：

| 修改项 | 说明 |
|--------|------|
| ==**使用 DelayQueue 作为任务队列**== | 替代常规的 `LinkedBlockingQueue` 或 `SynchronousQueue` |
| ==**获取任务的方式产生了改变**== | 从 `DelayQueue` 中获取任务时，会根据任务的延时时间来决定何时执行 |
| ==**执行周期性任务后增加了额外的处理**== | 执行完周期性任务后，会重新计算下次执行时间，并将任务重新放回 `DelayQueue` |

### 四、DelayQueue 的作用

`DelayQueue` 是一个**无界阻塞队列**，内部使用 `PriorityQueue` 实现。任务会根据**下次执行时间**进行排序，最早需要执行的任务排在队首。线程从 `DelayQueue` 获取任务时：

-   如果队首任务的执行时间**已到**，则取出并执行。
-   如果队首任务的执行时间**未到**，则线程进入**超时等待**，直到任务到期。

### 五、面试要点

| 问题                                   | 回答                                  |
| ------------------------------------ | ----------------------------------- |
| **ScheduledThreadPoolExecutor 的任务队列是什么** | ==**`DelayQueue`**==（无界阻塞队列）        |
| **为什么最大线程数无意义**                          | 因为使用无界队列，任务永远不会触发创建超过核心线程数的新线程      |
| **执行完周期性任务后如何处理**                        | 重新计算下次执行时间，将任务**重新放回 `DelayQueue`** |
| **`DelayQueue` 内部使用什么数据结构**              | ==**`PriorityQueue`**==，按任务执行时间排序   |
