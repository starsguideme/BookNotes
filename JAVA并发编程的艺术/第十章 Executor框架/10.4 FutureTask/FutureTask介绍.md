
### 一、核心定位

`FutureTask` 除了可以实现 `Future` 接口外，还实现了 `Runnable` 接口。因此 `FutureTask` 不仅可以交给执行器执行，还可以调用线程直接执行 `FutureTask.run` 方法。

### 二、三种状态

根据方法被执行的时机，其可以有三种状态：

| 状态 | 触发条件 | 说明 |
|------|---------|------|
| ==**未启动**== | `run` 方法还没有被执行 | 当创建一个 `FutureTask` 任务时，此时如果没有调用 `run` 方法之前，该任务依旧是处于未启动状态 |
| ==**已启动**== | 调用了 `run` 方法之后 | 任务开始执行，进入已启动状态 |
| ==**已完成**== | `run` 方法执行完正常结束，被取消（`cancel`）或被抛异常而结束 | 任务执行完毕，进入已完成状态 |

### 三、不同状态下的方法行为

| 方法                             | 未启动状态               | 已启动状态                       | 已完成状态                |
| ------------------------------ | ------------------- | --------------------------- | -------------------- |
| ==**`get()`**==                | **阻塞调用线程**，直到任务完成   | **阻塞调用线程**，直到任务完成           | **立即返回**结果或抛出异常      |
| ==**`cancel(boolean)`**==      | 任务**被取消**，返回 `true` | 返回 **`false`**，任务无法被取消      | 返回 **`false`**，任务已完成 |
| ==**`cancel(true)` 对已启动任务**==  | —                   | **中断任务线程**（`t.interrupt()`） | —                    |
| ==**`cancel(false)` 对已启动任务**== | —                   | **不中断**执行线程，等待任务自行完成        | —                    |

### 四、面试要点

| **问题**                                   | 回答                                          |
| ------------------------------------ | ------------------------------------------- |
| **FutureTask 实现了哪两个接口**                  | ==**`Future` 接口**== 和 ==**`Runnable` 接口**== |
| **FutureTask 有哪三种状态**                    | ==**未启动、已启动、已完成**==                         |
| **未启动状态下调用 `get()` 会怎样**                 | **阻塞调用线程**，直到任务完成                           |
| **已启动状态下调用 `cancel()` 会怎样**              | 返回 **`false`**，任务无法被取消                      |
| **`cancel(true)` 和 `cancel(false)` 的区别** | `true` 会中断任务线程，`false` 不中断                  |
