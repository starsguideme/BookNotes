
### 一、FutureTask 与 AQS 的关系

FutureTask 的实现一般是基于 [[AQS]]，与 [[Reentrantlock]]、[[Semaphore]]、可重入读写锁、[[CountDownLatch]] 以及 FutureTask 一同组成了 AQS 体系。

### 二、两种核心操作

以下是 JDK 6 之后都具有的两种类型操作：

| 操作类型 | 说明 | FutureTask 中的对应方法 |
|---------|------|----------------------|
| ==**acquire 操作**== | 可以阻塞调用线程，除非 AQS 的状态允许该线程继续执行 | **`get()` 和带超时的 `get` 方法** |
| ==**release 操作**== | 改变 AQS 的状态，使一个或多个阻塞线程被解除阻塞 | **`run()` 方法和 `cancel()` 方法** |

### 三、内部子类 Sync

基于"**复合优先于继承**"的原则，FutureTask 声明了一个内部私有的继承于 AQS 的子类 **Sync**，并对 FutureTask 所有的公有方法全权交给内部子类执行。

AQS 被视为"**模板方法模型**"的基础类提供给 FutureTask 的内部子类 Sync。这个内部子类只需处理**实现状态检查和状态更新**的方法即可，这些方法将控制 FutureTask 的获取和释放操作。具体说，Sync 实现了 AQS 的多个线程获取方法和多个线程释放方法，并用这两个方法来进行检查和更新同步状态。

### 四、`get()` 方法的执行流程

在使用 FutureTask 的 `get()` 方法时，会调用 AQS 的 `acquireSharedInterruptibly(int arg)` 方法。该方法的执行过程大致如下：

```text
get() 方法的执行流程：

① 调用 AQS 的 acquireSharedInterruptibly(int arg)
    ↓
② 回调子类 Sync 中实现的 tryAcquireShared() 判断 acquire 操作是否成功
   acquire 的使用条件是：state 字段为 RAN 或已取消的 CANCELLED，且 runner 不为 null
    ↓
    ├── 成功 → get 方法立即返回结果
    │
    └── 失败 → 当前线程进入 AQS 的线程等待队列中等待其他线程执行释放操作
              ↓
        ③ 其他线程执行释放操作时，唤醒当前线程
              ↓
        ④ 当前线程再次调用 tryAcquireShared()，返回值正 1 后离开队列
              ↓
        ⑤ 唤醒首节点的后继线程（传播唤醒）
              ↓
        ⑥ 返回计算结果或抛出异常
```

### 五、`run()` 方法的执行流程

当使用了 `run()` 方法之后，其执行情况如下：

```text
run() 方法的执行流程：

① 执行在构造函数中指定的任务（Callable.call()）
    ↓
② 以原子方式更新同步状态（调用 AQS 的 CAS 并设置 state 为完成状态 RAN）
    ├── 原子操作成功 → 设置返回结果为 Callable 下的 call 返回值类型
    │         ↓
    │   ③ 使用 AQS 的释放线程操作（回调子类 Sync 中实现的 tryReleaseShared 执行释放操作）
    │         ↓
    │   ④ 唤醒 CLH 队列中的首节点
    │         ↓
    │   ⑤ 执行 done() 方法（钩子方法）
    │
    └── 原子操作失败 → 说明有其他线程已抢先完成，不做处理
```

### 六、线程被唤醒后的链式传播

当 FutureTask 的 `get()` 方法执行时，如果 FutureTask 不是处于执行完成状态 RAN 或已取消的 CANCELLED，则当前执行线程将进入 AQS 的线程等待队列中等待。当某个线程执行 `run()` 方法或 `cancel()` 方法时，也会唤醒 CLH 队列中的首节点。

-   **当首节点被唤醒后**：会把自己从队列中删除，然后唤醒其后续节点。
-   **线程 A 从 `get()` 返回**：后续节点会依次执行这个操作，最终所有节点都会从队列中释放并从 `get()` 方法中返回。

### 七、面试要点

| **问题**                                        | 回答                                                                     |
| ----------------------------------------- | ---------------------------------------------------------------------- |
| **FutureTask 基于什么实现**                         | ==**AQS**==                                                            |
| **FutureTask 的 acquire 和 release 操作分别对应哪些方法** | acquire 对应 **`get()` 和带超时的 `get`**；release 对应 **`run()` 和 `cancel()`** |
| **`get()` 方法失败时线程去哪里等待**                      | 进入 AQS 的**线程等待队列**中等待                                                  |
| **`run()` 方法成功后如何唤醒等待线程**                     | 通过 AQS 的释放操作唤醒 **CLH 队列中的首节点**                                         |
| **唤醒操作是链式传播的吗**                               | ==**是**==，首节点被唤醒后依次唤醒后继节点，最终所有等待线程都从 `get()` 返回                        |
