**Java 内存模型（JMM）**

### 一、内存存储规则

|存储内容|存储位置|是否线程共享|
|---|---|---|
|==**对象、静态变量、数组元素**==|堆内存|✅ 线程共享|
|==**局部变量、方法参数、异常处理器参数**==|栈内存（线程私有）|❌ 线程私有，不共享|

### 二、JMM 的定义与作用

Java 线程之间的通信由 **Java 内存模型（JMM）** 控制。JMM 决定在何时将一个线程对共享变量的写入操作刷新到主内存，并在何时让另一个线程从主内存中读取到更新后的值。

在 JMM 中，每个线程都有自己的**本地内存**，用于存储共享变量的副本。共享变量本身存储在**主内存**中。本地内存是 JMM 的一个**逻辑定义**，不是物理概念——它实际上涵盖了 CPU 的缓存、寄存器、写缓冲区等硬件层面的优化机制，但 JMM 将其抽象为一个统一的"本地内存"概念。

### 三、线程间通信的标准流程

在多线程操作下，当线程 A 想要将共享变量的修改传递给线程 B 时，需要经历两步：

1. **线程 A** 将本地内存中更新过的共享变量刷新到主内存中。
    
2. **线程 B** 到主内存中读取线程 A 已更新过的共享变量。
    

具体实现方式和操作系统下进程通过共享内存进行通信的思路类似，都是通过一个中间存储来完成数据传递。但在 JMM 中，这些操作**必须经过主内存的处理**——线程之间无法直接访问对方的本地内存，只能通过主内存作为中转。这也是 JMM 保证线程之间可见性的核心机制。
**线程A                    主内存                    线程B**
  **|                        |                        |**
  **| ① 修改共享变量副本      |                        |**
  **|    (本地内存A)          |                        |**
  **|                        |                        |**
  **| ② 刷新共享变量到主内存→ |                        |**
  **|                        | 共享变量最新值          |**
  **|                        |                        |**
  **|                        | ③ JMM通知/线程B感知    |**
  **|                        |                        |**
  **|                        | ④ 读取最新值 →→→→→→→→→|**
  **|                        |                        | 更新共享变量副本**
  **|                        |                        | (本地内存B)**

### 四、[[指令序列的重排序]]

JMM 中的指令执行顺序并非总是和代码编写顺序一致。为了提高执行效率，编译器和处理器可能会对指令进行**重排序**。重排序分为三种类型：

|类型|执行者|说明|
|---|---|---|
|==**编译器重排序**==|编译器|在不改变单线程语义的前提下，调整语句执行顺序|
|==**指令级并行重排序**==|处理器|使用指令级并行技术，重叠执行多条指令|
|==**内存系统重排序**==|处理器|使用缓存和读写缓冲区，使得加载和存储操作看起来是乱序的|
