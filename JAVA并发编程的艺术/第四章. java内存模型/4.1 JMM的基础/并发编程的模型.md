### 一、写缓冲区的作用与弊端

现代 CPU 使用写缓冲区临时保存即将写入内存的数据。写缓冲区可以保证 CPU 流水线的持续运行，同时避免写入延迟——以批处理的方式处理缓冲区，以及合并写缓冲区对同一内存地址的多次写入，这样可以减少占用总线的时间。

虽然好处很多，但也有个巨大的弊端：每个处理器的写缓冲区只对自己的 CPU 可见，这个特性会影响到其他处理器对内存操作的感知顺序（也就是[[指令序列的重排序]]）。

例如：线程 A 和线程 B 先创建，初始化时加载了一个共享变量。此时如果启动 A 和 B，由于操作系统以时间片方式轮转调度，处理器可能因为写缓冲区的存在，让 A 和 B 的共享变量操作与实际读写顺序不一致，导致另一个线程看到"还未写入完成"的中间状态。

### 二、处理器允许的重排序规则

不同处理器对不同类型的重排序支持程度不同。以下是常见处理器架构下的重排序规则：

| 重排序类型               | 说明           | X86/X64  |
| ------------------- | ------------ | -------- |
| ==**Load-Load**==   | 读操作与读操作之间重排序 | ❌ 不允许    |
| ==**Load-Store**==  | 读操作与写操作之间重排序 | ❌ 不允许    |
| ==**Store-Store**== | 写操作与写操作之间重排序 | ❌ 不允许    |
| ==**Store-Load**==  | 写操作与读操作之间重排序 | ==✅ 允许== |

X86/X64 架构只允许 Store-Load 重排序。这也是为什么 `volatile` 在 X86 上主要通过 StoreLoad 屏障来保证可见性和有序性，其他三种屏障在硬件层面已经被保证了，不需要额外插入。

### 三、JMM 的四种内存屏障

为了保证内存可见性，JVM 会在生成指令序列的适当位置插入合适的内存屏障，以禁止某些情况下指令的重排序。JMM 将内存屏障分为以下四类：

| 屏障类型                  | 作用                                       | 示例                           |
| --------------------- | ---------------------------------------- | ---------------------------- |
| ==**LoadLoad 屏障**==   | 确保 Load1 的数据装载先于 Load2 及后续所有装载指令         | `Load1; LoadLoad; Load2`     |
| ==**StoreStore 屏障**== | 确保 Store1 的数据对其他处理器可见，先于 Store2 及后续存储指令  | `Store1; StoreStore; Store2` |
| ==**LoadStore 屏障**==  | 确保 Load1 的数据装载先于 Store2 及后续所有存储指令        | `Load1; LoadStore; Store2`   |
| ==**StoreLoad 屏障**==  | 确保 Store1 的数据对其他处理器可见，先于 Load2 及后续所有装载指令 | `Store1; StoreLoad; Load2`   |

**StoreLoad 屏障同时具有其他三个屏障的效果**，是唯一能够禁止 Store-Load 重排序的屏障。但它的代价也最大——执行时会将写缓冲区中的所有数据全部刷新到内存中，导致缓冲区被清空，后续写入都需要重新填充缓冲，产生显著的性能开销。

### 四、面试要点

|问题|回答|
|---|---|
|写缓冲区的好处和弊端|好处是减少总线占用、支持批处理和合并写；弊端是只对当前 CPU 可见，会导致其他处理器看到乱序的内存操作|
|X86 允许哪种重排序|只允许 Store-Load 重排序，其他三种在硬件层面已被禁止|
|四种屏障中哪个代价最大|StoreLoad 屏障，因为它会清空整个写缓冲区|
|StoreLoad 屏障为什么是其他三个的集合|它同时保证 Store 先于 Load，这个保证间接覆盖了 LoadLoad、StoreStore 和 LoadStore 的约束|
