### 一、定义

如果两个操作同时访问一个变量，且这两个操作中**至少有一个是写操作**，那么这两个操作之间就存在**数据依赖性**。

数据依赖分为三种类型：

| 依赖类型        | 示例              | 说明                                                                    |
| ----------- | --------------- | --------------------------------------------------------------------- |
| ==**写后读**== | `a = 1; b = a;` | 必须先写 `a`，再读 `a`。`b = a` 这个操作依赖于 `a = 1` 的结果                           |
| ==**写后写**== | `a = 1; a = 2;` | 两次写入的先后顺序直接决定 `a` 的最终值。`a = 2` 这个操作必须等待 `a = 1` 执行完后才能执行，否则最终结果可能变成 1 |
| ==**读后写**== | `b = a; a = 1;` | 必须先读 `a` 的旧值赋给 `b`，再写 `a` 的新值。`a = 1` 这个操作依赖于 `b = a` 读取到的值           |

这三种类型有一个共同的特点：**只要重排序两个操作的执行顺序，程序的执行结果就会改变。** 因此，存在数据依赖关系的操作不能被重排序——这正是 [[as-if-serial语义]]的核心保证。

### 二、数据依赖性的作用域

这里的数据依赖性**只针对单个处理器中执行的指令序列和单个线程中执行的操作**。不同处理器之间和不同线程之间的数据依赖性不被编译器和处理器所考虑。
单线程内：存在数据依赖 → 禁止重排序
多线程间：存在数据依赖 → 编译器和处理器不考虑，仍可能重排序

这也是为什么单线程程序总是正确的，而多线程程序会出现可见性和有序性问题的根本原因——编译器和处理器只保证单线程内的 as-if-serial 语义，不跨线程生效。

### 三、与 as-if-serial 语义的关系

数据依赖性是 as-if-serial 语义的底层支撑。as-if-serial 要求"单线程程序的执行结果不能被重排序改变"，而实现这一保证的手段就是**对存在数据依赖关系的操作禁止重排序**。两者是"规则"和"实现手段"的关系。

### 四、与 happens-before 的关系

数据依赖性只在单个线程内有效，而 [[happens-before规则]]则**跨线程生效**。当两个线程操作同一个共享变量且至少有一个是写操作时，数据依赖性无法提供任何保证，此时必须通过 happens-before 规则（如 `volatile` 规则、监视器锁规则）来保证跨线程的可见性和有序性。

### 五、面试要点

| 问题                      | 回答                                       |
| ----------------------- | ---------------------------------------- |
| **什么是数据依赖性**                | 两个操作访问同一变量，且至少有一个是写操作时，它们之间存在数据依赖关系      |
| **数据依赖有哪三种类型**              | 写后读、写后写、读后写                              |
| **为什么多线程中数据依赖性不生效**         | 编译器和处理器只保证单线程内的数据依赖性，不跨线程考虑              |
| **数据依赖性和 as-if-serial 的关系** | 数据依赖性是实现 as-if-serial 语义的手段——禁止有依赖的操作重排序 |
