### 一、传递性规则

根据先行发生的传递性规则，三行代码之间只要存在 happens-before 关系，就可以推导出三个先行发生的关系：

A happens-before B，B happens-before C → A happens-before C

可以简单理解为：**A 在 B 之前生效，B 在 C 之前生效，所以 A 一定在 C 之前生效。** 这是由 happens-before 的依赖传递性逻辑推导出的结论。

### 二、JMM 是规范，不是强制执行

虽然 A 在 B 之前声明，但根据处理器和编译器的重排序操作，B 完全可能在 A 之前优先生效。例如两个线程使用了 `start()` 方法，如果按顺序执行的方式，则 A 一定在 B 之前生效。但事实上，**这取决于操作系统的线程调度**，B 完全可能在 A 之前生效。

这是因为 JMM 只是一个**内存模型规范**，而不是一个严格执行的规则。它不要求 JVM 必须按顺序执行这段代码。JMM 的核心作用是：**定义 happens-before 规则，告诉程序员在什么条件下可以保证可见性**。只要不违反这些规则，JVM 可以自由进行性能优化，包括指令重排序。

### 三、happens-before 与重排序的对抗

- **单线程下**：[[as-if-serial语义]]保证即使发生重排序，执行结果也不变。
    
- **多线程下**：如果没有 happens-before 关系保护，重排序可能导致另一个线程看到乱序的执行结果。必须通过 `synchronized`、`volatile`、`Lock` 等同步机制建立 happens-before 关系，才能在多线程环境下保证可见性和有序性。
