### 一、没有数据依赖性的情况

假如有线程 A 和线程 B，如果这两者之间没有任何数据依赖性，则可能发生以下后果：

处理器优先对线程 A 的指令进行重排序后处理，处理到一半时，不管是时间片轮转还是人为操作，导致线程 A 在执行过程中被线程 B 强行插入执行队伍。如果此时线程 B 的操作和线程 A 有关（例如访问同一个共享变量），则会带来**线程竞争**或**与预期结果不一致**的问题。同时，这种重排序也会破坏多线程程序的执行语义。
线程 A                                   线程 B
  |                                        |
  | ① 写 a = 1                             |
  |                                        | ③ 读 a（此时 a 可能还是旧值 0）
  | ② 写 flag = true（重排序后先执行）        |
  |                                        |
  时间线：② → ③ → ①
  线程 B 读到 flag=true，但 a 还是旧值

### 二、有数据依赖性的情况

如果有数据依赖性，则完全不同。JVM 和处理器会优先识别相关的数据依赖关系，然后自行判断如何执行代码。存在数据依赖的指令不会被重排序——这不仅高效，还让自己的执行顺序对其他 CPU 看起来不会特别混乱，以此保证数据执行的正确性。

在单线程中，由于 as-if-serial 语义的存在，无论如何重排序，最终的执行结果都是一样的。可一旦到了多线程环境下，编译器和处理器只保证单线程内的数据依赖性，不跨线程考虑，因此仍可能因为重排序产生意想不到的结果。

### 三、内存屏障的作用

此时**内存屏障**就产生了巨大的作用。它可以限制处理器对重排序的具体执行情况，通过插入屏障指令来禁止特定类型的重排序。`volatile` 变量就是通过在写操作后插入 StoreLoad 屏障、在读操作前插入 LoadLoad 屏障，来保证多线程环境下的可见性和有序性。
**单线程：as-if-serial 语义保证结果正确**
    **↓**
**多线程：如果没有同步机制，重排序可能导致另一个线程看到错误的结果**
    **↓**
**内存屏障：禁止特定类型的重排序，保护多线程程序的执行语义**
    **↓**
**volatile / synchronized：通过内存屏障或锁语义建立 happens-before 关系**

### 四、面试要点

| 问题              | 回答                                                             |
| --------------- | -------------------------------------------------------------- |
| **多线程下没有数据依赖性会怎样**  | 可能被重排序，导致其他线程看到不一致的执行结果                                        |
| **有数据依赖性能解决多线程问题吗** | 不能，数据依赖性只在单个线程内有效，不跨线程生效                                       |
| **如何解决多线程下重排序的问题**  | 使用内存屏障限制重排序，或通过 `volatile`、`synchronized` 建立 happens-before 关系 |
