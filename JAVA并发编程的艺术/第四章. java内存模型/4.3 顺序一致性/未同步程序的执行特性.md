### 一、JMM 的最小安全性

对于未同步或未正确同步的多线程程序，JMM 只提供**最小安全性**：线程读取到的值要么是之前某个线程写入的值，要么是默认值（`null`、`0`、`false`），不会凭空产生一个不存在的值。

为了实现这个最小安全性，JVM 会在堆上为对象分配内存时，首先清空该内存空间（将数据置为零值），然后再创建对象并安排到堆上。这样，即使没有同步，线程读取对象字段时至少能得到零值，而不会是随机内存中的脏数据。

### 二、JMM 与顺序一致性模型的三个差异

由于未同步程序在 JMM 中的执行整体上是无序的，因此 JMM 和顺序一致性内存模型存在以下差异：

|差异|顺序一致性模型|JMM|
|---|---|---|
|==**单线程执行顺序**==|保证单线程下操作按顺序执行|不保证，允许重排序|
|==**所有线程看到的执行顺序**==|保证所有线程只能看到一致的操作执行顺序|不保证，不同线程可能看到不同的执行顺序|
|==**64 位变量的原子性**==|保证每次读/写操作都具有原子性|不保证在 32 位处理器上 long 和 double 的写操作具有原子性|

### 三、总线事务机制

处理器决定了数据是通过总线在处理器与内存之间进行数据交换的。每次数据交换都会经历一系列步骤，这些步骤统称为**总线事务**。

总线事务分为两类：**读事务**和**写事务**。当其中一个线程通过总线事务进行数据交换时，其他线程会被处理器强制处于等待状态，并在后续中继续以串行的方式执行线程。这个机制保证了单次总线事务内的原子性——在同一个总线事务中完成的操作不会被其他处理器打断。

### 四、64 位变量的原子性问题

在一些 32 位处理器上处理 64 位的读/写操作时，32 位处理器会把 64 位的数据拆分成两个 32 位数据进行执行。但这两个 32 位操作在**某些时候不会落在同一个总线事务里**，于是，此时这个 64 位变量将不再具有原子性。

举例：处理器 A 执行 64 位变量的写操作，处理器 B 同时执行该变量的读操作。由于 32 位处理器将 64 位写操作拆成两次 32 位写入，这两次写入可能分布在不同的总线事务中。处理器 B 的读操作恰好插入在两次写事务之间，就会读到**一半旧值、一半新值**的脏数据。

**解决方案**：使用 `volatile` 修饰 `long` 和 `double` 变量，JVM 会通过[[内存屏障]]和 Lock 前缀指令保证即使在 32 位处理器上，64 位变量的写操作也具有原子性。
