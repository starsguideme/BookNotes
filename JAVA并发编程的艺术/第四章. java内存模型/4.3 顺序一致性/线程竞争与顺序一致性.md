### 一、数据竞争的定义

当程序中没有正确的同步机制时，多个线程同时访问同一个变量，且其中至少有一个是写操作，这种情况就被称为**数据竞争**。由于数据竞争的存在，程序的执行结果往往是不确定的，并不一定是我们所期望的。

如果一个多线程程序能够以正确的同步方式执行，那么它就是一个**没有数据竞争的程序**。

### 二、顺序一致性

如果程序是按照正确的同步方式执行的，程序的执行将具有**顺序一致性**——即程序的结果与该程序在顺序一致性内存模型中的执行结果相同。

这里的同步是一个广义的概念，涵盖了 Java 中的各种同步机制，包括锁、原子操作类、`volatile` 变量以及等待/通知机制等。

### 三、JMM 的设计思路

JMM 对正确同步的程序的保证可以用以下三层来理解：
**正确同步的程序**
    **↓**
**没有数据竞争**
    **↓**
**程序的执行结果与顺序一致性模型中的执行结果相同**

如果程序没有正确同步，JMM 只提供**最小安全性**：线程读取到的值要么是之前某个线程写入的值，要么是默认值（`null`、`0`、`false`），不会凭空产生一个不存在的值。但除此之外，不保证任何可见性和有序性。

### 四、面试要点

| **问题**       | 回答                                                                  |
| ------------ | ------------------------------------------------------------------- |
| **什么是数据竞争**  | 多个线程同时访问同一个变量，且至少有一个是写操作，同时没有使用正确的同步机制                              |
| **什么是顺序一致性** | 程序的执行结果与在顺序一致性内存模型中的执行结果完全一致                                        |
| **如何消除数据竞争** | 使用 `synchronized`、`volatile`、`Lock`、`AtomicInteger` 等同步机制来保护共享变量的访问 |
| **同步的广义含义**  | 不仅包括锁，还包括 `volatile` 变量、原子操作、等待/通知机制等                               |
