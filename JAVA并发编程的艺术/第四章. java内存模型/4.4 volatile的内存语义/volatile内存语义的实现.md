### 一、volatile 重排序规则表

volatile 的内存语义实现，依靠在读写操作时插入内存屏障来限制重排序。重排序规则表根据第一个操作的类型，决定第二个操作受到的限制：

|第一个操作|第二个操作：普通读/写|第二个操作：volatile 读|第二个操作：volatile 写|
|---|---|---|---|
|==**普通读/写**==|允许|允许|❌ 禁止|
|==**volatile 读**==|❌ 禁止|❌ 禁止|❌ 禁止|
|==**volatile 写**==|允许|❌ 禁止|❌ 禁止|

**三个核心禁止规则**：

1. **普通操作后不能跟 volatile 写**：确保 volatile 写之前的所有普通操作的结果在 volatile 写之后对其他线程可见。
    
2. **volatile 读之后不能跟任何操作**：确保 volatile 读之后的操作不会在 volatile 读之前执行。
    
3. **volatile 写之后不能跟 volatile 读**：这是 `StoreLoad` 屏障的核心作用，确保 volatile 写的刷新对其他线程的 volatile 读可见。
    

### 二、内存屏障插入策略

在每次插入内存屏障时，`JMM` 会在每个被 volatile 修饰操作的前后加上相关的屏障：

| 操作类型               | 插入位置 | 屏障类型              | 作用                                      |
| ------------------ | ---- | ----------------- | --------------------------------------- |
| ==**volatile 写**== | 前面   | **StoreStore 屏障** | 确保 volatile 写之前的所有普通写操作已经刷新到主内存         |
| ==**volatile 写**== | 后面   | **StoreLoad 屏障**  | 确保这个 volatile 写的结果对后续的 volatile 读可见     |
| ==**volatile 读**== | 前面   | **LoadLoad 屏障**   | 确保 volatile 读之前的所有读操作已从主内存更新            |
| ==**volatile 读**== | 后面   | **LoadStore 屏障**  | 确保 volatile 读之后的所有写操作不会重排到 volatile 读之前 |

**插入这些屏障之后，再结合 happens-before 规则，就可以实现顺序一致性内存模型中的有序性和可见性保证。**

### 三、为什么 volatile 写后面必须是 StoreLoad 屏障？

由于编译器无法准确预测到 volatile 字段下需要插入什么屏障，为了完成线程之间的有序性保证，JMM 使用了在**每个 volatile 写操作之后执行 StoreLoad 屏障**的策略。这个屏障可以确保 volatile 执行完写操作之后，优先于任何其他线程的读操作之前完成，以此判断下一步要执行什么内容。

之所以选择 StoreLoad 屏障，是因为在实际场景中，往往只有一个或很少个线程在执行写操作，大部分线程进行的都是读操作——这和数据库的场景类似，写操作不多，但经常要执行 select 命令。因此，执行 StoreLoad 屏障往往可以比其他屏障带来更高的综合执行效率。

### 四、相邻操作之间的屏障规则

每相邻之间的线程操作，无论是**读读、写写、读写还是写读**，中间都只需要一个内存屏障。因为在合理的内存屏障保护下，无论处理器如何重排序，**几乎都无法越过相应的限制**。绝大多数情况下保留一个屏障即可让效率最大化且开销最小。根据处理器的不同，内存屏障仍然可以进一步优化，不过这属于操作系统层面的知识范围。

### 五、为什么最终几乎都以 StoreLoad 结尾？

无论之前的屏障和线程是如何执行的，最后几乎都以 **StoreLoad 屏障** 结尾。这是因为处理器无法判断出是否需要执行其他的内存屏障，也无法对其他操作进行重排序。在综合考虑下选择了 StoreLoad——它保证了**线程 A 的 volatile 写操作无法与线程 B 的 volatile 读操作进行重排序**。

StoreLoad 虽然有着其他内存屏障的所有优点，但其本身的开销太大。在 X86 处理器中，写的开销要远大于读的开销——这也是为什么 JMM 只在 **volatile 写之后**插入 StoreLoad 屏障，而不是在所有操作后都插入。

### 六、面试要点

| 问题                                      | 回答                                                                    |
| --------------------------------------- | --------------------------------------------------------------------- |
| **volatile 的四个屏障插入位置**                  | volatile 写前 StoreStore，写后 StoreLoad；volatile 读前 LoadLoad，读后 LoadStore |
| **为什么 volatile 写后面用 StoreLoad 而不是其他屏障** | StoreLoad 同时具备三种屏障的效果，确保 volatile 写对后续 volatile 读可见                   |
| **volatile 重排序的核心禁止规则**                 | 普通操作后不能跟 volatile 写；volatile 读之后不能跟任何操作；volatile 写之后不能跟 volatile 读    |
| **为什么读-读之间只需要一个屏障**                     | 因为内存屏障一旦插入，处理器无法越过它进行重排序，一个屏障已经足够保证有序性                                |
