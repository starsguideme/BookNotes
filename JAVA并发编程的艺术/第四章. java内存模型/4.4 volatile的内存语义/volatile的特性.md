### 一、volatile 的定位

volatile 本身是一个**轻量级同步机制**，而不是锁。它可以在没有较大开销的情况下，让被 volatile 修饰的变量的读写操作对其他线程可见。但 volatile **无法像锁一样对复合操作或多个 volatile 变量同时保证原子性**。

### 二、volatile 的两个核心特性

**1. 可见性**

对单个 volatile 变量的读操作，保证读取到的是最新写入的值，这个最新值对其他所有线程立即可见。

**2. ==单次==读/写的原子性**

对单个 volatile 变量的**单次读操作**和**单次写操作**本身是原子的。但 volatile 不能保证复合操作的原子性——例如 `count++` 这种"读-改-写"三步操作，即使 `count` 被 volatile 修饰，多个线程同时执行仍然会出现数据不一致。也不能保证多个 volatile 变量同时读写的原子性。

### 三、volatile 与锁的对比

| 维度       | volatile  | synchronized |
| -------- | --------- | ------------ |
| 单次读/写原子性 | ✅ 保证      | ✅ 保证         |
| 复合操作原子性  | ❌ 不保证     | ✅ 保证         |
| 可见性      | ✅ 保证      | ✅ 保证         |
| 是否阻塞线程   | 否         | 是（获取不到锁时阻塞）  |
| 开销       | 低（无上下文切换） | 较高           |
|          |           |              |

### 四、面试话术

"volatile 有两个核心特性：可见性和单次读/写的原子性。对单个 volatile 变量的读写本身是原子的，32 位处理器上修饰 long 和 double 也能保证原子性。但 volatile 不能保证复合操作的原子性——像 `count++` 这种需要先读后写的操作，volatile 无法保证中间不被其他线程插入。这是因为 volatile 只保证单次内存操作的原子性，而复合操作涉及多次内存操作。复杂场景需要升级为 `synchronized` 或 `AtomicInteger`。
