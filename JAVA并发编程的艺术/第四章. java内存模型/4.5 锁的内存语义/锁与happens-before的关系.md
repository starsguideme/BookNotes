**锁的内存语义**

### 一、锁的两个核心作用

锁是并发编程中很重要的机制，它有两个核心作用：

|作用|说明|
|---|---|
|==**互斥性**==|同一时刻只有一个线程能执行临界区代码|
|==**通信性**==|一个线程在释放锁的同时，通过主内存向另一个线程发送消息（共享变量的最新值）|

### 二、锁如何保证有序性和可见性

根据 happens-before 规则中的监视器锁规则：**对一个锁执行释放锁的资源的时候，根据happens-before中的有序性原则会随后对这个线程的执行加锁操作。**

根据 happens-before 的传递性，执行释放锁资源的线程会对之后的所有线程具有**可见性**。这和 volatile 修饰字段的内存语义是类似的——volatile 写，happens-before volatile 读，释放锁 后happens-before 获取锁。

在两个线程同时执行的时候，如果一方释放了锁资源，另一个线程同时获取了这把锁，那么释放锁的线程对共享变量的所有修改，对获取锁的线程具有可见性。同时，锁也通过 happens-before 规则保证了线程之间的**有序性**——释放锁之前的操作不会被重排序到释放锁之后，获取锁之后的操作不会被重排序到获取锁之前。

### 三、锁与 volatile 的内存语义对比

| 维度            | volatile                          | 锁                         |
| ------------- | --------------------------------- | ------------------------- |
| ==**通信机制**==  | volatile 写 → 主内存 → volatile 读     | 释放锁 → 主内存 → 获取锁           |
| ==**可见性保证**== | volatile 写之前的所有修改对 volatile 读之后可见 | 释放锁之前的所有修改对获取锁之后可见        |
| ==**有序性保证**== | 通过内存屏障禁止重排序                       | 通过 happens-before 规则禁止重排序 |
| ==**原子性保证**== | 不保证复合操作的原子性                       | 保证整个临界区代码的原子性             |

### 四、面试话术

“锁的内存语义和 volatile 在本质上是相同的——都是通过 happens-before 规则来保证可见性和有序性。释放锁等同于发送消息，获取锁等同于接收消息。区别在于锁还能保证临界区代码的原子性，这是 volatile 做不到的。两者共享同一套 happens-before 规则体系，只是锁的保护粒度更大、开销也更大
