### 一、写 final 域的重排序规则

JMM 禁止编译器把 final 域的写重排序到构造函数之外。具体实现是：编译器会在 final 域的写之后，构造函数 return 之前，插入一个 ==**StoreStore 屏障**==。

这个屏障的作用是：

- **只生效于该构造函数之内**：确保 final 域的写入只在当前构造函数内部完成，不会被重排序到构造函数之外。
    
- **保证 final 域写入的可见性**：StoreStore 屏障确保 final 域的值在构造函数执行完毕前，对所有其他线程可见。
    

**执行流程**：

假设线程 A 与 B 之间没有执行重排序，其执行过程如下：


**① 构造函数开始执行**
    **↓**
**② 写入 final 域**
    **↓**
**③ 插入 StoreStore 屏障（禁止 final 域的写重排序到构造函数之外）**
    **↓**
**④ 构造函数执行完毕**
    **↓**
**⑤ 将构造对象的引用赋值给引用变量 obj**
    **↓**
**⑥ 线程 B 开始执行，读取 final 域的值**

**面试关键点**：写入 final 域的重排序规则可以确保——**只要对象引用没有被提前暴露（没有发生 this 逃逸），那么在对象构造完成之后，其他线程一定能看到 final 域在构造函数中被初始化的正确值。**

### 二、读 final 域的重排序规则

在一个线程中，初次读对象引用与初次读该对象包含的 final 域，JMM 禁止处理器重排序这两个操作。编译器会在读 final 域的操作前插入一个 ==**LoadLoad 屏障**==。

**执行流程**：
① 线程 B 读取对象引用 obj
    ↓
② 插入 LoadLoad 屏障（禁止读引用与读 final 域重排序）
    ↓
③ 线程 B 读取 obj 中的 final 域的值（保证读到的是初始化后的正确值）

**面试关键点**：读 final 域的重排序规则确保——**在读一个对象的 final 域之前，一定会先读取包含这个 final 域的对象引用。** 这样就不会出现"先读到 final 域的默认值，后读到对象引用"的错误情况。

### 三、两条规则如何配合
线程 A（构造函数）                    线程 B（读取）
    |                                      |
    | ① 写入 final 域                      |
    | ② StoreStore 屏障                    |
    | ③ 构造函数完成                        |
    | ④ 将对象引用赋值给 obj               |
    |                                      | ⑤ 读取对象引用 obj
    |                                      | ⑥ LoadLoad 屏障
    |                                      | ⑦ 读取 final 域的值（保证正确）

写 final 域的 StoreStore 屏障 + 读 final 域的 LoadLoad 屏障，两者配合保证了：**只要对象正确构造完成（没有 this 逃逸），其他线程一定能看到 final 域在构造函数中被正确初始化的值，不需要额外的同步机制。**
