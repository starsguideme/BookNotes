### 一、happens-before 的定义

Java 内存模型可以通过以下定义来实现线程之间的有序性与可见性：

- **如果第一个操作 happens-before 第二个操作，则第一个操作的结果对第二个操作可见**：这是 JMM 保证可见性的核心机制。只要两个操作之间存在 happens-before 关系，前一个操作的结果对后一个操作一定可见。
    
- **JMM 允许处理器和编译器在不改变运行结果的前提下对线程使用重排序**：如果两个操作之间不存在 happens-before 关系，编译器和处理器可以自由地对它们进行重排序，以提升执行效率。
    

### 二、happens-before 与 as-if-serial 的共同局限

先行发生的规则与 as-if-serial 语义在本质上是一致的：**两者都只在单个线程内生效。**

- as-if-serial 保证：无论怎么重排序，**单线程**程序的执行结果不能被改变。
    
- happens-before 规则中，程序次序规则也只保证**同一个线程内**的操作顺序。
    

一旦遇到多线程之间的问题，两者都无法单独保证有序性和可见性。因为在多线程环境下，不同线程之间的操作不存在天然的 happens-before 关系，编译器和处理器可能对跨线程的操作进行重排序，导致一个线程看到另一个线程的乱序执行结果。

因此，两者均需要**同步机制**（`volatile`、`synchronized`、`Lock` 等）来建立跨线程的 happens-before 关系，以此确保多线程之下的有序性和可见性。
