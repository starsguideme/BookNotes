### 一、两条特别的 happens-before 规则

根据 [[happens-before规则]]，happens-before 共有**六种**具体实现的规则，其中有两个规则比较特别——一个是线程的**启动**规则（`start()` 规则），另一个是线程的**等待终止**规则（`join()` 规则）。**这两条规则分别控制线程生命周期的起点和终点**。

### 二、`start()` 规则

如果线程 A 执行了 `ThreadB.start()`，那么线程 A 的 `start()` 操作 happens-before 于线程 B 中的任意操作。

线程 A 在启动 B 之前修改了 volatile 变量中的一些值，根据传递性和 happens-before 规则，线程 A 在 `start()` 之前的所有操作，happens-before 于线程 B 的任意操作。因此线程 B 启动后，会先读到这些被 A 修改后的共享变量。

线程 A                                    线程 B
  |                                         |
  | ① 修改共享变量                           |
  | ② B.start()                            |
  |                                         | ③ B 开始执行
  |                                         | ④ 读取共享变量 → 保证看到 A 修改后的值

**关键点**：这里不需要共享变量被 volatile 修饰。`start()` 规则本身就建立了 happens-before 关系，保证了可见性。volatile 只是保证可见性的手段之一，`start()` 规则是另一种手段。

### 三、`join()` 规则

如果线程 A 执行了 `ThreadB.join()` 并成功返回，那么线程 B 中的任意操作 happens-before 于线程 A 从 `join()` 返回。

线程 A 调用 `B.join()` 后进入等待状态，直到线程 B 执行完毕。线程 B 执行完毕后，A 从 `join()` 方法返回。返回后，线程 A 能看到线程 B 在执行期间修改的所有共享变量。


**线程 A                                    线程 B**
  **|                                         |**
  **| B.join() 进入等待                       | ① B 开始执行**
  **|                                         | ② B 修改共享变量**
  **|                                         | ③ B 执行完毕**
  **| B.join() 返回                           |**
  **| 读取共享变量 → 保证看到 B 修改后的值      |**

### 四、`start()` 和 `join()` 的配合

`start()` 和 `join()` 通常配合使用，形成完整的线程间数据传递链路：
父线程设置共享变量 → start() → 子线程读取并修改 → join() → 父线程读取子线程的修改结果

这条链路通过 happens-before 的传递性保证：`start()` 前父线程的操作 → `start()` → 子线程操作 → `join()` → `join()` 返回后父线程的操作。

### 五、面试要点

| 问题               | 回答                                                  |
| ---------------- | --------------------------------------------------- |
| **`start()` 规则保证什么** | 父线程在 `start()` 之前的所有操作，对子线程可见                       |
| **`join()` 规则保证什么**  | 子线程执行期间的所有操作，对父线程从 `join()` 返回后可见                   |
| **两条规则如何配合**         | `start()` 传递数据给子线程，`join()` 回收子线程的修改结果              |
| **为什么不需要 volatile**  | `start()` 和 `join()` 本身就能建立 happens-before 关系，保证可见性 |
