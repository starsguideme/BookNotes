### 一、JMM 的核心是 happens-before 规则

内存模型的最核心点是**先行发生**规则，也就是 happens-before 规则。JMM 通过这一规则来定义线程之间共享变量的可见性和有序性。

内存模型中会根据数据的传递性和内存屏障来执行相应的重排序原则：对会改变执行结果的，JMM 选择禁止重排序；对不会改变结果的，则允许编译器和处理器自行优化。由此得到 JMM 设计的两个核心原则：

- **规则简单易懂且具有强可靠的可见性**：只要程序员正确使用同步机制（`volatile`、`synchronized`、`Lock` 等），JMM 就能保证线程间的可见性和有序性，即使某些底层优化操作并不存在可见的保障。
    
- **在满足规则的前提下，让处理器与编译器自行处理数据的关系**：JMM 不强制要求处理器以特定顺序执行所有指令，而是给编译器和处理器留出优化空间。只要不违反 happens-before 规则，重排序就是被允许的。
    

### 二、happens-before 的定义与作用

之所以内存模型可以这么做，就需要了解其核心规则的定义。详见：[[happens-before的定义]]

根据 JMM 基础中涉及到的 [[happens-before规则]]，它保证了数据的**有序性**与**可见性**。这也是为什么 volatile 可以保证有序性与可见性的原因之一——volatile 的写-读操作之间建立了 happens-before 关系，使得 volatile 写之前的所有操作对 volatile 读之后的所有操作可见,详细需要参考下[[volatile处理写与读操作时与happens-before的关系]]。

### 三、happens-before 的六大规则

在先行发生的规则中提到线程之间具有六大规则：

|规则|说明|
|---|---|
|==**程序次序规则**==|一个线程中的每个操作，happens-before 于该线程中的任意后续操作|
|==**监视器锁规则**==|对一个锁的解锁，happens-before 于随后对这个锁的加锁|
|==**volatile 变量规则**==|对一个 volatile 域的写操作，happens-before 于任意后续对这个 volatile 域的读操作|
|==**传递性**==|如果 A happens-before B，且 B happens-before C，则 A happens-before C|
|==**`start()` 规则**==|如果线程 A 执行 `ThreadB.start()`，那么 A 的 `start()` 操作 happens-before 于线程 B 中的任意操作|
|==**`join()` 规则**==|如果线程 A 执行 `ThreadB.join()` 并成功返回，那么线程 B 中的任意操作 happens-before 于线程 A 从 `join()` 返回|

**这六条规则为先行发生原则给予了很大的帮助，先行发生原则就是基于这六条规则来执行的。其中顺序规则（程序次序规则）、监视器锁规则和 volatile 规则是最常用的三个规则，传递性是推导工具，`start()` 和 `join()` 规则用于线程的生命周期同步。**

### 四、面试要点

|**问题**|回答|
|---|---|
|**JMM 的核心是什么**|happens-before 规则，它定义了线程之间可见性和有序性的保证|
|**happens-before 有哪些规则**|程序次序规则、监视器锁规则、volatile 规则、传递性、start() 规则、join() 规则|
|**happens-before 与 volatile 的关系**|volatile 写 happens-before volatile 读，这是 volatile 保证可见性的根本原因|
|**JMM 如何平衡性能与安全性**|在满足 happens-before 规则的前提下，允许编译器和处理器自由优化|
