
### 一、三类程序的定义

按运行种类和内存可见性，多线程程序可分为以下三种：

| 类型 | 核心机制 | 说明 |
|------|---------|------|
| ==**单线程程序**== | [[as-if-serial语义]] | 无论处理器如何重排序，结果都是正确且确定的 |
| ==**正确同步的多线程程序**== | happens-before + 内存屏障 | 通过同步机制保证可见性和有序性，程序的执行具有顺序一致性 |
| ==**未同步的多线程程序**== | 最小安全保障 | 线程读取到的值要么是之前某个线程写入的值，要么是默认值（0、NULL、false） |

### 二、三类程序的执行结果对比

```text
┌─────────────────────────────────────────────────────────────┐
│                    单线程程序                                │
│                                                             │
│   线程A: ① a=1  ② b=2  ③ c=a+b                             │
│                                                             │
│   结果: 无论①和②是否重排序，③的结果永远是3 (as-if-serial)     │
│   确定性: ✅ 完全确定                                        │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│                 正确同步的多线程程序                          │
│                                                             │
│   线程A: ① a=1  ② volatile flag=true                       │
│   线程B: ③ if(flag)  ④ read a                              │
│                                                             │
│   结果: ③看到true时，④一定读到1 (volatile写happens-before读)  │
│   确定性: ✅ 确定（如果正确同步）                              │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│                 未同步的多线程程序                            │
│                                                             │
│   线程A: ① a=1  ② flag=true (普通变量，无同步)               │
│   线程B: ③ if(flag)  ④ read a                              │
│                                                             │
│   可能的结果:                                                │
│     • 读到 a=1 ✅（运气好，A的修改已刷新到主内存）              │
│     • 读到 a=0 ⚠️（A的修改还在工作内存中，B看不到）            │
│     • 读到 a=null ❌（不可能！最小安全保障：不会是随机值）      │
│   确定性: ❌ 不确定                                           │
└─────────────────────────────────────────────────────────────┘
```

### 三、最小安全保障

其中有个概念叫做**最小的安全保障**——此保障在于，在多线程下，线程 B 不会访问到未初始化后 A 的值。因为线程访问是在线程使用过程中发生的，而不是在线程初始化过程中运行的。

具体来说，`JVM` 在堆上为对象分配内存时，会**首先清空该内存空间**（将数据置为零值），然后再创建对象。这样，即使没有同步，线程读取对象字段时至少能得到零值（0、NULL、false），而不会是随机内存中的脏数据。详细的需要参考下[[对象的创建]]

**但最小安全保障仅此而已**——它只保证你不会读到随机脏数据，不保证你能读到其他线程修改后的最新值。如果需要可见性保证，必须使用 `volatile`、`synchronized` 等同步机制。

### 四、面试要点

| 问题              | 回答                                                                                        |
| --------------- | ----------------------------------------------------------------------------------------- |
| **三类程序的可见性保证**      | ==**单线程**==靠 as-if-serial；==**正确同步的多线程**==靠 happens-before + 内存屏障；==**未同步的多线程**==只有最小安全保障 |
| **最小安全保障是什么**       | 线程读取到的值要么是其他线程写入的值，要么是默认值（0、NULL、false），**不会是随机脏数据**                                      |
| **未同步的程序能保证看到最新值吗** | ==**不能**==，最小安全保障只保证不会读到脏数据，不保证可见性                                                        |
| **如何让未同步程序变成正确同步**  | 使用 ==**volatile**==、==**synchronized**== 等同步机制建立 happens-before 关系                        |
