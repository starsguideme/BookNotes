
为了保证内存可见性，`JVM` 会在生成指令序列的适当位置插入合适的内存屏障，以禁止某些情况下指令的重排序。`JMM` 将**内存屏障**分为以下四类：

| 屏障类型                  | 作用                                            | 示例                           |
| --------------------- | --------------------------------------------- | ---------------------------- |
| ==**LoadLoad 屏障**==   | 确保 Load1 的数据优先于 Load2 及后续所有装载指令执行加载           | `Load1; LoadLoad; Load2`     |
| ==**StoreStore 屏障**== | 确保 Store1 的数据对其他处理器可见且优先于 Store2 及后续存储指令      | `Store1; StoreStore; Store2` |
| ==**LoadStore 屏障**==  | 确保 Load1 的数据优先比 Store2 及后续所有存储指令              | `Load1; LoadStore; Store2`   |
| ==**StoreLoad 屏障**==  | 确保 Store1 的数据对其他处理器可见，优先于 Load2 及后续所有装载指令执行加载 | `Store1; StoreLoad; Load2`   |

**StoreLoad 屏障同时具有其他三个屏障的效果**，是唯一能够禁止 Store-Load 重排序的屏障。但它的代价也最大——执行时会将写缓冲区中的所有数据全部刷新到内存中，导致缓冲区被清空，后续写入都需要重新填充缓冲，产生显著的性能开销。
