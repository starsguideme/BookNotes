### 一、继承关系

`BlockingQueue` 的完整继承链为：

**`Iterable`**
    **↑**
**Collection**
    **↑**
**Queue**
    **↑**
**`BlockingQueue`**

`BlockingQueue` 是 Java 并发包（`java.util.concurrent`）中最核心的阻塞队列接口，定义了一套支持线程安全、支持阻塞等待的生产者-消费者队列操作规范。

---

### 二、主要实现类（重要修正）

|实现类|是否有界|底层数据结构|关键特性|
|---|---|---|---|
|==**ArrayBlockingQueue**==|==**有界**==|数组|容量在创建时指定，不可动态扩容|
|==**LinkedBlockingQueue**==|==**有界**==（默认 `Integer.MAX_VALUE`）|链表|可以不指定容量，但本质是有界的（只是边界极大）|

**==关键修正==**：`LinkedBlockingQueue` **不是无界的**。它在不指定容量时，默认容量为 `Integer.MAX_VALUE`（约 21 亿），虽然这个值在大多数场景下大到"看起来像无界"，但从语义上讲它**仍然是有界队列**。如果将如此大量的任务堆积在内存中，会导致 `OutOfMemoryError`。因此面试中直接说"`LinkedBlockingQueue` 是无界的"是一个常见错误，会丢分。

**补充：真正的无界队列**

|实现类|是否有界|底层数据结构|
|---|---|---|
|==**PriorityBlockingQueue**==|**无界**|数组（自动扩容）|
|==**DelayQueue**==|**无界**|`PriorityQueue`|
|==**SynchronousQueue**==|没有容量|不存储元素，直接传递|
|==**LinkedTransferQueue**==|**无界**|链表|

### 三、生产者与消费者必须使用同一个队列实例

你笔记中"生产者与消费者用的队列应该为同一种"这个表述需要进一步明确：==**不仅类型要一致，而且必须是同一个实例对象**==。

`// 正确做法：生产者和消费者共享同一个队列实例
`BlockingQueu`e`<String> queue = new ArrayBlockingQueue<>(10);
// 生产者线程
new Thread(() -> {
    `queue.put`("data");  // 向同一个 queue 中放入数据
}).start();
// 消费者线程
new Thread(() -> {
    String data = `queue.take`();  // 从同一个 queue 中取出数据
}).start();

**设计原因**：生产者和消费者通过**共享的阻塞队列**来实现线程间的通信和协作。如果各用各的队列实例，两者之间就无法传递数据，阻塞等待机制也失去了意义。
