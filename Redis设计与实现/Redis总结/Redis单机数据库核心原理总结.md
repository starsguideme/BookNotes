# 正文

## 第一部分：客户端——请求的起点

### 1.1 客户端与服务端的关系

用户通过 `redis-cli` 与 Redis 交互之前，必须先启动 `redis-server` 服务端进程。Redis 是一个典型的一对多服务程序：一个服务端进程同时与成百上千个客户端保持连接，并为每个连接创建专属的数据结构来维护状态。

每当一个客户端连接到服务器，Redis 就会为其创建一个 `redisClient` 结构体，这个结构体保存了该客户端的所有相关信息，包括网络连接、输入输出缓冲区、当前正在使用的数据库等。

### 1.2 普通客户端与伪客户端

根据连接方式的不同，Redis 的客户端分为两类：

- **普通客户端**：套接字描述符 `fd` 为正整数，通过 TCP 连接的真实客户端，可以来自本机或远程机器。
    
- **伪客户端**：`fd` 的值为 -1，这意味着它没有实际的网络连接。伪客户端只能在本机内部使用，典型场景包括执行 Lua 脚本和载入 AOF 文件。因为 `fd = -1`，它无法接收外部命令，服务器同一时刻最多只有一个伪客户端在工作。伪客户端的好处在于省去了网络通信开销，可以更快地处理本机数据。只要不涉及多机共享数据，Redis 会优先使用伪客户端而不是普通客户端。
    

两类客户端共享以下核心属性：

| 属性                                 | 说明              |
| ---------------------------------- | --------------- |
| ==**fd（套接字描述符）**==                 | 标识客户端与服务器的网络连接  |
| **name（客户端[[名字]]）**                | 用于调试和管理的友好名称    |
| **flags（[[标志值]]）**                 | 记录客户端的角色和当前状态   |
| ==**querybuf（[[输入缓冲区]]）**==        | 暂存从客户端读取到的命令请求  |
| ==**buf/bufpos（[[命令回复与输出缓冲区]]）**== | 暂存要发送给客户端的回复数据  |
| **`argv/argc`**（[[命令参数与命令]])       | 当前被解析出的命令及参数    |
| **ctime（创建时间）**                    | 客户端连接创建的时间      |
| **lastinteraction（最后交互时间）**        | 用于检测超时，超时后可能被关闭 |
| **authenticated（[[身份验证]]）**        | 标记客户端是否已通过密码验证  |

### 1.3 输入缓冲区

客户端的命令请求首先被存入输入缓冲区 `querybuf`。这个缓冲区使用 **SDS**（简单动态字符串）实现。SDS 是 Redis 自行封装的字符串类型，相比 C 语言原生的字符串，SDS 支持快速获取长度、防止缓冲区溢出，并能高效地进行扩容操作。

`querybuf` 有一个硬性限制：最大只能存储 **1GB** 的命令请求。一旦某个客户端的输入缓冲区超出这个限制，服务器会立即断开该客户端的连接并释放相关资源。

### 1.4 命令执行与回复

当用户在客户端中输入一条命令（例如 `set redis 100`），这条命令会被暂存在输入缓冲区中。Redis 服务器以**单线程串行**的方式处理命令：一条命令执行完毕后，才会处理下一条。命令执行成功后，服务器将回复数据写入输出缓冲区，客户端收到后显示 `OK` 字样。



### 1.5 输出缓冲区
输出缓冲区一般由两种属性组成 一种是固定大小的缓冲区，这个缓冲区可以用于处理一些简单的字符串值，整数值与错误回复等，因为固定大小的字符串是由两种属性组成的一个是buf属性另一个则是bufpos属性，其中buf属性一般是默认属性其值大小是16KB,而bufpos属性则是记录了buf数组当前已经使用的字节，当字节数量一旦超过了16KB则输出缓冲区会直接使用另一种缓冲区——另一种缓冲区是一种可变大小的缓冲区，其值是由于数据的大小来决定的因为他是由reply链表和一个或多个字符串共同组成的，因此他可以处理一些较大的字符串值，其中也包括了其他的数据结构
