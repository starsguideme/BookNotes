在 Redis 中，每个对象的结构可以拆解为：[[类型]]、[[编码]]，以及一个[[指向数据结构底层的指针]]。

#### 1. 类型与键值对

[[类型]] 决定了一个对象能执行什么命令。

在 [[什么是对象及其作用]] 中提到，Redis 每创建一个数据结构，实际上会产生两个对象：一个保存 **键**（Key），一个保存 **值**（Value）。在 [[类型]] 的定义里，**键对象** 永远是 `String` 类型；而 **值对象** 则可以是五种常用类型中的任意一种。

#### 2. 编码：灵活切换的底层实现

[[编码]] 决定了对象底层采用哪种具体的数据结构。这在 [[集合对象]] 和 [[有序集合对象]] 中表现得最明显：

- **有序集合对象**：数据量小时用 [[压缩链表]] 节省内存；数据量大时切换为 [[跳跃表]] 加 [[字典]] 以保证查询效率。
    

#### 3. 命令的多态：统一指令，不同实现

在 [[类型检查与命令多态]] 中，详细说明了 Redis 是如何处理命令的：

- **类型检查**：Redis 在执行命令前，会先核对 [[类型]]。如果对 `String` 类型的键用 `LPUSH`，会直接报错。
    
- **命令多态**：同一个命令（如 `ZRANGE`），会根据 [[编码]] 的不同，自动调用不同底层结构的算法，但最终效果完全一致。
    

#### 4. 内存管理：引用计数与空转时长

关于内存，Redis 实现了高效的回收机制：

- **引用计数**：在 [[内存回收]] 中提到，Redis 没有直接套用 C 语言的手动回收，而是引入了一个**计数器系统**。它能自动判断对象不再被任何地方使用时，就将其释放。
    
- **空转时长**：这是 [[对象的空转时长]] 的作用。当内存不足需要淘汰数据时，Redis 会优先清空那些“空转”时间比较长、长时间没被访问过的冷数据。
    
- **节省内存**：此外，Redis 还利用 [[对象共享]] 技术，让多个键安全地指向同一个不可变的小整数对象，节省空间。
