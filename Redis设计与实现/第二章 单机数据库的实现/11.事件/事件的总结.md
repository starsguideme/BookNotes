## 1. 文件事件（已优化）

在 Redis 中，根据 **[[事件的分类]]**，事件分为文件事件和时间事件。  
**[[文件事件]]** 是 Redis 对**套接字（Socket）**操作的抽象，底层通过 **[[IO多路复用程序的实现]]** 来高效管理多个连接。

文件事件共有三种处理器，分别对应不同的操作阶段：

- **[[连接应答处理器]]**
    
- **[[命令请求处理器]]**
    
- **[[命令回复处理器]]**
    

这些处理器共同构成 **[[文件事件处理器的构成]]**，并通过 **[[文件事件类型的API]]** 来注册和触发。

> 重点：Redis 的文件事件模型是**单线程但高并发**的关键，依赖 I/O 多路复用机制。

---

## 2. 时间事件（补全）

与文件事件相对，**[[时间事件]]** 是 Redis 对**定时任务**的抽象，用于执行需要周期性或延迟执行的逻辑。

时间事件的管理包括：

- **[[时间事件的调度与执行]]**：决定何时执行哪些任务
    
- **[[时间事件的API]]**：如 `aeCreateTimeEvent`、`aeDeleteTimeEvent`
    
- **[[时间事件的分类与特点]]**：
    
    - **单次时间事件**：执行一次后自动删除
        
    - **周期性时间事件**：按固定间隔重复执行
        

> 重点：Redis 的时间事件采用**无序链表**存储，每次循环会检查并执行到期事件，**不保证绝对精确的时间**，但足够高效。

---

## 3. 事件的总结

|类型|底层机制|典型用途|执行方式|
|---|---|---|---|
|**[[文件事件]]**|I/O 多路复用（如 epoll、kqueue、select）|处理客户端请求、主从复制等网络操作|事件驱动、非阻塞|
|**[[时间事件]]**|无序链表 + 系统时间|定期清理过期键、RDB/AOF 持久化触发|主动轮询检查|

> 最终总结：Redis 通过统一的事件循环 `aeMain`，同时调度 **[[文件事件]]** 和 **[[时间事件]]**，实现高效的网络与定时任务处理。
