**文件事件处理函数**

Redis 的文件事件基于 Reactor 模式实现，通过 I/O 多路复用技术监听多个套接字的事件。`ae.c` 中提供了以下核心函数：

**1. `aeCreateFileEvent` —— 注册文件事件**

接受三个参数：

- 套接字描述符
    
- 事件类型（`AE_READABLE` 或 `AE_WRITABLE`）
    
- 事件处理器（回调函数）
    

==作用：将给定套接字的给定事件加入到 I/O 多路复用程序的监听范围之内==，并绑定相应的事件处理器。

**2. `aeDeleteFileEvent` —— 取消文件事件**

接受两个参数：

- 套接字描述符
    
- 监听事件类型
    

==作用：让 I/O 多路复用程序取消对给定套接字的给定事件的监听==，同时取消事件与事件处理器之间的关联。

**3. `aeGetFileEvents` —— 获取监听状态**

接受一个套接字描述符作为参数，==返回该套接字当前正在被监听的事件类型==：

|状态|返回值|
|---|---|
|没有任何事件被监听|`AE_NONE`|
|只有读事件被监听|`AE_READABLE`|
|只有写事件被监听|`AE_WRITABLE`|
|读事件和写事件同时被监听|`AE_READABLE \| AE_WRITABLE`|

**4. `aeWait` —— 阻塞等待单个事件**

接受三个参数：

- 套接字描述符
    
- 事件类型
    
- 毫秒数（超时时间）
    

==作用：在给定的时间内阻塞并等待指定套接字的指定类型事件产生==。当事件成功产生或等待超时之后，函数返回。

**5. `aeApiPoll` —— 阻塞等待所有事件**

接受两个参数：

- `struct timeval` 结构（sys/time.h 中定义）
    
- 指定阻塞等待的时间
    

==作用：在指定的时间内，阻塞并等待所有被 `aeCreateFileEvent` 设置为监听状态的套接字所产生的文件事件==。当至少有一个事件产生，或等待超时后，函数返回。
