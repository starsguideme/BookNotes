
### 1. 创建与关联

服务器在初始化时，会创建一个 ==**专门负责执行 Lua 脚本中包含的 Redis 命令的伪客户端**==，并将这个伪客户端关联在服务器状态结构的 ==`lua_client` 属性== 中。

### 2. 生命周期

这个伪客户端在 ==**服务器的整个生命周期中会一直存在**==，直到服务器被关闭时才会被销毁。

这与 AOF 载入伪客户端形成对比：AOF 伪客户端是临时创建的，AOF 文件载入完毕后立即销毁；而 Lua 伪客户端是常驻的，随服务器初始化而创建，随服务器关闭而销毁。

### 3. 为什么需要常驻？

- 在 Redis 运行期间，可能会多次执行 Lua 脚本（如 `EVAL` 命令）。
    
- 每次执行 Lua 脚本时，脚本中可能包含多条 Redis 命令（如 `redis.call('SET', ...)`）。
    
- 这些命令必须在一个客户端上下文中执行，但又没有真正的网络连接。
    
- 因此，==**创建一个常驻的 Lua 伪客户端**== 比每次执行脚本时临时创建、用完再销毁要高效得多。
    

### 4. 面试要点

**Q：Lua 伪客户端和普通客户端的区别是什么？**

|维度|普通客户端|Lua 伪客户端|
|---|---|---|
|fd|> -1（真实 socket）|==**-1**==|
|命令来源|网络请求|Lua 脚本中的 `redis.call()`|
|生命周期|随连接建立/断开|==**随服务器常驻，直到服务器关闭**==|
|存储位置|`server.clients` 链表|==**`server.lua_client` 属性单独存储**==|

**Q：为什么不直接复用 AOF 伪客户端来执行 Lua 命令？**

> 两者的生命周期和使用场景完全不同。AOF 伪客户端只在服务器启动时临时使用，AOF 载入完毕即销毁。而 Lua 脚本在服务器运行期间随时可能执行，需要一个常驻的伪客户端。除此之外，**Lua 脚本的命令执行本身也是可写入 AOF 的**，如果被脚本修改了数据，这些写命令也需要通过脚本的传播逻辑写入 AOF 或发给从节点。用独立的伪客户端能让状态管理更清晰，不会和 AOF 恢复的上下文冲突。
