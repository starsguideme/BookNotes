**客户端的身份验证属性（authenticated）**

**1. 属性的作用**

客户端的 `authenticated` 属性用于 ==**记录客户端是否通过了身份认证**==。

**2. 属性值的含义**

|值|状态|说明|
|---|---|---|
|==**0**==|未通过身份验证|客户端连接到服务器，但尚未执行 `AUTH` 命令|
|==**1**==|已通过身份验证|客户端已成功执行 `AUTH` 命令，或服务器未开启认证|

**3. 对命令执行的限制**

当客户端未通过身份验证时（`authenticated == 0`），==**除了 `AUTH` 命令之外，所有其他命令都会被服务器拒绝执行**==。客户端必须先通过 `AUTH` 命令完成身份验证，将 `authenticated` 置为 1，才能正常向服务器发送其他命令请求。

**4. 前提条件**

上述限制有一个重要前提：==**服务器配置了 `requirepass` 参数，启用了身份认证功能**==。

- 如果服务器设置了 `requirepass`，则必须通过认证才能执行命令。
    
- 如果服务器**没有**设置 `requirepass`，即使 `authenticated` 的值为 0，服务器也不会拦截任何命令，客户端可以直接执行所有操作。
    

**5. 面试要点**

**Q：如何判断一个 Redis 实例是否开启了认证？**

> 通过 `CONFIG GET requirepass` 查看。如果返回空字符串，说明没有设置密码；否则说明已经设置了密码，所有新连接的客户端都必须通过 `AUTH` 认证后才能执行命令。

**Q：生产环境中 Redis 必须设置密码吗？**

> ==**强烈建议设置。**== 虽然 Redis 通常在受信内网环境运行，但设置密码是纵深防御的重要一环，可以防止未授权访问。2015 年著名的“Redis 挖矿病毒”攻击，就是利用了未设密码且暴露在公网的 Redis 实例，通过写入 SSH 公钥的方式入侵服务器。设置密码是成本最低的安全防护手段之一。

**Q：`authenticated` 在从节点连接主节点时也有作用吗？**

> 是的。如果主节点设置了 `requirepass`，从节点必须在配置文件中通过 `masterauth` 指定密码，连接主节点后自动执行 `AUTH` 完成认证，否则主从复制无法正常工作。
