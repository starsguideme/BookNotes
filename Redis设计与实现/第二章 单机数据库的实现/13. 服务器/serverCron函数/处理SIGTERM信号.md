**服务器优雅关闭的信号处理机制**

### 一、信号处理器的注册

在服务器启动时，Redis 会为服务器进程的 ==**`SIGTERM` 信号**== 关联处理器 ==**`sigtermHandler` 函数**==。这个信号处理器负责在服务器接收到 `SIGTERM` 信号时，打开服务器状态的 ==**`shutdown_asap` 标识**==（即将其值设为 1）。

**补充细节**：`SIGTERM` 是 Linux 系统中最常用的"优雅终止"信号。当运维人员执行 `kill <pid>` 或 `systemctl stop redis` 时，操作系统会向 Redis 进程发送 `SIGTERM` 信号。与之对应的 `SIGKILL`（`kill -9`）则无法被捕获，进程会被立即强制终止。

### 二、信号处理器的行为

`sigtermHandler` 函数并不直接关闭服务器，而是 ==**仅仅设置一个标志位**==。这样做的原因是：

- 信号处理器执行时，==**主线程的执行会被中断**==（信号处理器在中断上下文中执行）。
    
- 如果在信号处理器中直接执行 `exit()` 或复杂的关闭逻辑，可能导致数据不一致或死锁（如持锁状态被中断）。
    
- 因此，信号处理器只做一个最轻量的操作——==**设置 `shutdown_asap = 1`**==，然后立即返回，将实际的关闭工作交给主线程在安全的时间点执行。
    

### 三、关闭时机的检查

每次 `serverCron` 函数运行时，都会检查服务器状态的 ==**`shutdown_asap`**== 属性：

- 如果 `shutdown_asap == 1`，服务器会执行 ==**优雅关闭流程**==，包括：
    
    - 停止接收新的命令请求。
        
    - 将 AOF 缓冲区和 AOF 重写缓冲区中的内容刷盘。
        
    - 执行 `BGSAVE` 生成最终的 RDB 文件（如果配置允许）。
        
    - 关闭所有客户端连接。
        
    - 释放服务器资源并退出进程。
        
- 如果 `shutdown_asap == 0`，服务器继续正常运行。
    

由于 `serverCron` 默认每 100ms 执行一次，服务器在收到 `SIGTERM` 信号后，==**最多延迟 100ms**== 就会执行关闭流程。

### 完整流程图

**运维人员执行 kill <pid> `systemctl`和`stop`和`redis`**
         **↓**
**操作系统向 Redis 进程发送 SIGTERM 信号**
         **↓**
**信号处理器`sigtermHandler` 被触发**
         **↓**
**`sigtermHandler`设置`shutdown_asap`= 1（仅此而已，立即返回）**
         **↓**
**主线程在下次 ·serverCron 执行时检查 shutdown_asap**
         **↓**
**发现 shutdown_asap == 1，执行优雅关闭流程**
         **↓**
**刷盘 AOF、保存 RDB、关闭客户端、释放资源、退出**

### 面试要点

**Q：为什么信号处理器只设置标志位，而不直接关闭服务器？**

> 信号处理器运行在中断上下文中，此时主线程可能正持有某个锁、正在写入 AOF 缓冲区或正在执行命令。如果在信号处理器中直接执行关闭逻辑，可能导致数据不一致甚至死锁。将关闭操作交给主线程在事件循环中安全执行，是更可靠的"优雅关闭"模式。

**Q：如果**`serverCron`**还没有执行，服务器是否会立即关闭？**

> 不会。Redis 只会在 `serverCron` 执行时检查 `shutdown_asap` 标志。由于 `serverCron` 每 100ms 执行一次，最坏情况下关闭操作会延迟 100ms。对于绝大多数场景，这个延迟可以忽略不计。如果服务器正在执行一个耗时很长的命令（如 `KEYS *`），关闭操作可能会等待更久。

**Q：`SIGTERM` 和 `SHUTDOWN` 命令有什么区别？**

> 两者最终都会触发优雅关闭流程，但触发方式不同：
> 
> - `SIGTERM`：由操作系统发送给进程，信号处理器设置 `shutdown_asap` 标志，由 `serverCron` 检查并执行关闭。
>     
> - `SHUTDOWN` 命令：由客户端发送，是一个 Redis 命令，直接调用关闭函数执行关闭流程，可以附带 `SAVE` 或 `NOSAVE` 参数控制是否持久化。
