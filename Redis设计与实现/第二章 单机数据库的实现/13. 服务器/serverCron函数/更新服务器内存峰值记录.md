**服务器内存峰值记录**

### 一、内存峰值属性

服务器状态中的 ==**`stat_peak_memory`**== 属性记录了服务器的内存峰值大小。这个值对于评估 Redis 的内存使用情况非常重要，直接关系到 [[AOF后台重写]]和[[RDB的创建与载入]]时是否需要预留足够的内存（`fork` 子进程需要额外的内存空间，写时复制可能导致内存翻倍）。

### 二、更新机制

每次 `serverCron` 函数执行时，程序都会查看服务器当前已使用的内存数量，并与 `stat_peak_memory` 保存的数值进行比较：

- 如果当前已使用的内存数量 ==**大于**== `stat_peak_memory` 属性记录的值，则用当前值覆盖更新 `stat_peak_memory`。
    
- 如果当前值小于或等于历史峰值，则不做更新。
    

因此，`stat_peak_memory` 始终保存着 ==**服务器启动以来内存使用的历史最大值**==，而不仅仅是某一个时刻的快照。

### 三、查看方式

通过 `INFO memory` 命令可以查看内存峰值，对应以下两个域：

| 域                                | 格式     | 示例                |
| -------------------------------- | ------ | ----------------- |
| ==**`used_memory_peak`**==       | 原始字节数  | `1048576`（表示 1MB） |
| ==**`used_memory_peak_human`**== | 人类可读格式 | `"1.00M"`         |

### 面试要点

**Q：为什么运维需要关注 `used_memory_peak`？**

> 这个值代表了 Redis 运行期间所需的最大内存上限。运维人员可以据此：
> 
> - 判断当前服务器的物理内存是否足够（如果峰值接近物理内存上限，需要扩容或优化数据结构）。
>     
> - 评估 `fork` 子进程时是否有足够的内存空间（`BGSAVE` / `BGREWRITEAOF` 依赖 `fork`，写时复制可能导致内存翻倍）。
>     
> - 配合 `maxmemory` 配置，设定合理的淘汰策略。
>     

**Q：`stat_peak_memory` 和 `used_memory` 有什么区别？**

> `used_memory` 是当前时刻的内存占用量（实时值），`stat_peak_memory` 是服务器启动以来的历史最大值（只增不减）。前者用于实时监控，后者用于容量规划和上限评估。
