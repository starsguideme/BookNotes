### 一、为什么现在才初始化数据结构？

在之前的 `initServerConfig` 阶段，程序**只创建了命令表这一个数据结构**。但服务器状态中还有大量其他数据结构需要初始化：

|数据结构|属性名|说明|
|---|---|---|
|==**客户端链表**==|`server.clients`|记录所有与服务器相连的客户端的状态结构，每个节点是一个 `redisClient` 实例|
|==**数据库数组**==|`server.db`|包含服务器的所有数据库（默认 16 个）|
|==**频道订阅字典**==|`server.pubsub_channels`|保存频道订阅信息，key 为频道名，value 为客户端链表|
|==**模式订阅链表**==|`server.pubsub_patterns`|保存模式订阅信息|
|==**Lua 环境**==|`server.lua`|用于执行 Lua 脚本的 Lua 解释器环境|
|==**慢查询日志**==|`server.slowlog`|保存慢查询日志记录|

**设计原因**：服务器将初始化分为两步进行，是为了解决一个关键问题——==**配置项的加载顺序**==。

如果在 `initServerConfig` 阶段就初始化数据结构，而用户之后通过配置文件修改了与数据结构相关的属性（如数据库数量 `databases`），服务器就需要**重新调整甚至销毁重建**已初始化的数据结构。为了避免这个麻烦，Redis 采用了"**先载入配置，再创建结构**"的策略：

第一步：initServerConfig()
    ↓  只设置默认值，创建命令表
第二步：载入配置项
    ↓  读取 redis.conf，覆盖用户自定义的配置
第三步：initServer()
    ↓  此时配置已最终确定，可以正确创建所有数据结构

### 二、`initServer` 函数的完整职责

初始化数据结构只是 `initServer` 的核心工作之一，除此之外它还负责以下重要操作：

#### 1. 初始化数据结构

为上述所有数据结构（`clients`、`db`、`pubsub_channels`、`lua`、`slowlog` 等）分配内存，并在需要时设置或关联初始值。

#### 2. 设置[[处理SIGTERM信号]]

为服务器进程注册信号处理函数，如 `SIGTERM` 对应的 `sigtermHandler`，用于实现优雅关闭。

#### 3. 创建共享对象

==**共享对象**== 是 Redis 中一个精巧的内存优化设计。服务器会预先创建一些经常用到的值，通过重用这些对象来避免反复创建和销毁相同的字符串对象。

常见的共享对象包括：

|共享对象|说明|
|---|---|
|==**"OK" 字符串对象**==|命令执行成功的标准回复|
|==**"ERR" 字符串对象**==|通用错误回复|
|==**1 到 10000 的整数对象**==|高频使用的整数值，直接共享而不是每次创建|

**设计原因**：Redis 是单线程的，共享对象不需要考虑线程安全问题。通过共享这些高频对象，可以显著减少内存分配和 GC 开销。

#### 4. 打开监听端口并关联连接应答处理器

打开服务器的监听端口（默认 6379），并为监听套接字关联 ==**连接应答处理器 `acceptTcpHandler`**==，等待服务器正式运行时接受客户端连接。

#### 5. 为 `serverCron` 创建时间事件

调用 `aeCreateTimeEvent`，将 `serverCron` 函数注册为时间事件，使其在服务器运行期间以默认 100ms 一次的频率周期性执行。

#### 6. 初始化 AOF 相关资源

如果 AOF 持久化功能已开启，打开现有的 AOF 文件；如果 AOF 文件不存在，则创建并打开一个新的 AOF 文件，为后续的 AOF 写入做好准备。

#### 7. 初始化后台 I/O 模块

为服务器初始化后台 I/O 模块（如后台 `fsync` 线程），为将来的 I/O 操作做好准备。

#### 8. 输出启动信息

当以上所有步骤完成后，服务器会通过 ASCII 码在日志中输出 Redis 的图标、版本号以及运行模式信息，标志着初始化工作完成。

### 三、服务器初始化全流程

**① `initServerConfig()`**
    **↓ 创建命令表，设置默认配置值**
**② 载入配置项**
    **↓ 读取 `redis.conf` / 命令行参数，覆盖默认值**
**③ `initServer()`**
    **↓ 初始化数据结构（clients / `db` / `pubsub / lua / slowlog`）**
    **↓ 设置信号处理器**
    **↓ 创建共享对象**
    **↓ 打开监听端口，关联连接应答处理器**
    **↓ 为 `serverCron` 创建时间事件**
    **↓ 初始化 AOF 文件**
    **↓ 初始化后台 I/O 模块**
    **↓ 输出 Redis 启动图标和版本信息**
**④ 载入持久化文件**
    **↓ 从 RDB 或 AOF 文件恢复数据**
**⑤ 进入事件循环**
    **↓ 开始监听并处理客户端请求**

### 面试要点

| 考点                         | 回答要点                                                  |
| -------------------------- | ----------------------------------------------------- |
| **为什么初始化分两步**                  | **==先载入配置，再创建结构==，避免配置文件覆盖默认值后需要重建数据结构**              |
| **共享对象的作用**                    | **预先创建常用值（"OK"、"ERR"、1-10000 的整数），通过重用减少内存分配开销**          |
| **为什么共享对象可行**                  | **Redis 是单线程模型，不存在多线程并发修改共享对象的问题**                        |
| **`initServer` 除了创建数据结构还做了什么** | **信号处理器、共享对象、监听端口、`serverCron` 时间事件、AOF 文件初始化、后台 I/O 模块** |
| **数据库数量何时确定**                  | **在 `initServer` 阶段，因为此时已载入配置文件，`databases` 参数已最终确定**     |
