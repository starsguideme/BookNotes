### 一、创建服务器实例

初始化服务器的第一步是创建一个 ==**`struct redisServer`**== 类型的实例变量 `server` 作为服务器的状态，并为结构中的各个属性设置默认值。

### 二、`initServerConfig` 函数

初始化服务器配置的工作由 ==**`redis.c/initServerConfig`**== 函数完成。这个函数的主要职责是**为 `server` 结构中的基本属性赋默认值**。

**主要初始化内容**：

| 初始化项               | 说明                                       |
| ------------------ | ---------------------------------------- |
| ==**运行 ID**==      | 生成服务器的唯一标识，用于主从复制、Sentinel 等场景           |
| ==**默认配置文件路径**==   | 设置 `redis.conf` 的默认路径                    |
| ==**默认运行频率（hz）**== | 设置 `serverCron` 的执行频率，默认为 10（即 100ms 一次） |
| **运行架构**           | 设置服务器运行模式（单机、集群、Sentinel）                |
| ==**默认端口号**==      | 设置服务器监听端口，默认为 6379                       |
| ==**RDB 持久化条件**==  | 设置 `save` 的默认配置（如 `save 900 1`）          |
| ==**AOF 持久化条件**==  | 设置 AOF 的默认开关和策略                          |
| ==**LRU 时钟**==     | 初始化服务器的 LRU 时钟                           |
| ==**命令表**==        | 创建命令字典，将所有 Redis 命令及其实现函数注册进去            |

### 三、`initServerConfig` 的特点

==**`initServerConfig` 函数只创建命令表这一项数据结构，其他的数据库、慢查询日志、Lua 环境、共享对象等复杂结构均未创建。**==

它设置的属性基本都是：

| 类型          | 示例            |
| ----------- | ------------- |
| 整数          | 端口号、频率、LRU 时钟 |
| 浮点数         | 内存限制比例等       |
| 字符串         | 运行 ID、配置文件路径  |
| 字典（唯一的数据结构） | 命令表           |

**设计原因**：初始化配置阶段只是"填充默认值"，不涉及内存分配和复杂结构的创建。真正的数据结构（数据库、客户端链表、AOF 缓冲区等）在后续的 `initServer` 阶段才会创建。将两者分离，可以使初始化流程更清晰，也便于在载入配置文件后覆盖默认值。

### 四、初始化全流程概览

**服务器初始化共有以下阶段：**

**① `initServerConfig()`   ← 当前阶段：初始化基本属性为默认值**
         **↓**
**② [[载入配置项]]          ← 读取 `redis.conf` 或命令行参数，覆盖默认值**
         **↓**
**③ `initServer()`        ← [[初始化服务器数据结构]]（数据库、客户端链表、AOF 缓冲区、共享对象等）**
         **↓**
**④ 载入持久化文件      ← 从 RDB 或 AOF 文件[[还原数据库的状态]]**
         **↓**
**⑤ [[执行事件循环]]        ← 开始监听客户端请求**

### 面试要点

| **考点**                      | **回答要点**                                                      |
| ----------------------- | --------------------------------------------------------- |
| **`initServerConfig` 做了什么** | **为 `redisServer` 结构赋默认值，只创建命令表这一个数据结构**                      |
| **为什么数据库等结构不在此阶段创建**        | **配置项尚未载入，数据库数量等参数可能被配置文件覆盖，提前创建会造成浪费或需要重建**                  |
| **命令表为什么要在此时创建**            | **命令表是静态数据（200+ 条命令的元信息），不依赖配置文件，提前注册不影响后续流程**                |
| **四个阶段的顺序**                 | **`initServerConfig` → 载入配置 → `initServer` → 载入持久化文件 → 事件循环** |
