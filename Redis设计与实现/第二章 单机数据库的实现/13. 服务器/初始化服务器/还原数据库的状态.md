### 一、为什么要载入持久化文件？

在完成 `initServer` 对服务器状态的数据结构初始化之后，服务器需要载入 RDB 文件或 AOF 文件，根据文件记录的内容来还原服务器的数据库状态。这样服务器在启动后才能恢复到上一次关闭前的数据状态，而不是每次重启都从空数据库开始。

### 二、载入优先级

根据服务器是否启用了 AOF 持久化功能，服务器载入数据时所使用的目标文件会有所不同：

| 条件                 | 载入目标文件     | 原因                                    |
| ------------------ | ---------- | ------------------------------------- |
| ==**启用了 AOF 功能**== | **AOF 文件** | AOF 文件记录的是写命令，数据完整性更高，通常比 RDB 文件更新更及时 |
| ==**未开启 AOF 功能**== | **RDB 文件** | RDB 是默认的持久化方式，用于冷备份和快速恢复              |

==**AOF 优先级高于 RDB**==，这是 Redis 持久化机制的核心设计原则之一。即使服务器同时开启了 AOF 和 RDB，启动时也只会使用 AOF 文件来恢复数据，RDB 文件仅作为备份保留。

### 三、还原过程

- **使用 AOF 文件还原**：创建一个 AOF 载入伪客户端，逐条执行 AOF 文件中保存的写命令，直至所有命令执行完毕。
    
- **使用 RDB 文件还原**：直接将 RDB 二进制文件加载到内存中，恢复数据库状态。
    

### 四、打印载入日志

当服务器完成数据库状态的还原工作之后，服务器会在日志中打印出载入文件并还原数据库状态所耗费的时长，用于运维监控和性能分析。

### 面试要点

| **考点**                       | **回答要点**                                         |
| ---------------------------- | ------------------------------------------------ |
| **AOF 和 RDB 的载入优先级**         | **==AOF 优先于 RDB==，因为 AOF 数据完整性更高**               |
| **为什么 AOF 优先级更高**            | **AOF 记录每条写命令，更新频率通常更高，最多只丢 1 秒数据（everysec 模式）** |
| **如果同时开启了 AOF 和 RDB，启动时用哪个** | **只用 AOF，RDB 文件作为冷备份保留**                         |
| **载入 AOF 文件的方式**             | **创建[[伪客户端]]，逐条执行 AOF 文件中的写命令**                  |
| **载入 RDB 文件的方式**             | **直接将二进制文件加载到内存中，速度更快**                          |
