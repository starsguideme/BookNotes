**命令执行器（1）：查找命令实现**

命令执行器要做的第一件事，就是根据客户端 `argv[0]` 参数的值，在命令表中查找对应的命令实现，然后将找到的 `redisCommand` 结构体指针赋值给客户端状态的 ==**`cmd` 属性**==。

命令表本质上是一个 ==**字典（dict）**==，其结构如下：

| 键（key）                                    | 值（value）                          |
| ----------------------------------------- | --------------------------------- |
| SDS 字符串，保存命令名字（如 `"SET"`、`"GET"`、`"DEL"`） | 指向 ==**`redisCommand` 结构体**== 的指针 |

---

### `redisCommand` 结构体的主要属性

`redisCommand` 结构体定义在 `redis.h` 中，保存了一条 Redis 命令的完整元信息。其主要属性分为以下几类：

**一、核心执行属性**

| 属性            | 类型       | 说明                                                     |
| ------------- | -------- | ------------------------------------------------------ |
| ==**name**==  | `char *` | 命令的名字（如 `"set"`、`"get"`）                               |
| ==**proc**==  | 函数指针     | 命令的实现函数，指向具体的 C 函数（如 `setCommand`、`getCommand`）        |
| ==**arity**== | `int`    | 命令的参数个数（包括命令名本身），例如 `SET` 的 arity 为 3（也可以是负数，表示参数数量可变） |

**二、命令属性标志**

|属性|类型|说明|
|---|---|---|
|==**sflags**==|`char *`|命令的标志字符串，每个字符代表一种属性，用于快速判断命令类型|

常见的 `sflags` 标志字符：

| 标志字符    | 含义        | 说明                          |
| ------- | --------- | --------------------------- |
| ==`w`== | write     | 写命令，会修改数据库                  |
| ==`r`== | read      | 只读命令，不修改数据库                 |
| ==`m`== | memory    | 可能会占用大量内存，执行前需检查            |
| ==`a`== | admin     | 管理命令（如 `SHUTDOWN`、`CONFIG`） |
| ==`p`== | pubsub    | 发布/订阅相关命令                   |
| ==`s`== | scripting | 不能在 Lua 脚本中使用               |
| ==`t`== | stale     | 允许在从节点数据过期时执行               |
| ==`M`== | monitor   | 在 MONITOR 模式下不自动传播          |
| ==`F`== | fast      | 快速命令，O(1) 或 O(logN) 复杂度     |

**三、统计信息**

|属性|类型|说明|
|---|---|---|
|==**calls**==|`long long`|命令被调用的总次数，`INFO commandstats` 命令可查看|
|==**milliseconds**==|`long long`|命令执行的总消耗时长（毫秒），与 calls 结合可计算平均耗时|

**四、键参数辅助信息（集群模式使用）**

| 属性                   | 类型    | 说明                                                  |
| -------------------- | ----- | --------------------------------------------------- |
| ==**firstkey**==     | `int` | 第一个键参数在 argv 中的位置（如 `SET key value` 中 firstkey = 1） |
| ==**lastkey**==      | `int` | 最后一个键参数在 argv 中的位置                                  |
| ==**keystep**==      | `int` | 键参数之间的步长（通常为 1）                                     |
| ==**getkeys_proc**== | 函数指针  | 可选，用于从 argv 中提取键名的函数（当 firstkey/lastkey 无法满足时使用）    |
|                      |       |                                                     |

### 示例：`SET` 和 `GET` 命令的 `redisCommand` 结构

#### `SET` 命令

|属性|值|说明|
|---|---|---|
|==**name**==|`"set"`|命令名字|
|==**proc**==|`setCommand`|命令的实现函数|
|==**arity**==|`-3`|==**负数表示参数数量可变**==，绝对值为最小参数个数。`-3` 表示最少需要 3 个参数（`SET key value`），但还可以接受可选参数（如 `EX`、`NX` 等）|
|==**sflags**==|`"wm"`|==`w` 表示写命令==，会修改数据库，需写入 AOF 和传播给从节点；==`m` 表示可能占用内存==，执行前需检查内存并进行可能的淘汰|

#### `GET` 命令

|属性|值|说明|
|---|---|---|
|==**name**==|`"get"`|命令名字|
|==**proc**==|`getCommand`|命令的实现函数|
|==**arity**==|`2`|==**正数表示参数数量固定**==，`2` 表示只能接受 2 个参数（`GET key`，即命令名本身 + 一个键名）|
|==**sflags**==|`"r"`|==`r` 表示只读命令==，不修改数据库，不需要写入 AOF，也不需要传播给从节点|
注: 对于Redis来说，客户端的命令无论是任何大小写对Redis来说都是一样的.
