1. **优点**：对内存最友好。使用定时器，键一过期就立刻删除，内存释放最快，不会出现“过期键还占着内存”的情况。
    
2. **缺点**：对 CPU 极不友好。当过期键数量庞大时，CPU 需要频繁执行删除操作，会严重挤占正常业务请求的处理时间，降低吞吐量。
    
3. **复杂度**：需要遍历所有设置了过期时间的键，时间复杂度为 O(N)。这里的 N 是带过期时间的键的总数，因此在 CPU 资源紧张的场景下不可用。
    
4. **Redis 的实际选择**：正因为以上缺点，Redis **没有采用**定时删除策略。它选择的是[[惰性删除]] + [[定期删除]]的组合，在 CPU 和内存之间取得平衡。
