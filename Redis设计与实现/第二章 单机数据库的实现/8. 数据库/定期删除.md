1. **出现原因**：由于定时删除（CPU不友好）和惰性删除（内存不友好）各有弊端，定期删除应运而生，试图在两者之间取得平衡。
    
2. **优点**：
    
    - 每隔一段时间执行一次删除过期键的操作，通过限制删除操作的执行时长和频率来减少对 CPU 时间的影响
        
    - 相比惰性删除，能更主动地清理过期键，减少内存浪费
        
3. **缺点（两个退化方向）**：
    
    - 如果执行得太过频繁或每次执行时间太长，可能退化成[[定时删除]]，占用大量 CPU
        
    - 如果执行次数太少或每次执行时间太短，可能退化成[[惰性删除]]，浪费内存
        
4. **实际使用**：Redis 采用的是[[惰性删除]] + [[定期删除]]的组合策略，惰性删除处理日常访问时的清理，定期删除主动抽查，两者配合使用。具体参数需要根据实际场景和需求来调整。
