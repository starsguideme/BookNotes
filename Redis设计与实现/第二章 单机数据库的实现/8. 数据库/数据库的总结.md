Redis 是键值对数据库，在其结构中 [[数据库的键空间及其操作]]，这个空间叫做键空间。键空间中的每个键都是一个[[字符串对象]]，但其对应的值可以是[[列表对象]]、[[Hash对象]]、[[集合对象]]和[[有序集合对象]]这五种常规对象之一。键空间支持添加、删除、更新、取值等基本操作，以及 FLUSHDB、RANDOMKEY、DBSIZE、EXISTS、RENAME、KEYS 等其他操作，这些命令本质上都是通过对键空间的字典进行操作来实现的。

关于目标数据库与服务器中的调用参考[[服务器中的目标数据库与使用]].

Redis 通过 [[设置键的生存时间和过期时间]] 来管理键的生命周期。EXPIRE、PEXPIRE、EXPIREAT 和 SETEX 命令最终都会转换成 PEXPIREAT命令来执行。redisDB 结构的 expires 字典（过期字典）保存了所有键的过期时间，其键是一个指向目标数据库键的指针，值是一个毫秒精度级的 UNIX 时间戳。通过 [[TTL 和 PTTL]] 命令可以查看键的剩余生存时间，通过 [[PERSIST]] 命令可以移除过期时间。[[过期键的删除策略]] 中可以通过检查过期字典中该键的时间戳是否小于当前时间来选择对应的删除策略。

当键过期后，Redis 有三种删除策略：[[定时删除]]（对内存最友好但 CPU 开销大）、[[惰性删除]]（对 CPU 最友好但浪费内存）和 [[定期删除]]（前两种的折中方案）。实际使用中，Redis 采用 [[惰性删除策略的实现|惰性删除]] 和 [[定期删除策略的实现|定期删除]] 的组合策略，在 CPU 和内存之间取得平衡。

关于持久化，[[AOF，RDB 和复制功能对过期键 的处理]]确保了数据一致性。生成 RDB 文件时已过期的键不会被保存；载入 RDB 文件时，主服务器会忽略过期键，从服务器虽全部载入但主从同步时会被清空，因此过期键不会产生影响。在 AOF 模式下，当过期键被惰性删除或定期删除后，程序会向 AOF 追加一条 DEL 命令；AOF 重写时过期键也不会被保存。

当调用方法时，想让数据发送通知告诉后端做了什么事 请参考[[数据库的通知]].
