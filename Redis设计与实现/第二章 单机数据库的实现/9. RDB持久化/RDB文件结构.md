### 一、整体结构

RDB 文件由以下五个部分组成，从开头到结尾依次为：

| REDIS (5字节) | `db_version` (4字节) | databases (变长) | EOF (1字节) | `check_sum` (8字节) |

|部分|长度|说明|
|---|---|---|
|==**REDIS**==|5 字节|文件头，存储 `"REDIS"` 五个字符，用于快速校验是否为合法 RDB 文件|
|==**db_version**==|4 字节|RDB 版本号，以字符串形式记录（如 `"0009"`）|
|==**databases**==|变长|保存 0 个或多个数据库及其键值对数据|
|==**EOF**==|1 字节|正文结束标志，读到此处说明所有键值对已载入完毕|
|==**check_sum**==|8 字节|CRC64 校验和，用于完整性校验|

---

### 二、各部分详解

#### 1. REDIS（文件头）

`REDIS` 是 RDB 文件的开头部分，占 ==**5 字节**==。通过检查这 5 个字节，程序可以快速判断载入的文件是否为合法的 RDB 文件。

#### 2. db_version（版本号）

`db_version` 长度为 ==**4 字节**==，它的值是一个字符串表示的整数（如 `"0009"`），记录了这个 RDB 文件所使用的版本号。不同版本的 Redis 使用不同的 RDB 格式，版本号用于兼容性检查。

#### 3. databases（数据库数据）

`databases` 部分包含 0 个或多个数据库以及各个数据库中的键值对数据：

- 如果服务器的数据库状态为**空**，那么这个部分也为空，长度为 0 字节。
    
- 如果服务器的数据库状态为**非空**，那么这个部分也为非空。根据数据库所保存键值对的数量、类型和内容不同，这个部分的长度也会不同。
    

每个非空数据库由以下三个部分组成：

| SELECTDB (1字节) | `db_number` (变长) | `key_value_pairs` (变长) |

- ==**SELECTDB**==：常量为 1 字节。当读入程序遇到这个值时，就知道接下来要读入一个数据库号码。
    
- ==**`db_number`**==：记录数据库号码。根据号码大小的不同，这部分长度可以是 **1 字节、2 字节或 5 字节**。程序读入 `db_number` 之后，服务器会调用 `SELECT` 命令切换到对应数据库，保证后续读入的键值对载入到正确的目标数据库中。
    
- ==**`key_value_pairs`**==：保存了该数据库中的所有键值对数据。如果键值对带有过期时间，过期时间也会一起保存。根据键值对的数量、类型、内容以及是否有过期时间等条件不同，其长度也不同。

### 三、键值对的存储结构

#### 1. 不带过期时间的键值对

由三个部分组成：


| type (1字节) | key (变长) | value (变长) |

- ==**type**==：记录 value 的类型，占 1 字节。共可分为以下类型：
    

| TYPE 常量                       | 对应的值对象        |
| ----------------------------- | ------------- |
| `REDIS_RDB_TYPE_STRING`       | [[字符串对象]]     |
| `REDIS_RDB_TYPE_LIST`         | [[列表对象]]      |
| `REDIS_RDB_TYPE_SET`          | [[集合对象]]      |
| `REDIS_RDB_TYPE_HASH`         | [[Hash对象]]    |
| `REDIS_RDB_TYPE_ZSET`         | [[有序集合对象]]    |
| `REDIS_RDB_TYPE_LIST_ZIPLIST` | 压缩列表编码的列表     |
| `REDIS_RDB_TYPE_SET_INTSET`   | [[整数集合]]编码的集合 |
| `REDIS_RDB_TYPE_ZSET_ZIPLIST` | 压缩列表编码的有序集合   |
| `REDIS_RDB_TYPE_HASH_ZIPLIST` | 压缩列表编码的哈希     |

- ==**key**==：总是一个字符串对象，编码方式和 `REDIS_RDB_TYPE_STRING` 类型中的对应值一样。根据内容不同，key 的长度也会有所不同。
    
- ==**value**==：根据 TYPE 的不同，保存 value 的结构和长度会有所不同。
    

#### 2. 带有过期时间的键值对

由五个部分组成：


| EXPIRETIME_MS (1字节) | `ms` (8字节) | type (1字节) | key (变长) | value (变长) |

- ==**EXPIRETIME_MS**==：长度为 1 字节，告知读入程序，接下来要读入的将是一个以毫秒为单位的过期时间。
    
- ==**ms**==：8 字节长度的带符号整数，记录着一个以毫秒为单位的 UNIX 时间戳，即该键值对的过期时间。
    
- **type、key、value**：与不带过期时间的键值对含义完全相同。
    

**面试要点**：过期时间使用 ==**绝对时间戳**==（`EXPIRETIME_MS + ms`），而不是剩余的相对秒数。这样即使 RDB 文件被长期保存后再恢复，过期时间也不会因为时间流逝而产生偏移。

---

### 四、Value 的编码规则

RDB 文件中的每个 value 都保存了一个值对象，每个值对象的类型由对应的 TYPE 决定。根据类型的不同，value 的结构和长度也会有所不同。

#### 1. 字符串对象

当 TYPE 为 `REDIS_RDB_TYPE_STRING` 时，value 保存一个字符串对象。其内部编码可以是：

- ==**`REDIS_ENCODING_INT`**==：整数值，直接以整数形式存储，节省空间。
    
- ==**`REDIS_ENCODING_RAW`**==：原始字符串值，记录字符串长度后存储实际内容。
    

#### 2. 列表对象

当 TYPE 为 `REDIS_RDB_TYPE_LIST` 时，value 保存一个列表对象。存储方式为：==**先记录列表长度（元素数量），然后依次记录每个元素**==。

#### 3. 集合对象

当 TYPE 为 `REDIS_RDB_TYPE_SET` 时，value 保存一个集合对象。存储方式为：==**先记录集合大小（元素数量），然后依次记录每个元素**==。

#### 4. 哈希对象

当 TYPE 为 `REDIS_RDB_TYPE_HASH` 时，value 保存一个哈希对象。存储方式为：==**先记录键值对数量，然后依次成对存储 key 和 value**==。

#### 5. 有序集合对象

当 TYPE 为 `REDIS_RDB_TYPE_ZSET` 时，value 保存一个有序集合对象。存储方式为：==**先记录元素数量，然后依次成对存储 member 和 score**==。

---

### 五、特殊编码类型的存储方式

为节省内存，Redis 定义了以下特殊 TYPE：

|特殊 TYPE|说明|
|---|---|
|`REDIS_RDB_TYPE_LIST_ZIPLIST`|压缩列表编码的列表|
|`REDIS_RDB_TYPE_SET_INTSET`|整数集合编码的集合|
|`REDIS_RDB_TYPE_ZSET_ZIPLIST`|压缩列表编码的有序集合|
|`REDIS_RDB_TYPE_HASH_ZIPLIST`|压缩列表编码的哈希|

这些特殊编码类型的存储方式是相同的：==**将整个紧凑数据结构转换为字符串对象，再将该字符串对象保存到 RDB 文件中**==。

**整数集合的存储**：如果 TYPE 的值为 `REDIS_RDB_TYPE_SET_INTSET`，程序会先将整数集合转换为字符串对象，然后将这个字符串对象保存到 RDB 文件。读入时，程序根据 TYPE 的指示，先读入字符串对象，再将其还原为整数集合对象。

**ZIPLIST 编码的存储**：如果 TYPE 的值是某种压缩列表类型，存储方式是：

1. 将压缩列表转换为一个字符串对象。
    
2. 将转换所得的字符串对象保存到 RDB 文件。
    

读入时，程序根据 TYPE 的指示执行以下操作：

1. 读入字符串对象，将其还原为原来的压缩列表对象。
    
2. 根据 TYPE 的值，将压缩列表对象的类型设置为对应的数据结构。
    

**设计原因**：压缩列表和整数集合本身就是一块连续的内存，直接作为字符串写入 RDB 文件是最简单高效的方式，无需逐元素遍历。

### 面试要点汇总

|考点|回答要点|
|---|---|
|RDB 文件整体结构|`REDIS` → `db_version` → `databases` → `EOF` → `check_sum`|
|如何判断文件是 RDB|检查前 5 字节是否为 `"REDIS"`|
|校验和的作用|CRC64 校验，载入时比对，不一致则拒绝加载|
|过期时间如何存储|`EXPIRETIME_MS + ms`，记录绝对时间戳而非相对秒数|
|特殊编码类型的存储|压缩列表/整数集合整体转为字符串对象写入，读入时还原|
|数据库如何切换|通过 `SELECTDB` + `db_number`，读入后调用 `SELECT` 命令|
