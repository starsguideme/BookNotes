1. `WebSecurityConfigurerAdapter` 中的configure()方法 这个方法接受一个HTTPSecurity对象 能够用来配置在web上的安全问题 HTTPSecurity配置的功能包括:
   1.1 在为某个请求提供服务之前，需要预先满足特定的条件
   1..2 配置自定义的登录页；
   1.3 支持用户退出应用
   1.4 预防跨站的伪造请求
2. 何为保护请求: 只有在认证下的用户才能对被保护的对象方法才可以发起请求，但被保护的对象是无法被无认证的用户使用的，他们只能使用其他没被保护的方法.
3. 对于security这个框架来说，顺序很重要，比声明在前的安全规则要比后面声明的规则具有更高的优先级
4. 在web中，可以通过更改默认的成功页来对用户的请求方式进行更改，并且还可以强制用户进入某个界面，这个方式可以通过defaultSuccessUrl(`"/design",true`)的方式进行来实现
5. web端上的退出: 为了启用退出功能，只需要调用HTTPSecurity的logout方法 如果logout中的路径是("/")的形式 而不是其他的路径的话，那他只会重新打开这个界面 但会清除登录的session, 但如果方法里是其他路径 则会登录到其他界面中
6. 防止跨站的请求伪造：跨站请求伪造(CSRF)是一种常见的安全攻击，会让用户在一个恶意的web页面上填写信息，然后其以自动且秘密的方式将所填写的表单以攻击受害者的身份提交到另一个应用上，为了防止这种情况 Security通过CSRF token的方式，将其放到隐藏域且临时存储起来，以便后续在对比使用请求方法前会先拦截对比下token是否合理正确，如果正确则正常使用方法，否则会阻止该请求的使用.
7. 了解用户是谁: 要想了解用户是谁 通过以下的方式确认
   7.1 注入Principal 对象到控制器方法中;
   7.2 注入Authentication对象到控制器方法中
   7.3 使用SecurityContextHolder来获取安全上下文
   7.4 使用@AuthenticationPrincipal注解来标注方法
8. `@AuthenticationPrincipal`比`@Authentication` 的优势在于 不需要进行类型转换，且将安全相关的代码限制于注解本身
