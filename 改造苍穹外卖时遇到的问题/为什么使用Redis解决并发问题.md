
1. **核心原因**：MySQL 是磁盘型数据库，高并发下 IO 压力巨大，容易成为瓶颈。Redis 基于内存，读写极快，天然适合应对高并发。
    
2. **实现过程 (营业额统计)**：
    
    - 我先根据业务需求，在 Mapper.xml 中写好查营业额的 SQL 语句。
        
    - 在 Service 层，我先查 Redis 缓存。如果没有，就调 Mapper 查 MySQL，然后把结果存进 Redis。
        
    - **选型思考**：我用 Redis 的 **Hash 结构**来存，因为将来可能需要拓展统计字段，用 Hash 更新更方便，查询也是接近 O(1)。
        
3. **兜底策略**：我意识到数据不能一直留在内存里，就**设置了过期时间**来释放空间。同时，为了保证核心业务稳定，所有 Redis 读写操作我都加了 **try-catch**，万一 Redis 挂了，程序能自动降级查 MySQL，不会影响主流程。
