### 一、原子性

==**原子性**== 是指单次操作的完整性与正确性，即一个操作要么全部执行完毕，要么全部不执行，中间不会被其他线程插入操作。

`JMM` 通过以下机制保证原子性：

|机制|说明|
|---|---|
|==**8 种原子操作**==|JMM 定义的 lock、unlock、read、load、use、assign、store、write 操作本身具有原子性|
|==**`synchronized` 互斥锁**==|同一时刻只有一个线程能执行临界区代码，保证整个代码块的原子性|
|==**JUC 原子类（`AtomicInteger` 等）**==|通过 CAS 实现复合操作（如 `count++`）的原子性|
|==**`volatile` 的单次读写**==|`volatile` 保证单次读/写具有原子性，但**不能保证复合操作的原子性**|

### 二、可见性

==**可见性**== 是指当一个线程修改了共享变量的值时，其他线程能够立即得知这个值的修改。

`JMM` 通过以下机制保证可见性：

|机制|实现原理|
|---|---|
|==**`volatile`**==|通过内存屏障（StoreLoad 屏障）直接将数据刷新到主内存中，并使其他线程的工作内存中该变量的缓存副本失效|
|==**`synchronized`**==|释放锁时将工作内存中的修改刷新到主内存，获取锁时从主内存重新读取最新值|
|==**`final`**==|对象构造完成后，`final` 域的值对所有线程可见（前提是没有 this 逃逸）|

**关键区别**：`volatile` 变量与普通变量在可见性上的核心区别在于，`volatile` 由于存在内存屏障，可以**强制**将修改后的值立即刷新到主内存中，并让其他线程的缓存副本失效。普通变量没有这个保证，线程可能一直读到工作内存中的旧值。

### 三、有序性

==**有序性**== 是指程序按照代码的先后顺序执行，但可能会遇到编译器和处理器的重排序优化。

`JMM` 通过以下机制保证有序性：

| 机制                        | 实现原理                                                           |
| ------------------------- | -------------------------------------------------------------- |
| ==**`volatile`**==        | 通过插入内存屏障（StoreStore、StoreLoad、LoadLoad、LoadStore）来禁止特定类型的指令重排序 |
| ==**`synchronized`**==    | 通过"释放锁 happens-before 获取锁"的规则，保证临界区内的代码不会被重排序到临界区外             |
| ==**happens-before 规则**== | 通过八条 happens-before 规则，在更高层次上保证操作的执行顺序                         |

### 四、三大性质的实现机制总结

| 性质          | volatile       | synchronized             | JUC 原子类          | happens-before |
| ----------- | -------------- | ------------------------ | ---------------- | -------------- |
| ==**原子性**== | 单次读写保证，复合操作不保证 | ✅ 保证整个临界区                | ✅ 保证复合操作         | —              |
| ==**可见性**== | ✅ 通过内存屏障保证     | ✅ 通过锁释放-获取语义保证           | ✅ 通过 volatile 保证 | ✅ 通过规则保证       |
| ==**有序性**== | ✅ 通过内存屏障禁止重排序  | ✅ 通过 happens-before 规则保证 | —                | ✅ 通过规则保证       |

### 五、面试要点

| 问题                   | 回答                                                     |
| -------------------- | ------------------------------------------------------ |
| **JMM 有哪三大核心性质**         | ==**原子性、可见性、有序性**==                                    |
| **volatile 能保证原子性吗**     | 只保证单次读/写的原子性，**不能保证复合操作的原子性**                          |
| **volatile 如何保证可见性**     | 通过==**内存屏障**==将数据刷新到主内存，并使其他线程的缓存副本失效                  |
| **synchronized 如何保证有序性** | 通过"释放锁 happens-before 获取锁"的规则，禁止临界区内外重排序               |
| **三大性质各自的实现机制**          | 原子性靠锁和 CAS，可见性靠 volatile 和锁语义，有序性靠内存屏障和 happens-before |
