### 一、什么是非原子性协定？

JMM 要求八种内存交互操作（lock、unlock、read、load、use、assign、store、write）都具有原子性。但对 64 位的数据类型（long 和 double），JMM 允许虚拟机自己实现是否要保证 load、store、read 和 write 这四个核心操作的原子性需求。

这就是 long 和 double 的**非原子性协定**——JMM 不强制要求 64 位变量的单次读写操作具有原子性。原因是处理器可以将 64 位数据分成两个 32 位来执行，在某段时间内会执行一段 32 位。如果此时线程被挂起，数据可能处于一个"一半旧值、一半新值"的中间状态。

### 二、非原子性访问会导致什么问题？

如果在共享内存中有多个线程同时共享一个**没有被 volatile 修饰**的 long 或 double 类型的变量，并且同时对它们进行读写操作，那么某些线程就可能读到一个既不是原值、也不是经由其他线程完整修改后的数值。这个数值可以简单理解为在修改过程中某个特定时刻的中间值——比如高 32 位是新值，低 32 位还是旧值。

### 三、不同环境下的实际情况

|环境|情况|
|---|---|
|==**64 位 JVM**==|不会出现对非原子性数据执行访问的行为，因为 64 位处理器可以一次性完成 64 位数据的读写|
|==**32 位 JVM（X86）**==|有可能出现 long 类型的非原子性访问，因为 32 位处理器需要拆分成两个 32 位操作|
|==**double 类型**==|即是在 32 位 X86 下，由于有专门的浮点处理器支持，也依然不会产生非原子性访问的情况|

### 四、如何保证 64 位变量的原子性？

使用 ==**volatile**== 修饰 long 和 double 变量，可以保证即使在 32 位 JVM 上，64 位变量的单次读写操作也具有原子性。`volatile` 通过 Lock 前缀指令和缓存一致性协议，确保 64 位数据被一次性完整地写入或读取。
