

**`JVM` 视角下的 volatile 详解**

### 一、volatile 的两个核心特性

当一个变量被声明成 volatile 变量的时候，它会具有两个特性：

| 特性              | 说明                                                |
| --------------- | ------------------------------------------------- |
| ==**可见性**==     | 被 volatile 修饰的字段在共享内存中的所有线程互相可见，一个线程修改后，其他线程立即可见  |
| ==**禁止指令重排序**== | 通过自动添加的[[内存屏障]]（特别是 StoreLoad 屏障）来限制编译器和处理器的重排序优化 |

### 二、为什么 volatile 不能保证原子性？

详见[[volatile的特性]]，一个变量的复合操作可以被分成四个步骤，volatile 只保证单次读和单次写的原子性，无法保证整个复合操作不被中断。这也是为什么需要在多线程下使用 `synchronized` 与 `JUC` 下原子类的原因之一。

### 三、volatile 如何禁止指令重排序？

volatile 的第二个作用是通过自动添加的[[内存屏障]]中的 `StoreLoad` 屏障来达到限制重排序优化的功能。具体实现方式详见[[volatile内存语义的实现]]。

### 四、volatile 与 `JMM` 内存交互操作的关系

当被加上 volatile 的字段遇到[[内存间的交互操作]]中的一些操作时，会受到以下约束：

-   **Load 与 use 必须连用**：保证工作内存中的变量值始终是最新的。
-   **assign 与 store 必须连用**：保证每次修改都能立即同步回主内存。
-   **write 后必须触发后续的 Load**：形成完整的数据通路，保证可见性。
