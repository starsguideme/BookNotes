
### 一、什么是 happens-before 规则？

提及虚拟机视角下的 happens-before，首先就得了解什么是先行发生原则。这个我在[[happens-before的定义]]已经说明，其本质就是用来指定线程之间的有序性的一套规则。既然是规则就有其一套自己的规则，参考[[happens-before规则]]。

由于 happens-before 是 `JMM` 下的规则，而 `JMM` 只是一个规范，具体仍然由 `JVM` 实现。在 `JVM` 中具体实现的规则与 `JMM` 规范中的定义在**表述上**有所不同，但**本质上是同一套规则**——`JVM` 的实现严格遵循 `JMM` 规范的要求。

### 二、`JVM` 视角下的八条 happens-before 规则

| 规则 | 说明 |
|------|------|
| ==**程序次序规则**== | 在单个线程中，按照控制流顺序，书写在前面的操作 happens-before 后续的操作 |
| ==**管程锁定规则**== | 一个 unlock 操作 happens-before 后续对同一个锁的 lock 操作 |
| ==**volatile 变量规则**== | 对一个 volatile 域的写操作 happens-before 任意后续对这个 volatile 域的读操作 |
| ==**线程启动规则**== | 线程对象的 `start()` 方法 happens-before 此线程的每一个操作 |
| ==**线程终止规则**== | 线程中的所有操作 happens-before 对此线程的终止检测，可以通过 `join()` 和 `isAlive()` 方法来检测是否终止 |
| ==**线程中断规则**== | 对线程的 `interrupt()` 方法调用 happens-before 被中断线程检测到的中断事件 |
| ==**对象终结规则**== | 一个对象的初始化完成 happens-before 其 `finalize()` 方法的开始 |
| ==**传递性**== | 如果 A happens-before B，B happens-before C，则 A 一定 happens-before C |

### 三、程序次序规则与重排序的关系
**"程序次序规则要求书写在前面的操作先执行，可重排序不是会影响这个东西吗？"**

程序次序规则的正确理解是：**在单个线程中，按照控制流顺序，书写在前面的操作 happens-before 后续的操作。** 这里的"happens-before"并不意味着前面的操作必须在物理时间上先执行，而是指**前面操作的结果对后续操作可见**。

重排序确实可以改变指令的物理执行顺序，但有一个重要前提：**不能改变单线程程序的执行结果**。这就是 [[as-if-serial语义]]——无论怎么重排序，单线程程序的执行结果不能被改变。如果两个操作之间存在数据依赖关系，编译器和处理器就不会对它们进行重排序，因为这会改变执行结果。

举个例子：

```java
int a = 1;  // 操作 A
int b = 2;  // 操作 B
int c = a + b; // 操作 C
```

操作 A 和操作 B 之间没有数据依赖，可以被重排序。但操作 C 依赖于 A 和 B 的结果，所以 A 和 B 都必须 happens-before C。即使 A 和 B 被重排序，C 依然能看到 A 和 B 的结果——这就是程序次序规则在重排序存在时依然成立的保证。

### 四、时间上的先后 ≠ happens-before

由于时间上的优先不一定等于代码执行层面上的优先，所以在编码的时候一定要优先考虑先行发生原则。两个操作之间即使有时间上的先后顺序，如果没有 happens-before 关系，另一个线程也可能看到它们被重排序后的结果。

正确的并发编程方式是：**通过同步机制（volatile、synchronized、Lock 等）来建立 happens-before 关系，而不是依赖时间上的先后顺序。**

### 五、面试要点

| **问题**                         | 回答                                                                 |
| ------------------------------ | ------------------------------------------------------------------ |
| **happens-before 规则的本质**       | 用来指定线程之间的**有序性**的一套规则，保证前面操作的结果对后面操作可见                             |
| **程序次序规则和重排序矛盾吗**              | ==**不矛盾**==，happens-before 保证结果可见，重排序不能改变单线程的执行结果（as-if-serial 语义） |
| **时间上的先后能替代 happens-before 吗** | ==**不能**==，必须通过同步机制来建立 happens-before 关系                           |
| **happens-before 的核心规则有哪些**    | 程序次序、管程锁定、volatile、线程启动/终止/中断、对象终结、传递性                             |
