

**线程调度**

### 一、什么是线程调度？

线程调度的意思是系统为线程分配处理器使用权的过程，调度的方式主要分为两种：**协同式调度**与**抢占式调度**。

### 二、协同式调度

| 维度           | 说明                                          |
| ------------ | ------------------------------------------- |
| ==**核心机制**== | 线程的执行时间由线程本身来控制，当线程执行完工作之后，会主动通知系统切换到另一个线程上 |
| ==**优点**==   | 实现简单，切换操作可知，没有同步问题                          |
| ==**缺点**==   | 执行时间不可知，代码编写有误会导致系统直接阻塞                     |

**致命缺陷**：如果一个线程陷入死循环或长时间不主动让出 CPU，整个系统都会被阻塞，其他线程永远无法执行。

### 三、抢占式调度

| 维度 | 说明 |
|------|------|
| ==**核心机制**== | 每个线程将由系统来分配执行的时间，线程的切换不由其本身来控制 |
| ==**优点**== | 系统可控，不会产生由一个线程导致整个系统阻塞的问题 |
| ==**缺点**== | 实现复杂，存在同步问题 |

Java 的线程调度使用的就是**抢占式调度**，并且为此设置了 10 个级别的线程优先级。

### 四、Java 线程优先级

| 常量 | 数值 | 说明 |
|------|------|------|
| ==**`Thread.MIN_PRIORITY`**== | 1 | 最低优先级 |
| ==**`Thread.NORM_PRIORITY`**== | 5 | 默认优先级 |
| ==**`Thread.MAX_PRIORITY`**== | 10 | 最高优先级 |

**Java 线程优先级的五个特点**：

1.  **继承性**：子线程默认继承父线程的优先级。
2.  **平台依赖性**：优先级映射取决于操作系统，不同 OS 对优先级的支持不同。
3.  **不可靠性**：优先级并不是一个稳定的调节手段，在 Windows 系统上存在优先级提升机制，在 Linux 系统上则可能被完全忽略。
4.  **并非绝对优先**：优先级高的线程只是**获得 CPU 时间片的概率更大**，并不保证一定优先执行。
5.  **不能作为并发控制手段**：由于操作系统的优先级可能被私自改变，因此**不能**在实际过程中判断究竟是哪个线程会被优先执行。线程的并发控制应当使用 `synchronized`、`volatile`、`Lock` 等机制，而非依赖优先级。

### 五、协同式调度 vs 抢占式调度对比

| 维度 | 协同式调度 | 抢占式调度 |
|------|----------|----------|
| ==**控制权**== | 线程自己控制 | 操作系统控制 |
| ==**切换时机**== | 线程主动让出 | 时间片用完后系统强制切换 |
| ==**实现复杂度**== | 简单 | 复杂 |
| ==**稳定性**== | 低，一个线程出错会导致整个系统阻塞 | 高，系统可控 |
| ==**同步问题**== | 无 | 有，需要同步机制 |
| ==**代表**== | 早期 Windows 3.x、绿色线程 | Java HotSpot、现代操作系统 |

### 六、适用范围

**协同式调度的适用场景**：

| 适用场景 | 说明 |
|---------|------|
| ==**单线程或简单协作场景**== | 如早期单任务操作系统、简单的嵌入式系统，线程数量少，协作关系简单 |
| ==**特定性能优化场景**== | 在明确知道线程执行时间的场景下，可以减少操作系统调度开销 |

**抢占式调度的适用场景**：

| 适用场景              | 说明                                         |
| ----------------- | ------------------------------------------ |
| ==**通用多任务操作系统**== | 所有现代操作系统（Windows、Linux、macOS）都使用抢占式调度      |
| ==**Java 后端开发**== | HotSpot JVM 默认使用抢占式调度，所有 Java 线程都由操作系统统一调度 |
| ==**交互式应用**==     | 需要快速响应用户输入的场景，抢占式调度能保证响应线程及时获得 CPU         |
|                   |                                            |

### 七、面试要点

| 问题              | 回答                                      |
| --------------- | --------------------------------------- |
| **线程调度有哪两种方式**      | ==**协同式调度**==和==**抢占式调度**==             |
| **Java 使用哪种调度方式**   | ==**抢占式调度**==                           |
| **Java 线程优先级有几个级别** | **10 个级别**，从 1（MIN）到 10（MAX），默认 5（NORM） |
| **线程优先级能保证执行顺序吗**   | ==**不能**==，优先级只是增大获得 CPU 的概率，不能作为并发控制手段 |
| **为什么不能依赖优先级控制并发**  | 因为操作系统可能会私自改变优先级，不同平台的优先级映射也不同          |
