
### 一、六种状态的定义

在 Java 中一共定义了 6 种线程状态，在任意一个时间点中，一个线程只能有且只有其中的某个状态，并且可以通过特定的方法在不同状态之间互相转化。这六种状态分别是：

| 状态 | 对应 `Thread.State` | 说明 |
|------|-------------------|------|
| ==**新建（NEW）**== | `NEW` | 创建后尚未启动的线程，即 `new Thread()` 后、`start()` 之前 |
| ==**运行（RUNNABLE）**== | `RUNNABLE` | 对应操作系统线程状态中的 Running 和 Ready，可能正在执行，也可能正在等待被分配时间片 |
| ==**无限期等待（WAITING）**== | `WAITING` | 不会被分配处理器执行时间，必须被其他线程**显式通知**才能唤醒 |
| ==**限期等待（TIMED_WAITING）**== | `TIMED_WAITING` | 不会被分配处理器执行时间，但**不需要被显式通知**，等到特定时间后自动唤醒 |
| ==**阻塞（BLOCKED）**== | `BLOCKED` | 线程被**互斥锁**阻塞，等待进入 `synchronized` 同步块 |
| ==**结束（TERMINATED）**== | `TERMINATED` | 线程执行完毕，`run()` 方法返回 |

### 二、各状态触发条件

**进入 WAITING 状态**（无限期等待，必须被其他线程显式唤醒）：

| 方法                           | 说明                |
| ---------------------------- | ----------------- |
| **==`Object.wait()`==**      | 没有设置超时时间的等待方法     |
| **==`Thread.join()`==**      | 没有设置超时时间的 join 方法 |
| **==`LockSupport.park()`==** | 同步机制中的线程暂停方法      |

**进入 TIMED_WAITING 状态**（限期等待，时间到自动唤醒）：

| 方法 | 说明 |
|------|------|
| ==**`Thread.sleep(millis)`**== | 线程中的睡眠方法 |
| ==**`Object.wait(timeout)`**== | 设置了超时时间的 wait 方法 |
| ==**`Thread.join(timeout)`**== | 设置了超时时间的 join 方法 |
| ==**`LockSupport.parkNanos()` / `parkUntil()`**== | 同步机制中的限时暂停方法 |

### 三、BLOCKED 与 WAITING 的核心区别

| 维度 | BLOCKED | WAITING / TIMED_WAITING |
|------|---------|------------------------|
| ==**进入原因**== | 被**互斥锁**阻塞，等待进入 `synchronized` 同步块 | 线程**主动**让出 CPU，等待其他线程通知或等待超时 |
| ==**退出条件**== | 拿到锁后自动退出 | 需要 `notify()`/`notifyAll()` 唤醒，或超时到期 |
| ==**是否持有锁**== | 正在竞争锁，尚未持有 | 已经释放了持有的锁 |
| ==**典型方法**== | 等待进入 `synchronized` 块 | `wait()`、`join()`、`park()`、`sleep()` |

### 五、适用范围

| 状态                    | 适用场景                                    |
| --------------------- | --------------------------------------- |
| ==**NEW**==           | 线程对象创建但尚未启动，如预配置线程池参数后等待启动              |
| ==**RUNNABLE**==      | 线程正在执行或等待 CPU 调度，是所有活跃线程的常规状态           |
| ==**WAITING**==       | 生产者-消费者模式中消费者等待数据，或线程等待其他线程执行完毕（`join`） |
| ==**TIMED_WAITING**== | 带超时的等待场景，如超时获取锁、限时等待数据、线程休眠             |
| ==**BLOCKED**==       | 多个线程竞争 `synchronized` 锁，未拿到锁的线程进入此状态    |
| ==**TERMINATED**==    | 线程执行完毕，可用于 `join()` 检测线程是否完成            |

### 六、面试要点

| 问题                    | 回答                                                                |
| --------------------- | ----------------------------------------------------------------- |
| **Java 线程有几种状态**          | ==**6 种**==：NEW、RUNNABLE、WAITING、TIMED_WAITING、BLOCKED、TERMINATED |
| **BLOCKED 和 WAITING 的区别** | BLOCKED 是在**等锁**（被动阻塞），WAITING 是在**等通知**（主动等待）                    |
| **RUNNABLE 包含 OS 的哪两种状态** | Running（正在执行）和 Ready（就绪等待 CPU）                                    |
| **sleep() 和 wait() 的区别**  | sleep() 不释放锁，进入 TIMED_WAITING；wait() 释放锁，进入 WAITING               |
| **线程优先级能保证执行顺序吗**         | ==**不能**==，优先级只是增大获得 CPU 的概率                                      |
