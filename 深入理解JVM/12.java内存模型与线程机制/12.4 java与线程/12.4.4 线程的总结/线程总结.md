
**线程的核心特性总结**

### 一、线程的实现方式

线程的实现大致分为以下几种：

| 实现方式 | 模型 | 核心特点 |
|---------|------|---------|
| ==**[[内核线程的实现]]**== | 1:1 | 线程的使用完全由内核态提供，一个线程损坏不会影响其他线程，但开销大、容易资源浪费 |
| ==**[[用户线程的实现]]**== | 1:N | 早期使用，线程执行完全由用户自行选择，灵活高效、不需要系统支撑，但一个线程阻塞会导致整个系统阻塞 |
| ==**[[混合的实现]]**== | M:N | 结合内核线程与用户线程的优点，兼具高效与稳定，但实现复杂 |
| ==**[[Java线程的实现]]**== | 1:1（特殊） | 由早期的用户线程演变为现在的内核线程，不受限于 JVM 的限制，完全由操作系统管理，是目前主流平台常用的实现方式 |

### 二、线程调度的分类

[[线程调度的分类]]又可以分为以下两种：

| 调度方式 | 核心机制 | 优点 | 缺点 |
|---------|---------|------|------|
| ==**协同式调度（协程）**== | 由线程自行控制，执行完毕主动让出 CPU | 实现简单 | 一个线程阻塞会导致系统宕机，执行时间不可知 |
| ==**抢占式调度（常用）**== | 操作系统以时间片轮转方式执行线程调度，可设置优先级 | 运行时间可知，系统可控 | 实现复杂，有同步问题 |

### 三、线程的六种状态及其转换

在实际的线程运行中会有**六种状态**，但每次只能拥有一种状态，这些状态在一定条件下互相转换：

| 状态 | 说明 | 进入条件 |
|------|------|---------|
| ==**新建（NEW）**== | 线程对象创建后尚未启动 | `new Thread()` 后、`start()` 前 |
| ==**运行（RUNNABLE）**== | 正在执行或等待 CPU 调度 | `start()` 后，或从等待/阻塞状态被唤醒 |
| ==**无限期等待（WAITING）**== | 必须被其他线程显式唤醒 | `wait()`、`join()`、`park()` |
| ==**限期等待（TIMED_WAITING）**== | 超时后自动唤醒 | `sleep(timeout)`、`wait(timeout)`、`join(timeout)` |
| ==**阻塞（BLOCKED）**== | 等待获取互斥锁 | 等待进入 `synchronized` 同步块 |
| ==**结束（TERMINATED）**== | 线程执行完毕 | `run()` 方法返回 |

**关键区别**：

-   **有限等待 vs 无限等待**：区别在于**有无设置超时时间**。有限等待超时后自动唤醒，无限等待必须被显式唤醒。
-   **阻塞 vs 等待**：阻塞会使用**互斥锁**，处于 BLOCKED 状态的线程无论如何都不会被调用，要么等待拿到锁，要么被 `kill`。等待状态的线程则没有互斥锁的限制，可以被 `notify()`/`notifyAll()` 正常唤醒。

### 四、线程状态之间的配合

线程与线程之间的配合就是在这六种状态中完成的。而且根据 JVM 的规则来看，实际上运行情况应该远不止这么点——比如 RUNNABLE 状态在操作系统层面还细分为 Running（正在执行）和 Ready（就绪等待 CPU），WAITING 和 TIMED_WAITING 还会根据不同触发方法进入不同的等待队列。

### 五、适用范围

| 场景 | 推荐线程模型 | 说明 |
|------|------------|------|
| ==**Java 后端开发**== | 1:1 内核线程 | HotSpot 默认模型，稳定可靠，所有操作系统原生支持 |
| ==**高并发 I/O 密集型**== | 协程/纤程 | 如 Web 服务器、API 网关等海量短连接场景，协程能大幅降低线程切换开销 |
| ==**需要精细调度控制**== | 抢占式调度 + 优先级 | 需要对任务执行顺序进行细粒度控制的场景 |
| ==**简单嵌入式系统**== | 协同式调度 | 线程数量少，协作关系简单，实现成本低 |

### 六、面试要点

| 问题                    | 回答                                                            |
| --------------------- | ------------------------------------------------------------- |
| **线程实现有哪几种模型**            | ==**1:1 内核线程、1:N 用户线程、M:N 混合实现**==，Java HotSpot 使用 1:1 模型     |
| **线程调度有哪两种方式**            | ==**协同式调度**==和==**抢占式调度**==，Java 使用抢占式调度                      |
| **Java 线程有哪六种状态**         | ==**NEW、RUNNABLE、WAITING、TIMED_WAITING、BLOCKED、TERMINATED**== |
| **BLOCKED 和 WAITING 的区别** | BLOCKED 是在**等锁**（被动阻塞），WAITING 是在**等通知**（主动等待）                |
| **有限等待和无限等待的区别**          | 有限等待**设置了超时时间**，超时自动唤醒；无限等待**没有超时时间**，必须被显式唤醒                 |
