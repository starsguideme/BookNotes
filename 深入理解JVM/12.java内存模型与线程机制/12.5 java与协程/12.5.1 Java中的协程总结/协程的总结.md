

### 一、为什么需要协程？

因为内核线程模型本身具有一定致命性的局限性，可以参考[[内核线程的局限性]]。内核线程的创建、切换和销毁都需要在内核态完成，开销较大，且每个线程都需要消耗内核资源，导致系统能支持的线程总数有限。因此，Java 中引入了协程这一概念。

协程的全称叫作**协同式线程**，其不仅是一个轻量级的线程，且由用户态自行控制——等到结束调度时会通知其他线程进行下一步的资源调度。这是协程的核心作用。

### 二、协程调度开销的演进阶段

协程是由内核线程演变出来的一种轻量级线程，因此它也有开销上的调度问题。这种调度方式一共经历了以下三个阶段：

```text
用户线程（1:N，纯用户态调度，阻塞问题严重）
        ↓
内核线程（1:1，内核态调度，开销大）
        ↓
混合线程（M:N，用户态与内核态配合，兼顾高效与稳定）
```

现在的协程在资源调度的开销上变得很少（对比起内核线程来说），而且兼具了一些内核线程的优点。由于协程从早期用户线程上的难用，到内核线程上的复杂实现，再到现在轻量高效的特点，这种情况被叫做[[协程的复苏]]。

### 三、协程的分类

通过使用协程方式的不同，可以分为：

| 类型 | 特点 |
|------|------|
| ==**有栈协程**== | 拥有独立的调用栈，可以在任意嵌套函数中挂起和恢复 |
| ==**无栈协程**== | 不依赖独立栈，通过状态机实现，更轻量级 |

### 四、纤程：有栈协程中的特殊存在

在有栈协程中还有一种很特殊的存在，它是一种更加轻量级的线程，其名为**纤程**。纤程的核心作用之一是解决并发情况下降低单机执行线程延迟的问题。

纤程解决延迟的核心方式是将**执行线程与调度器进行分离**。一旦进行了分离，就可以在执行线程的情况下并行执行调度器的诸如上下文切换、寻址操作等，这就是纤程降低延迟的一种核心方式。

### 五、适用范围

| 场景 | 推荐方案 | 说明 |
|------|---------|------|
| ==**高并发 I/O 密集型**== | 协程/纤程 | 如 Web 服务器、API 网关等海量短连接场景，协程能大幅降低线程切换开销 |
| ==**需要精细调度控制**== | 纤程 | 执行过程与调度器分离，提供更灵活的任务编排能力 |
| ==**单机资源受限环境**== | 协程 | 在有限 CPU 核心上承载大量并发任务，充分利用单机资源 |
| ==**Java 后端开发**== | 虚拟线程（Project Loom） | Java 19+ 引入，本质是在 JVM 层面实现协程，兼顾开发效率与性能 |
