
### 一、什么是纤程？

在有栈协程中，有一种特例的实现叫做**纤程**。纤程的目的就是为了解决在并发下辅助虚拟机完成单机下的实现，可以有效降低多线程下的执行延迟。

### 二、纤程的核心设计：执行过程与调度器的分离

在新并发模型下，一段使用纤程的并发代码可以分为两个部分：

| 组成部分 | 职责 | 说明 |
|---------|------|------|
| ==**执行过程**== | 维护现场、保护上下文、恢复上下文状态 | 负责"做什么"——即具体的业务逻辑执行 |
| ==**调度器**== | 编排代码的执行顺序 | 负责"何时做"——即任务的分发和调度 |

**分离的核心优势**：将执行过程与调度器分离的好处在于，用户可以根据需要自行选择和控制其中的一个或多个调度器。同时，Java 中现有的调度器（如 `ForkJoinPool`）也可以被重用，作为纤程的底层调度器。

### 三、纤程要解决的问题

纤程的设计目标是在并发环境下辅助虚拟机完成单机下的实现，具体要解决以下问题：

| 问题 | 说明 |
|------|------|
| ==**减少内核线程的调度开销**== | 内核线程的上下文切换需要在内核态完成，开销较大。纤程的切换在用户态完成，无需系统调用 |
| ==**降低多线程下的执行延迟**== | 纤程通过用户态调度减少了不必要的线程阻塞，可以更细粒度地控制任务的执行顺序，降低延迟 |
| ==**提高单机资源利用率**== | 纤程可以在少量内核线程上承载大量并发任务，充分利用 CPU 资源，避免线程过多导致的资源浪费 |

### 四、纤程与协程的关系

```text
协程（Coroutine）
    ├── 有栈协程（Stackful Coroutine）
    │       └── 纤程（Fiber）← 一种特殊的有栈协程实现
    │
    └── 无栈协程（Stackless Coroutine）
```

纤程是**有栈协程的一种特例实现**，它拥有独立的调用栈，可以在任意嵌套函数中挂起和恢复。与一般有栈协程的区别在于，纤程特别强调**执行过程与调度器的分离**，并且可以与 Java 的 `ForkJoinPool` 等现有调度器深度集成。

### 五、适用范围

| 适用场景 | 说明 |
|---------|------|
| ==**高并发 I/O 密集型**== | 如 Web 服务器、API 网关等海量短连接场景，纤程能大幅降低线程切换开销 |
| ==**需要精细调度控制的任务**== | 需要对任务执行顺序进行细粒度控制的场景，纤程的执行-调度分离设计提供了灵活性 |
| ==**单机资源受限环境**== | 在有限的 CPU 核心上承载大量并发任务，纤程能充分利用单机资源 |

| 不适用场景 | 说明 |
|-----------|------|
| ==**CPU 密集型任务**== | 需要长时间占用 CPU 的计算任务，纤程的用户态调度优势不明显，反而增加了实现复杂度 |
| ==**已有成熟异步框架的场景**== | 如 Netty、Vert.x 等已提供完善的异步 I/O 支持，引入纤程可能增加不必要的复杂度 |

| **问题**          | 回答                                  |

| **纤程是什么**       | ==**有栈协程的一种特例实现**==，核心设计是执行过程与调度器分离 |
| **纤程解决什么问题**    | 减少内核线程调度开销，降低多线程执行延迟，提高单机资源利用率      |
| **纤程与协程的关系**    | 纤程是有栈协程的子集，特别强调执行过程与调度器的分离          |
| **Java 中纤程的实现** | Java 19+ 引入虚拟线程，其底层实现借鉴了纤程的设计思想     |
