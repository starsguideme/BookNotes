
**线程安全的五层模型**

### 一、什么是线程安全？

线程安全的含义指的是：当多个线程同时访问一个对象时，不用考虑其他事情，却依然可以得到相应正确的数据，这个叫做线程安全。

### 二、线程安全的五个层级

在 Java 中，根据安全程度从强到弱进行排序，我们可以将其分为五大类：

```text
不可变 > 绝对线程安全 > 相对线程安全 > 线程兼容 > 线程对立
   强                                             弱
```

#### 1. 不可变

**核心特征**：被 `final` 修饰的字段/方法对于多线程之间的调度时一定是可靠的。需要考虑[[final引用的规定]]中的具体规则。由于 `final` 字段的限制，一旦对象被生成，可见状态永不改变，因此数据永远不会发生不一致的情况，具有高可靠性。

**适用范围**：

-   `final` 字段的作用只适用于**基本数据类型**。
-   对于对象类型或引用类型的数据，由于 Java 中不存在这种限制手段，因此对象操作在 `final` 域中一般只能执行**读操作**或者是**创建一个新的对象**，只在新的对象中使用数据等不会改变原有状态的引用类型。
-   可以保证原有状态的方法还有很多种，如：API 调用、数值包装类以及枚举类等操作。

**`AtomicInteger` 和 `AtomicLong` 的特殊情况**：

虽然 `AtomicInteger` 和 `AtomicLong` 同为原子类，但它们是**可变的**。这是因为 `AtomicInteger` 和 `AtomicLong` 的内部使用了 `volatile` 来保证可见性的同时，使用了自旋 `CAS` 来完成原子性操作。这意味着虽然引用地址不可变，但它们的值确实可见且具有原子性。`final` 也只能确认在初始化时的不可变——它保证引用不被重新赋值，但无法阻止对象内部状态的变化。

#### 2. 绝对线程安全

**核心特征**：无论如何，在多线程下数据一定是安全可靠的。

**实际情况**：在实际中确实是不可能的。一旦在某些特定时间内删除了某个索引/数据的同时，下一个线程却正好访问到了这个索引，发现该索引不存在的话就会抛异常。为了解决这个异常就会带来更多的麻烦和资源开销，往往得不偿失。所以在 Java 的线程中一般**不存在绝对的线程安全**。

#### 3. 相对线程安全

**核心特征**：这是一般意义上的线程安全。它只需保证这个对象**单次的操作**是线程安全的，我们在调用时不需要有额外的保障措施。但在**连续调用**（迭代或递归下）可能就需要同步手段来保证数据的正确性。

**典型代表**：`Vector`、`Hashtable`、`StringBuffer` 等。它们的每个单独方法都是 `synchronized` 修饰的，单次调用安全，但多个方法组合使用时仍需外部同步。

#### 4. 线程兼容

**核心特征**：对象本身并不安全，可在调用时正确地使用同步方法来保证在多线程下可以被安全地使用。

**典型代表**：`ArrayList`、`HashMap` 等。它们本身不是线程安全的，但可以通过 `Collections.synchronizedList()` 或 `ConcurrentHashMap` 等方式包装后安全使用。

#### 5. 线程对立

**核心特征**：无论如何都无法保证数据在多线程下的安全性。由于 Java 的特性，这种代码不会经常出现，且应当**避免使用**。

**典型代表**：`Thread.suspend()` 和 `Thread.resume()` 等方法，已被标记为 `@Deprecated`。

### 三、五个层级对比

| 层级 | 安全程度 | 是否需要额外同步 | 典型代表 |
|------|---------|----------------|---------|
| ==**不可变**== | 最高 | 不需要 | `final` 基本数据类型、枚举类、数值包装类 |
| ==**绝对线程安全**== | 理论最高 | 不需要 | 实际中几乎不存在 |
| ==**相对线程安全**== | 较高 | 单次操作不需要，连续调用需要 | `Vector`、`Hashtable` |
| ==**线程兼容**== | 一般 | 需要外部同步 | `ArrayList`、`HashMap` |
| ==**线程对立**== | 无 | 无法保证 | `Thread.suspend()`、`Thread.resume()` |

### 四、适用范围

| 场景 | 推荐层级 | 说明 |
|------|---------|------|
| ==**配置信息、常量**== | 不可变 | 状态永不改变，天然线程安全 |
| ==**需要连续读写的共享变量**== | 相对线程安全 | 单次操作安全，连续调用时需额外同步 |
| ==**高并发读写**== | 相对线程安全 + JUC 工具类 | 使用 `ConcurrentHashMap`、`CopyOnWriteArrayList` 等 |
| ==**单线程环境**== | 线程兼容 | 不需要考虑线程安全，使用基础集合类即可 |
| ==**任何多线程环境**== | 避免线程对立 | 过时方法应立即替换 |

### 五、面试要点

| 问题                      | 回答                                              |
| ----------------------- | ----------------------------------------------- |
| **线程安全有几个层级**               | ==**五个**==：不可变、绝对线程安全、相对线程安全、线程兼容、线程对立          |
| **`final` 能保证线程安全吗**        | ==**能**==，但仅限于基本数据类型。引用类型的内部状态仍然可以改变            |
| **为什么不存在绝对线程安全**            | 因为连续调用场景下，删除索引/数据的操作和访问操作之间无法保证原子性              |
| **`Vector` 是绝对线程安全的吗**      | ==**不是**==，它是相对线程安全。单次操作安全，连续调用需要外部同步           |
| **`AtomicInteger` 是线程安全的吗** | ==**是**==，通过 `volatile` + `CAS` 实现线程安全，值可以原子地改变 |
