

**线程安全的其他实现方式**

### 一、三种线程安全实现方式总览

除了[[非阻塞同步]]与[[互斥同步]]外，还有一种保证线程安全的方式——本身就是线程安全的一些 API。这些 API 不涉及任何的数据共享，因此其也算是某种程度上的线程安全。

```text
线程安全的实现方式
├── 阻塞同步（互斥同步）：synchronized、ReentrantLock
├── 非阻塞同步（乐观锁）：CAS、AtomicInteger
└── 无同步方案（天然线程安全）：可重入代码、线程本地存储
```

### 二、可重入代码

可重入代码叫做**纯代码**，指的是可以在任何阶段下中断它，转而去执行另外一段代码（包括递归调用它本身），而在控制权返回后，原本的程序不会出现任何问题。这里的中断指的是多线程的上下文切换。

**可重入代码的特征**：

| 特征 | 说明 |
|------|------|
| ==**不依赖任何共享变量**== | 所有数据都是局部变量或参数，不涉及堆上的共享数据 |
| ==**不依赖系统资源**== | 不操作文件、网络连接等全局资源 |
| ==**不调用非可重入的方法**== | 调用的方法本身也必须是可重入的 |

**典型示例**：一个纯函数，只依赖传入的参数，不修改任何外部状态，天然就是线程安全的。`Math.max()`、`String.length()` 等都是可重入代码。

### 三、线程本地存储

如果一段代码中所需要的数据必须与其他代码共享，只要共享数据的代码在同一个线程中执行，这种方式也可以通过无同步机制下没有资源竞争的方式来实现线程安全。

这些方式一般以**消息队列中生产者与消费者的形式**来出现。每个消费者线程拥有自己独立的数据副本，生产者将数据分发到不同的线程，各线程之间没有共享数据，因此不需要同步。

在 Java 中：

-   如果一个变量要被多线程访问，可以使用 `volatile` 关键字将它声明为**易变的**（保证可见性）。
-   如果一个变量只要被某个线程独享，Java 中没有让你用 `Thread` 方式的关键字去修饰，但在 API 中则有着 **`java.lang.ThreadLocal`** 类来实现线程本地存储的功能。

**`ThreadLocal` 的实现原理**：每个线程内部维护了一个 `ThreadLocalMap`，Key 是 `ThreadLocal` 对象，Value 是用户设置的值。不同线程通过同一个 `ThreadLocal` 对象存取的数据彼此隔离，天然不存在竞争关系。

### 四、`ThreadLocal` 的注意事项

使用 `ThreadLocal` 时，需要注意**内存泄漏**问题。`ThreadLocalMap` 的 Entry 中，Key 是弱引用，Value 是强引用。当 `ThreadLocal` 对象在外部的强引用被清除后，GC 会回收 Key，但 Value 仍然存在强引用链。如果线程一直存活（如线程池线程），这些 Key 为 `null` 的 Value 就永远不会被回收。

**解决方案**：使用完毕后主动调用 **`remove()`** 方法，同时清理 Key 和 Value。

### 五、适用范围

| 场景 | 推荐方案 | 说明 |
|------|---------|------|
| ==**纯函数，不依赖外部状态**== | 可重入代码 | 天然线程安全，无需任何同步 |
| ==**线程独立的数据副本**== | 线程本地存储（`ThreadLocal`） | 如用户会话信息、数据库连接、事务上下文等 |
| ==**多线程共享变量**== | `volatile` 或锁 | 保证可见性和原子性 |
| ==**消息队列的消费者**== | 线程本地存储 | 每个消费者线程独立消费，无共享数据 |
