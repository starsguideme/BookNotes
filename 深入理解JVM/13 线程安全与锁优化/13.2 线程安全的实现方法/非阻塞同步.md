

**非阻塞同步**

### 一、什么是非阻塞同步？

在[[互斥同步]]中提到了资源的调度与开销在这种模式中是一个很大的挑战。互斥同步也被叫做**阻塞同步**，从解决方式的角度来看是一种**悲观锁**的机制，由此会经常性地导致用户态到内核态的角度切换。

为了避免资源的极大浪费，就诞生了另一种同步方式：**非阻塞同步**。这种同步方式的实现类似于一种**乐观锁**的策略机制。乐观锁的实现方式是通过不断的自旋直到没有任何的数据共享为止，由于此特性，这种实现同步的编码方式也叫做**无锁编程**。

### 二、互斥同步与非阻塞同步对比

| 维度 | 互斥同步（悲观锁） | 非阻塞同步（乐观锁） |
|------|------------------|-------------------|
| ==**核心思想**== | 先锁住资源，确保没有冲突再操作 | 先操作，没有冲突就成功，有冲突就重试 |
| ==**是否阻塞线程**== | 是，未获取锁的线程进入 BLOCKED 状态 | 否，线程不断自旋尝试，不阻塞 |
| ==**是否有上下文切换**== | 有（用户态 ↔ 内核态） | 无 |
| ==**适用场景**== | 锁竞争激烈，临界区执行时间长 | 锁竞争不激烈，临界区执行时间短 |

### 三、乐观锁的实现基础

乐观锁的实现主要是依靠**操作的原子性**与**冲突检测的原子性**来完成的。在硬件的角度上，只要满足**无论执行多少次命令，实际也只有一条命令在执行**的情况下，就完成了乐观锁的实现。

常见的乐观锁实现方式有：

| 实现方式 | 说明 |
|---------|------|
| ==**测试并设置（Test-and-Set）**== | 原子地测试一个内存位置的值，如果符合条件则设置新值 |
| ==**获取并增加（Fetch-and-Increment）**== | 原子地获取一个内存位置的值并增加 |
| ==**交换（Swap）**== | 原子地交换两个内存位置的值 |
| ==**[[CAS]]（Compare and Swap）**== | 比较并交换，现代处理器最常用的原子指令 |
| ==**加载链接/条件存储（Load-Linked/Store-Conditional）**== | LL/SC，另一种实现原子操作的方式 |

前三个实现一直存在，而后两个是随着架构的发展所诞生的新的两种实现方式。其中在 Java 中经常使用的是 **CAS**。

### 四、CAS 的工作原理

CAS 需要三个值：

| 操作数 | 含义 |
|--------|------|
| ==**V（内存位置）**== | 需要读取和修改的变量在内存中的地址 |
| ==**A（旧的预期值）**== | 执行 CAS 前，从 V 中读取到的值 |
| ==**B（新的值）**== | 希望写入 V 的新值 |

**执行逻辑**：只有当 V 的当前值等于 A 时，CAS 才会原子地将 V 的值更新为 B，否则不做任何操作。无论是否更新成功，CAS 都会返回 V 原有的值。

CAS 本质是一个实现策略，具体实现由 `incrementAndGet` 方法来实现，这个方法主要是通过**自旋**来实现的——循环调用 CAS 直到成功为止。

### 五、CAS 的 ABA 问题

尽管 CAS 简单高效，可并不能适用于所有情况。其存在经典的 **ABA 问题**：

**场景**：一个共享变量 V 的初始值为 A。
1.  线程 1 读取 V 的值为 A，准备修改为 C。
2.  在线程 1 执行 CAS 之前，线程 2 将 V 从 A 改为 B，又从 B 改回了 A。
3.  线程 1 执行 CAS 时，发现 V 仍然是 A，认为没有发生过变化，将 V 更新为 C。

虽然最终 V 的值是 C，但**中间发生了两次修改**，线程 1 完全没有感知到。

**解决方案**：通过**版本号**来解决 ABA 问题。`AtomicStampedReference` 在维护值的同时维护一个整数版本戳，每次更新时同时修改值和版本号。CAS 比较时同时检查值和版本戳，即使值相同，只要版本号不对，CAS 也会失败。

不过在实际应用中，一般情况下不如选择互斥同步的方式来实现同步需求——因为版本号机制实现复杂，且大部分场景下 ABA 问题不会造成实质性影响。

### 六、适用范围

| 场景 | 推荐方案 | 说明 |
|------|---------|------|
| ==**简单计数器/状态标志**== | CAS（`AtomicInteger` 等） | 竞争不激烈，临界区极短，CAS 性能远超锁 |
| ==**锁竞争不激烈**== | 非阻塞同步 | 线程不需要阻塞，避免上下文切换开销 |
| ==**锁竞争激烈或临界区较长**== | 互斥同步（`synchronized` / `ReentrantLock`） | CAS 自旋会浪费大量 CPU，此时让线程阻塞反而更划算 |
| ==**需要感知中间变化**== | `AtomicStampedReference` | 需要解决 ABA 问题的特殊场景 |

### 七、面试要点

| **问题**               | 回答                                             |
| ---------------- | ---------------------------------------------- |
| **非阻塞同步和互斥同步的区别**    | 互斥同步是悲观锁（先锁住资源），非阻塞同步是乐观锁（先操作，冲突再重试）           |
| **CAS 的三个操作数**       | ==**V（内存位置）、A（旧值）、B（新值）**==                    |
| **ABA 问题是什么**        | 值从 A 变 B 再变回 A，CAS 只比较值，检测不到中间变化               |
| **如何解决 ABA 问题**      | ==**版本号机制**==，`AtomicStampedReference` 通过版本戳解决 |
| **CAS 和互斥同步的使用场景区别** | 竞争不激烈用 CAS，竞争激烈或临界区长用互斥同步                      |
