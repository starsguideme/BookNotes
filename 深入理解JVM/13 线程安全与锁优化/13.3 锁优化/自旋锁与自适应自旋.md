

**自旋锁与自适应自旋锁**

### 一、为什么需要自旋锁？

互斥同步对性能影响的点在于**阻塞的实现**。不管是挂起线程还是恢复线程，都需要转入到内核态中完成，一旦转换就必然带来开销，也正因此会给 `JVM` 带来了很大的压力。

同时，由于大多数情况下锁存在的时间过于短暂，并且随着发展，使用多核处理器越发是常态。因此为了解决不必要的开销，只需要将线程执行一个**空循环**（忙等待），并这种方式叫做**自旋锁**。

### 二、自旋锁的演变

| 阶段                | 说明                                       |
| ----------------- | ---------------------------------------- |
| ==**JDK 1.4.2**== | 自旋锁概念出现，默认关闭，可通过参数 `-XX:+UseSpinning` 开启 |
| ==**JDK 6 及之后**== | 自旋锁**默认开启**                              |

**自旋锁的核心概念**：让某个线程在一段时间内进行自旋操作，在该操作进行时，不会有任何效果产生。这样的好处是在短时间内可以**减少不必要的上下文开销**，但坏处是时间一旦过长就会带来**性能的浪费**。

**自旋时间的控制**：

| 控制方式 | 说明 |
|---------|------|
| ==**超时时间**== | 自旋超过一定时间后仍未获取锁，则停止自旋，改为传统阻塞 |
| ==**旋转次数**== | 默认值一般是 10 次，可通过 `-XX:PreBlockSpin` 来更改次数 |

### 三、自适应自旋锁

虽然可以通过设置旋转次数来更改资源上的花销，但无论是默认值还是设置值，对线程锁来说效果都不够精确。为了解决不够精确的问题，在 Java 的 `JDK 6` 之后，就增加了能够**自适应的自旋锁**。

在这个锁面前，时间变得不再重要，因为它可以**根据实际线程获取锁的时间来自行判断是否需要自旋**。如果上一次自旋成功获取了锁，`JVM` 会认为这次也值得自旋，允许自旋等待更久；如果上一次自旋失败，`JVM` 会认为这次自旋的概率较低，可能直接进入阻塞。

这种机制可以有效避免处理器资源的浪费，并为虚拟机判断运行时间打下很好的基础。在如今阶段，随着监视器的不断升级，`JVM` 对锁的释放与获取判断已经越来越精确了。

### 四、自旋锁与自适应自旋锁对比

| 维度 | 自旋锁 | 自适应自旋锁 |
|------|--------|------------|
| ==**自旋次数**== | 固定（默认 10 次） | 动态调整，根据历史成功率决定 |
| ==**是否浪费 CPU**== | 可能（如果自旋失败） | 较少（根据实际情况自适应） |
| ==**引入版本**== | JDK 1.4.2 | JDK 6 |
| ==**使用场景**== | 锁竞争不激烈，锁持有时间极短 | 所有场景，JVM 自动判断 |

### 五、适用范围

| 场景 | 说明 |
|------|------|
| ==**锁持有时间极短**== | 自旋锁非常适合，自旋等待的开销远小于线程阻塞和唤醒的开销 |
| ==**多核处理器环境**== | 自旋锁在多核环境下效果更好，因为另一个线程可以在其他核心上执行 |
| ==**锁竞争不激烈**== | 自旋成功率较高时，自适应自旋锁会倾向于继续自旋 |
| ==**锁竞争激烈**== | 自适应自旋锁会自动缩短自旋次数，尽快转为阻塞，避免 CPU 空转 |

### 六、面试要点

| **问题**                | 回答                                      |
| --------------------- | --------------------------------------- |
| **为什么需要自旋锁**          | ==**避免线程阻塞和唤醒的上下文切换开销**==，适用于锁持有时间极短的场景 |
| **自旋锁的缺点**            | 如果自旋时间过长，会**浪费 CPU 资源**                 |
| **自适应自旋锁的优势**         | ==**根据历史成功率动态调整**==，不需要手动设置自旋次数         |
| **自适应自旋锁从哪个版本开始默认开启** | ==**JDK 6**==                           |
| **自旋次数默认是多少**         | ==**10 次**==，可通过 `-XX:PreBlockSpin` 调整  |
