
### 一、什么是锁消除？

锁消除指的是虚拟机在处理器执行**运行期**时，虽然要求一些程序保持同步，但如果判断某些锁是无效的，则进行删除的一种机制。这里的无效的锁指的是**没有任何资源竞争的线程锁**。

锁消除的方式主要是通过根据**逃逸分析**的数据支撑。如果判断出这段程序不会发生任何的逃逸情况且逃逸后无法被其他线程看见，那么就可以把它们当作栈上的数据，根据栈的特性导致其默认为**线程私有**的。也正因为线程是私有的，所以就不需要加锁了。因此`JVM` 会直接把这个锁消除掉，省去加锁和解锁的开销。

### 二、锁消除的典型场景

在实际使用过程中，有些方法虽然没有任何的显式同步语句，可由于其特性就导致了必定会出现类似于同步的情况。

**典型示例**：`StringBuffer` 的 `append()` 方法本身就是 `synchronized` 修饰的，但在以下场景中，`sb` 对象不会逃逸出当前线程，`JVM` 会认为这个锁是无效的，直接消除它：

```java
public String concat() {
    StringBuffer sb = new StringBuffer();  // sb 是局部变量，不会逃逸
    sb.append("hello");
    sb.append("world");
    return sb.toString();
}
```

在这个例子中，`sb` 对象只在当前方法内部使用，不会被其他线程访问。因此，`append()` 方法上的 `synchronized` 锁是多余的，`JVM` 会在运行时将其消除。

### 三、锁消除的前提条件

| 条件 | 说明 |
|------|------|
| ==**逃逸分析**== | JVM 必须开启逃逸分析（`-XX:+DoEscapeAnalysis`，默认开启），才能判断对象是否逃逸出当前线程 |
| ==**对象不会逃逸**== | 被锁保护的对象必须是局部变量，不会被其他线程访问 |
| ==**运行时判断**== | 锁消除是在 JIT 编译时进行的优化，不是静态分析 |

### 四、锁消除与[[锁粗化]]的区别

| 维度           | 锁消除          | 锁粗化          |
| ------------ | ------------ | ------------ |
| ==**优化方向**== | 消除无效的锁       | 合并多个相邻的锁操作   |
| ==**触发条件**== | 对象不会逃逸，锁没有竞争 | 频繁对同一个对象加锁解锁 |
| ==**效果**==   | 去除锁的开销       | 减少加锁解锁的次数    |

**锁粗化**：如果 `JVM` 发现同一个对象反复被加锁和解锁（比如在循环中），它会将加锁的范围粗化到整个操作序列的外部，减少加锁解锁的次数。

### 五、适用范围

| 场景 | 说明 |
|------|------|
| ==**局部变量使用线程安全类**== | 如 `StringBuffer`、`Vector` 等，但对象是局部变量，不会逃逸出当前线程 |
| ==**单线程环境下的同步代码**== | 代码本身没有多线程竞争，但由于使用了线程安全的类而存在隐式同步 |
| ==**需要手动开启逃逸分析**== | 确保 `-XX:+DoEscapeAnalysis` 是开启状态（JDK 6 之后默认开启） |
