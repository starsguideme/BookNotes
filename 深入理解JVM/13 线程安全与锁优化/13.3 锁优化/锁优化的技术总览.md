y### 一、锁优化技术总览

随着`JDK`的发展，逐渐出现了越来越多的锁优化手段，其中包括但不限于[[自旋锁与自适应自旋]]、[[适应锁的消除与粗化]]、[[轻量级锁]]和[[偏向锁]]等。

```text
JVM锁优化技术
├── 自旋锁与自适应自旋：避免线程阻塞和唤醒的上下文切换开销
├── 锁消除：基于逃逸分析，删除无效的同步锁
├── 锁粗化：合并相邻的锁操作，减少加锁解锁次数
├── 偏向锁：一个线程反复获取锁时，几乎零开销
└── 轻量级锁：两个线程交替执行时，通过CAS自旋避免阻塞
```

### 二、锁的升级路径

其中轻量级锁与偏向锁曾在并发编程的艺术中讲述过，它两的相同点在于都是依赖于**Mark Word**来实现的，并且轻量级锁是由偏向锁升级而来的。

**偏向锁**和**轻量级锁**的区别在于：偏向锁通过记录线程ID来避免`CAS`操作，当另一个线程竞争时撤销偏向锁。轻量级锁则比偏向锁多一个**自旋的`CAS`**来争抢线程资源——竞争线程在用户态自旋尝试获取锁，而不是立刻阻塞。当自旋的`CAS`始终无法获取到锁时，就会升级成**重量级锁**，线程进入BLOCKED状态，在Monitor的同步队列中等待。

```text
无锁 → 偏向锁（一个线程反复获取，几乎零开销）
          ↓ 另一个线程竞争，撤销偏向锁
       轻量级锁（两个线程交替执行，CAS自旋）
          ↓ 自旋超阈值，锁膨胀
       重量级锁（多个线程激烈竞争，线程阻塞等待）
```

### 三、锁优化技术对比

| 锁优化技术 | 核心思想 | 适用场景 | 开销 |
|-----------|---------|---------|------|
| ==**偏向锁**== | 记录偏向线程ID，同一线程再次获取时无需CAS | 只有一个线程反复访问同步块 | 几乎零开销 |
| ==**轻量级锁**== | CAS自旋获取锁，失败线程自旋等待 | 两个线程交替执行同步块 | 自旋消耗CPU，但避免上下文切换 |
| ==**重量级锁**== | 未获取锁的线程进入BLOCKED状态 | 多个线程激烈竞争 | 线程阻塞和唤醒涉及上下文切换 |
| ==**自旋锁**== | 线程在用户态自旋等待，不进入内核态阻塞 | 锁持有时间极短 | 自旋消耗CPU，但避免上下文切换 |
| ==**自适应自旋锁**== | 根据历史成功率动态调整自旋次数 | 所有场景，JVM自动判断 | 更精确地控制CPU消耗 |
| ==**锁消除**== | 基于逃逸分析删除无效锁 | 对象是局部变量，不会逃逸 | 消除不必要的同步开销 |
| ==**锁粗化**== | 合并相邻锁操作 | 频繁对同一个对象加锁解锁 | 减少加锁解锁次数 |

### 四、适用范围

| 场景 | 推荐优化 | 说明 |
|------|---------|------|
| ==**一个线程反复访问同步块**== | 偏向锁 | 几乎零开销，无需CAS操作 |
| ==**两个线程交替执行同步块**== | 轻量级锁 | CAS自旋避免线程阻塞，响应快 |
| ==**多个线程激烈竞争**== | 重量级锁 | 让等待线程阻塞，释放CPU资源 |
| ==**锁持有时间极短**== | 自旋锁/自适应自旋锁 | 自旋等待的开销小于线程阻塞的开销 |
| ==**局部变量使用线程安全类**== | 锁消除 | 对象不会逃逸，锁是无效的 |
| ==**循环内频繁加锁解锁**== | 锁粗化 | 减少加锁解锁的次数 |

### 五、面试要点

| 问题              | 回答                                       |
| --------------- | ---------------------------------------- |
| **JVM有哪些锁优化技术**     | ==**自旋锁、自适应自旋锁、锁消除、锁粗化、偏向锁、轻量级锁**==      |
| **偏向锁和轻量级锁的相同点**    | 都依赖于**Mark Word**来实现，都是`synchronized`的优化 |
| **偏向锁和轻量级锁的区别**     | 偏向锁记录线程ID避免CAS，轻量级锁通过**自旋CAS**争抢锁        |
| **轻量级锁什么时候升级为重量级锁** | ==**自旋CAS始终无法获取锁时**==，即自旋超阈值后锁膨胀         |
| **锁消除依赖什么技术**       | ==**逃逸分析**==，判断对象是否逃逸出当前线程               |
