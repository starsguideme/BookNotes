### 一、核心定位

堆是虚拟机所管理的内存中**最大**的一块。Java 堆是被**所有线程共享**的一块**内存区域**，在虚拟机启动时创建。此内存区域的唯一目的是**存放对象实例**——Java 世界里几乎所有的对象和数组都存储在堆区。

不过随着技术的发展，对象和数组并不完全存储在堆区了。逃逸分析和栈上分配等优化技术，使得某些对象可以在方法结束后自动销毁，无需 GC 介入，因此它们被分配在虚拟机栈上而非堆中。

由于 Java 的堆是垃圾收集器管理的内存区域，因此一些资料中也将其称为**GC 堆**。从回收内存的角度看，现代 GC 大部分基于**分代收集理论**设计，将堆分为新生代和老年代，以不同的策略回收不同生命周期的对象。

### 二、堆的内存分配

从分配内存的角度看，所有线程共享的 Java 堆中可以划分出多个**线程私有的分配缓冲区**（TLAB, Thread Local Allocation Buffer）。TLAB 的设计是为了提升对象分配的效率——**线程在自己的私有缓冲区中分配对象，无需加锁，只有缓冲区用完了才需要向共享堆区申请新的空间。**

由线程创建的所有对象都保存在堆区，这也是堆区唯一的存在目的。

### 三、堆的扩展与异常

目前在主流的 JVM 版本中，堆区是可以根据需求来实现扩展的（通过 `-Xms` 和 `-Xmx` 参数设置初始值和最大值）。但扩展取决于两个条件：

- **堆中是否还有空闲空间**：如果堆区中没有任何可回收的实例对象，且堆区无法再次扩展时，JVM 会抛出 `OutOfMemoryError` 异常。
    

### 四、面试要点

| 问题              | 回答                               |
| --------------- | -------------------------------- |
| **Java 堆的作用**   | ==**存放对象实例和数组**==，是所有线程共享的内存区域   |
| **为什么叫 GC 堆**   | 因为堆是垃圾收集器管理的内存区域，基于分代收集理论设计      |
| **TLAB 是什么**    | ==**线程私有的分配缓冲区**==，提升对象分配效率，避免加锁 |
| **什么情况下抛出 OOM** | 堆中没有可回收的对象，且无法继续扩展时              |
| **对象一定在堆上分配吗**  | 不一定，逃逸分析和栈上分配可能将对象分配在虚拟机栈上       |
|                 |                                  |
