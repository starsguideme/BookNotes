### 一、方法区到底是什么？

方法区与堆区一样，是各个线程共享的内存区域。它用于存储被 JVM 加载的类型信息、常量、静态变量、即时编译器编译的代码缓存等数据。

**为什么方法区又叫“非堆”？**

这两个概念是从不同维度说的。说它是“堆的逻辑部分”，是因为从内存管理上看，它和堆一样是线程共享的，都归 GC 管。把它叫做“非堆”，是为了让程序员知道：**它和堆不一样，别指望它能像堆一样频繁分配和回收对象。** 你平常 `new` 出来的对象全在堆里，方法区放的是类的结构信息，这些东西很少变动。所以“非堆”是为了告诉开发者：这两个区域虽然都是共享的，但用途和管理方式完全不同，需要分开配置内存参数。

### 二、永久代 vs 元空间

**永久代**是早期 HotSpot 对方法区的具体实现。GC 会回收永久代中不再需要的常量池和无用的类。但这里的回收条件极其苛刻，一不小心就容易导致内存泄漏，再加上永久代的内存上限是固定的，一旦加载的类太多（比如用了大量第三方框架），这块内存很容易溢出。

**元空间**是 JDK 8 之后取而代之的方案。它把存储位置从 JVM 内部挪到了**堆外内存**（直接内存），不再受 JVM 最大堆内存的限制。比如原来要设置 `-XX:PermSize` 和 `-XX:MaxPermSize`，现在这两个参数直接作废，改成了 `-XX:MetaspaceSize` 和 `-XX:MaxMetaspaceSize`。默认情况下，元空间会用多少就分配多少，只受限于当前可用的系统内存。

### 三、方法区的回收

虽然方法区在规范中不是必须实现 GC 的，但在现代 HotSpot 中，元空间里的**常量池和类元数据是会被回收的**。不过这些回收相当困难，因为需要判断一个类是否“不再被引用”远比判断一个堆上的对象复杂——你必须确保这个类的所有实例都已经被回收、加载这个类的 ClassLoader 已经被回收、这个类的 Class 对象没有在任何地方被引用。三个条件缺一不可，所以方法区的回收成功率远低于堆区。

### 四、面试要点

| 问题                 | 回答                                              |
| ------------------ | ----------------------------------------------- |
| **方法区是什么**         | 线程共享，存储类信息、常量、静态变量、JIT 编译的代码缓存                  |
| **为什么叫“非堆”**       | ==**用来和堆区分**==，用途和管理方式不同，需要分别配置内存               |
| **永久代和元空间的区别**     | 永久代在 JVM 内部，有固定上限，易 OOM；元空间在直接内存，受系统内存限制        |
| **JDK 8 之后永久代去哪了** | ==**被元空间取代**==，存储位置从 JVM 内部移到堆外直接内存             |
| **方法区的 GC 为什么困难**  | ==**需要同时满足三个条件**==：所有实例已回收、类加载器已回收、Class 对象无处引用 |
