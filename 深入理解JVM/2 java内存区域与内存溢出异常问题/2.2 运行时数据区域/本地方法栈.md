### 一、核心定位

本地方法栈与虚拟机栈所发挥的作用非常类似，其核心区别在于：

|栈类型|服务对象|说明|
|---|---|---|
|==**虚拟机栈**==|为 JVM 执行 **Java 方法**（字节码）服务|每个 Java 方法对应一个栈帧，入栈到出栈|
|==**本地方法栈**==|为 JVM 使用到的 **native 方法**服务|同样以栈帧为单位，管理 native 方法的调用与返回|

其他特点——如线程私有、生命周期与线程相同、可能抛出 `StackOverflowError` 和 `OutOfMemoryError`——均与虚拟机栈一样。

### 二、为什么需要本地方法栈？

JVM 本身也是用 C/C++ 写的，它需要调用操作系统底层的本地库来完成一些 Java 层面无法直接实现的操作——比如创建线程、文件 I/O、内存分配等。这些操作通过 `native` 方法调用底层实现。本地方法栈就是为这些 `native` 方法提供运行时栈空间的内存区域。

### 三、与虚拟机栈的对比

|维度|虚拟机栈|本地方法栈|
|---|---|---|
|服务对象|Java 方法（字节码）|native 方法（C/C++ 代码）|
|是否线程私有|是|是|
|可能抛出的异常|`StackOverflowError`、`OutOfMemoryError`|同左|
|栈帧存储内容|局部变量表、操作数栈、动态链接、方法出口|对应的本地方法调用信息|

### 四、面试要点

| 问题            | 回答                                                      |
| ------------- | ------------------------------------------------------- |
| **本地方法栈和虚拟机栈的区别** | 虚拟机栈为 Java 方法服务，本地方法栈为 native 方法服务，其他特性一致               |
| **什么时候用到本地方法栈**   | 调用 `native` 方法时，如 `Thread.start()` 底层调用 OS 创建线程         |
| **本地方法栈会抛异常吗**    | 会，和虚拟机栈一样可能抛出 `StackOverflowError` 和 `OutOfMemoryError` |
