### 一、核心定位

直接内存并非是`JVM`[[数据区域的划分与总结]]的一部分，也不是`JVM`规范中定义的内存区域。它是在`JDK` 1.4之后加入的`NIO`类中引入的一种基于**通道与缓冲区的I/O方式**。它可以使用**Native函数**直接在**堆外**进行内存分配，随后通过一个存储在堆区中的`DirectByteBuffer`对象来作为这块内存的操作引用，这个对象就是可直接使用的API。

### 二、为什么需要直接内存？

直接内存的核心优势是**避免了Java堆和Native堆之间的数据来回复制**。

在传统I/O中，当Java程序要读取文件时，数据需要从操作系统内核缓冲区先拷贝到Java堆中的缓冲区，然后才能被Java程序处理。这个过程涉及两次拷贝，以及用户态与内核态的频繁切换。而NIO使用直接内存后，数据可以直接从内核缓冲区写入堆外内存，Java程序通过`DirectByteBuffer`直接操作这块内存，省去了中间的拷贝环节，大幅降低了用户态与内核态之间的切换开销。

### 三、直接内存的限制

由于直接内存存在于Java堆之外，它不受`JVM`堆大小的限制（不归`-Xmx`管）。但它仍然是内存，一定会受到两个限制：

1. **本机总内存的大小**：直接内存的总量不能超过物理内存的容量。
    
2. **操作系统在时间片轮转和处理器寻址时的限制**：操作系统本身也需要内存来运行，直接内存分配过多会挤占OS自身的空间。
    

如果这些内存没有处理好，即直接内存加上`JVM`堆内存的总和超出了物理内存的限制，就会出现**`OutOfMemoryError`**异常。

### 四、面试要点

| 问题                   | 回答                                            |
| -------------------- | --------------------------------------------- |
| **直接内存属于JVM运行时数据区吗** | ==**不属于**==，它是JDK 1.4 NIO引入的堆外内存              |
| **直接内存有什么优势**        | ==**避免数据在Java堆和Native堆之间来回复制**==，减少用户态与内核态的切换 |
| **直接内存受什么限制**        | 受本机物理内存大小和操作系统自身内存需求的限制                       |
| **直接内存OOM和堆OOM的区别**  | 堆OOM是因为堆空间不足，直接内存OOM是因为==**物理内存被耗尽**==        |
