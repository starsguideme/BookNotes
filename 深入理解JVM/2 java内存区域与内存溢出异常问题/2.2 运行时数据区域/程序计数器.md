
### 一、核心定位

程序计数器是一块较小的内存空间，可以看作当前线程所执行的 Class 字节码的**行号指示器**。它负责控制程序的执行流程，支持分支、循环、跳转、异常处理和线程恢复等功能。

### 二、为什么程序计数器是线程私有的？

JVM 的多线程是通过线程轮流切换实现的，其切换方式依赖于操作系统的**时间片轮转**。在任何一个确定的时刻，一个处理器（一个内核）都只会执行一条线程中的指令。

==**线程切换后能继续正确执行，靠的不是自动加锁，而是程序计数器的值。**== `synchronized` 是程序员主动添加的同步机制，用于保证临界区的原子性。而线程切换后恢复到正确的断点继续执行，是 JVM 自动完成的——每个线程都有自己独立的程序计数器，记录当前线程执行到哪一行字节码。线程被挂起时，这个值被保存下来；线程恢复时，JVM 根据这个值继续从上次断点执行。这和 `synchronized` 是两套完全独立的机制。

==**每个线程都需要自己独立的计数器，相互不影响的同时独立存储。**== 这种线程独享的内存空间，被称为**线程私有**的内存。

### 三、为什么程序计数器只用内存，不使用外存？

程序计数器存储的是**当前正在执行的那一条指令的地址**。这个信息的特征决定了它只能放在内存中：

| 特征    | 内存                                  | 外存（硬盘）                   |
| ----- | ----------------------------------- | ------------------------ |
| **读写速度**  | 纳秒级                                 | 毫秒级（慢百万倍）                |
| **读写频率**  | 每条指令执行时都要读写                         | 无法承受如此高频的随机访问            |
| **持久化需求** | ==**不需要**==——线程执行时才有意义，线程结束后计数器自然销毁 | 持久化是对长期保存的数据，不是对"当前执行位置" |

==**程序计数器不需要持久化。**== 它只在线程活着的时候有意义，线程结束后这个值就作废了。把程序计数器放在硬盘上，就像把 CPU 的寄存器存在硬盘上——理论上可以，但会导致每条指令的执行都要等磁盘 IO，系统根本无法正常运行。

### 四、为什么执行 native 方法时计数器为空？

==**程序计数器记录的是 JVM 字节码指令的地址。**==

native 方法是 C/C++ 写的，它在 JVM 外部执行，不存在 JVM 字节码。如果程序计数器非要指向一个地方，它指向的是 JVM 内部的字节码指令空间，而 native 方法的代码在 JVM 外部的本地库中——==**JVM 的程序计数器根本无法指向它，也没有对应的字节码地址可以记录，所以置为空。**==

这并不意味着"没有对象、没有变量"，而是此时此刻执行的代码已经超出了 JVM 的管辖范围，计数器自然不需要工作。等到 native 方法执行完毕回到 Java 方法时，程序计数器会恢复为正常的字节码地址继续工作。

| 程序计数器的作用              | ==**记录当前线程正在执行的字节码指令地址**==，控制程序执行流程              |
| 为什么程序计数器是线程私有的        | 每个线程独立记录自己的执行位置，线程切换后能恢复到正确的断点                   |
