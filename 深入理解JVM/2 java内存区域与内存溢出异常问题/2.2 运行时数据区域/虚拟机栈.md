**虚拟机栈**

### 一、核心定位

与程序计数器一样，Java 的虚拟机栈也是**线程私有**的，它的生命周期与线程相同。虚拟机栈描述的是正在执行的 Java 方法的内存模型——==**JMM 的工作内存，在 JVM 中最重要的承载体就是虚拟机栈**==。

每个方法被执行的时候，JVM 会同步地创建一个**栈帧**，用于存储局部变量表、操作数栈、动态链接、方法出口等信息。每一个方法被调用到执行完毕的过程，就对应着一个栈帧在虚拟机栈中从入栈到出栈的过程。

### 二、你的三个追问

**1. 为什么是"栈帧"，而不是一个独立的小空间？**

==**因为方法的调用天然具有"先调用后返回"的 LIFO 特性。**==

方法 A 调用方法 B，B 执行完一定先返回 A，然后 A 才继续执行。这种嵌套调用关系，用**栈**来管理最自然——入栈对应方法调用，出栈对应方法返回。如果用独立空间（比如在堆上为每个方法单独分配一块内存），则需要额外的数据结构来维护方法之间的调用关系，而且方法返回后需要 GC 来回收这块空间——这比你直接用栈管理要复杂得多，开销也更大。

==**栈帧在栈上的分配和释放几乎是零成本的**==——入栈时移动一下栈顶指针，出栈时再移回去，不需要 GC 参与。这正是你说的"开销很大"问题的答案：用栈帧正是为了**避免**为每个方法单独开辟对象空间的高昂代价。

**2. 为什么要给操作数栈创建一个栈？**

==**操作数栈是字节码指令的执行引擎。**==

JVM 的字节码指令集是基于栈的，而不是基于寄存器的。比如执行 `1 + 2`，字节码会先把 `1` 压入操作数栈，再把 `2` 压入操作数栈，然后执行 `iadd` 指令（弹出两个操作数，相加后把结果压回栈顶）。操作数栈就是字节码指令的"工作台"，没有它，字节码指令无法完成任何计算。

**3. 局部变量槽是什么？**

==**局部变量槽（Slot）是局部变量表的最小存储单元，大小是 4 字节（32 位）。**==

它不是字节的存储空间，而是一个逻辑单元。JVM 规范规定每个 Slot 占 32 位，能存放 `boolean`、`byte`、`char`、`short`、`int`、`float`、`reference` 和 `returnAddress` 这 8 种类型。`long` 和 `double` 是 64 位的，所以占用两个 Slot。局部变量槽的大小在编译期就确定好了——方法中有多少个局部变量、每个变量的类型是什么，编译后是一目了然的，因此每个栈帧需要多大的局部变量表在编译期就能完全确定。

### 三、两种异常情况

| 异常 | 触发条件 |
|------|---------|
| ==**StackOverflowError**== | 线程请求的栈深度大于 JVM 允许的最大深度（如无限递归） |
| ==**OutOfMemoryError**== | JVM 的虚拟机栈在自动扩容时，无法向内存申请到足够的所需空间 |
