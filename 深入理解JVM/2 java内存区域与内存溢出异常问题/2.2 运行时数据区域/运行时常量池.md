### 一、什么是常量池？

常量池是 Class 文件（编译后的 `.class` 字节码文件）中的一个部分，它存放的是**编译期生成的各种字面量与符号引用**。字面量包括你在代码里写的字符串常量（如 `"hello"`）、被声明为 `final` 的常量值等；符号引用则包括类和接口的全限定名、字段的名称和描述符、方法的名称和描述符——这些信息在编译时只是一个符号，等到类加载时才被解析为真正的内存地址。

### 二、常量池与运行时常量池的关系

Class 文件中的常量池，在类加载完成后会被**搬进方法区**，变成**运行时常量池**。两者是"模板"与"运行时副本"的关系——Class 文件中的常量池是静态的模板，运行时常量池是这个模板在 JVM 内存中的动态存在形式。

### 三、运行时常量池的动态性

运行时常量池与 Class 文件常量池的一个重要区别在于：==**运行时常量池具有动态性**==。Class 文件中的常量池在编译期就确定好了，但运行时常量池可以在程序运行期间放入新的常量。这意味着，并非所有常量都必须在编译期就确定——程序在运行时也可以通过某些机制向常量池中添加新的内容。

最典型的例子是 `String` 类的 **`intern()`** 方法。当你调用 `str.intern()` 时，JVM 会把当前字符串对象的值放入运行时常量池中（如果池中还没有这个值）。这是运行时常量池动态性的最直接体现。

### 四、常量池的内存限制

由于运行时常量池是方法区的一部分，而方法区的内存是有限的，因此常量池也会受到方法区内存大小的限制。当运行时常量池中的常量过多，无法再申请到新的内存时，会抛出 `OutOfMemoryError`。在 JDK 8 之后，方法区的实现变为元空间，存储于堆外内存，受系统可用内存限制，可通过 `-XX:MetaspaceSize` 和 `-XX:MaxMetaspaceSize` 参数调整。

### 五、面试要点

| **问题**                    | 回答                                         |
| --------------------- | ------------------------------------------ |
| **常量池和运行时常量池的区别**         | 常量池在 Class 文件中，是静态模板；运行时常量池在方法区中，是运行时副本    |
| **为什么运行时常量池具有动态性**        | 因为不仅编译期产生的常量可以进入，运行时也可以通过 `intern()` 等方法添加 |
| **常量池的内存限制由谁决定**          | 受方法区限制，JDK 8 后由元空间大小决定                     |
| **`String.intern()` 的作用** | 将字符串值放入运行时常量池，如果池中已有则返回池中的引用，否则创建新常量并放入池中  |
