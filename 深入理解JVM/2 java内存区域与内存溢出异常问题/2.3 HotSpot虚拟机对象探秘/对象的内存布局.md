### 一、整体结构

在堆内存中，对象的存储空间可以划分为三个部分：

| 部分           | 说明                             |
| ------------ | ------------------------------ |
| ==**对象头**==  | 包含 Mark Word 和类型指针，数组对象还包含数组长度 |
| ==**实例数据**== | 对象中定义的成员变量，真正存储的有效信息           |
| ==**对齐填充**== | 保证对象大小是 8 字节的整数倍，起占位符作用        |

### 二、对象头的组成

对象头中又可以分为两部分：

**1. Mark Word（运行时数据）**

将哈希值、GC 分代年龄、锁状态等运行时数据存储在 Mark Word 中，32 位虚拟机中占 32 位（4 字节），64 位虚拟机中占 64 位（8 字节）。开发团队考虑到 JVM 的空间效率，Mark Word 被设计成一个**具有动态性的数据结构**，以方便在**很小的空间**内存储尽量多的数据，根据对象的状态复用自己的存储空间。

32 位 HotSpot 中 Mark Word 的状态变化如下：

|锁状态|23位|2位|4位|1位（偏向锁标志）|2位（锁标志位）|
|---|---|---|---|---|---|
|==**无锁**==|对象的 HashCode（25位中的23位，其余2位分散）|—|对象分代年龄|0|01|
|==**偏向锁**==|线程 ID（23位）|Epoch（2位）|对象分代年龄|1|01|
|==**轻量级锁**==|指向线程栈中 Lock Record 的指针（前30位）|—|—|—|00|
|==**重量级锁**==|指向 Monitor 的指针（前30位）|—|—|—|10|
|==**GC 标记**==|空|—|—|—|11|

==**锁标志位记录的是 `synchronized` 的锁状态**==——无锁、偏向锁、轻量级锁、重量级锁。`synchronized` 的锁升级过程就是通过修改 Mark Word 中的锁标志位来实现的。而 **`volatile` 不修改 Mark Word**，`volatile` 的可见性是通过内存屏障在编译层面实现的，不涉及对象头的锁状态变化。

**2. 类型指针**

类型指针是对象指向它的数据类型元数据的指针，JVM 通过这个指针来确定对象是哪个类的实例。但并不是所有虚拟机的实现都在数据存储上保留了类型指针，因为某些数据信息可以通过其他方式间接确定对象的类型。

如果对象是某个数组，那么对象头还需要使用额外的空间来保存数组的长度。如果不用空间来保存数组的长度，则无法通过元数据来推断数组的大小——因为数组的元素数量是运行时动态确定的，无法从类元数据中推导。

### 三、实例数据

实例数据是对象真正存储的有效信息，即我们在程序代码里面所定义的各种类型的字段内容，无论是父类继承的还是子类中创建的。

这部分数据在存储的时候会受到 JVM 内存分配时的影响，影响顺序大致有两点：

- **相同宽度的字段会放在一起**：比如 `long` 和 `double`（8 字节）放在一起，`int` 和 `float`（4 字节）放在一起。
    
- **在满足条件的前提下，父类的变量会在子类之前**：但这并不是固定的，可以通过 JVM 参数让子类中占用字节较短的数据存放在父类与子类的中间，以减少内存碎片。
    

### 四、对齐填充

对齐填充并非天然存在，也没什么实际意义，只是起到了**占位符**的作用。HotSpot 虚拟机的自动内存管理系统要求对象起始地址必须是 8 字节的整数倍，因此如果对象实例数据部分没有对齐到 8 字节的倍数，就需要通过对齐填充来补全。对齐填充的存在也使得压缩指针技术能更高效地工作——因为对齐后的地址低位总是 0，可以用更少的位数来表示更多的地址空间。

### 五、面试要点

| **问题**                       | 回答                                              |
| ---------------------------- | ----------------------------------------------- |
| **对象内存布局分几部分**               | ==**对象头、实例数据、对齐填充**==                           |
| **Mark Word 为什么设计成动态的**      | 在很小的空间内存储尽量多的数据，根据对象状态复用自己的存储空间                 |
| **锁标志位记录什么**                 | 记录 ==**`synchronized` 的锁状态**==，无锁/偏向锁/轻量级锁/重量级锁 |
| **volatile 会修改 Mark Word 吗** | ==**不会**==，volatile 通过内存屏障保证可见性，不涉及对象头锁状态变化     |
| **数组对象头有什么特殊**               | 需要额外空间保存数组长度，因为数组大小无法从元数据推断                     |
| **对齐填充的作用**                  | 保证对象大小是 8 字节的整数倍，便于内存管理和压缩指针                    |
| **实例数据的排列规则**                | 相同宽度字段放一起，父类变量在子类之前（可通过参数调整                     |
