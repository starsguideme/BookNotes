### 一、类加载检查

当使用 `new` 关键字创建一个对象时，首先会去检查这个指令的参数是否能在常量池中找到对应的符号引用，并且检查这个符号所代表的类是否已经被加载、解析和初始化过。如果没有，会先执行相应的类加载过程。

### 二、分配内存

当类被加载且没发现任何问题之后，接下来虚拟机为新创建的对象分配内存。Java 的对象一般存放在[[堆区]]上，当类加载执行完之后就可以确认该对象需要的内存空间大致是多少。

在具体分配对象时，先根据计算得出大致需要多少内存，然后开辟内存空间，最后放入这个对象。在开辟空间的过程中，内存会被分为三块：

- **被使用过的内存**
    
- **空闲的内存**
    
- **一个指针作为分界点的指示器**
    

分成这三块之后有个好处：当有新的对象被分配空间时，只需要移动指示器就可以为其分配空间。这种方式被叫做**指针碰撞**。

当内存空间一旦乱序，即已使用和未使用的空间交错分布时，虚拟机就会采用另一种方法——创建一个名为**空闲列表**的列表结构，这个列表中存放可用的空闲内存块。这两种方法由 GC 是否存在**空间压缩整理**的能力决定：

|GC 是否有压缩能力|堆中空间状态|采用的分配方式|
|---|---|---|
|==**有**==（如 Serial、Parallel）|完整且连续|==**指针碰撞**==（简单高效）|
|==**无**==（如 CMS）|碎片化、不连续|==**空闲列表**==（灵活但复杂）|

### 三、并发安全的处理

对象的创建在 JVM 中是非常频繁的一件事，所以哪怕只是修改一个指针所指向的位置，在多线程下也并非是安全的。因为根据操作系统的**时间片轮转**方式，线程可能在执行分配的过程中意外中断——如果线程 A 刚移动指针但还没完成对象的写入就被挂起，线程 B 此时恰好读取了这个指针并获得错误的数据，就会带来数据不一致的问题。

为了解决这个问题，开发团队提供了两种方案：

| 方案                      | 实现方式                                                            | 说明                            |
| ----------------------- | --------------------------------------------------------------- | ----------------------------- |
| ==**[[CAS]] + 失败重试**==  | 对分配内存空间的动作执行同步处理，采用**自旋 CAS** 配合失败重试来保证更新操作的原子性                 | **本质上就是循环 CAS 直到成功**          |
| ==**本地线程分配缓冲区（TLAB）**== | 把内存分配的动作按线程划分在不同的空间中执行，即每个线程在堆区中预先分配一块**私有**的缓冲区，在该缓冲区内分配对象无需加锁 | 只有当 TLAB 用完时才需要新的同步锁定来分配新的缓冲区 |

是否使用 TLAB 以及 TLAB 的大小，可以通过 JVM 参数进行调整。

### 四、初始化零值

等待内存分配完之后，JVM 会将分配到的内存空间（不包括对象头）都初始化为**零值或 NULL**。如果此时使用了 TLAB，初始化的工作会被安排在 TLAB 分配时一并执行。

这种操作保证了对象的实例字段在代码中可以不初始化仍然访问其值（虽然是 0 或 NULL），而不是抛出异常导致程序的意外终止。

### 五、设置对象头

除了执行将值设置为 0 或 NULL 的工作外，根据需求，JVM 也会将对象的所属类、类的元数据、对象的哈希值、对象的 GC 分代年龄等信息存入[[Java 对象头]]**中。这一系列的操作会根据虚拟机的当前状态不同而有着不同的参数，如是否使用了锁、volatile 等关键字。

### 六、执行 `<init>` 方法

当以上步骤彻底执行完之后，从 JVM 的视角来看，一个新的对象已经被创建完毕。但从 Java 的视角来看，虽然对象已经被创建完毕，可类的初始化却未开始——构造函数还没有执行。

此时 JVM 会执行 `<init>` 方法（即构造函数），按照程序员的意愿对对象进行真正的初始化。类的创建会经历五个阶段，这在[[java中的类与接口的初始化]]时已经被讲述过了。

当执行完以上所有步骤之后，真正可被调用的对象才会被完整地构造出来。

### 七、完整流程总结


**① 类加载检查 → 检查常量池中的符号引用，确保类已被加载、解析、初始化**
        **↓**
**② 分配内存 → 根据 GC 是否有压缩能力，选择指针碰撞或空闲列表**
        **↓**
**③ 并发安全 → CAS + 失败重试 或 TLAB 保证多线程下对象分配的线程安全**
        **↓**
**④ 初始化零值 → 将分配的内存空间（不包括对象头）初始化为零值或 NULL**
        **↓**
**⑤ 设置对象头 → 存储类元数据、哈希值、GC 分代年龄、锁状态等信息**
        **↓**
**⑥ 执行 <`init`> → 调用构造函数，按程序员的意愿进行真正的初始化**
        **↓**
**对象创建完成，可被正常使用**

### 八、面试要点

| 问题               | 回答                                         |
| ---------------- | ------------------------------------------ |
| **对象创建的主要步骤**    | 类加载检查 → 分配内存 → 初始化零值 → 设置对象头 → 执行 `<init>` |
| **指针碰撞和空闲列表的区别** | 指针碰撞用于内存规整时，移动指针即可；空闲列表用于内存碎片化时，维护可用空间列表   |
| **TLAB 的作用**     | ==**线程私有的分配缓冲区**==，避免多线程下对象分配的锁竞争          |
| **为什么要初始化零值**    | 保证实例字段在未初始化时也能被访问，返回默认值而非抛出异常              |
| **对象头存储什么信息**    | 类元数据、哈希值、GC 分代年龄、锁状态标志等                    |
