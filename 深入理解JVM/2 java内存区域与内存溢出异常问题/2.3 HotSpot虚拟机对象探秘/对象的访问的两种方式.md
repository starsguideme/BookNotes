### 一、问题的本质

JVM 通过栈上的 `reference` 类型来操作堆区上的具体对象。`reference` 类型只存在指向对象引用这一个作用，所有对象访问均由 JVM 来完成，并为此产生了两种访问方式：**句柄访问**和**直接指针访问**。

### 二、句柄访问

句柄访问将堆区中的内存空间划分出一块可用内存来作为**句柄池**。`reference` 数据中存储的是对象的句柄地址，而在句柄中包含了对象的实际数据地址与类型数据的具体地址。

当需要修改对象与数据类型的具体地址时，只需要修改句柄池中的指针地址，`reference` 本身不需要变动。这样有个好处就是**降低了 GC 的实现复杂度**——GC 移动对象时不需要遍历所有线程的栈帧来更新引用。但在访问对象实例的时候，需要先访问这个句柄地址，再通过句柄地址去访问实际地址，相当于**两次寻址**。

### 三、直接指针访问

直接指针访问直接在堆区中的对象实例数据中放置访问类型的具体地址（即对象头中的类型指针）。此时 `reference` 存储的就是对象的实际地址。当线程执行访问对象这个操作时，只需要访问这个实际地址即可访问到对象。

同样的，直接指针访问也有其缺点：**高额的 GC 成本**。当 GC 移动对象时，必须找到所有指向该对象的引用并更新它们的地址，这需要更复杂的 GC 实现。

### 四、两者的对比

|维度|句柄访问|直接指针访问|
|---|---|---|
|访问对象次数|==**两次寻址**==（先找句柄池，再找实例数据）|==**一次寻址**==（直接找实例数据）|
|GC 实现复杂度|**低**（只需修改句柄池中的指针）|**高**（需遍历所有引用并更新地址）|
|reference 存储|句柄地址|对象实际地址|
|代表虚拟机|早期的 JVM 实现|==**HotSpot**==（当前主流）|

### 五、为什么 HotSpot 选择直接指针？

由于现实中，访问对象的频率要远高于 GC 移动对象的频率，所以一般使用的都是**直接指针访问**。牺牲一点 GC 时的便利性，换取每次对象访问时的性能提升，从整体来看是更划算的选择。HotSpot 采用直接指针访问，配合 TLAB（线程本地分配缓冲区）和压缩指针等优化技术，将直接指针的优势发挥到极致。
