### 一、堆溢出异常的产生

堆用于存储对象实例，随着对象的逐渐变多且 `GC` **回收速度不如创建速度时**，在堆区就会抛出 `OutOfMemoryError` 异常。要解决这个问题，常见的方法是通过内存映像分析工具对 Dump 出来的堆转储快照进行分析。

### 二、排查第一步：确认是内存泄漏还是内存溢出

第一步首先应确认内存中导致内存溢出的对象是否必须存在，这一步是为了确定到底是**内存泄漏**还是**内存溢出**。

| 情况 | 判定标准 | 处理方向 |
|------|---------|---------|
| ==**内存泄漏**== | 对象已不再被使用，但 GC 无法回收 | 通过工具查看泄漏对象到 GC Roots 的引用链，找到泄漏的根源 |
| ==**内存溢出**== | 对象确实必须存活 | 调大堆内存参数（`-Xmx`），优化数据结构，减少对象占用 |

**内存泄漏**是指那些本应该被 GC 回收的对象，因为被某些长生命周期的对象无意中持有引用而无法回收。**内存溢出**则是对象确实都是必要的，只是堆内存确实不够用了。

### 三、内存泄漏的排查

当确定是内存泄漏时，可以通过工具来查看泄漏对象到 `GC` Roots 的引用链。这个引用链会告诉你：这个对象被谁持有、为什么 `GC` 无法回收它。找到引用链之后，就能定位到具体代码位置——比如某个静态集合类不断往里面放对象却从未清理，或者某个监听器注册后忘记注销。

常见的排查工具包括 Eclipse Memory Analyzer（MAT）、JProfiler、JVisualVM 等。

### 四、内存溢出的解决

如果确定是内存溢出（对象都是必要的），解决方案包括：

| 方案 | 说明 |
|------|------|
| ==**调大堆内存**== | 增加 `-Xmx` 参数，给 JVM 分配更大的堆空间 |
| ==**优化数据结构**== | 减少单个对象的占用空间，使用更紧凑的数据结构 |
| ==**引入缓存淘汰**== | 对缓存中的数据设置过期时间或淘汰策略，避免无限增长 |
| ==**分批处理**== | 将一次性加载大量数据的操作改为分页或分批处理 |

### 五、面试要点

| 问题             | 回答                                     |
| -------------- | -------------------------------------- |
| **堆 OOM 排查第一步做什么** | ==**区分是内存泄漏还是内存溢出**==                  |
| **内存泄漏怎么排查**       | 通过 MAT 等工具查看泄漏对象到 GC Roots 的引用链，定位泄漏根源 |
| **内存溢出怎么解决**       | 调大 `-Xmx`、优化数据结构、引入缓存淘汰、分批处理           |
| **内存泄漏的常见原因**      | 静态集合类无限增长、监听器未注销、连接未关闭、ThreadLocal 未清理 |
