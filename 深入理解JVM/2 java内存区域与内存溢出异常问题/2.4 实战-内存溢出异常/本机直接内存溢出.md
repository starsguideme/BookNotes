### 一、[[直接内存]]的容量设置

直接内存的容量可以通过 ==**`-XX:MaxDirectMemorySize`**== 这个参数来设置。如果不设置，默认与 Java 堆的最大值（`-Xmx`）一致。

### 二、`DirectByteBuffer` 与 `Unsafe` 分配的区别

直接内存的分配通常在 Java 中有两种方式：

| 分配方式                              | 异常处理                                                              | 底层方法                           |
| --------------------------------- | ----------------------------------------------------------------- | ------------------------------ |
| ==**`DirectByteBuffer`**==        | 在分配前会**先检查**是否有足够的直接内存空间，如果不足则抛出 `OutOfMemoryError`               | 内部调用 `Unsafe.allocateMemory()` |
| ==**`Unsafe.allocateMemory()`**== | **不做检查**，直接向操作系统申请内存。如果申请失败，操作系统会返回错误，JVM 随后抛出 `OutOfMemoryError` | `Unsafe.allocateMemory()`      |

**关键区别**：`DirectByteBuffer` 在分配内存之前，会通过计算得知这部分内存是否可以被申请到。如果剩余直接内存不足，它会**手动抛出异常**，而不是真正去调用 `Unsafe.allocateMemory()` 后再失败。这是一种"预检查"机制，避免了不必要的系统调用。

而直接使用 `Unsafe.allocateMemory()` 分配内存时，不会有这种预检查——它直接向操作系统要内存，申请失败后由 JVM 抛出 `OutOfMemoryError`。

### 三、如何获取 `Unsafe` 实例

由于 `Unsafe` 类是 JDK 内部使用的，不能直接通过 `new` 创建，只能通过反射获取其实例：

java

Field field = Unsafe.class.getDeclaredField("theUnsafe");
field.setAccessible(true);
Unsafe unsafe = (Unsafe) field.get(null);

获取到 `Unsafe` 实例后，就可以调用 `unsafe.allocateMemory(size)` 来分配直接内存。

### 四、直接内存溢出的排查特点

在直接内存中出现的内存溢出有个明显特征：在 Heap Dump 文件中不会看见有什么明显的异常情况。如果抛出异常时发现 Dump 文件很小，同时程序中直接或间接地使用了 NIO 的 `DirectByteBuffer` 或调用了 `Unsafe.allocateMemory()`，就可以考虑到是不是直接内存出现了问题。

排查思路：直接内存溢出时，堆内存可能还有很多空闲，所以 Heap Dump 文件不大。重点检查程序中对直接内存的使用——NIO 的 `ByteBuffer.allocateDirect()`、Netty 的 `PooledByteBufAllocator`、以及任何通过反射调用 `Unsafe.allocateMemory()` 的代码。

### 五、面试要点

| **问题**                                         | 回答                                                                   |
| ------------------------------------------ | -------------------------------------------------------------------- |
| **直接内存的容量如何设置**                                | ==**`-XX:MaxDirectMemorySize`**==，默认与 `-Xmx` 一致                      |
| **`DirectByteBuffer` 和 `Unsafe` 分配内存的区别**      | `DirectByteBuffer` 有预检查机制，发现不足时手动抛异常；`Unsafe` 直接向 OS 申请，失败后由 JVM 抛异常 |
| **如何获取 `Unsafe` 实例**                           | 通过反射获取 `theUnsafe` 字段                                                |
| **为什么要用 `DirectByteBuffer` 而不是直接 `Unsafe` 分配** | `DirectByteBuffer` 提供了内存预检查、自动回收、更安全的 API，适合大多数场景                    |
| **直接内存 OOM 的排查特点**                             | ==**Heap Dump 文件很小**==，无明显异常对象，需重点排查 NIO 的直接内存使用                     |
