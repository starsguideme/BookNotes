
**虚拟机栈与本地方法栈的异常**

### 一、`HotSpot` 的不区分设计

由于 `HotSpot` 虚拟机中并**不区分虚拟机栈和本地方法栈**，所以它们遇到的异常都是一样的，大致分为以下两点：

| 异常类型 | 触发条件 | 说明 |
|---------|---------|------|
| ==**StackOverflowError**== | 栈深度大于虚拟机所允许的最大深度 | 如无限递归调用，每个方法对应一个栈帧，栈帧数量超出栈深度限制 |
| ==**OutOfMemoryError**== | 栈内存无法申请到足够的内存 | 如线程过多，每个线程都需要独立的栈空间，总内存耗尽 |

### 二、为什么默认情况下只会出现栈深度溢出？

默认下 `HotSpot` 虚拟机的选择是**不支持动态扩展内存**的——每个线程的栈容量在创建时就固定下来（可通过 `-Xss` 参数设置）。除非在一开始创建时就因分配的空间不够导致抛出 `OutOfMemoryError`，否则在线程运行时不会因为扩展而导致内存溢出。

因此，在默认配置下，线程运行时只会因为**栈容量无法容纳新的栈帧**而导致 `StackOverflowError`，而不是 `OutOfMemoryError`。只有在极端情况下——比如创建了成千上万个线程，每个线程的栈空间加起来超出了物理内存——才会触发 `OutOfMemoryError`。

### 三、为什么大的栈帧更容易 `OOM`？

由于虚拟机栈和本地方法栈都是存在于操作系统中的内存空间里的，如果对应栈里的栈帧产生了过大的分配空间——比如方法中定义了大量的局部变量、超长的数组，或者递归调用的层级极深——每个栈帧都会占用大量空间，导致总栈空间更容易被耗尽，从而更容易抛出 `OutOfMemoryError`。这也是为什么编写代码时要避免在方法中分配过大的局部变量表。

### 四、两种异常的对比

| 维度        | StackOverflowError  | OutOfMemoryError  |
| --------- | ------------------- | ----------------- |
| **触发条件**      | 栈深度超过 `-Xss` 设置的最大值 | 线程过多，总内存无法分配新的栈空间 |
| **常见场景**      | 无限递归                | 创建大量线程（如线程泄漏）     |
| **默认配置下是否常见** | ==**常见**==          | 少见（默认不支持动态扩展）     |
| **排查方式**      | 检查递归深度，调整 `-Xss`    | 减少线程数，检查线程池配置     |

### 五、面试要点

| 问题                            | 回答                                                    |
| ----------------------------- | ----------------------------------------------------- |
| **HotSpot 中虚拟机栈有哪两种异常**       | ==**StackOverflowError**== 和 ==**OutOfMemoryError**== |
| **默认配置下哪种异常更常见**              | ==**StackOverflowError**==，因为 HotSpot 默认不支持动态扩展栈      |
| **什么情况下会触发 OOM**              | 创建大量线程，每个线程的栈空间耗尽物理内存                                 |
| **为什么 HotSpot 不区分虚拟机栈和本地方法栈** | 两者在内存管理上是统一处理的，异常表现相同                                 |
