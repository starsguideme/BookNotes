### 一、JVM 内存区域划分

在本章中详细讲述了 JVM 内存中的区域划分，详见于[[数据区域的划分与总结]]。JVM 的内存区域大致分为：

|区域|是否线程共享|主要作用|
|---|---|---|
|==**堆区**==|是|存放对象实例和数组|
|==**方法区**==|是|存储类信息、常量、静态变量、JIT 编译的代码缓存|
|==**虚拟机栈**==|否（线程私有）|描述 Java 方法的执行内存模型，每个方法对应一个栈帧|
|==**本地方法栈**==|否（线程私有）|为 native 方法服务|
|==**程序计数器**==|否（线程私有）|记录当前线程正在执行的字节码指令地址|

### 二、虚拟机栈与栈帧

对象存在于堆区中，调用类会把类的信息存储在方法区，而方法执行时的局部变量、操作数栈等信息则存储在虚拟机栈的栈帧中。由于栈满足**后进先出**的特性，这也就是为什么在类中调用其他方法时，被调用的方法会先返回数据，然后再执行调用者方法的剩余部分——被调用的栈帧在栈顶，先出栈返回，调用者的栈帧随后继续执行。

### 三、内存溢出异常（`OOM`）

每个具体区域都有其特定的异常，但它们也有相同的异常：==**`OutOfMemoryError`**==，内存溢出异常。内存溢出异常大致由以下问题导致：

|原因|说明|
|---|---|
|==**JVM 的 GC 回收速度小于创建对象的速度**==|对象创建太快，GC 来不及回收，堆空间被撑满|
|==**JVM 的内存分配参数设置错误**==|创建了过小的堆或过大的某个区域，导致无法满足运行时的内存需求|
|==**系统内存分配出错**==|只和[[直接内存]]有关，因为只有直接内存是独立于 JVM 运行区域的额外内存，只受限于处理器的物理内存|

**`JVM` 内存分配错误**：如果创建了一个过小的`JVM`（如 `-Xmx` 设置太小），或者创建了过大的某个区域导致 `JVM` 无法满足运行时的内存需求，就会导致线程在创建对象时直接产生内存溢出问题。

**系统内存分配错误**：在直接内存中出现的内存溢出有个明显特征——在 Heap Dump 文件中不会看见明显的异常对象，Dump 文件很小，但程序直接或间接地使用了 `DirectByteBuffer` 或调用了 `Unsafe.allocateMemory()`。

### 四、对象创建的并发安全机制

在线程创建的时候，由于系统会先去运行时常量池查找是否有这个类的符号引用。如果没有，会使用 `<init>` 函数来初始化类。此时初始化类可能会带来类的重排序问题，也有可能由于操作系统给予的线程资源不够，导致对象只是创建了但还没完成空间上的分配。

为了解决这个问题，开发团队提供了两种方案：

|方案|说明|
|---|---|
|==**TLAB（本地线程分配缓冲区）**==|每个线程在堆区中预先分配一块私有的缓冲区，在该缓冲区内分配对象无需加锁。只有当 TLAB 用完时才需要新的同步锁定来分配新的缓冲区|
|==**自旋 CAS**==|对分配内存空间的动作执行同步处理，采用循环 CAS 配合失败重试来保证更新操作的原子性。CAS 全称是比较并交换，是一种无锁的原子操作策略|

详见：[[CAS]]

### 五、对象的访问方式

当对象创建完之后也带来了如何访问的问题。详见[[对象的访问的两种方式]]，大致分为两种：

|访问方式|原理|优点|缺点|
|---|---|---|---|
|==**句柄访问**==|在堆区中划分一块句柄池，`reference` 存储的是句柄地址，句柄中保存对象的实际地址和类型数据地址|GC 移动对象时只需修改句柄池中的指针，`reference` 不变，GC 实现简单|需要两次寻址，访问速度慢|
|==**直接指针访问**==|`reference` 直接存储对象的实际地址|一次寻址，访问速度快|GC 移动对象时需遍历所有引用并更新地址，GC 实现复杂|

由于现实中访问对象的频率要远高于 GC 移动对象的频率，所以 HotSpot 使用的是**直接指针访问**。这也是直接指针的优点和缺点——用 GC 的复杂度换取访问性能。

### 六、对象的内存布局

在堆内存中，对象的存储空间可以划分为三个部分：

| 部分           | 说明                                                         |
| ------------ | ---------------------------------------------------------- |
| ==**对象头**==  | 包含 Mark Word（存储哈希值、GC 分代年龄、锁状态等运行时数据）和类型指针（指向方法区中该类元数据的指针） |
| ==**实例数据**== | 对象中定义的成员变量，真正存储的有效信息                                       |
| ==**对齐填充**== | 保证对象大小是 8 字节的整数倍，起占位符作用                                    |
详见于:[[对象的内存布局]]
