
### 一、可达性分析算法的核心原理

目前主流的语言中，一般都是使用的是**可达性分析算法**来判断对象是否存活的。其数据结构类似于一个**树形结构**（更准确地说是有向图），从根节点 **GC Roots** 的根对象作为起始节点集，从这些节点开始，根据引用关系向下探索，其中的路径叫做**引用链**。如果某个对象**不可达**时，则证明对象是不可用的（带权树）。

### 二、Java 中的 GC Roots 对象

在 Java 中，GC Roots 的对象主要包括以下几种：

| GC Roots 类型 | 说明 |
|-------------|------|
| ==**虚拟机栈中引用的对象**== | 在 JVM 的堆区中引用的对象，各个线程被调用的方法堆栈中使用到的参数、局部变量与临时变量 |
| ==**方法区中常量引用的对象**== | 比如说字符串常量池的引用 |
| ==**方法区中静态类属性的引用对象**== | 比如说 Java 类的静态变量 |
| ==**本地方法栈中 JNI 的引用对象**== | 在本地方法栈中 JNI（Native 方法）的引用对象 |
| ==**JVM 内部引用的对象**== | 如 Class 对象、异常对象以及系统类加载器 |
| ==**所有被同步锁持有的对象**== | Lock 接口下的锁与 `synchronized` 持有的对象 |
| ==**监视器类**== | 如 JMXBean、JVMTI 中注册的回调、本地代码的缓存 |

### 三、临时性 GC Roots

除了这些固定的 GC 根节点外，根据用户的需求和当前回收的内存区域不同，还有其他对象会**临时性地加入**。

比如说**分代收集器与局部回收**：如果只针对 Java 堆中某一区域使用 GC 时，考虑到 JVM 的使用细节，并且在使用时由于内存不是独立存在的，因此在整个工作内存中，可能会出现其他内存的数据会被堆区中的对象使用。这个时候就需要将一些**对应区中的关键数据**加入到 GC 根节点中，才可以正确的使用可达性分析。

### 四、面试要点

| 问题                   | 回答                                                                              |
| -------------------- | ------------------------------------------------------------------------------- |
| **可达性分析算法的核心思想**         | 从 **GC Roots** 出发，通过**引用链**向下搜索，不可达的对象判定为可回收                                    |
| **GC Roots 包括哪些**        | ==**虚拟机栈中引用的对象、方法区中常量/静态属性引用的对象、本地方法栈中 JNI 引用的对象、JVM 内部引用的对象、被同步锁持有的对象、监视器类**== |
| **什么情况下需要临时扩展 GC Roots** | 分代收集器对堆中某一区域进行**局部回收**时，需要将关联区域的关键数据加入 GC Roots                                 |
