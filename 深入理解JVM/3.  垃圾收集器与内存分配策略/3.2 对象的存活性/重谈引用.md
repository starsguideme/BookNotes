

**四种引用类型**

### 一、引用的定义演变

无论是通过[[引用计数方法]]还是[[可达性分析算法与GC根节点]]，判断对象的存活都和引用脱离不开关系。

**JDK 1.2 之前**：引用无非就是如果 `reference` 类型的数据中存储的数值使用的是另外一个内存的起始地址，就认为该 `reference` 数据代表的是某块内存，也就是引用了该内存区域的值。

**JDK 1.2 之后**：Java 新增了以下概念：**强引用、软引用、弱引用以及虚引用**，这四个引用方式的强度从高到低依次排序。

### 二、四种引用类型对比

| 引用类型 | 强度 | 回收时机 | 使用场景 |
|---------|------|---------|---------|
| ==**强引用（Strong Reference）**== | 最强 | **永远不会被 GC 回收**，只要强引用存在 | 最普遍的引用，如 `Object obj = new Object()` |
| ==**软引用（Soft Reference）**== | 中等 | 只有在发生 **OOM** 的情况下，才会把这种引用对象进行回收 | 内存敏感的缓存，如图片缓存 |
| ==**弱引用（Weak Reference）**== | 较弱 | 一旦开始 **GC**，无论如何弱引用都会被回收掉 | `WeakHashMap`、ThreadLocal |
| ==**虚引用（Phantom Reference）**== | 最弱 | 其作用只限于被 GC 时候得到一个**通知**，其他情况几乎完全不存在引用 | 对象被回收时的跟踪，如 NIO 直接内存的清理 |

### 三、面试要点

| **问题**          | 回答                            |
| ----------- | ----------------------------- |
| **四种引用类型的强度排序** | ==**强引用 > 软引用 > 弱引用 > 虚引用**== |
| **软引用的回收时机**    | 只有在发生 **OOM** 的情况下才会被回收       |
| **弱引用的回收时机**    | 一旦开始 **GC**，无论如何都会被回收         |
| **虚引用的作用**      | 只限于被 GC 时得到一个**通知**，本身不持有对象引用 |
| **软引用的典型使用场景**  | 内存敏感的**缓存**，如图片缓存             |
| **弱引用的典型使用场景**  | `WeakHashMap`、**ThreadLocal** |
