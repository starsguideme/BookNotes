
### 一、两大分类

GC 的分类大致可以分为**“引用计数式 GC”**和**“追踪式垃圾收集”**两大类，这两类也常被称作**直接回收**和[[间接回收]]。

| 分类 | 别名 | 管理方式 |
|------|------|---------|
| ==**引用计数式 GC**== | 直接回收 | 由**内存**管辖，每个对象维护一个引用计数器 |
| ==**追踪式垃圾收集**== | 间接回收 | 由 **JVM 代管**，通过可达性分析算法判断对象是否存活 |

### 二、两种方式的对比

| 维度 | 引用计数式 GC（直接回收） | 追踪式垃圾收集（间接回收） |
|------|------------------------|--------------------------|
| ==**核心原理**== | 每个对象维护一个引用计数器，引用为 0 时立即回收 | 从 GC Roots 出发，通过可达性分析判断对象是否存活 |
| ==**回收时机**== | 引用计数归零时**立即回收** | 由 JVM 统一调度，在 GC 发生时**批量回收** |
| ==**优势**== | 实时性高，回收及时 | 不会产生循环引用问题，适合复杂对象图 |
| ==**劣势**== | ==**无法解决循环引用问题**== | 需要 STW（Stop The World），会产生停顿 |
| ==**代表应用**== | Python、早期 JVM 实现 | Java（HotSpot）、C# |

### 三、为什么 Java 选择追踪式 GC？

引用计数式 GC 最大的缺陷是**无法解决循环引用问题**——两个对象互相引用，但外部已经没有任何引用指向它们，此时引用计数永远不会归零，导致内存泄漏。而追踪式 GC 通过可达性分析，从 GC Roots 出发，循环引用的对象不可达时会被正确识别为垃圾并回收。
