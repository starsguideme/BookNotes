
### 一、核心定位

该方法主要是解决由[[标记-清除]]中面对大量可回收对象而产生的**效率低下问题**的升级算法。

### 二、执行流程

```text
标记-复制算法：

① 将内存分割成两个大小相同的区域（A 区和 B 区）
    ↓
② 每次使用内存时只调用其中一个区域（如 A 区）
    ↓
③ 当 A 区内存使用完之后
    ↓
④ 将 A 区中所有存活对象复制到 B 区
    ↓
⑤ 一次性清空 A 区
    ↓
⑥ 下次使用时，交换 A 区和 B 区的角色
```

### 三、优缺点分析

| 维度 | 说明 |
|------|------|
| ==**优点**== | 如果多数对象都是可回收的，算法只需要复制**少部分存活对象**，只需要对堆顶指针进行操作，按顺序分配，简单高效，且**不会产生内存碎片** |
| ==**缺点**== | 如果多数对象都是存活的，将会产生**大量的内存间复制的开销**；需要分割出两个内存区域，有可能会造成**一半空间的浪费** |

### 四、适用场景

| 场景 | 说明 |
|------|------|
| ==**适用于新生代**== | 新生代中绝大多数对象都是朝生夕灭的，存活对象少，复制开销小 |
| ==**不适用于老年代**== | 老年代存活对象多，复制开销大，不适用此算法 |

### 五、面试要点

| **问题**             | 回答                                                |
| ------------------ | ------------------------------------------------- |
| **标记-复制算法的核心原理**   | 将内存分成两块，每次只使用一块，回收时把存活对象复制到另一块，然后**一次性清空**原区域     |
| **标记-复制算法的优点**     | 适用于**存活对象少**的场景，简单高效，不会产生内存碎片                     |
| **标记-复制算法的缺点**     | 需要**双倍内存空间**，存活对象多时复制开销大                          |
| **标记-复制算法适用于哪个区域** | ==**新生代**==（Serial、ParNew、Parallel Scavenge 等收集器） |
