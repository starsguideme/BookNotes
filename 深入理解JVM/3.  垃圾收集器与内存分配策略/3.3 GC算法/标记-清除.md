
### 一、核心定位

最早出现的基础GC算法，其步骤分为两个步骤：**标记**与**清除**。一般情况下都是选择标记的内容进行判断是否删除，如果是，则保留未标记的，反之亦然。

### 二、执行流程

```text
标记-清除算法：

① 标记阶段：从GC Roots出发，遍历所有可达对象，将其标记为"存活"
    ↓
② 清除阶段：遍历整个堆，将所有未被标记的对象进行回收
    ↓
③ 完成：存活对象保留在堆中，但可能产生大量内存碎片
```

### 三、两个核心缺点

| 缺点 | 说明 |
|------|------|
| ==**效率不稳定**== | 清除的效率取决于堆中的对象数量，如果其中有大部分的对象都需要被回收，性能就会随着对象的增加而降低 |
| ==**内存空间碎片化**== | 由于在标记并清除后会产生大量不连续的内存碎片。空间碎片太多可能会导致线程中出现某个较大的对象（要么是主类对象，要么是线程对象）时，该对象无法找到合适的连续内存，以此触发新一轮GC |

### 四、面试要点

| 问题 | 回答 |
|------|------|
| 标记-清除算法的两个步骤 | ==**标记**==（标记存活对象）和 ==**清除**==（回收未标记对象） |
| 标记-清除算法的两个缺点 | ==**效率不稳定**==（性能随对象数量增加而降低）和 ==**内存空间碎片化**==（无法分配大对象） |
| 标记-清除算法适用于哪个区域 | 主要适用于**老年代**（如CMS收集器） |
