

**分代收集理论与GC算法**

### 一、分代收集理论的两个假说

分代收集理论建立在两个核心假说之上：

| 假说 | 内容 | 对应区域 |
|------|------|---------|
| ==**弱分代假说**== | 绝大多数对象都是**朝生夕灭**的，生命周期很短 | 新生代（Young Generation） |
| ==**强分代假说**== | 熬过越多次GC的对象就**越难被销毁** | 老年代（Old Generation） |

这两个分代假说共同组建了收集器应该将Java堆划分出不同的区域，然后根据回收对象的年龄（新生代与老年代分别代表经历过多少次GC）分配到不同的区域中存储这一原则。通过年龄划分可以有效地减少大量不必要的空间浪费和时间开销。

等到在堆区划分出不同的区域后，GC才可以回收其中的部分对象，由此诞生了**"Minor GC"、"Major GC"和"Full GC"**等。这种划分同样也方便了进行不同程度的GC算法。

### 二、三种GC类型

| GC类型 | 回收区域 | 触发条件 | 特点 |
|--------|---------|---------|------|
| ==**Minor GC**== | 仅回收**新生代** | Eden区满 | 频繁，速度快，会产生STW |
| ==**Major GC**== | 仅回收**老年代** | 老年代空间不足 | 速度通常比Minor GC慢 |
| ==**Full GC**== | 回收**整个堆**（新生代+老年代+方法区） | 老年代/方法区空间不足 | 最慢，STW时间最长，应尽量避免 |

### 三、跨代引用假说

虽然分代收集理论通过前两点已经可以做出基本的GC算法，可在实际运行中却依旧有一个巨大的困扰——即**如何解决对象跨代引用问题**。

为了解决这个问题，根据经验便诞生了第三个假说：**跨代引用假说**。这个假说是基于前两假说诞生的——存在互相引用关系的两个对象本应该是倾向于同一个生命周期的。通过这个原理设计，就不必为少量的跨代引用去寻找整个老年代的划分区，因此就不需要任何时间和空间上的浪费。

但在具体实际上，是通过在新生代引入了**记忆集（Remembered Set）**，将其划分变成若干个小块的对象，在经过可达性分析算法的步骤来判断新生代是否与老年代有关联即可。

### 四、三种GC算法

| 算法                | 核心原理                               | 优点            | 缺点                       | 适用区域                                 |
| ----------------- | ---------------------------------- | ------------- | ------------------------ | ------------------------------------ |
| ==**[[标记-清除]]**== | ①标记所有可达对象 ②清除所有未标记对象               | 简单，不需要额外空间    | 产生**内存碎片**，碎片过多导致无法分配大对象 | 老年代（CMS）                             |
| ==**[[标记-复制]]**== | ①标记所有可达对象 ②将存活对象复制到另一块空白区域，然后清空原区域 | 无内存碎片，效率高     | 需要**双倍空间**，存活对象多时复制开销大   | 新生代（Serial、ParNew、Parallel Scavenge） |
| ==**[[标记-整理]]**== | ①标记所有可达对象 ②将所有存活对象向一端移动，然后清空边界外的空间 | 无内存碎片，不需要双倍空间 | 整理过程**耗时较长**，需要STW       | 老年代（Serial Old、Parallel Old）         |
|                   |                                    |               |                          |                                      |

### 五、三种GC算法的流程图

```text
标记-清除：
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  标记存活对象  │ → │  清除未标记对象 │ → │  产生内存碎片  │
└─────────────┘    └─────────────┘    └─────────────┘

标记-复制：
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  标记存活对象  │ → │ 复制到空白区域  │ → │  清空原区域   │
└─────────────┘    └─────────────┘    └─────────────┘

标记-整理：
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  标记存活对象  │ → │ 向一端移动整理  │ → │  清空边界外   │
└─────────────┘    └─────────────┘    └─────────────┘
```

### 六、面试要点

| 问题                  | 回答                                                   |
| ------------------- | ---------------------------------------------------- |
| **分代收集理论的两个假说**         | ==**弱分代假说（对象朝生夕灭）**== 和 ==**强分代假说（熬过多次GC的对象难被销毁）**== |
| **跨代引用如何解决**            | 通过新生代中的**记忆集（Remembered Set）**判断                     |
| **三种GC算法**              | ==**标记-清除、标记-复制、标记-整理**==                            |
| **新生代一般使用哪种算法**         | ==**标记-复制**==，因为新生代存活对象少，复制开销小                       |
| **老年代一般使用哪种算法**         | ==**标记-清除**==或==**标记-整理**==                          |
| **Minor GC和Full GC的区别** | Minor GC只回收新生代，速度快；Full GC回收整个堆，STW时间最长              |
