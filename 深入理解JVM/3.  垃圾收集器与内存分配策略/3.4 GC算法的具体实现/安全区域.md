### 一、核心定位

安全区域就是指在某个区域内，对象引用的关系不会产生任何变化，因此在这个区域的地方执行 GC 操作都是**安全**的。因此我们也可以把安全区域看作是**安全点的扩展**——安全点要求线程必须执行到特定位置才能暂停，但对于处于阻塞或休眠状态的线程，它们无法主动走到安全点，此时就需要安全区域来覆盖。

### 二、安全区域的执行流程

当用户线程执行到安全区域时的程序时，首先会**标识自己已经进入安全区域**。那样这段时间的 JVM 就不必要发起任何 GC，就不需要去管这些已声明自己在安全区域的线程了。

但当线程离开了安全区域时，就得检查 JVM 是否完成了[[根节点枚举]]的操作。如果此时的枚举操作已经完成，就会继续执行操作；否则会**一直自旋等待**，直到被通知得知可以离开这个安全区域。

```text
安全区域的执行流程：

① 线程进入安全区域 → 标识自己已处于安全区域
    ↓
② JVM 发起 GC → 该线程不会被强制暂停（因为已处于安全区域）
    ↓
③ 线程准备离开安全区域 → 检查 JVM 是否已完成根节点枚举
    ↓
    ├── 已完成 → 线程继续执行
    │
    └── 未完成 → 线程自旋等待，直到枚举完成后被唤醒
```

### 三、面试要点

| 问题             | 回答                                                      |
| -------------- | ------------------------------------------------------- |
| **安全区域与安全点的区别**    | 安全点是**主动到达**的位置；安全区域是**长时间停留**的区域，线程处于阻塞或休眠状态时无法主动走到安全点 |
| **安全区域的作用**        | 保证处于阻塞或休眠状态的线程也能在 GC 时**安全暂停**                          |
| **线程离开安全区域时需要做什么** | 检查 JVM 是否完成了**根节点枚举**，如果未完成则**自旋等待**                    |
