
### 一、可达性分析的并发挑战

曾在[[分代收集理论与GC算法]]中提到，目前的主流语言基本上都是基于**可达性分析算法**来判定对象是否存活的。可达性分析算法理论上要求全程都必须保障**一致性快照**中才可以分析，这意味着必须全程暂停其他用户线程才可以执行。

在[[根节点枚举]]中，由于 GC 根节点比起整个 Java 堆来说毕竟是少数。当开始像遍历树一样遍历 GC Roots 的时候，其所需时间会随着带权路径和对象的增加而增加。

### 二、并发标记的问题

收集器在对象图上标记颜色时，用户线程会在此时修改引用关系——即修改对象图的结构。此时可能会遇到两种后果：

| 后果                       | 说明                        |
| ------------------------ | ------------------------- |
| ==**把原本消亡的对象标记为存活**==    | 产生**浮动垃圾**，下次 GC 再回收，影响较小 |
| ==**把原本应该存活的对象标记为已消亡**== | 导致**对象消失**，程序出错，必须解决      |

### 三、三色标记的具体实现

三色标记法的具体实现很像**有向图的遍历**，大致可以分为五步：

| 步骤 | 操作 | 说明 |
|------|------|------|
| ==**步骤 1**== | 初始状态 | 所有对象都是**白色**，表示尚未被 GC 访问 |
| ==**步骤 2**== | 从 GC Roots 开始遍历 | 将 GC Roots 直接引用的对象标记为**灰色** |
| ==**步骤 3**== | 处理灰色对象 | 将灰色对象的所有直接引用对象标记为**灰色**，然后将当前对象标记为**黑色** |
| ==**步骤 4**== | 重复步骤 3 | 直到所有灰色对象都被处理完毕 |
| ==**步骤 5**== | 回收白色对象 | 所有未被标记为黑色的白色对象都是不可达的，可以被回收 |

**三色标记中三种颜色的含义**：

| 颜色         | 含义                             |
| ---------- | ------------------------------ |
| ==**白色**== | 尚未被 GC 访问过的对象，标记结束后白色对象即为可回收对象 |
| ==**灰色**== | 对象已被 GC 访问，但其引用的其他对象尚未全部被访问    |
| ==**黑色**== | 对象已被 GC 访问，且其引用的所有其他对象也都已被访问   |

### 四、对象消失问题的两种产生条件

在并发的情况下，只有两种方式会产生**对象消失**的问题：

| 条件 | 说明 |
|------|------|
| ==**条件 1**== | 赋值器插入一条或多条从**黑色对象到白色对象**的新引用 |
| ==**条件 2**== | 赋值器删除了全部从**灰色对象到白色对象**的直接或间接引用 |

**同时满足上述两个条件**时，白色对象就会从对象图中"消失"，被错误地回收。

### 五、两种解决方案

为了解决这个问题，就有了两种方式：**增量更新**与**原始快照**。

| 方案 | 原理 | 核心操作 |
|------|------|---------|
| ==**增量更新（Incremental Update）**== | 将新插入的引用记录下来，等并发结束之后，再将这些记录过的引用关系中的黑色对象看作是根，重新扫描一下 | 黑色对象一旦插入新的指向白色对象的引用之后，会**立即变成灰色对象** |
| ==**原始快照（Snapshot At The Beginning，SATB）**== | 当灰色对象要删除指向白色对象的引用关系时，就记录下来。等到并发结束之后，再将记录的灰色对象为根，重新扫描一下 | 无论引用关系删除与否，都会按照**刚刚开始扫描那一刻的对象图快照**来进行搜索 |

**增量更新的核心思想**：破坏条件 1，当黑色对象新增指向白色对象的引用时，将黑色对象重新标记为灰色，让 GC 重新扫描它的引用。

**原始快照的核心思想**：破坏条件 2，当灰色对象删除指向白色对象的引用时，将被删除的引用记录下来，在重新标记阶段将这些白色对象重新扫描。

### 六、面试要点

| **问题**              | 回答                                                  |
| --------------- | --------------------------------------------------- |
| **三色标记是哪三种颜色**      | ==**白色、灰色、黑色**==                                    |
| **并发标记的两种后果**       | 产生**浮动垃圾**（不致命）和**对象消失**（必须解决）                      |
| **对象消失问题的两种产生条件**   | ==**黑色对象新增指向白色对象的引用**== + ==**灰色对象删除全部指向白色对象的引用**== |
| **增量更新的核心思想**       | 破坏**条件 1**，黑色对象新增引用后**立即变灰**                        |
| **原始快照的核心思想**       | 破坏**条件 2**，以**扫描开始时的对象图快照**为准                       |
| **增量更新和原始快照的代表收集器** | 增量更新 → ==**CMS**==；原始快照 → ==**G1、Shenandoah**==     |
