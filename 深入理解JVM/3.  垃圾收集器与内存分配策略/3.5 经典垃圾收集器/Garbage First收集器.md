
### 一、核心定位

1.  G1 收集器是 JVM 很重要的 GC 机制，其具有可**局部回收垃圾**的机制，也是功能很全面的 GC 收集器。

2.  G1 是一款主要面向**服务端应用**的垃圾收集器，在服务端下其是默认使用的垃圾收集器（JDK 9 之后）。而之前提到的[[CMS收集器]]则是因其缺点导致不再被推荐使用。

3.  在 G1 收集中有**混合垃圾回收**的方式。这个混合垃圾不仅收集新生代，也可以收集老年代，即它可以在任何区域任何地方收集任何垃圾对象。但其也有自己的**可预测的停顿时间模型**。

### 二、基于区域的内存布局

4.  虽然 G1 也基于**分代收集理论**收集，但与其他收集器不同的是，其会把连续的 Java 堆分为**多个大小相等的独立区域**。每个区域都可以根据需要在新生代和老年代之间切换。

    该区域中有一个很特殊的 **Humongous 区域**，专门用于存储**大对象**。G1 认为只要大小超过了一个区域中容量**一半**的对象即可判定为大对象。这个大对象的定义可以通过设置一些操作来设定，但一般推荐的取值范围为 **1MB~32MB**，取 2 的幂。此时遇到一个对象超过了整个区域容量的大对象，就会被分割到 **N 个连续的区域**中，并将这些操作的对象看作成老年代的一部分。

### 三、可预测的停顿时间模型

5.  可预测的停顿时间模型，是因为可以将**区域作为单次回收的最小单元**，这样可以避免在整个 Java 堆中进行全区域的垃圾收集。G1 会在后台维护一个**优先级列表**，每个根据用户设定允许的收集停顿时间，**优先处理回收价值最大的那些区域**。这也就是 **Garbage First（垃圾优先）** 的名字由来——使用区域来划分空间内存，以及具有优先级的区域回收方式。

### 四、G1 收集器的四个步骤

6.  G1 收集器的运行过程大致可以分为 4 个步骤：

| 步骤 | 说明 | 是否需要 STW |
|------|------|------------|
| ==**初始标记（Initial Mark）**== | 通过标记 GC 根节点能**直接关联到**对象，并且修改 **TAMS 指针**的值，让下一阶段的用户线程并发运行，能正确地在可用的区域中重新分配新对象。此阶段需要停顿线程，但可以**借由 Minor GC 同步完成**，因此 G1 的停顿并没有消耗太多 | 需要（短暂） |
| ==**并发标记（Concurrent Mark）**== | 从 GC 根节点开始对堆中对象进行**可达性分析**，并递归扫描整个堆里的对象图。要想找出可回收的对象，可以借助并发扫描对象图来完成 | 不需要 |
| ==**最终标记（Remark）**== | 对用户线程做一个短暂的暂停，这个主要是用于处理并发阶段结束后依然遗留下来的 **SATB 记录** | 需要（短暂） |
| ==**筛选回收（Cleanup）**== | 负责更新区域的统计数据，对各个区域的回收价值和成本进行排序，并根据用户所期望的停顿时间来制定计划。这个回收不仅可以选择任意个对象，还可以将存活的对象**复制到空的区域中**（结合了标记-整理与标记-复制），最后清理掉整个旧区域的全部空间。虽然这涉及到了存活对象的移动时需要暂停用户线程，但其可以**交给其他收集器线程来处理** | 需要（短暂） |

### 五、G1 的设计哲学

7.  由第六点得到一个概念：G1 并非是纯粹为了低延迟而诞生，而是基于**延迟、吞吐、回收多少垃圾**而做出**相对平衡**的一个收集器。由于其可以**自设定用户线程的暂停时间**（`-XX:MaxGCPauseMillis`），因此在设定暂停时间时应设置一个较为合适的时间。

### 六、G1 收集器的优点

| 优点                          | 说明                                         |
| --------------------------- | ------------------------------------------ |
| ==**整体基于标记-整理，局部基于标记-复制**== | 因此 G1 里**不会出现任何不连续的小空间**，也因此不会产生任何的大对象分配困难 |
| ==**可预测的停顿时间模型**==          | 通过优先级列表，优先回收价值最大的区域，可以在用户设定的时间内完成 GC       |
| ==**混合收集**==                | 可以同时收集新生代和老年代，不需要单独的 Full GC               |

### 七、G1 收集器的缺点

| 缺点                      | 说明                                                       |
| ----------------------- | -------------------------------------------------------- |
| ==**执行负载较高**==          | 每个区域中都要有自己的**卡表**，这会导致其记忆集需要大量的堆区空间，通常占堆总容量的 **10%~20%** |
| ==**具有更复杂的写屏障与快照搜索**==  | G1 使用 **SATB（原始快照）** 来保证并发标记的正确性，写屏障的实现比 CMS 更复杂         |
| ==**基于消息队列的结构来实现收集器**== | 经典模型是消费者与生产者，执行完通知后会把要做的事放入到队列中，然后并发执行                   |

### 八、面试要点

| 问题               | 回答                                     |
| ---------------- | -------------------------------------- |
| **G1 的全称和命名由来**      | **Garbage First**，优先回收价值最大的区域          |
| **G1 的内存布局**         | 将堆分为**多个大小相等的独立区域**，每个区域可以在新生代和老年代之间切换 |
| **G1 的四个步骤**         | ==**初始标记 → 并发标记 → 最终标记 → 筛选回收**==      |
| **G1 的优点**           | ==**不会产生内存碎片、可预测的停顿时间、混合收集**==         |
| **G1 的缺点**           | ==**记忆集占用内存大、写屏障复杂、基于消息队列实现**==        |
| **G1 使用哪种并发标记方案**    | ==**SATB（原始快照）**==                     |
| **什么是 Humongous 区域** | 专门存储**大对象**的区域，超过一个区域容量一半的对象即判定为大对象    |
