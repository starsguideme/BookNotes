
### 一、核心定位

在 JDK 11 之后，出现了一个收集器——**Epsilon**，其是一种**无操作的垃圾收集器**，也是可以作为自动内存管理子系统的一种。从字面上可以得出，其可以负责**堆的管理与布局、对象的分配、解释器的协作、编译器的协作与子系统监控的监视器**等作用。

### 二、Epsilon 的独特之处

Epsilon 只负责**分配内存**，而**不执行任何垃圾回收**。它带来的最大优势，就是**极致的吞吐量**和**零 GC 停顿**，因为它把所有的内存管理开销都去掉了，让程序可以跑到硬件允许的极限速度。

### 三、适用场景

| 适用场景 | 说明 |
|---------|------|
| ==**短生命周期应用**== | 比如运行完就退出的命令行工具、短任务脚本，不需要考虑 GC |
| ==**性能测试**== | 对程序性能进行基准测试时，排除 GC 的影响，测量纯业务逻辑的耗时 |
| ==**无内存压力的场景**== | 程序所需内存远小于堆容量，即使只分配不回收也不会耗尽内存 |

| 不适用场景 | 说明 |
|-----------|------|
| ==**需要长时间运行的应用**== | 内存会持续增长，最终导致 OOM |
| ==**内存受限环境**== | 没有 GC 回收，内存会迅速耗尽 |
| ==**需要自动内存管理的应用**== | 没有 GC，需要手动管理内存，不如直接使用 C/C++ |
