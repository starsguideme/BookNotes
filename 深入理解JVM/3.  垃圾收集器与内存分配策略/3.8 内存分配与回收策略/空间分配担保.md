

**空间分配担保机制**

### 一、Minor GC 前的检查流程

在发生 **Minor GC** 之前，JVM 必须检查**老年代目前最大可用的连续空间**是否大于**新生代所有对象的总空间**：

| 检查步骤        | 条件                                           | 结果                     |
| ----------- | -------------------------------------------- | ---------------------- |
| ==**第一步**== | 老年代最大连续空间 **大于** 新生代所有对象总空间                  | Minor GC 是**安全**的，直接执行 |
| ==**第二步**== | 老年代最大连续空间 **小于** 新生代对象总空间                    | 检查参数是否允许**担保失败**       |
| ==**第三步**== | 允许担保失败，且老年代最大连续空间 **大于** 历次晋升到老年代对象的**平均大小** | 尝试一次 Minor GC（**有风险**） |
| ==**第四步**== | 允许担保失败，但老年代最大连续空间 **小于** 平均大小                | 直接进行 **Full GC**       |

### 二、空间分配担保流程图

```text
① Minor GC 前
    ↓
② 检查老年代最大连续空间 > 新生代对象总空间？
    ↓
    ├── 是 → Minor GC 安全，直接执行
    │
    └── 否 → 检查是否允许担保失败
              ↓
              ├── 不允许 → 直接执行 Full GC
              │
              └── 允许 → 继续检查
                        ↓
                  ③ 老年代最大连续空间 > 历次晋升平均大小？
                        ↓
                        ├── 是 → 尝试 Minor GC（有风险）
                        │
                        └── 否 → 执行 Full GC
```

### 三、担保机制的核心思想

空间分配担保机制的核心思想是：**在无法确定 Minor GC 是否安全时，根据历史数据（历次晋升平均大小）来估算风险**。如果历史数据表明风险可接受，就"赌一把"执行 Minor GC；如果历史数据表明风险太高，就直接执行 Full GC 来确保安全。

### 四、面试要点

| 问题                | 回答                                                               |
| ----------------- | ---------------------------------------------------------------- |
| **空间分配担保是什么**         | Minor GC 前，JVM 检查老年代空间是否足够容纳新生代对象，根据检查结果决定执行 Minor GC 还是 Full GC |
| **担保失败是什么意思**         | 老年代最大连续空间**小于**新生代对象总空间，即老年代可能无法容纳所有晋升对象                         |
| **什么情况下会尝试 Minor GC** | 允许担保失败，且老年代最大连续空间**大于历次晋升平均大小**                                  |
| **什么情况下会直接 Full GC**  | 不允许担保失败，或老年代最大连续空间**小于历次晋升平均大小**                                 |
