
### 一、自动内存管理

| 功能                   | 说明                                 |
| -------------------- | ---------------------------------- |
| ==**自动给对象分配内存**==    | JVM 根据对象的类型和当前内存状况，自动为新创建的对象分配内存空间 |
| ==**自动回收分配给对象的内存**== | GC 自动识别不再使用的对象并回收其占用的内存空间          |
|                      |                                    |

### 二、对象内存分配的位置

对象的内存分配虽然可以在**堆上**分配，但也可以通过**间接**的方式在**栈上**分配（如逃逸分析和标量替换）。

**经典分代设计下的分配规则**：

| 分配位置 | 触发条件 | 说明 |
|---------|---------|------|
| ==**新生代（Eden 区）**== | 默认情况 | 新生对象通常会被分配到新生代的 Eden 区 |
| ==**老年代**== | 对象超过一定阈值 | 少数情况下，如大对象或长期存活的对象，可能直接分配到老年代 |
| ==**栈上分配**== | 逃逸分析确认对象不会逃逸 | 通过标量替换将对象拆解为局部变量，在栈帧中分配 |

### 三、对象分配规则的不确定性

对象分配的规则**并不是固定的**，这取决于当前使用的是哪个**收集器**。不同的收集器（如 Serial、Parallel、G1、ZGC）在内存布局和分配策略上有所不同。

例如：
-   在 G1 收集器中，新生对象分配到**新生代区域**，大对象直接分配到 **Humongous 区域**。
-   在 ZGC 收集器中，内存分配使用**颜色指针**来标记对象的 GC 状态，分配策略与传统分代收集器差异很大。

### 四、面试要点

| 问题                | 回答                              |
| ----------------- | ------------------------------- |
| **JVM 的自动内存管理包括哪两部分** | ==**自动分配内存**== 和 ==**自动回收内存**== |
| **对象默认分配到哪里**         | ==**新生代的 Eden 区**==             |
| **什么情况下对象会直接分配到老年代**  | 大对象或长期存活的对象超过一定阈值               |
| **对象分配规则是固定的吗**       | ==**不是**==，取决于当前使用的是哪个**收集器**   |
