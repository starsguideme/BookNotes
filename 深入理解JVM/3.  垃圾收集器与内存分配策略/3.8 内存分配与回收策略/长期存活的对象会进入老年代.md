**对象年龄计数与晋升机制**

### 一、为什么需要对象年龄？

由于收集器都采用了**分代收集**来管理堆内存，那内存回收就必须要考虑哪些存活对象应该放入新生代和老年代。为了方便计算，因此就使用了一种名为**对象年龄**的计数器。

### 二、年龄的存储位置

对象年龄存储在 **Java 对象头部分的 Mark Word** 中。Mark Word 中的分代年龄字段占 **4 位**，最大值为 **15**（即对象最多经历 15 次 Minor GC 后必须晋升到老年代）。

### 三、年龄的增长规则

由之前提到的 Eden 区可得，对象一般由该区域诞生。可如果经过一次 **Minor GC** 仍可存活，并且能被**幸存区（Survivor 区）**容纳的话，该对象会被移到幸存空间中，并设对象年龄为 **1 岁**。

| 阶段 | 年龄 |
|------|------|
| ==**在 Eden 区出生**== | 0 岁 |
| ==**经过一次 Minor GC 并存活，进入 Survivor 区**== | 1 岁 |
| ==**每经过一次 Minor GC 并存活**== | 年龄 +1 |
| ==**年龄达到阈值（默认 15）**== | 晋升到老年代 |

### 四、年龄阈值的设置

这个年龄也可以被设置，通过 JVM 参数 `-XX:MaxTenuringThreshold` 来指定对象晋升到老年代的年龄阈值。

| 参数 | 说明 |
|------|------|
| ==**`-XX:MaxTenuringThreshold`**== | 设置对象晋升到老年代的最大年龄阈值，默认 **15** |

### 五、补充说明：动态年龄判断

除了固定的年龄阈值，HotSpot 还会进行**动态年龄判断**。当 Survivor 区中**同龄对象的大小总和**大于 Survivor 区空间的一半时，年龄大于或等于该年龄的对象**会直接晋升到老年代**，无需等到 MaxTenuringThreshold。
