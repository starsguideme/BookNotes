
### 一、OopMap 与安全点

在现代 JVM 中，只有特定的位置才有 **OopMap** 属性，这些位置被叫做**安全点（Safepoint）**。有了安全点的设定，也就决定了用户程序在执行时并非在代码的任意位置都可以停顿下来并开始收集 GC，而是**强制要求必须执行到安全点后才能够暂停**。

### 二、安全点的位置选择

安全点的位置应该选在适中的位置，这个适中的位置取决于**能不能让程序具有长时间运行的能力**为标准进行选定的。因为每条指令执行的时间实际上都是十分短暂的，程序不太可能因为某条指令太长而长时间执行。长时间执行的最明显特征就是**指令序列的复用**。

因此安全点通常设置在以下位置：

| 位置 | 说明 |
|------|------|
| ==**方法返回之前**== | 方法调用结束，即将返回调用者 |
| ==**循环的末尾**== | 循环执行完一次迭代后 |
| ==**异常跳转的位置**== | 抛出异常后跳转的位置 |
| ==**JNI调用之后**== | 本地方法执行完毕后 |

### 三、两种中断机制

如何在 GC 发生时让所有线程（不包括 JNI）都移动到最近的安全点后停顿下来？为了解决这个问题，其实有两种选择：

| 机制 | 原理 | 是否常用 |
|------|------|---------|
| ==**抢先式中断**== | 在 GC 时，系统首先会把所有用户线程**全部中断**。在中断的过程中发现有用户线程不在安全点上，会恢复这条线程的执行，直到一会后确保其正确地出现在安全点上 | **几乎没人使用** |
| ==**主动式中断**== | 通过设置**标识符**，而不用对线程进行任何操作时，让线程以**轮询**的方式去查询各个标志。一旦发现中断标志为真时，就需要其主动中断并挂起 | ==**主流方式**== |

**主动式中断的底层实现**：为了确保轮询操作足够高效，JVM 使用了**内存保护陷阱**的方式，将轮询操作精简到只有**一个汇编指令**。JVM 在运行时发现这个指令为不可读的时候，线程就会自动产生一个**自陷异常信号**，然后在预先注册的异常处理器中挂起线程实现等待。

### 四、面试要点

| 问题           | 回答                                             |
| ------------ | ---------------------------------------------- |
| **什么是安全点**       | 只有特定位置才有 OopMap 属性，**必须执行到安全点后才能暂停 GC**        |
| **安全点通常设置在哪些位置** | ==**方法返回之前、循环末尾、异常跳转位置、JNI调用之后**==             |
| **两种中断机制**       | ==**抢先式中断**==（几乎不用）和 ==**主动式中断**==（主流，通过轮询标志位） |
| **主动式中断如何保证高效**  | 通过**内存保护陷阱**，将轮询操作精简到**一个汇编指令**                |
