
### 一、GC Roots的枚举

从可达性算法中GC根节点来看，通过引用链去找对象的概念可以固定作为GC根节点在全局性的作用（如常量与静态类属性）与执行上下文（本地变量表）。尽管目标明确，但高效完成却很困难。

### 二、为什么GC必须停顿？

[[标记-整理]]等GC算法导致在启用该GC回收时会导致所有用户线程停止。虽然现在的可达性分析可以在某些情况下与用户线程进行**并发操作**，但GC Roots必须要保证其是在以**快照型的数据一致性**下才可以进行。

这种数据一致性更多说的是在整个枚举期间，数据执行某个子系统任务的时候像停止在某一刻一样，不会影响到任何可达性的分析操作。由于根节点集合的对象引用处于**时刻变化中**，必须让其在某一刻的数据**固定下来**。正因为这个机制，所以GC时其必然卡顿（STW，Stop The World）。

### 三、准确式GC的作用

由于现在大部分使用的是**准确式GC**，所以当用户线程停顿下来后，虚拟机应当是直接**开辟内存并给予对象进行引用**。这意味着JVM不需要逐个猜测哪些内存位置是引用，而是能精确地知道所有引用位置，从而快速完成GC Roots的枚举。

### 四、面试要点

| 问题                 | 回答                                                |
| ------------------ | ------------------------------------------------- |
| **为什么GC Roots枚举必须STW** | GC Roots处于**时刻变化中**，必须让数据在某一刻**固定下来**，保证**快照一致性** |
| **什么是准确式GC**           | JVM能**精确知道**所有引用位置，不需要猜测，快速完成GC Roots枚举           |
| **准确式GC的优势**           | 快速完成GC Roots枚举，减少STW时间                            |
