
### 一、七个阶段

一个类型从被加载到 JVM 中开始，到卸载出内存为止，其整个生命周期将会经历以下步骤：

| 阶段 | 说明 |
|------|------|
| ==**加载（Loading）**== | 通过类的全限定名获取二进制字节流，将其转换为方法区中的运行时数据结构，并在堆中创建 `Class` 对象 |
| ==**验证（Verification）**== | 确保字节码符合 JVM 规范，不会危害 JVM 安全 |
| ==**准备（Preparation）**== | 为静态变量分配内存并设置**零值**（不是用户在代码中写的初始值） |
| ==**解析（Resolution）**== | 将常量池中的符号引用替换为直接引用 |
| ==**初始化（Initialization）**== | 执行 `<clinit>()` 方法，真正为静态变量赋初始值 |
| ==**使用（Using）**== | 类被实际使用时 |
| ==**卸载（Unloading）**== | 类被 GC 从方法区中回收 |

### 二、加载与连接的关系

其中**验证、准备和解析**可以看出**连接**的一步。这些步骤几乎是确定的：

```text
加载 → 验证 → 准备 → 初始化 → 卸载
```

类的加载过程必须按照这种顺序**按部就班地开始**。但**解析阶段不一定**——在某些情况下可以在初始化开始之后再开始，这是为了支持 Java 的**动态绑定或晚期绑定**，甚至在运行时它们是可以交叉运行的。

### 三、触发初始化的六种情况

遇到 `new`、`getstatic`、`putstatic`、`invokestatic` 这四条 class 指令时，如果该类型没有进行过任何初始化，则需要先触发其初始化阶段。能够生成这四条指令的典型 Java 代码有：

| 触发情况 | 说明 |
|---------|------|
| ==**使用 `new` 关键字实例化对象**== | 创建类的实例 |
| ==**读取或设置一个类型的静态字段**== | 访问静态变量 |
| ==**调用一个类型的静态方法**== | 调用静态方法 |
| ==**使用反射包的方法对类型进行反射调用**== | 如果此时没有进行初始化时，会先触发初始化 |
| ==**当初始化类时，发现其父类还没有进行过初始化**== | 先触发父类的初始化 |
| ==**JVM 启动时用户指定的主类**== | 虚拟机先初始化这个主类 |
| ==**JDK 7 以上动态语言支持**== | 方法句柄的最后解析是 `REF_getStatic`、`REF_putStatic`、`REF_invokeStatic`、`REF_newInvokeSpecial` 四种类型 |
| ==**接口中定义了 `default` 方法**== | 如果这个接口的实现类发生了初始化，那该接口会在其之前被初始化 |

### 四、子类与父类静态方法


-   静态方法是**类级别**的，不存在"子类覆盖父类静态方法"（Java 静态方法不支持多态）。
-   通过**子类调用**继承自父类的静态方法时，实际上是**父类的静态方法被执行**，但 JVM 会**先初始化父类**。
-   子类中定义的同名静态方法，只是**隐藏**了父类的静态方法，不是重写。

### 五、面试要点

| 问题            | 回答                                        |
| ------------- | ----------------------------------------- |
| **类加载的七个阶段**      | ==**加载 → 验证 → 准备 → 解析 → 初始化 → 使用 → 卸载**== |
| **哪些阶段属于连接**      | ==**验证、准备、解析**==                          |
| **解析阶段可以后于初始化吗**  | ==**可以**==，为了支持动态绑定                       |
| **触发初始化的典型场景**    | `new`、访问静态字段、调用静态方法、反射、父类未初始化、主类启动        |
| **准备阶段为静态变量赋什么值** | ==**零值**==，不是用户代码中的初始值                    |
