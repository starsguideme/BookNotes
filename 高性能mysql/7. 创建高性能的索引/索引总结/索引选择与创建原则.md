
### 一、选择索引的三个核心考量

在 MySQL 中，大多数情况下使用的都是 B 树，其他类型的索引大多只能适用于特殊场景。因此在什么场景下选择相适应的索引方式是很重要的事，因为这会大幅度减少查询时间。在选择并创建索引时，有三个方面是需要考虑的：

| 考量维度 | 说明 |
|---------|------|
| ==**单行访问总是很慢**== | 单行访问需要随机 I/O，磁盘寻道开销大，应尽量避免 |
| ==**按顺序访问范围数据是很快的**== | 顺序 I/O 不需要多次磁盘寻道，比随机 I/O 快很多；如果服务器能够按需顺序读取数据，那么就不再需要额外的排序操作，使用 `GROUP BY` 查询也无需再做排序和按行进行聚合计算 |
| ==**索引覆盖查询是很快的**== | 如果一个索引包含了查询需要的所有列（[[覆盖索引]]），那么存储引擎就不需要再回表后查询行，这可以避免大量的单行查询 |

### 二、编写查询语句的原则

综上所述，编写查询语句和创建索引时应遵循以下原则：

| 原则 | 说明 |
|------|------|
| ==**1. 尽可能选择合适的索引以避免单行查找**== | 单行访问是随机 I/O，性能较差 |
| ==**2. 尽可能使用数据内部顺序从而避免额外的排序操作**== | 利用索引的有序性，避免 `ORDER BY` 和 `GROUP BY` 的额外排序 |
| ==**3. 尽可能使用索引覆盖查询**== | 避免回表，减少随机 I/O |
| ==**4. 通过 `Explain` 分析响应时间的快慢并以此创建合适的索引**== | 使用 `EXPLAIN` 查看查询计划，分析是否用了索引、是否有回表 |
| ==**5. 根据全表结构选择合适的索引**== | 结合表的字段类型、查询频率、数据分布来选择索引 |

### 三、面试要点

| 问题                      | 回答                                            |
| ----------------------- | --------------------------------------------- |
| **选择索引的三个核心考量**         | ==**单行访问慢、顺序访问快、索引覆盖快**==                     |
| **为什么顺序 I/O 比随机 I/O 快** | 顺序 I/O 不需要**多次磁盘寻道**                          |
| **如何避免额外排序操作**          | 利用索引的**有序性**，避免 `ORDER BY` 和 `GROUP BY` 的额外排序 |
| **如何分析查询性能**            | 使用 ==**`EXPLAIN`**== 查看查询计划                   |
| **什么是索引覆盖查询**           | 索引包含查询需要的**所有列**，无需回表                         |
