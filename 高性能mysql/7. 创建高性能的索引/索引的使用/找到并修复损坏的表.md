
### 一、表损坏的原因

如果发现表被损坏，可能是由于硬件问题、MySQL 本身的问题或者操作系统的问题导致的索引损坏。这些都是有可能导致表损坏的原因。

### 二、检测损坏的表

要想查找库中已被损坏的表，可以通过 **`CHECK TABLE`** 来查看。

| 命令                    | 说明               |
| --------------------- | ---------------- |
| ==**`CHECK TABLE`**== | 检查表是否损坏，返回表的健康状态 |

### 三、修复损坏的表

当使用损坏的索引时，会返回错误的结果或出现莫须有的 **primary key 冲突**问题，严重时还会导致**数据的崩溃**。此时可以通过 **`REPAIR TABLE`** 命令来修复损坏的表。

但由于不是所有的存储引擎都支持该命令，此时可以通过以下替代方式：

| 修复方式                    | 说明                                                    |
| ----------------------- | ----------------------------------------------------- |
| ==**`REPAIR TABLE`**==  | 直接修复损坏的表，但**不是所有引擎都支持**                               |
| ==**空白的 ALTER 操作重建表**== | 通过 `ALTER TABLE table_name ENGINE=InnoDB` 来重建表结构，修复损坏 |
| ==**数据导出再导入**==         | 将数据导出后重新导入，间接重建表                                      |

### 四、无法修复的情况

不过如果损坏的是**系统区域**或**表的行数据区域**，而不是索引，那么以上两种方法（`REPAIR TABLE` 和重建表）**均无法使用**，只能通过**备份**来恢复数据。

### 五、面试要点

| 问题        | 回答                                                   |
| --------- | ---------------------------------------------------- |
| **表损坏的可能原因**  | ==**硬件问题、MySQL 本身问题、操作系统问题**==                       |
| **如何检测损坏的表**  | 使用 ==**`CHECK TABLE`**==                             |
| **如何修复损坏的表**  | 使用 `REPAIR TABLE`，或通过**重建表**（空白 ALTER 操作），或**导出再导入** |
| **什么情况下无法修复** | 损坏的是**系统区域**或**行数据区域**时，只能通过**备份恢复**                 |
