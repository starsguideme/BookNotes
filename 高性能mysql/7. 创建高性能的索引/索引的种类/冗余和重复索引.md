
### 一、重复索引

因为 MySQL 允许在相同的列上创建多个相同的索引，虽然会抛出警告，但依旧允许你这么做。因此 MySQL 需要单独维护重复的索引，优化器在优化查询时也会逐个地进行评估。正因如此，这对**磁盘 I/O**产生大量的负担——维护重复索引需要额外的存储空间，每次写入操作也需要更新多个索引。

| 问题 | 说明 |
|------|------|
| ==**重复索引的定义**== | 在**相同的列**上创建了**多个相同类型**的索引 |
| ==**重复索引的危害**== | 浪费存储空间、增加写入开销、让优化器评估时增加额外负担 |

### 二、冗余索引

冗余索引与重复索引会有一些不同。如果创建了索引 `(A, B)`，再创建索引 `A` 就是**冗余索引**，因为索引 `A` 只是索引 `(A, B)` 的**前缀索引**。因此索引 `(A, B)` 也可以当做索引 `A` 来使用，这种冗余是针对 B+ 树来说的。

但是如果在创建索引 `(A, B)` 之后，再创建索引 `(B, A)`，则**不算**是冗余索引。因为之前创的是 `(A, B)` 而不是 `(B, A)`，因此索引 `B` 也不是冗余索引，因为索引 `B` 不是索引 `(A, B)` 的前缀索引（此前缀索引是 `A`）。另外，如果创建的**不是前缀索引的其他索引**，对于 B+ 树索引来说都**不是冗余的**。

冗余索引通常发生在为表中添加索引的时候。

| 场景 | 是否冗余 | 说明 |
|------|---------|------|
| ==**已有 `(A, B)`，再创建 `A`**== | ==**是冗余**== | `A` 是 `(A, B)` 的前缀索引 |
| ==**已有 `(A, B)`，再创建 `B`**== | **不是冗余** | `B` 不是 `(A, B)` 的前缀索引 |
| ==**已有 `(A, B)`，再创建 `(B, A)`**== | **不是冗余** | 不是前缀索引关系 |

### 三、有时需要冗余索引

大多数情况下虽然冗余索引都是不必要的，但有时候出于**性能考虑**也需要冗余索引。因为扩展已有的索引会变得很大，反而会影响数据查询——维护索引也是需要开销的。比如一个已有索引已经包含了很多列，如果在其上继续扩展，会导致索引页的存储空间变大，查询效率反而降低。此时单独创建一个更紧凑的索引，反而能提升查询性能。

### 四、面试要点

| 问题                            | 回答                                         |
| ----------------------------- | ------------------------------------------ |
| **重复索引和冗余索引的区别**                  | 重复索引是在**相同列**上创建**多个相同**索引；冗余索引是**前缀索引**关系 |
| **重复索引的危害**                       | 浪费存储空间、增加写入开销、增加优化器评估负担                    |
| **已有 `(A, B)`，再创建 `(B, A)` 是冗余吗** | ==**不是**==，`(B, A)` 不是 `(A, B)` 的前缀索引      |
| **什么情况下可以保留冗余索引**                 | 当扩展已有索引会使其变得**过大**，反而影响查询性能时               |
