
### 一、核心定义

可以**只访问索引**，而无须访问数据行的方式叫做**覆盖索引**。即查询只需要扫描索引即可获取所有需要的数据，不需要回表。

### 二、触发条件

要触发覆盖索引，需要满足以下两个条件：

| 条件 | 说明 |
|------|------|
| ==**索引包含查询所需的全部字段**== | 查询中涉及的所有列都包含在索引中 |
| ==**不能访问额外的字段**== | 如果访问了索引之外的额外字段，则覆盖索引会失效 |

### 三、案例分析

```sql
SELECT user_id, status, create_time
FROM orders
WHERE user_id = 1;
```

**触发覆盖索引的前提**：`user_id`、`status`、`create_time` 三个字段已经创建了**[[联合索引]]**。

**执行效果**：

| 情况 | 说明 |
|------|------|
| ==**满足覆盖索引**== | 查询只访问索引即可返回所有结果，**不需要回表**，性能极高 |
| ==**多访问了额外字段**== | 覆盖索引会失效，需要**回表**进行全表扫描访问数据，性能下降 |

**修正说明**：回表时通常是根据主键进行**随机 I/O**，不一定是"全表扫描"，但确实需要访问数据行，性能比覆盖索引差很多。

### 四、覆盖索引的优势

| 优势 | 说明 |
|------|------|
| ==**避免回表**== | 查询只需要访问索引，不需要回到主键索引中查找数据行 |
| ==**减少随机 I/O**== | 索引通常比数据行更紧凑，扫描索引的成本更低 |
| ==**提高查询性能**== | 能显著减少磁盘 I/O 次数 |
