### 一、三个核心指标

在确定了要查询的数据后，就需要看下是否为了该查询结果扫描了过多的数据。对于 MySQL 来说，最简单的衡量查询的三个指标如下：

| 指标 | 说明 |
|------|------|
| ==**响应时间**== | 数据库处理查询的**总时间**，包括服务时间和排队时间 |
| ==**扫描的行数**== | 查询过程中扫描的数据行数 |
| ==**返回的行数**== | 查询最终返回给客户端的数据行数 |

### 二、响应时间

响应时间大致可以分为两个部分：

| 组成部分         | 说明                                 |
| ------------ | ---------------------------------- |
| ==**服务时间**== | 数据库处理这个查询的**真实时间**                 |
| ==**排队时间**== | 服务器因为等待某些资源的**等待时间**（如等待磁盘 I/O、行锁） |

**快速上限估计算法**：可以根据查询需要哪些索引和它的目的，来推断多个需要多少**顺序 I/O 和随机 I/O**，并根据硬件来计算得出，以此判断该响应时间是否合理。

### 三、扫描的行数

扫描的行数根据目的不同，又可以分为两个维度：

**1. 扫描的行数与返回的行数的关系**

在使用 `EXPLAIN` 分析查询的时候，查看该查询扫描的行数是很有必要的，因为它可以在一定程度上反映该查询的效率。但由于每行的查询时间并不相同，所以它并不能很好地定位某行慢查询的问题。

在理想情况下，**扫描的行数应该和返回的行数相同**，可实际并不允许，其大部分情况下都是 **N:1** 的关系（扫描了 N 行，只返回了 1 行）。

**2. 扫描的行数与访问类型的关系**

在评估查询开销时，需要考虑从表中找到某行数据的成本。在 MySQL 中有几种方法可以查找并返回结果：

| 访问方式         | 说明                    |
| ------------ | --------------------- |
| ==**多行扫描**== | 需要扫描多行数据才能找到目标        |
| ==**单行扫描**== | 通过主键或唯一索引，只需访问一行      |
| ==**无扫描**==  | 通过覆盖索引直接返回结果，不需要访问数据行 |

**如果没有使用合适的索引**，数据库在查询时会进行**全表扫描**。如果此时有 `WHERE` 来筛选条件，MySQL 会通过以下三种方式来使用 `WHERE`，从好到坏依次为：

| 优先级 | 方式 | 说明 |
|--------|------|------|
| ==**最好**== | 在索引中使用 WHERE 条件来过滤不匹配的记录 | 利用索引，过滤发生在存储引擎层 |
| ==**中等**== | 使用覆盖索引扫描来返回记录 | 直接从索引中过滤不需要的记录并返回命中的结果，**不会扫全表** |
| ==**最差**== | 从数据表中返回数据并过滤其中不满足条件的记录 | 需要**扫全表**，在服务器层过滤 |

### 四、三个指标与慢查询日志

以上三个指标可以粗略地表示查询的开销，但它们也反映了 MySQL 内部在执行查询时需要多少数据，并以此推出大致所需时间。这三个指标都会被记录到 MySQL 对应的**慢日志**中。

因此查询**慢日志**可以有效地找出被扫描过多的行数。如果发现查询需要扫描大量的数据但只返回少数行，就可以通过以下三种方式进行优化：

| 优化方式 | 说明 |
|---------|------|
| ==**使用索引覆盖扫描**== | 避免回表，减少扫描行数 |
| ==**改变库表结构**== | 如使用汇总表、拆分表等 |
| ==**重写这个复杂的查询**== | 将复杂查询拆分为多个简单查询，或使用 `LIMIT` 限制 |

### 五、面试要点

| 问题                  | 回答                             |
| ------------------- | ------------------------------ |
| **衡量查询开销的三个指标**         | ==**响应时间、扫描的行数、返回的行数**==       |
| **响应时间的两个组成部分**         | ==**服务时间**== 和 ==**排队时间**==    |
| **理想情况下扫描行数和返回行数的关系**   | ==**1:1**==，实际大多是 **N:1**      |
| **`WHERE` 的三种过滤方式从好到坏** | ==**索引过滤 → 覆盖索引过滤 → 全表扫描过滤**== |
| **如何发现扫描过多的行**          | 查询 ==**慢日志**==                 |
| **发现扫描过多行后如何优化**        | ==**使用覆盖索引、改变表结构、重写查询**==      |
