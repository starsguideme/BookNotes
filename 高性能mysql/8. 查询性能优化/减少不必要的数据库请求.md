
### 一、请求超过实际需要的数据

有些查询会请求超过实际需要的数据，然后这些多余的数据会被应用程序丢弃。这会给 MySQL 服务器带来额外的负担，并增加网络开销，另外，这也会消耗应用服务器的 CPU 和内存资源。

**典型的错误**：

| 错误                        | 说明                                                                                                                                  |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| ==**误以为 MySQL 会按需返回数据**== | 实际上是 MySQL **先返回全部结果再进行计算**。先使用 `SELECT` 语句查询大量的结果，然后获取前面的 N 行关闭结果集。会误以为 MySQL 会执行查询，并只返回所需的数据并停止查询，但实际上是 MySQL 会**扫全表**后丢弃大量不必要的数据 |

**解决方案**：加上 **`LIMIT`** 关键字是很有必要的，让 MySQL 只返回需要的数据量。

### 二、多表联结时返回全部列

根据范围查找永远比纯 `SELECT *` 要快很多，因为**范围查找或许能用到索引**来加速查询，但**全表查询一定是无法使用索引**的，因此全表查询会带来大量不必要的磁盘 I/O、内存和 CPU 的消耗。

| 错误 | 说明 |
|------|------|
| ==**多表联结时返回全部列**== | 使用 `SELECT *` 获取所有列，即使业务只需要其中的几列 |
| ==**范围查找优于全表**== | 范围查找可能使用索引；全表查询无法使用索引 |

**解决方案**：只查询需要的列，避免使用 `SELECT *`。

### 三、重复查询相同的数据

不断的重复执行相同的查询（如循环查询），每次查询都会返回完全相同的数据。这一定会带来不必要的磁盘 I/O、网络开销和 CPU 资源浪费。

| 错误                | 说明                         |
| ----------------- | -------------------------- |
| ==**重复执行相同的查询**== | 在循环中反复执行相同的 SQL，每次都需要访问数据库 |

**解决方案**：最好在查询时将这个数据**缓存**起来，然后从缓存中取出。

### 四、面试要点

| 问题          | 回答                                       |
| ----------- | ---------------------------------------- |
| **查询优化的三个常见误区** | ==**请求超过实际需要的数据、多表联结时返回全部列、重复查询相同的数据**== |
| **如何避免请求过多数据**  | 使用 ==**`LIMIT`**== 关键字                   |
| **如何避免返回全部列**   | 只查询需要的列，避免 **`SELECT *`**                |
| **如何避免重复查询**    | 将数据**缓存**起来，从缓存中取出                       |
