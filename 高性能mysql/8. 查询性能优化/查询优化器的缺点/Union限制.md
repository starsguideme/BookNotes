### 一、UNION 查询的优化限制

有时，MySQL 在实现 `UNION` 联接查询时，无法将优化器和筛选条件一直**下推**到多表查询中。这会让原本能够限制的部分返回结果无法被完成整套的优化。

**核心原因**：`UNION` 需要先将各个子查询的结果合并到**临时表**中，再对临时表进行去重和排序。这个过程中，原本可以下推到各个子查询的 `LIMIT` 或 `WHERE` 条件，可能无法被有效利用。

### 二、UNION 中使用 LIMIT 的正确方式

如果此时希望 `UNION` 的各个子句能够根据 `LIMIT` 来获得部分结果集，或者希望能够先排好序然后合并结果集并返回的话，就需要在 `UNION` 所创建的**临时表**上加上 `LIMIT` 筛选条件。

但需要注意的是，**`LIMIT` 并不能保证临时表会变得有序**。如果需要按照自己的想法进行排序，还需要同时加上 `ORDER BY`。

### 三、正确用法示例

```sql
-- 错误用法：LIMIT 放在各个子查询中，可能无法获得期望的结果
(SELECT * FROM t1 LIMIT 10)
UNION
(SELECT * FROM t2 LIMIT 10);

-- 正确用法：将 LIMIT 和 ORDER BY 放在整个 UNION 的临时表上
(SELECT * FROM t1)
UNION
(SELECT * FROM t2)
ORDER BY id
LIMIT 10;
```

### 四、面试要点

| 问题                         | 回答                                           |
| -------------------------- | -------------------------------------------- |
| **`UNION` 查询中 `LIMIT` 应该放在哪里** | 放在 `UNION` 所创建的**临时表**上，而不是各个子查询中            |
| **`LIMIT` 能保证结果有序吗**           | ==**不能**==，需要同时使用 `ORDER BY` 才能保证排序          |
| **`UNION` 和 `UNION ALL` 的区别**  | `UNION` 会**去重**（需要临时表），`UNION ALL` 不去重（性能更好） |
| **`UNION` 为什么要使用临时表**          | 为了对多个子查询的结果进行**合并和去重**                       |
