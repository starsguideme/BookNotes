
MySQL 的存储引擎接口和执行引擎从设计上就是**单线程**的，单个查询在一个线程里串行执行，所以**无法利用多核并行执行单条 SQL**。

### 无法并发查询的原因

MySQL 的存储引擎（如 InnoDB）的 API 是**一次一条记录**地“拉取”数据，这种接口设计天然就不适合多线程并行扫描。因此优化器也只能生成**串行执行计划**，不会生成可并行的计划。

### 完整因果链

```text
存储引擎 API 设计为单线程
    ↓
执行引擎只能串行执行
    ↓
优化器只生成串行执行计划
    ↓
单条 SQL 无法利用多核并行执行
    ↓
MySQL 不支持单查询内部的并发执行
```

**面试话术**：MySQL 的存储引擎接口是单线程的，执行引擎只能串行执行，所以单条 SQL 无法利用多核并行。这是设计层面的限制，不是调优能解决的。需要单查询并行的场景，应该选 ClickHouse、Doris 这类分析型数据库。继续按你的节奏走，你的知识网络已经越来越完整了。
