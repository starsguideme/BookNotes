
### 一、核心定义

在某些时候，等值传递会带来额外的消耗。优化器通过将**列表复制到所有与其相关的对应列中**来完成共享的操作。这是优化器在生成执行计划时的一种优化策略，目的是让各个表都能利用 `WHERE` 条件中的等值关系来缩小扫描范围。

### 二、等值传递的优势

在通常情况下，因为各个表新增了过滤条件，所以优化器可以更高效地从存储引擎筛选记录。

**示例**：

```sql
SELECT * 
FROM t1
JOIN t2 ON t1.id = t2.id
WHERE t1.id = 100;
```

优化器会将 `t1.id = 100` 传递给 `t2.id`，使 `t2` 表也获得 `t2.id = 100` 的过滤条件，从而利用 `t2` 表上的索引加速查询。

### 三、等值传递的劣势

如果出现这个列很大，则会因为字段和索引的缘故导致**复制、优化和执行会变得很慢**：

| 场景 | 说明 |
|------|------|
| ==**大字段列的等值传递**== | 如果被传递的列是长字符串、大文本等类型，复制这个条件本身就会消耗资源 |
| ==**多表联接的等值传递**== | 表数量多时，等值传递会让每个表都带上过滤条件，优化器评估的组合会变多，优化时间会变长 |
| ==**索引维护成本**== | 等值传递产生的额外条件可能让优化器选择不合适的索引 |

### 四、面试要点

| 问题      | 回答                                           |
| ------- | -------------------------------------------- |
| **什么是等值传递** | 优化器将 `WHERE` 中的等值条件**复制到所有相关表**，让每张表都能利用过滤条件 |
| **等值传递的优势** | 各表新增过滤条件，优化器可以更高效地筛选记录                       |
| **等值传递的劣势** | 当列很大或表很多时，会导致**复制、优化和执行变慢**                  |
| **等值传递的本质** | 优化器对**共享操作**的优化，通过复制条件来缩小扫描范围                |
