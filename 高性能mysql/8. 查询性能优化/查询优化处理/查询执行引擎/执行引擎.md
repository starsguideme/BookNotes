
### 一、查询执行阶段的核心

在[[查询优化器]]中的解析和优化阶段，MySQL 会根据生成的**查询计划**来执行，MySQL 也会根据**执行引擎**的选择来完成整个查询。

### 二、查询执行与查询优化的对比

| 阶段 | 核心工作 | 复杂程度 |
|------|---------|---------|
| ==**查询优化阶段**== | 选择索引、决定联接顺序、生成最优执行计划 | 非常复杂，涉及成本估算 |
| ==**查询执行阶段**== | 根据执行计划给出的指令**逐步执行** | 相对简单，按部就班 |

### 三、存储引擎接口的调用

在根据执行计划逐步执行的过程中，有大量的操作只需通过调用**存储引擎实现的接口**来完成（如 `InnoDB` 或 `MyISAM` 的 API）。

**执行过程中的流程**：

```text
① 优化器生成执行计划
    ↓
② 查询执行引擎根据执行计划逐步执行
    ↓
③ 大量底层操作通过调用存储引擎 API 完成
    ↓
④ 每次查询后会生成一个 handler 对象
    ↓
⑤ 优化器根据 handler 对象获取表的相关信息
```

### 四、handler 对象的作用

每次查询完之后会诞生一个 **handler 对象**。优化器会根据这个 handler 对象获取表的相关信息。

| 作用 | 说明 |
|------|------|
| ==**存储表信息**== | handler 对象中保存了表的统计信息、索引信息等 |
| ==**供优化器使用**== | 优化器通过 handler 对象了解表的结构，辅助生成执行计划 |

### 五、面试要点

| **问题**                | 回答                               |
| ----------------- | -------------------------------- |
| **查询执行阶段和优化阶段的区别**    | 优化阶段复杂，负责生成执行计划；执行阶段简单，按计划逐步执行   |
| **查询执行中大量底层操作通过什么完成** | 通过调用**存储引擎 API** 完成              |
| **handler 对象是什么**     | 每次查询后生成的**表信息对象**，优化器通过它获取表的相关信息 |
