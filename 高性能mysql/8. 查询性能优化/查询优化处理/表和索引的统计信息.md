
### 一、核心关系

因为服务器没有存储任何统计信息，所以 MySQL 查询优化器在生成查询的执行计划时，需要向**存储引擎**获取相应的统计信息。

### 二、存储引擎提供的统计信息

存储引擎给优化器提供对应的统计信息包括但不限于：

| 统计信息 | 说明 |
|---------|------|
| ==**每个表或索引具有多少页**== | 数据页和索引页的总数量，用于估算扫描成本 |
| ==**每个表或索引的基数**== | 索引列不同取值的数量，基数越大，索引区分度越高 |
| ==**数据行和索引长度**== | 每行数据的平均长度，用于估算内存和磁盘开销 |
| ==**索引的分布信息**== | 数据在索引中的分布情况，用于判断索引是否有效 |

优化器会从这些统计信息中**选择一个最优执行计划**。

### 三、统计信息的存储位置

| 存储引擎 | 统计信息存储方式 |
|---------|----------------|
| ==**InnoDB**== | 通过**抽样**方式计算统计信息，存储在内存中，持久化到 `mysql.innodb_table_stats` 和 `mysql.innodb_index_stats` 表中 |
| ==**MyISAM**== | 将统计信息存储在磁盘上，分析速度较慢 |

### 四、面试要点

| 问题               | 回答                         |
| ---------------- | -------------------------- |
| **优化器的统计信息来自哪里**     | ==**存储引擎**==               |
| **存储引擎提供哪些统计信息**     | ==**表的页数、基数、行长度、索引分布信息**== |
| **优化器如何选择执行计划**      | 根据统计信息，选择**成本最小**的执行计划     |
| **InnoDB 的统计信息如何获取** | 通过**抽样**方式计算               |
