
### 一、MySQL 的通信协议

在 MySQL 中通常使用的通信协议是**半双工**形式（基于 TCP 协议）。这意味着在任何时刻，要么是由服务器向客户端发送数据，要么是客户端向服务器发送数据，但两者**不能同时发生**。

### 二、半双工协议的特点

| 特点 | 说明 |
|------|------|
| ==**优点**== | 通信简单快速，协议实现简单 |
| ==**缺点**== | 无法进行**流量控制**。一旦开始发送消息，另一端必须要接收其全部信息才可以发送消息 |

### 三、客户端发送查询的限制

客户端用一个**单独的数据包**将查询发送给服务器。这导致查询语句过长时，参数 **`max_allowed_packet`** 就变得逐渐重要。由于通信协议是半双工的形式，因此一旦客户端发送了请求，该客户端只能**等待服务器响应**了。

### 四、服务器响应结果集

服务器响应给用户的数据通常是非常多的，且由**多个数据包**组成。当服务器开始响应客户端请求时，客户端会按**组包的形式**得到完整的返回结果。

但不能以此仅依赖部分 ACK 回应的数据，或者是接受全部的组包 ACK 但舍弃掉部分数据，都会导致数据的不准确。因此只需要部分数据的话，在查询语句加上 **`LIMIT`** 是一种很好的选择。

### 五、使用缓存区的两种情况

**情况一：使用缓存区**

在绝大多数联接 MySQL 的库函数中，都可以将得到的**全部结果集缓存到内存里**，还可以逐行获取数据（如加上 `LIMIT`）。默认是获取全部的结果集后将其缓存到内存的缓冲区中。此时 MySQL 通常需要等所有数据确保客户端接收到发送的消息后，才能释放这条查询所占用的资源。

所以通过接收全部数据并缓存到内存中，一般情况下可以有效地**减少服务器的压力**的同时**加快查询**。

| 优点 | 说明 |
|------|------|
| ==**减少网络开销**== | 无需通过多次请求向服务器发送数据，直接从缓冲区中获取数据 |
| ==**减少查表开销**== | 避免多次查询数据库 |
| ==**减少 CPU 开销**== | 不需要反复执行查询解析和优化 |

**情况二：不使用缓存区**

如果不使用缓存区获取数据，在查询语句的时候，几乎是每次请求都要经过[[查询执行的步骤]]中的五个步骤。如果循环次数少的时候还行，可如果循环次数一旦变多，其**网络开销、CPU 消耗、多次查表带来的大量磁盘 I/O** 问题会非常严重。

| 缺点 | 说明 |
|------|------|
| ==**网络开销大**== | 每次请求都需要网络往返 |
| ==**CPU 消耗高**== | 每次请求都需要重新解析和优化 |
| ==**磁盘 I/O 频繁**== | 每次请求都需要查表 |

### 六、面试要点

| 问题             | 回答                                         |
| -------------- | ------------------------------------------ |
| **MySQL 使用什么通信协议** | ==**半双工**==协议（基于 TCP）                      |
| **半双工协议的限制**       | 无法进行**流量控制**，一方发送时另一方必须等待                  |
| **客户端发送查询用什么**     | ==**单独的数据包**==，受 `max_allowed_packet` 参数限制 |
| **使用缓存区的好处**       | ==**减少网络开销、查表开销、CPU 开销**==                 |
| **不使用缓存区的缺点**      | ==**网络开销大、CPU 消耗高、磁盘 I/O 频繁**==            |
