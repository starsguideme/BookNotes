
### 一、什么是线程状态？

在 MySQL 中亦或者是其一个线程中，任何时刻都会有一个**状态**，该状态表示了 MySQL 正在做的事。其中有很多种方式可以查看当前的状态，最简单的是使用 **`SHOW FULL PROCESSLIST`**。如果返回了 `Command` 列，该列中的数据就是该线程或表的状态。

但由于状态是动态的，因此就需要理解这些状态的含义。

### 二、状态表

| 状态 | 说明 |
|------|------|
| ==**`Sleep`**== | 线程正在等待客户端发送新的请求 |
| ==**`Query`**== | 线程正在执行查询或将要把结果发送给客户端 |
| ==**`Locked`**== | 在 MySQL 服务器层，该线程正在等待**表锁**。但在存储引擎上实现的锁（例如 InnoDB 的行锁），不会被显示为 `Locked`，而是显示为其他状态 |
| ==**`Analyzing and statistics`**== | 线程正在检查存储引擎的统计信息并开始优化查询 |
| ==**`Copying to tmp table [on disk]`**== | 线程正在执行查询并将其结果复制到一个**临时表**中。正在此状态要么是在进行 `GROUP BY` 操作，要么就是进行**文件排序**操作，或是再进行 `UNION` 操作。如果这个状态后面还跟着 **`on disk`** 标记，那表示 MySQL 正在将一个**内存临时表放到磁盘上**进行持久化存储 |
| ==**`Sorting result`**== | 线程正在对结果集进行**排序** |

### 三、关键解读

**1. `Copying to tmp table [on disk]` 是重点排查信号**

这个状态说明查询正在使用**磁盘临时表**，通常发生在：
-   `GROUP BY` 或 `DISTINCT` 的字段没有索引
-   `ORDER BY` 与 `GROUP BY` 的字段不一致
-   数据量太大，内存临时表无法容纳，被溢出到磁盘

**磁盘临时表远比内存临时表慢**，当看到这个状态时，应检查查询是否可以优化。

**2. `Locked` 通常指表锁**

InnoDB 的行锁不会显示为 `Locked`，而是显示为其他状态（如 `updating`、`statistics`）。如果看到大量 `Locked` 状态，说明可能存在 MyISAM 表的表锁竞争问题。

| ----------------------------------------- | ------------------------------------------------------------------ |
| **如何查看 MySQL 线程状态**                       | 使用 ==**`SHOW FULL PROCESSLIST`**==                                 |
| **哪些线程状态说明存在性能问题**                        | ==**`Copying to tmp table [on disk]`、`Sorting result`、`Locked`**== |
| **`Copying to tmp table [on disk]` 说明什么** | 查询使用了**磁盘临时表**，通常由 `GROUP BY`、文件排序或 `UNION` 触发                     |
| **`Locked` 状态说明什么**                       | 线程正在等待**表锁**，行锁不会显示为 `Locked`                                      |
