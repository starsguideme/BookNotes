
### 一、核心思想

简单来说，就是将**大查询切分成小查询**，每个查询的功能是完全一样的，其只完成大查询的一小部分且只返回一小部分的查询结果。

### 二、典型应用场景

比如说**删除旧的数据**就是一个很好的例子。定期清除大量数据时，如果用一个大的语句一次性完成查询，就需要一次性锁住很多数据，可能会**占满整个事务日志并耗尽系统资源**。

因此将大查询切成较多且较小的查询，可以尽可能小地影响 MySQL 性能，同时降低复制时的延迟。在删除数据时也可以借鉴此方法，其是一种比较高级且对服务器影响较小的做法。

### 三、切分查询的优势

| 优势 | 说明 |
|------|------|
| ==**减少锁的持有时间**== | 每次只处理一小部分数据，锁的持有时间大幅缩短 |
| ==**分散服务器压力**== | 将压力分散到一个很长的时间段中，大大降低对服务器的影响 |
| ==**降低复制延迟**== | 小事务在主从复制时更快完成，减少从库延迟 |
| ==**避免耗尽系统资源**== | 不会一次性占满事务日志或耗尽内存 |

### 四、需要注意的点

如果每次删除数据后都需要**停顿后再做一次删除**，其会把服务器上次的压力分散到一个很长的时间段中，这会大大降低对服务器的影响，也可以减少锁的持有时间。

### 五、与微服务思想的类比

你补充的类比非常精准：这确实和**微服务的思想模型**类似——将大查询分成若干个小查询，然后小查询之间彼此互相独立的同时，分别完成大查询的一小部分并返回查询到的数据。这样的目的就是方便维护、减少开销、减少使用功能的所需时间。
