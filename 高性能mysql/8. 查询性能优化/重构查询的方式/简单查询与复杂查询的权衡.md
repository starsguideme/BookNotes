

-   简单查询可以适用于单次复杂查询无法满足性能的需求，因为多个简单查询可以大幅度减少延迟。
-   在 MySQL 内部中，如果要将查询到的数据返回给客户端时会慢得多。这时如果需要快速返回给前端，应该使用一次复杂的查询。



| 场景                   | 推荐方式           | 原因                                  |
| -------------------- | -------------- | ----------------------------------- |
| ==**数据在同一台服务器上**==   | **复杂查询（JOIN）** | 简单查询需要多次网络往返，每次往返都有延迟开销；复杂查询只需要一次往返 |
| ==**数据分布在不同的服务器上**== | **简单查询（拆分）**   | 跨服务器的 JOIN 代价极高，拆分查询后由应用层聚合反而更快     |
|                      |                |                                     |

**核心矛盾**：在 MySQL 内部做 JOIN 通常比在应用层做多次简单查询要快，因为**网络往返次数少**。但简单查询的优势在于**应用层缓存**——如果部分数据可以被缓存复用，简单查询的总体开销就会降低。

### 三、面试要点

| **问题**            | 回答                                               |
| ----------------- | ------------------------------------------------ |
| **简单查询和复杂查询如何选择** | 数据在同一台服务器时，优先使用**复杂查询**；数据分布在不同服务器时，优先使用**简单查询** |
| **简单查询的优势**       | 可以利用**应用层缓存**，减少重复查询                             |
| **复杂查询的优势**       | 减少**网络往返次数**，在服务器内部完成数据处理                        |
