1. 一条 SELECT 语句性能差，最常见的原因是访问了太多不必要的数据。优化思路分为两个层面：
    
    **1.1 应用程序层面：是否查询了大量不必要的数据**
    
    - 是否使用了 `SELECT *`导致不必要的列
        
    - 是否缺少 `LIMIT`导致返回不必要数量的行
        
    - 是否重复查询相同数据，应考虑缓存
        
    - WHERE 条件是否能有效过滤数据
        
    
    **1.2 服务器层面：是否分析了大量不必要的数据行**
    
    - 使用 EXPLAIN 查看执行计划
        
    - 关注 `rows` 列（估算扫描行数）
        
    - 关注 `type` 列（访问类型，ALL 和 index 是警告信号）
        
    - 关注 `Extra` 列（`Using filesort`、`Using temporary` 说明有额外开销）
 1. 有些查询会请求超过实际需要的数据，多余的数据最终被应用程序舍弃。这会增加 MySQL 服务器负担、网络开销，以及应用服务器的 CPU 和内存消耗。
    
2. 以下是错误的典型案例：
    
    **1.2.1 漏加 LIMIT**
    
    - 误区：以为 MySQL 会按需返回数据
        
    - 实际：MySQL 先查出所有符合条件的行，应用程序再舍弃多余的数据
        
    - 解决：加上 `LIMIT` 子句，让 MySQL 在扫描到足够行数后立即停止
        
    
    **1.2.2 多表连接时 SELECT ***
    
    - 错误做法：两个 INNER JOIN 后用 `SELECT *` 返回全部列
        
    - 正确做法：只查真正需要的列，减少网络传输和内存消耗
